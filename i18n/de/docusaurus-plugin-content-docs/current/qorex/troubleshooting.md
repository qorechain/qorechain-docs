# Fehlerbehebung

Häufige Fragen und schnelle Lösungen für die QoreX-App und -Erweiterung.

| Symptom | Ursache / Lösung |
|---|---|
| **„Sichern Sie zuerst Ihr Gerät"** beim Onboarding | Richten Sie Face ID / einen Fingerabdruck **oder eine Bildschirmsperre (PIN / Muster)** in Ihren Systemeinstellungen ein und kehren Sie dann zurück. Ein Wallet kann nur auf einem Gerät mit einem starken Entsperrfaktor erstellt werden. Unter Android ist die 2D-Gesichtsentsperrung allein eine *schwache* Biometrie - die dahinterliegende PIN ist das, was qualifiziert. |
| **Anmeldeblatt geschlossen** / „Dieser Anmeldeversuch ist abgelaufen" | Ein vorheriger Versuch wurde abgebrochen - tippen Sie einfach erneut auf Anmelden. |
| **„Passkey hinzufügen" fehlt** nach der Anmeldung über Google / Dashboard | Erwartet: Passkeys werden nur an Konten mit E-Mail-Code angehängt (siehe den Hinweis unter [Konto & Dashboard](/qorex/account-and-dashboard#sign-in)). |
| **„Handles in Kürze verfügbar"** | Das @handle-Register ist vorübergehend nicht erreichbar. Ihr Wallet ist nicht betroffen; Handles werden automatisch aktiviert, sobald das Register zurückkehrt. |
| **Erweiterung: Das Bezahlen eines @handles schlägt mit einem Fehler zur Abfrage fehl** | Behoben in Erweiterung **0.3.7** und später (jeder Store liefert jetzt 0.3.8 oder neuer aus). Ist Ihre Erweiterung älter, aktualisieren Sie sie auf der Erweiterungsseite Ihres Browsers; bis dahin fügen Sie stattdessen die `qor1…`-Adresse ein oder verwenden Sie die mobile App. |
| **Die Erweiterung bietet keine Möglichkeit, ein @handle zu beanspruchen** | Erwartet: Das Beanspruchen erfordert ein angemeldetes Konto und erfolgt in der mobilen App. Einmal beansprucht, können Sie es aus der Erweiterung bezahlen und auflösen. |
| **Ein Handle, das ich beanspruchen wollte, wird als reserviert abgelehnt** | Namen, die QoreChain nachahmen (seine Markennamen oder Vertrauenswörter wie *official*, *support*, *airdrop*, *treasury*, einschließlich ähnlich aussehender Schreibweisen), sind reserviert. Wählen Sie ein anderes Handle. |
| **Eine Genehmigung besagt, QoreX könne die Anfrage nicht anzeigen, oder lehnt sie als mehrdeutig ab** | QoreX zeigt keine Anfrage an, die es nicht entschlüsseln kann, oder deren Bytes sich auf zwei Arten lesen ließen (zum Beispiel ein wiederholtes Feld, sodass eine Gebühr oder ein Betrag auf dem Bildschirm anders gelesen wird als on-chain). Suchen Sie keinen Umweg - die Website sendet etwas Unsicheres oder Nicht-Unterstütztes. |
| **QoreX warnt, dass sich die Adresse eines Handles geändert hat** | Erwartetes Sicherheitsverhalten, kein Fehler - QoreX merkt sich die Adresse, zu der ein Handle beim ersten Mal, als Sie ihn bezahlt haben, aufgelöst wurde, und markiert eine spätere Änderung, anstatt ihr stillschweigend zu vertrauen. Bestätigen Sie die neue Adresse auf einem unabhängigen Kommunikationsweg beim Empfänger, bevor Sie fortfahren. |
| **Senden wegen „mehr als Ihr verfügbares Guthaben" abgelehnt** bei einem Vesting-Konto | Ein Teil Ihres Guthabens ist noch durch einen Vesting-Zeitplan gesperrt. Nur der **verfügbare** Anteil (angezeigt auf Startseite, Senden und in den Asset-Details) kann gesendet werden; der Rest wird nach und nach freigeschaltet. |
| **Eine Wallet-Anfrage besagt, sie sei „für Testnet/Mainnet, Ihr Wallet ist aber auf…"** | Die Anfrage (z. B. vom Dashboard) richtet sich an ein anderes Netzwerk als das, mit dem Sie gerade verbunden sind. Wechseln Sie zuerst selbst das Netzwerk, falls das beabsichtigt war - QoreX wechselt nicht automatisch für Sie. |
| **„Falscher Code oder beschädigter QR"** beim Verknüpfen von Geräten | Überprüfen Sie den 10-stelligen Code erneut (das Alphabet lässt ähnlich aussehende Zeichen aus: kein 0/O/1/I/L) und scannen Sie erneut. Beide Artefakte sind einmalig verwendbar. |
| **Kamerabildschirm meldet, dass eine Berechtigung erforderlich ist** | iOS: Einstellungen → QoreX → Kamera. Android: App-Info → Berechtigungen → Kamera. |
| **Erweiterung: kein Wallet beim ersten Öffnen** | Die Erweiterung ist ein **eigenständiges** Wallet - öffnen Sie das Popup und wählen Sie **Neue Wallet erstellen** oder **Wiederherstellungsphrase importieren**. Die mobile App ist nicht erforderlich. |
| **Senden von einer schreibgeschützten Adresse abgelehnt** | Diese Adresse gehört zu einem anderen Wallet (die Bezeichnung zeigt, zu welchem). QoreX kann nur für seine eigenen abgeleiteten Konten signieren - senden Sie von dem Wallet, dem die Adresse gehört. |
| **Testnet-Badge wird angezeigt** | Einstellungen → **„Testnet verwenden (Entwickler)"** ist aktiviert. Deaktivieren Sie es, um zum Mainnet zurückzukehren. |
| **Swap-Schaltfläche ist deaktiviert** | Vorerst erwartet (Android) - Swap wird automatisch aktiviert, sobald Pool-Liquidität verfügbar ist; ein App-Update ist nicht erforderlich. Der Tab Swap wird unter iOS nicht angezeigt, und die Erweiterung hat keinen Swap-Bildschirm. |
| **Ich habe die App deinstalliert / die Erweiterung entfernt und sehe jetzt kein Wallet mehr** | Der Vault existierte nur auf diesem Gerät oder in diesem Browser. Wenn Sie Ihre 24-Wörter-Phrase gesichert hatten, stellen Sie das Wallet damit wieder her. Wenn Sie [Social Recovery](/qorex/security-and-recovery#social-recovery) eingerichtet hatten, starten Sie eine Wiederherstellung mit Ihren Guardians. Ohne eines von beidem kann das Wallet nicht wiederhergestellt werden - siehe [Jetzt sichern](/qorex/security-and-recovery#back-up-now), um jedes neue Wallet sofort zu schützen. |
| **Ich finde meine 24 Wörter nicht / die App hat sie mir nie angezeigt** | Die mobile App zeigt die Phrase nicht an, während sie das Wallet erstellt. Öffnen Sie **Einstellungen → Sicherheit → Wiederherstellungsphrase anzeigen** (Reveal recovery phrase), bestätigen Sie mit Biometrie oder Ihrer Geräte-PIN und schreiben Sie die Wörter dann auf. Verwenden Sie in der Erweiterung **Reveal recovery phrase** im Popup (Ihr Passwort ist erforderlich). Wenn sich das Wallet nur auf einem Telefon befindet, das Sie bereits verloren haben, kann QoreChain es nicht wiederherstellen - siehe [Jetzt sichern](/qorex/security-and-recovery#back-up-now). |
| **Ein finanziertes Konto ist aus „Ihre Konten" verschwunden** | Nichts ist verloren gegangen - jedes Konto wird erneut aus Ihrer Wiederherstellungsphrase abgeleitet, es handelt sich also um ein Anzeigeproblem, nicht um Datenverlust. Dies war ein echter, inzwischen behobener Fehler in mobilen Builds vor **1.0.9**: Ein kurzzeitig fehlgeschlagener Lesevorgang aus dem sicheren Speicher des Geräts (höchstwahrscheinlich genau beim Entsperren) konnte eine verkürzte Kontenliste anzeigen. Aktualisieren Sie QoreX (die Korrektur erschien in 1.0.9 und jeder späteren Version); falls Sie bereits auf dem aktuellen Stand sind und dies dennoch auftritt, sollte das Schließen und erneute Öffnen der App die Konten wieder anzeigen - das Antippen von „Konto hinzufügen" würde ein **neues** Konto erstellen, anstatt das fehlende wiederherzustellen, vermeiden Sie dies also, bis das vorhandene Konto wieder erscheint. |
| **„The EVM lane needs an open authorisation window for this account. Open one here first - MetaMask cannot."** (oder „Your EVM authorisation window has run out" oder „That authorisation window was refused") | Eine MetaMask-/EVM-Lane-Transaktion wurde abgelehnt, weil das Konto kein offenes Fenster hat (oder es hat die Blöcke, Transaktionen oder den Wert aufgebraucht). Öffnen Sie eines unter [EVM-Zugriffsfenster](/qorex/security-and-recovery#evm-window) (es ist für Ethereum-artige Coin-60-Konten gedacht) und versuchen Sie es dann erneut. Öffnen Sie es *bevor* Sie senden - das Öffnen eines Fensters erhöht die Konto-Nonce, sodass eine zuvor vorbereitete Transaktion mit „nonce too low" fehlschlägt. Hat Ihr Konto noch keinen ML-DSA-87-Schlüssel, weist QoreX Sie an, zuerst einen zu registrieren. |
| **„This network needs an updated QoreX. Update the app and try again - nothing was sent."** | Das Netzwerk verifiziert eine neuere Signaturform, als Ihr Build erzeugt. Aktualisieren Sie QoreX über Ihren Store und versuchen Sie es erneut; es wurde nichts gesendet und keine Gebühr erhoben. |
| **„Too many transactions from this account in a short time. Wait a minute and try again."** | Das Netzwerk begrenzt, wie viele Transaktionen ein Konto in kurzer Zeit senden kann. Warten Sie eine Minute. |
| **„That address can't receive ordinary transfers."** | Das Netzwerk lehnt einfache Überweisungen an diese Adresse ab (einige System- oder Modul-Adressen). Prüfen Sie den Empfänger. |
| **„Not enough unlocked QOR to pay the network fee. Vesting QOR cannot pay fees…"** oder **„Claiming needs about … QOR unlocked"** | Claims und das Unstaking zahlen ihre Gebühr aus Ihrem *entsperrten* Guthaben (bevor Belohnungen eintreffen). Senden Sie einen kleinen QOR-Betrag an diese Adresse und versuchen Sie es dann erneut. |
| **„The network ran out of gas before finishing. The fee was taken and nothing moved - your rewards are still there."** | Die Transaktion hat einen Block erreicht und ist dort fehlgeschlagen. Versuchen Sie es erneut; die Gebühr für den fehlgeschlagenen Versuch ist verbraucht. |
| **„Unstaking this much would drop your validator's self-bond below the required 100,000 QOR."** | Das betrifft nur Validator-Betreiber: Die Untergrenze für den Self-Bond gilt, solange der Validator läuft. Heben Sie weniger Stake auf. |
| **„Account 'qor1…' does not exist on chain"** beim Senden von einem Konto, das aus dem Dashboard oder aus MetaMask wiederhergestellt wurde | Aktualisieren Sie QoreX auf die aktuelle Version; das Konto ist ein Ethereum-artiges Konto (Coin 60) - siehe [Eine Phrase aus MetaMask oder dem Dashboard wiederherstellen](/qorex/getting-started#restore-dashboard). Das erste Senden registriert außerdem den ML-DSA-87-Schlüssel dieses Kontos (eine zusätzliche kleine Gebühr). |
| **Ich habe meine Phrase wiederhergestellt und mein zweites Konto / meine Guthaben fehlen** | Die Wiederherstellung bringt nur **Konto 1** zurück. Tippen Sie unter Einstellungen → Ihre Konten auf **Konto hinzufügen** (und bei einer Phrase, die in MetaMask oder im Dashboard verwendet wurde, auf **Ethereum-Konto hinzufügen (Coin 60)**) - die Konten werden an denselben Adressen erneut abgeleitet. |
| **Erweiterung: „Wallets" meldet, der Passkey sei deaktiviert worden** | Das Hinzufügen oder Entfernen eines Wallets versiegelt den Vault neu und hebt die Passkey-Entsperrung auf (sie konnte das neue Wallet nicht abdecken). Aktivieren Sie sie auf dem Startbildschirm des Popups erneut; Firefox bietet die Passkey-Entsperrung nie an. |
| **Es ist keine Push-Benachrichtigung eingetroffen** | Push gibt es nur im Mainnet und erfordert erlaubte Benachrichtigungen für QoreX in den Einstellungen Ihres Telefons sowie den eingeschalteten Schalter **Push-Benachrichtigungen** (Home → Glocke). Sie teilt Ihnen nur mit, dass QOR eingetroffen ist, nicht den Betrag; die Liste **Benachrichtigungen** in der App zeigt die Details. |
| **Android: die Zurück-Taste** | Zurück führt zum vorherigen Bildschirm; auf Home beendet sie die App. |
