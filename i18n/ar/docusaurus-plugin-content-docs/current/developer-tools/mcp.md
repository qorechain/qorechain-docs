# خادم MCP لـ QoreChain (`@qorechain/mcp`)

يمنح خادم MCP لـ QoreChain وكلاء الذكاء الاصطناعي وأدوات المطورين وصول قراءة إلى QoreChain عبر [Model Context Protocol](https://modelcontextprotocol.io): الكتل والمعاملات والحسابات والمدققين وطبقات التخزين (staking tiers) وحالة التوقيع الهجين secp256k1 مع ML-DSA-87 (FIPS 204) وقراءات عقود EVM والمحاكاة وتقديرات الرسوم والتحويلات غير الموقّعة التي يوقّعها مالك الحساب في محفظته. وهو موجّه للمطورين الذين يربطون عميلًا أو وكيلًا يدعم MCP بـ QoreChain، وللفرق التي تريد عرضًا للسلسلة قابلًا للبرمجة وللقراءة فقط بمخرجات ثابتة.

لا يوقّع الخادم أبدًا، ولا يحتفظ بمفاتيح، ولا يبثّ معاملة. يعمل على جهازك عبر stdio، أو كخادم Streamable HTTP تستضيفه أنت أو تستضيفه QoreChain. الإصدار **0.1.0**، نُشر في 27 أكتوبر 2026، بترخيص Apache-2.0. وتعمل أداة سطر الأوامر المقابلة [`qore`](/developer-tools/qore-cli) بالأدوات نفسها من الطرفية.

## الابتكارات {#innovations}

- **فحص للتوقيع الهجين، لا مجرد وسم.** تأخذ `get_pq_status` تجزئة معاملة، وتتأكد من أن جسم المعاملة يحمل طبقة `/qorechain.pqc.v1.PQCHybridSignature` واحدة بالضبط، وتتحقق محليًا من طبقة ML-DSA-87 هذه بواسطة [QoreSign](/qoresign/overview) مقابل المفتاح الذي سجّله الموقّع على السلسلة، مجرّبةً sign-bytes v1 وv2. والجواب هو `verified: true` أو `false` مع السبب، وليس تخمينًا من نوع المعاملة.
- **تحويلات غير موقّعة تحمل الرسم الحقيقي.** تقرأ `prepare_transfer` رقم حساب المرسل وتسلسله ومفتاحه العام، وتحاكي التحويل بطبقة ML-DSA-87 نائبة بالحجم الصحيح حتى يشمل الغاز الطبقة التي تضيفها المحفظة عند التوقيع، وتعيد SignDoc وملخصًا مقروءًا وفحوصات. ولا ينقص سوى توقيع المالك.
- **محاكاة برفض مفكوك الترميز.** تعيد `simulate_tx` و`estimate_fee` الغاز المستهلك وحدًّا مقترحًا للغاز وتغيّر الرصيد لكل عنوان، وعندما سترفض الشبكة المعاملة تعيد رفضًا مفكوك الترميز بدلًا من نص خطأ خام.
- **مخطط واحد للخادم ولأداة سطر الأوامر.** كل أمر في `qore` يشغّل أداة MCP واحدة، وتطبع `qore --json` بالضبط ملف JSON الذي تعيده الأداة. وتقدّم حزمة Python أسماء الأدوات نفسها ومخططات الإدخال والإخراج نفسها ورموز الأخطاء نفسها؛ وكلتاهما مختبرتان مقابل إجابات السلسلة المسجّلة نفسها.
- **تُرفض الأسرار قبل أن يغادر أي شيء الجهاز.** الإدخال الذي يشبه عبارة استرداد (12 كلمة BIP-39 متتالية أو أكثر) أو مفتاحًا خاصًا مجرّدًا من 32 بايت يُرفض بالرمز `INVALID_INPUT` قبل إجراء أي طلب، وتطلب رسالة الخطأ من المستخدم معاملة ذلك السر على أنه مكشوف.
- **استجابات تُبنى حقلًا حقلًا.** كل مخرج يُجمَّع من حقول مسمّاة في جواب السلسلة. ولا تصل أجسام أخطاء المنبع ولا تتبّعات المكدس إلى العميل؛ وتُحوَّل الإخفاقات إلى سبعة رموز أخطاء ثابتة.

## كيفية الاستخدام {#how-to-use}

تحتاج إلى Node.js 20 أو أحدث لحزمة npm، أو Python 3.10 أو أحدث لحزمة Python.

### التشغيل محليًا باستخدام npx {#run-npx}

تأكد من أن الخادم يبدأ، ثم أضفه إلى عميل MCP لديك. تقرأ معظم العملاء التي تشغّل خوادم محلية ملف JSON فيه كائن `mcpServers` (يختلف اسم الملف وأسماء المفاتيح لخوادم HTTP من عميل إلى آخر؛ راجع وثائق عميلك):

```bash
npx -y @qorechain/mcp --version
```

```json
{
  "mcpServers": {
    "qorechain": { "command": "npx", "args": ["-y", "@qorechain/mcp"] }
  }
}
```

أعد تشغيل العميل. سيعرض 14 أداة. يتحدث الخادم إلى العميل عبر stdio. ثم اسأل مثلًا:

- "ما آخر كتلة على الشبكة الرئيسية لـ QoreChain؟" (`get_block`)
- "هل تحمل معاملة الشبكة التجريبية F642F59F2A2FEDA2B3A61A3CF49F8B5F792D65985027997004FEBB22A6F42152 طبقة ML-DSA-87 صالحة؟" (`get_pq_status`)
- "جهّز تحويل 1.5 QOR على الشبكة التجريبية من عنواني إلى qor1... وقدّر الرسم." (`prepare_transfer`, `estimate_fee`)

### التشغيل محليًا باستخدام pip أو uvx {#run-pip}

```bash
pip install qorechain-mcp
qorechain-mcp --network testnet      # stdio
# or, without installing:
uvx qorechain-mcp
```

```json
{ "mcpServers": { "qorechain": { "command": "uvx", "args": ["qorechain-mcp"] } } }
```

تقدّم حزمة Python stdio فقط. أما Streamable HTTP ومفاتيح API وحدود المعدل فاستخدم لها حزمة npm (أدناه). وللحزمة أيضًا نقطة دخول مكتبية هي `run_tool`.

### التشغيل كخادم HTTP {#run-http}

```bash
npx -y @qorechain/mcp serve --port 8787
# listening on http://127.0.0.1:8787/mcp
```

نقل HTTP عديم الحالة ويجيب بصيغة JSON: `POST /mcp` لطلبات MCP، و`GET /healthz` للحصول على `{"status":"ok"}`. الخيارات:

| الخيار | الافتراضي | المعنى |
|---|---|---|
| `--port` | 8787 | منفذ TCP |
| `--host` | 127.0.0.1 | عنوان الربط؛ `0.0.0.0` يستمع على كل الواجهات |
| `--api-keys-file` | none | ملف يحوي تجزئات SHA-256 للمفاتيح المقبولة؛ وعند تعيينه تحتاج الطلبات إلى `Authorization: Bearer <key>` |
| `--rate-limit` | 60 | عدد الطلبات في الدقيقة لكل مفتاح API ولكل IP عميل؛ و`0` يعطّله |
| `--allowed-origin` | none | أصل متصفح مسموح له باستدعاء نقطة النهاية (قابل للتكرار)؛ وتحصل الأصول الأخرى على HTTP 403 |
| `--trust-proxy` | off | يأخذ IP العميل من `X-Forwarded-For`؛ فقط خلف وكيل تتحكم به |
| `--network` | testnet | الشبكة للاستدعاءات التي لا تسمّي شبكة |

لحماية نقطة النهاية الخاصة بك، أنشئ مفتاحًا، واحفظ تجزئته فقط، وسلّم المفتاح إلى العميل:

```bash
openssl rand -hex 32 > my.key
npx -y @qorechain/mcp hash-key < my.key >> api-keys.txt
npx -y @qorechain/mcp serve --api-keys-file api-keys.txt
```

يحتوي `api-keys.txt` على تجزئة واحدة من 64 رقمًا ست عشريًا في كل سطر (يُقبل اختياريًا البادئة `sha256:`، ويبدأ `#` تعليقًا). المفتاح المفقود أو المجهول يحصل على HTTP 401 مع رسالة خطأ تبدأ بـ `UNAUTHORIZED`؛ وعند تجاوز حد المعدل يجيب الخادم بـ HTTP 429 مع `Retry-After`. ضع TLS أمام أي خادم يمكن الوصول إليه من خارج جهازك.

تصدّر الحزمة أيضًا `createServer` و`createHttpHandler` و`startNodeServer` للتضمين في بيئة التشغيل الخاصة بك. التفاصيل الكاملة: [الاستضافة الذاتية](https://github.com/qorechain/qorechain-mcp/blob/main/docs/self-hosting.md) في مستودع المصدر.

### الإعدادات {#configuration}

| الإعداد | كيف | الأثر |
|---|---|---|
| الشبكة لكل استدعاء | الوسيط `network` في أي أداة: `testnet` أو `mainnet` | يختار السلسلة لذلك الاستدعاء |
| الشبكة الافتراضية | `--network testnet` أو `--network mainnet` في أمر الخادم | الشبكة المستخدمة عندما لا يسمّي الاستدعاء شبكة. الافتراضي `testnet` |
| منفذ HTTP والمضيف والمفاتيح والحدود | خيارات `serve` أعلاه | وضع HTTP فقط |
| مهلة المنبع | ثابتة عند 10 ثوانٍ لكل طلب، وحد استجابة 4 MiB، بلا إعادة محاولة | النقاط البطيئة تعطي `UPSTREAM_UNAVAILABLE` |

الشبكة الرئيسية هي `qorechain-vladi` (معرّف سلسلة EVM 9801) والشبكة التجريبية هي `qorechain-diana` (معرّف سلسلة EVM 9800). والتحويل المجهّز للشبكة الرئيسية يحمل تحذيرًا إضافيًا. لا توجد متغيرات بيئة للشبكة: إنها خيار سطر الأوامر أو الوسيط لكل استدعاء. لجعل الشبكة الرئيسية الافتراضية لعميل ما:

```json
{ "command": "npx", "args": ["-y", "@qorechain/mcp", "--network", "mainnet"] }
```

### الأدوات {#tools}

الأدوات الـ 14 كلها للقراءة فقط وتقبل `network` اختياريًا. مدخلاتها ومخرجاتها مولَّدة من مخططات الخادم نفسه؛ ويسرد [مرجع الأدوات](https://github.com/qorechain/qorechain-mcp/blob/main/docs/tools.md) كل حقل.

| الأداة | ما تعيده |
|---|---|
| `get_chain_info` | معرّفات السلسلة وآخر كتلة والحد الأدنى لسعر الغاز وإصدار sign-bytes ومفاتيح ميزات البروتوكول وترقية معلّقة إن كانت مجدولة وprecompiles الـ EVM النشطة |
| `get_block` | كتلة واحدة (أو الأخيرة): التجزئة والوقت والمقترِح وعدد المعاملات وحتى 100 تجزئة معاملة |
| `get_transaction` | معاملة بتجزئتها الأصلية أو بتجزئة EVM (بالبادئة `0x`): الحالة والرسم والمذكرة والغاز وحتى 50 رسالة والموقّعون وفئة التوقيع (`pqc` أو `enrollment` أو `shake` أو `classical`) |
| `get_address_info` | صيغتا العنوان (`qor1...` و`0x...`) وحالة الحساب وحتى 100 رصيد والمبلغ المودَع في staking وهل سُجّل مفتاح ML-DSA-87 وهل نُشرت شيفرة بايت |
| `get_pq_status` | لعنوان: المفتاح المسجّل والخوارزمية وإثبات الحيازة ونافذة تفويض EVM. ولمعاملة: هل تحمل طبقة هجينة واحدة بالضبط وهل يتحقق منها |
| `get_validators` | المدققون بحسب الحصة (الافتراضي bonded، بحد أقصى 50، والحد حتى 200): الحالة وعلم الاحتجاز (jailed) والحصة ونسبة قوة التصويت والعمولة |
| `get_staking_tiers` | وحدة طبقات التخزين: شروط القفل والمكافآت وعقوبة فك القفل المبكر ومجمّع المكافآت، واختياريًا أقفال حامل واحد. سلسلة v3.2.4 وما بعدها |
| `search` | يكشف ارتفاع كتلة أو تجزئة معاملة أو عنوانًا أو مدققًا من نص واحد، ويقرأه، ويسمّي الأداة التي تعيد البيانات نفسها |
| `read_contract` | استدعاء EVM `eth_call` فقط، مع ترميز ABI اختياري لتوقيع دالة وفك ترميز النتيجة |
| `estimate_fee` | الغاز المحاكى وحد الغاز المقترح والرسم (حد الغاز مضروبًا في الحد الأدنى لسعر الغاز)، شاملًا طبقة ML-DSA-87 |
| `simulate_tx` | الغاز المستهلك وحد الغاز المقترح وتغيّر الرصيد لكل عنوان ورفض مفكوك الترميز لمعاملة مرمَّزة |
| `prepare_transfer` | `MsgSend` غير موقّعة من uqor: SignDoc وملخص مقروء وفحوصات وتحذيرات |
| `get_token_holders` | دائمًا `NOT_AVAILABLE_ON_CHAIN`: سرد الحاملين يحتاج مفهرسًا لا تقدمه النقاط العامة |
| `request_faucet` | دائمًا `NOT_AVAILABLE_ON_CHAIN`: تأتي QOR للشبكة التجريبية من [الصنبور](/dashboard/faucet) في لوحة التحكم |

الأخطاء هي نتائج أدوات مع `isError: true` وجسم JSON هو `{"error": {"code", "message", "details?"}}`. والرموز هي `NOT_FOUND` و`INVALID_INPUT` و`UPSTREAM_UNAVAILABLE` و`NOT_AVAILABLE_ON_CHAIN` و`RATE_LIMITED` و`UNAUTHORIZED` و`INTERNAL_ERROR`.

### ما الذي شُغِّل {#what-was-run}

في 27 أكتوبر 2026 ثُبّتت الحزم المنشورة من السجلات وشُغّلت مقابل نقاط الشبكة التجريبية والشبكة الرئيسية العامة:

- طبعت `qorechain-mcp --version` القيمة `0.1.0`؛ وعبر stdio أعادت `initialize` اسم الخادم `qorechain-mcp` وأعادت `tools/list` أسماء الأدوات الـ 14 أعلاه؛ وثُبّتت `pip install qorechain-mcp==0.1.0` وطبع `--version` فيها `0.1.0`.
- أجابت `qorechain-mcp serve --port 18787` عن `GET /healthz` بـ `{"status":"ok"}` وعن استدعاء `tools/call` للأداة `get_chain_info` عبر `POST /mcp`.
- أعادت `get_chain_info` السلسلة `qorechain-diana` ومعرّف سلسلة EVM 9800 والحد الأدنى لسعر الغاز 0.1 uqor وsign-bytes `v2` على الشبكة التجريبية، والسلسلة `qorechain-vladi` ومعرّف سلسلة EVM 9801 وsign-bytes `v2` على الشبكة الرئيسية.
- أعادت `get_pq_status` على معاملة الشبكة التجريبية أعلاه الفئة `pqc` وطبقة هجينة واحدة بالضبط و`verified: true` مع sign-bytes `v2`.
- أعادت `prepare_transfer` لتحويل 1.5 QOR على الشبكة التجريبية SignDoc بحد غاز 171698 ورسم 17170 uqor (0.01717 QOR)، وأعادت `simulate_tx` على معاملتها غير الموقّعة `ok: true` مع خصم الرسم من المرسل. لم يُوقَّع شيء ولم يُرسَل شيء.

## كيفية الوصول {#how-to-access}

- **محليًا (الخيار الأساسي).** stdio عبر `npx -y @qorechain/mcp` أو `uvx qorechain-mcp`. لا يحتاج إلى حساب ولا إلى مفتاح API. يقرأ من نقاط QoreChain العامة، لذا يحتاج إلى HTTPS صادر.
- **خادم HTTP خاص بك.** `qorechain-mcp serve`، كما سبق، مع مفاتيح API وحدود معدل تضبطها أنت.
- **نقطة نهاية مستضافة.** يقدّم `https://mcp.qorechain.io/mcp` نقل Streamable HTTP. وتستخدم الشبكة التجريبية ما لم يسمِّ الاستدعاء `"network": "mainnet"`. يحتاج كل طلب إلى مفتاح API يُرسل بالصيغة `Authorization: Bearer <key>`؛ وتُصدَر المفاتيح عند الطلب. وبدون مفتاح تجيب النقطة بـ HTTP 401 (`UNAUTHORIZED`)، وهذا كان الجواب في 27 أكتوبر 2026. وتطبّق النقطة المستضافة حدود معدل لكل مفتاح. وفي معظم الاستخدامات لا يحتاج الإعداد المحلي إلى مفتاح وهو الخيار الأبسط.

إعداد عميل HTTP لخادم يحتاج إلى مفتاح (تختلف أسماء المفاتيح بالضبط من عميل إلى آخر):

```json
{
  "mcpServers": {
    "qorechain": {
      "type": "http",
      "url": "https://mcp.qorechain.io/mcp",
      "headers": { "Authorization": "Bearer ${QORECHAIN_MCP_KEY}" }
    }
  }
}
```

لا تضع أبدًا عبارة استرداد أو مفتاحًا خاصًا في إعداد عميل: لا تحتاج أي أداة في QoreChain إلى واحد منهما.

يقرأ الخادم من هذه النقاط العامة:

| | الشبكة التجريبية | الشبكة الرئيسية |
|---|---|---|
| REST | `https://api-testnet.qore.host` | `https://api.qore.host` |
| RPC الإجماع | `https://rpc-testnet.qore.host` | `https://rpc.qore.host` |
| EVM JSON-RPC | `https://evm-testnet.qore.host` | `https://evm.qore.host` |

التكلفة: الخادم مجاني. والقراءات لا تكلّف شيئًا. وإذا بثثت معاملة بنتها `prepare_transfer` فيسري رسم الشبكة (الحد الأدنى للرسم 0.1 uqor لكل وحدة غاز).

## الحدود والمشكلات المعروفة {#limits}

- **للقراءة فقط.** لا يوجد مسار شيفرة للتوقيع ولا تخزين للمفاتيح ولا بثّ. تعيد `prepare_transfer` مستندًا غير موقّع. لإتمام التحويل، وقّعه بـ [QoreSign](/qoresign/overview) أو بمحفظة QoreX وابثّه بنفسك؛ ثم اقرأ النتيجة بـ `get_transaction`. تستخدم `read_contract` الأداة `eth_call` فقط ولا تستطيع تغيير الحالة.
- **يُجهَّز نوع معاملة واحد.** تبني `prepare_transfer` رسالة `MsgSend` من uqor على المسار الأصلي. ولا تبني معاملات EVM أو SVM أو staking أو الحوكمة أو العقود. أما `estimate_fee` و`simulate_tx` فتقبلان أي معاملة مرمَّزة على المسار الأصلي.
- **أرقام الغاز تختلف بحسب الشبكة.** تشمل محاكاة الشبكة التجريبية (v3.2.6) تكلفة التحقق من ML-DSA-87 أصلًا، فالغاز دقيق. أما محاكاة الشبكة الرئيسية (v3.2.4) فلا تشملها، لذا يحمل حد الغاز المقترح هامشًا (`exact_gas_simulation` تساوي false على الشبكة الرئيسية).
- **تاريخ الشبكة التجريبية مقتطع.** كتلة قديمة من الشبكة التجريبية تعيد `NOT_FOUND`، ويسمّي الخطأ أدنى ارتفاع متاح (8,790,799 على الشبكة التجريبية وقت الفحص؛ وكانت الشبكة الرئيسية تخدم من الارتفاع 1). وتفحص `get_pq_status` الطبقة مقابل المفتاح المسجّل الآن، لذا لا تطابق المعاملات الأقدم بعد تدوير المفتاح.
- **precompiles ما بعد الكمّي في EVM.** العنوانان `0x...0A01` (تحقق ML-DSA-87) و`0x...0A02` (حالة المفتاح) نشطان على الشبكة التجريبية فقط؛ وعلى الشبكة الرئيسية يعيد الاستدعاء إليهما بيانات فارغة.
- **الحدود.** لكل طلب منبع مهلة 10 ثوانٍ وحد استجابة 4 MiB دون إعادة محاولة. تسرد الكتل 100 تجزئة معاملة كحد أقصى، وتعرض المعاملات 50 رسالة كحد أقصى، والحسابات 100 رصيد كحد أقصى. أجسام طلبات HTTP محدودة بـ 512 KiB. والمذكرة 256 حرفًا كحد أقصى، وهي عامة ودائمة، فلا تضع فيها سرًا أبدًا. وحد المعدل في الخادم المستضاف ذاتيًا خاص بكل نسخة ومحفوظ في الذاكرة؛ وخلف موازن أحمال تعدّ كل نسخة على حدة.
- **غير متاح:** `get_token_holders` (لا مفهرس على النقاط العامة) و`request_faucet` (استخدم صنبور لوحة التحكم، الذي يحتاج إلى تسجيل دخول). تحتاج النقطة المستضافة إلى مفتاح API وتُصدَر المفاتيح عند الطلب؛ أما الإعداد المحلي فلا.
- **الشبكة الرئيسية صريحة.** تذهب الاستدعاءات إلى الشبكة التجريبية ما لم تسمِّ `"network": "mainnet"` أو بدأ الخادم بالخيار `--network mainnet`.
- **لا تُنشر صورة حاويات.** شغّل الخادم بـ `npx` أو `pip`.
- **الإصدار.** 0.1.0 هو الإصدار الأول؛ قد تتغير أسماء الأدوات والمخططات في إصدارات لاحقة، والملف المولَّد `spec/tools.json` في المستودع هو المرجع للإصدار الذي ثبّتّه.
