# الإعدادات المسبقة

يأتي الـ RDK مزوّدًا بـ **إعدادات مسبقة** توفّر تهيئات rollup جاهزة للاستخدام ومضبوطة لفئات التطبيقات الشائعة. يجمع الإعداد المسبق بين وضع تسوية، ووضع مُرتِّب (sequencer)، وخلفية لتوفّر البيانات (DA)، ومعاملات تنفيذ، بحيث يمكنك إطلاق rollup دون الحاجة إلى اختيار كل خيار يدويًا.

يُمرَّر الإعداد المسبق كوسيط موضعي إلى `create-rollup`:

```bash
qorechaind tx rdk create-rollup [rollup-id] [profile] [stake-amount]
```

:::note
القيم الخاصة بكل إعداد مسبق أدناه تطابق القيم الافتراضية للإعدادات المشحونة في **`@qorechain/rdk`**، والتي تعكس جدول الإعدادات المنشور للشبكة. ومع ذلك قد تتطور هذه القيم مع نضوج الـ RDK — استعلم عن معاملات الوحدة الحيّة باستخدام `qorechaind query rdk config` (أو `RdkClient.params()` من الـ SDK) للحصول على التهيئة المرجعية، وتحقّق على شبكة الاختبار **`qorechain-diana`** قبل الشبكة الرئيسية.
:::

## الإعدادات المسبقة المتاحة

يجمع كل إعداد مسبق بين نموذج تسوية (ونظام الإثبات الذي تتطلبه تلك التسوية)، ووضع مُرتِّب، وخلفية لتوفّر البيانات، ونموذج غاز، وآلة افتراضية (VM):

| الإعداد المسبق | التسوية (الإثبات) | المُرتِّب | توفّر البيانات (DA) | نموذج الغاز | الآلة الافتراضية | حالة الاستخدام المقصودة |
| ------- | ------------------ | --------- | -- | --------- | -- | ----------------- |
| **`defi`** | zk (SNARK) | dedicated | native | EIP-1559 | EVM | تطبيقات DeFi والتطبيقات على نمط AMM — أسواق الإقراض ومنصات التداول اللامركزية (DEX) والمشتقات حيث تهمّ النهائية السريعة والرسوم القابلة للتنبؤ |
| **`gaming`** | based | based | native | flat | custom | حالة ألعاب عالية الإنتاجية ومنخفضة زمن الاستجابة واقتصادات داخل اللعبة |
| **`nft`** | optimistic (fraud) | dedicated | native (مع Celestia DA مخطط لها) | standard | QoreChain Native (`native`) | سكّ رموز NFT والأسواق والمقتنيات الرقمية |
| **`enterprise`** | based | based | native | subsidized | EVM | عمليات النشر المصرّح بها والاتحادية مع رسوم مدعومة (subsidized) |
| **`custom`** | قابل للتخصيص بالكامل (الافتراضيات: optimistic / fraud) | قابل للتخصيص بالكامل | قابل للتخصيص بالكامل | قابل للتخصيص بالكامل | قابل للتخصيص بالكامل (الافتراضي: EVM) | كل حقل يحدّده المستخدم — ابدأ من الصفر واضبط كل خيار بنفسك |

تنبثق بعض القيود من [مصفوفة التسوية ← الإثبات](/rollups/overview): تستخدم تسوية `optimistic` إثباتات `fraud`، وتستخدم `zk` إثباتات `snark` (أو `stark`)، بينما لا تحمل `based` و`sovereign` أي إثبات. تقترن تسوية `based` دائمًا بوضع المُرتِّب `based`. الإعداد المسبق `nft` يسوّي محليًا (native) اليوم مع **Celestia DA مخطط لها**.

اعتبارًا من RDK v0.4.2، أصبح خيار الآلة الافتراضية Wasm (بيئة التشغيل التي تنفّذ عقود CosmWasm) يحمل الاسم **`native`** — أي QoreChain Native. يبقى `cosmwasm` اسمًا مستعارًا قديمًا مقبولًا، وكلاهما يُترجَم إلى `cosmwasm` على مستوى البروتوكول، لذا تبقى السلسلة والمستكشف ولوحة التحكم دون تغيير.

:::note
جرى التحقق المباشر من تهيئة كل إعداد مسبق على السلسلة في إصدار السلسلة **v3.1.74**، حيث يطبّق `create-rollup` الإعداد المسبق للملف التعريفي تلقائيًا: **`defi` = zk + EVM، و`gaming` = based + آلة افتراضية custom، و`nft` = optimistic + QoreChain Native (Wasm)، و`enterprise` = based + EVM، و`custom` = optimistic + EVM (الافتراضيات)**. يترك الإعداد المسبق `custom` كل حقل مفتوحًا — والقيم المعروضة هي مجرد افتراضياته الأولية.
:::

تعامل مع الإعدادات المسبقة الأربعة الخاصة بالمجالات كنقاط انطلاق معقولة، ومع الإعداد المسبق **`custom`** كخيار مفتوح بالكامل. قد تتغير المعاملات المجمّعة الدقيقة بين الإصدارات — استعلم عن `rdk config` (أدناه) للحصول على القيم المرجعية، ثم ابدأ من أقرب إعداد مسبق وحسّنه.

تقوم أداة سطر الأوامر [`create-qorechain-rollup`](/rollups/deploying-a-rollup#scaffold-a-project-with-create-qorechain-rollup) بإنشاء هيكل مشروع بدء قابل للتشغيل — قالب واحد لكل إعداد مسبق (`defi-rollup` و`gaming-rollup` و`nft-rollup` و`enterprise-rollup` و`custom-rollup`) — بحيث يمكنك الانتقال من إعداد مسبق إلى كود إنشاء/استعلام عامل بأمر واحد.

## الحصول على توصية: `suggest-profile`

إذا لم تكن متأكدًا من الإعداد المسبق المناسب، فإن الاستعلام `suggest-profile` يأخذ وصفًا بلغة عادية لحالة الاستخدام الخاصة بك ويعيد إعدادًا مسبقًا موصى به.

```bash
qorechaind query rdk suggest-profile [use-case]
```

**مثال:**

```bash
qorechaind query rdk suggest-profile "a lending protocol with predictable fees"
```

الاقتراح هو نقطة انطلاق مفيدة — راجع التوصية مقابل متطلباتك المحددة (ضمانات التسوية، ونموذج الثقة الخاص بالمُرتِّب، واحتياجات توفّر البيانات، والآلة الافتراضية) قبل الالتزام بتهيئة معيّنة.

## فحص تهيئة الإعداد المسبق على السلسلة

نظرًا لأن تفاصيل الإعدادات المسبقة تُحسم على السلسلة، فإن الطريقة المرجعية لمعرفة ما يؤول إليه إعداد مسبق معيّن هي الاستعلام عن الوحدة وعن الـ rollup الذي أُنشئ:

```bash
# Module-level parameters that govern rollup creation and defaults
qorechaind query rdk config

# After creation, inspect the resolved configuration of a specific rollup
qorechaind query rdk rollup [rollup-id]

# List all registered rollups
qorechaind query rdk list-rollups
```

هذا النمط — الاستعلام عن `config` قبل النشر، ثم الاستعلام عن `rollup` بعده — يتيح لك التأكد بدقة مما أنتجه الإعداد المسبق الذي اخترته، بدلًا من الاعتماد على قيم موثّقة قد تتطور.
