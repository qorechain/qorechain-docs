# 버전 기록

QoreChain의 공개 버전 기록입니다. 메인넷 **`qorechain-vladi`**(EVM 체인 ID **9801**, 2026년 6월 7일부터 가동)는 블록 높이 **3,742,566**까지 **v3.2.3**(2026년 10월 20일 블록 높이 3,662,051에서 거버넌스로 적용)을 실행하고, 해당 블록부터는 **v3.2.4**를 실행합니다(메인넷 거버넌스 제안 13). 테스트넷 **`qorechain-diana`**(EVM 체인 ID **9800**)는 블록 높이 8,337,253(2026년 10월 19일)부터 **v3.2.4**를 실행해 왔습니다.

:::note
아래 항목은 상위 수준의 기능 요약입니다. 초기 `v1.x` 항목은 메인넷 이전의 테스트넷 릴리스 라인에 대한 기록으로 보존되어 있습니다. 릴리스 매니페스트([메인넷 연결](/getting-started/connecting-to-mainnet))는 태깅과 별개로 승격되며 태그보다 다소 늦게 반영될 수 있습니다 — 신규 설치 시 실제로 무엇이 다운로드되는지는 매니페스트를 직접 확인하세요.
:::

## v3.2.4 — 라이트 노드 등록 구간 및 선택적 시간 잠금 스테이킹 (메인넷 적용 예정)

**릴리스 초점:** 메인넷에 예정된 다음 릴리스입니다. 테스트넷 거버넌스 제안 13이 블록 높이 **8,337,253**(2026년 10월 19일)에서 적용한 이후 테스트넷 `qorechain-diana`에서 실행되어 왔습니다(테스트넷 매니페스트는 `minCompatible`을 3.2.4로 설정합니다). 메인넷에서는 거버넌스 제안 13이 블록 높이 **3,742,566**에서의 적용을 예약합니다. 노드는 해당 블록까지 v3.2.3을 유지하다가 그 블록에서 정지한 뒤 v3.2.4로 재시작하며, 트랜잭션 서명은 변경되지 않습니다. 따라서 아래 모든 기능은 현재 테스트넷에서 가동 중이며, (제안이 통과되면) 블록 높이 3,742,566부터 `qorechain-vladi`에 적용됩니다.

* **라이트 노드 등록 구간.** 라이트 노드의 보상 범위는 직전 정산 시점과 해당 노드 자체의 등록 시점 중 더 늦은 시점부터 시작하므로, 새로 등록한 노드가 합류 이전에 누적된 금액을 수령하지 않습니다.
* **선택적 시간 잠금 스테이킹(`x/stakingtier`, 새 모듈).** 위임자는 위임의 일부를 3개월, 6개월 또는 12개월 동안 잠글 수 있으며, 잠긴 부분은 위임 해제나 재위임을 할 수 없고, 조기 잠금 해제는 소각되는 페널티와 함께 허용됩니다. 최소 잠금액은 10 QOR입니다. [스테이킹 및 위임](/user-guide/staking-and-delegation#time-locked-staking)을 참고하세요.
* **새로운 발행 모드.** `x/inflation`에 세 번째 발행 모드인 `target_apy`가 추가되며, `target_apy_bps` 파라미터(테스트넷에서는 `0`)를 사용합니다. 네트워크의 발행 모드를 변경하는 것은 별도의 거버넌스 결정이며, 현재 적용 중인 모드는 `/qorechain/inflation/v1/params`에서 확인할 수 있습니다.
* 사후양자 계정 레코드의 **`possession_proven` 플래그**. 계정 키에 대한 소유 증명은 계속 선택 사항입니다.
* **브리지 검증인 소유 증명.** 브리지 검증인을 등록하려면 소유 증명과 다른 브리지 검증인이 사용하지 않는 키가 필요합니다.
* **블록 시간 기준의 RDK 이의 제기 기간.** 낙관적 이의 제기 기간은 이로부터 계산된 블록 수가 아니라 블록 시간으로 집계됩니다.
* **노드 로컬 하드닝**(JSON-RPC 요청 제한, 상태 동기화 청크 예산, 키 등록 사전 검사)과 새로운 조회(`protocol_features`, `auth_nonce`, 그리고 `monthly_cap_active` 같은 추가 라이트 노드 보상 풀 필드).

## v3.2.3 — 10월 두 번째 보안 배치 (메인넷)

**릴리스 초점:** 10월의 두 번째 하드닝 배치로, 메인넷에서는 거버넌스 제안 11을 통해 블록 높이 **3,662,051**(2026년 10월 20일 16:01 UTC)에서 적용되었으며, 테스트넷에는 이보다 먼저 블록 높이 8,003,746(10월 15일)에서 적용되었습니다. 메인넷 매니페스트는 `minCompatible`을 3.2.3으로 설정합니다. 이제 메인넷에 합류하는 노드는 v3.2.3이 필요합니다. 이 업그레이드는 해당 높이에서 52개의 프로토콜 기능을 켜며, 서명 형식, 주소, 소수 자릿수, 메모, 수수료는 변경되지 않습니다.

* **사후양자 키 무결성.** 약한 키, 퇴화(degenerate) 키, 이미 사용된 키는 등록 시 거부되며, 하이브리드 키 유지 관리가 강화되고, 사후양자 키 관리 메시지는 더 이상 authz를 통해 실행될 수 없으며, 계정은 마지막 서명 알고리즘을 제거할 수 없습니다. 등록(`MsgRegisterPQCKeyV2`, `tx pqc register-key-v2 ... --pqc-key <name>`)은 **선택적 소유 증명**을 받으며, 증명이 있으면 검증됩니다.
* **범위가 제한된 EVM 창.** `MsgOpenEVMWindow`는 창을 좁히는 선택적 `native_only`(일반 네이티브 QOR 이체만 허용)와 `allowed_targets`(최대 16개 수신자) 필드를 받습니다. [EVM 승인 창](/getting-started/first-transaction#evm-window)을 참고하세요.
* RDK를 위한 **롤업 에스크로 원장**, 프리컴파일 하드닝이 적용된 **원자적 크로스 VM 큐**, **정규 스테이크 승인**.
* **본인 계정 전용 베스팅 생성.** 베스팅 계정 생성은 생성자 본인의 계정만 충당할 수 있습니다(세 가지 베스팅 메시지는 서킷 브레이커에서도 계속 꺼져 있습니다).
* **경제 관련 수정.** 발행 연도는 에포크 길이로부터 도출되고, AMM 엔드 블록 작업에는 상한이 있으며, 소각 기록은 정리(prune)되고, 기록된 묶인 스테이커 몫은 업그레이드 높이에서 0에서 3,807,496.79 QOR로 재계산되었습니다([토크노믹스](/architecture/tokenomics#stranded-and-reserve) 참고).
* **라이트 노드 월별 상한.** 노드별 보상 상한이 이제 월 단위로 명시됩니다. 노드당 30일에 2,000 QOR이며, 블록 시간과 가동시간에 비례하여 안분됩니다.
* **거버넌스로 변경 가능한 라이선스 권한.** 새로운 `MsgUpdateAuthority`를 통해 거버넌스가 라이선스를 부여하는 권한 주체를 교체할 수 있습니다.
* **공개 빌드는 공개 네트워크를 거부.** 공개 소스 트리에서 빌드한 바이너리는 라이브 네트워크를 가리키면 중지됩니다.
* **새로운 읽기 경로.** `x/inflation` 파라미터와 에포크 레코드가 메인넷에서 REST로 제공됩니다(`/qorechain/inflation/v1/params`, `/epoch_info`).

## v3.2.2 — 의존성 업데이트 및 10월 첫 번째 보안 배치 (메인넷)

**릴리스 초점:** 메인넷에서는 거버넌스 제안 7을 통해 블록 높이 **3,556,788**(2026년 10월 16일 17:59 UTC)에서 적용된 조율된 업그레이드이며, 테스트넷에는 블록 높이 6,905,034(10월 2일)에서 적용되었습니다. 서명 형식은 변경되지 않습니다.

* **의존성.** Cosmos SDK v0.53.8, 합의 엔진 v0.38.26, ibc-go v10.7.
* 업그레이드 높이에서 **26개 프로토콜 기능**이 켜지며, 여기에는 다음이 포함됩니다. EIP-7702 위임에는 사후양자 동의가 필요하고(`MsgAuthorizeEVMDelegation`, `MsgClearEVMDelegation` 또는 `MsgCloseEVMWindow`로 해제), 멀티시그 한도가 블록 실행에서 강제되며, 검증인 승인이 모든 경로에서 검사되고, AMM 무결성 검사가 추가되며, 모듈 계정은 EVM을 통해 점유될 수 없고, EIP-155 이전 트랜잭션은 거부되며, 사후양자 키 등록 시 고전 키를 검증하고, RDK 및 멀티레이어 앵커 메시지가 두 번째 형식(v2)으로 이동하며, 실패한 트랜잭션 소각 채널이 적용됩니다.

## v3.2.1 — 노드 하드닝

**릴리스 초점:** 메인넷을 위한 노드 로컬 보안 릴리스(2026년 10월 14일): **업그레이드 높이 없음, 합의 변경 없음, 거버넌스 투표 없음**. v3.2.0 노드는 계속 체인을 따라갑니다.

* 공개 API의 리소스 제한을 강화하고, EVM JSON-RPC와 멤풀에 상한을 두며, 승격된 EVM 트랜잭션을 가십(gossip)합니다.
* 노드 설정에 EVM 체인 ID를 고정하고 Cosmos 체인 ID와 교차 검증합니다. 운영자는 `app.toml`에 `evm-chain-id = 9801`을 설정해야 합니다(다른 값은 오류로 기록됩니다).
* 합의 엔진 의존성을 갱신합니다. 시스템 시계를 NTP로 동기화된 상태로 유지하세요(60초를 초과하는 시차가 생기면 노드가 중지됩니다).
* 모든 운영자에게 권장되며, 당시 메인넷 매니페스트의 `minCompatible`은 3.2.0이었습니다.

v3.2.1은 노드별로 순차 적용되었으며 업그레이드 높이가 없습니다. 메인넷에서는 v3.2.2(10월 16일)와 v3.2.3(10월 20일)으로 대체되었습니다.

## v3.2.0 — EVM 승인 창 및 회계 수정

**릴리스 초점:** 사후양자 요구사항을 모든 레인에서 실제로 성립하게 하고, 두 가지 회계상의 허점을 해소. 메인넷에서는 거버넌스 제안 #6으로 블록 높이 **2,981,742**(2026년 9월 25일 12:07 UTC)에 적용되었으며, 테스트넷에서는 블록 높이 5,920,000에 적용되었습니다.

* **EVM 승인 창(EVM 지갑에 대한 호환성 깨짐 변경).** EVM 트랜잭션은 이제 등록된 ML-DSA-87 키가 있고 **동시에** 열린 창이 있는 계정에서만 허용됩니다. 창은 Cosmos 레인 메시지(`MsgOpenEVMWindow`, 사후양자 서명)로 열리며 블록 수(≤ 17,280), 트랜잭션 수(≤ 1,000), 총 가치(이체 금액 더하기 각 트랜잭션의 최대 수수료)로 한도가 정해지고, `MsgCloseEVMWindow`로 철회합니다. 창 안에서는 표준 이더리움 서명 방식이 그대로 유지됩니다. 9월 16일부터 서킷 브레이커로 메인넷에서 중단되어 있던 EVM 레인은 이 규칙이 적용된 바로 그 블록에서 다시 열렸습니다. [EVM 승인 창](/getting-started/first-transaction#evm-window)을 참고하세요.
* **하이브리드 서명 v2.** 사후양자 서명은 이제 도메인 태그가 붙고 체인에 바인딩된 서명 바이트에 대해 이루어지며, 첫 번째 형식은 업그레이드 높이부터 거부됩니다. 클라이언트는 노드의 적용된 업그레이드 플랜을 확인하여 형식을 선택하며, CLI(`--sign-bytes auto`), SDK 0.8.x, wallet-adapter 0.2.x가 이를 수행합니다. 키 마이그레이션 및 브리지 증명(attestation) 페이로드도 같은 방식으로 옮겨졌습니다. [사후양자 보안](/architecture/post-quantum-security#sign-bytes-v2)을 참고하세요.
* **스테이커 몫 지급.** 수수료 분배 중 스테이커 몫 10 %가 어떤 청구권도 뒷받침하지 못하는 곳에 적립되고 있었으며, 이번 업그레이드부터는 일반 스테이킹 보상으로 지급됩니다. 이미 누적된 금액(메인넷 기준 6,693,045.92 QOR)은 온체인에 기록되어 있고(`GET /qorechain/burn/v1/stranded_rewards`) 거버넌스 투표(`MsgReleaseStrandedRewards`)로만 이동할 수 있었으며, 거버넌스는 이를 2026년 10월에 해제했습니다([거버넌스 타임라인](#governance-timeline) 및 [토크노믹스](/architecture/tokenomics#stranded-and-reserve) 참고).
* **라이트 노드 보상 준비금.** 자격을 갖춘 노드가 없는 동안 누적된 라이트 노드 몫 3 %(메인넷 기준 3,156,009.33 QOR)는 준비금으로 기록되고(`GET /qorechain/lightnode/v1/reward_pool`), 분배에서 제외되며 거버넌스로만 이동할 수 있습니다(2026년 10월에 해제됨). 이후 분배는 직전 실행 이후에 발생한 금액만 지급하며, 노드별로 상한이 정해집니다. 이 릴리스 시점에는 라이트 노드 등록이 아직 닫혀 있었으나 이후 열렸습니다([라이트 노드](/light-node/overview#reward-program-status) 참고).
* **발신자별 트랜잭션 한도**가 이제 강제 적용됩니다(릴레이어가 운영될 수 있도록 발신자당 30블록에 600개 트랜잭션).
* **업그레이드 모듈 버전 맵**이 이제 모든 모듈(48개)을 나열하여, 이후 마이그레이션에 영향을 줄 수 있었던 누락을 바로잡았습니다.
* 그 밖에도: 브리지 모듈 계정과 증명 페이로드 하드닝, 제안된 블록 검증, 롤업 정산을 롤업의 시퀀서로 제한하고 롤업별 에스크로와 실효성 있는 생성 소각 적용, 멀티레이어 생성자 스테이크를 등록 시점에 잠그고 폐기 시 반환, 스마트 계정의 `enabled` 플래그를 모든 경로에서 강제, 검증인 승인 및 베스팅 생성 경로를 authz 중첩에 대해 차단.

## v3.1.96 + v3.1.97 — QoreChain Native 접근 잠금

**릴리스 초점:** QoreChain Native의 기반 런타임인 CosmWasm에 대한 업계 전반의 보안 권고에 따라, 권한 없는 컨트랙트 코드 업로드와 인스턴스화를 차단.

* **컨트랙트 업로드 및 인스턴스화에 이제 명시적 권한이 필요합니다.** `code_upload_access`와 `instantiate_default_permission`이 메인넷과 테스트넷 모두에서 `Nobody`로 설정되어 있음이 확인되었습니다 — 이는 온체인 파라미터이지 최신 바이너리만 강제하는 값이 아니므로, 노드가 이 두 태그 중 어느 것을 실행 중인지와 무관하게 적용됩니다. 컨트랙트를 개발할 때 이것이 어떤 의미인지는 [QoreChain Native 개발](/developer-guide/cosmwasm-development)을 참고하세요. 이미 인스턴스화된 컨트랙트는 영향을 받지 않으며, `execute`와 `query`는 이전과 동일하게 작동합니다. 두 네트워크 모두 QoreChain Native 업로드 및 인스턴스화 메시지 3종도 서킷 브레이커로 꺼져 있습니다.
* **위치 독립적(PIE) 릴리스 빌드** — 동일한 권고의 하드닝 지침에 따라, 익스플로잇이 추측해야 하는 메모리 주소가 프로세스마다 무작위화됩니다. 동적으로 링크된 바이너리는 빌드 플래그 하나만 추가하면 되었으며, 상태를 깨뜨리지 않음이 확인되었습니다.

* 이 릴리스로 직접 업데이트하는 노드를 위해 v3.1.92의 노드 온보딩 신뢰성 수정 사항도 포함합니다.

## v3.1.90 — 라이트 노드 가동시간 산정

**릴리스 초점:** 라이트 노드 보상 자격을 위해 측정되는 가동시간이 이제 시간에 걸쳐 일관되게 누적됩니다.

* **전진 누적 방식 가동시간** — 라이트 노드의 보상 자격 가동시간은 이제 각 시점에 적용되었던 하트비트 간격을 기준으로 등록 시점부터 앞으로 예상 하트비트 수를 누적하여 계산되며, 현재 적용 중인 간격을 기준으로 전체 이력을 다시 계산하는 방식이 아닙니다. 따라서 하트비트 간격에 대한 거버넌스 변경은 이후의 가동시간에만 영향을 미치며, 노드의 과거 실적을 소급하여 재평가하지 않습니다.

## v3.1.86 — 검증인 복구 안전장치

**릴리스 초점:** 검증인이 다운타임 감금(jail)으로부터의 복구에서 영구적으로 차단되지 않도록 함.

* **감금 잠금 수정** — 사후양자 키가 등록되지 않은 검증인 운영자 계정도, 하이브리드 서명 강제가 고전 방식 폴백 없이 필수(required)로 설정되어 있는 경우에도, 이제 항상 `MsgUnjail`을 제출하여 다운타임 감금으로부터 복구할 수 있습니다. 이전에는 이러한 계정이 감금 해제를 위해 자신이 보낼 수 없도록 차단된 바로 그 트랜잭션을 보내야 했기 때문에 복구할 방법이 전혀 없었습니다.
* **상태 동기화 스냅샷** — 스냅샷 생성이 네트워크 전역에서 활성화되어, 신규 검증인과 풀 노드가 전체 과거 이력 재생 대신 상태 동기화를 통해 빠르게 합류할 수 있습니다.

## v3.1.85 — 연결된 지갑을 통한 위임 지출

**릴리스 초점:** 연결된 외부 지갑 키(Phantom, MetaMask)가 이제 최소 권한, 지출 한도, 즉시 철회 하에 하나의 정규 사후양자 계정에서 **지출**할 수 있습니다.

* **인증자 실행 레인** — 두 개의 새 메시지를 통해 등록된 인증자가 계정 소유자가 자리에 없어도 정규 계정으로부터의 이체를 승인할 수 있습니다. **`MsgExecuteEVM`**(계정의 `0x…` 주소에서의 EVM 호출/이체)과 **`MsgExecuteCosmos`**(네이티브 레인 뱅크 전송)입니다. **릴레이어**가 봉투(envelope)를 제출하고 수수료를 지불하며 — 자체 하이브리드 PQC 서명이 트랜잭션 요구사항을 충족시킵니다 — 도메인 분리되고 재전송 방지가 적용된 서명 바이트에 대한 인증자의 서명이 승인 근거가 됩니다. 외부 키는 ML-DSA 공동 서명이 전혀 필요하지 않습니다.
* **인증자로서의 MetaMask** — secp256k1 인증자는 이제 33바이트 압축 키 형식뿐 아니라 **20바이트 이더리움 주소**로도 등록할 수 있으며 **EIP-191 `personal_sign`**을 통해 검증할 수 있어, 표준 MetaMask 계정을 연결하여 한도 내에서 지출할 수 있습니다.
* **세 레인 모두에 대한 강제 적용** — 권한 범위와 **SpendingRule** 금액 한도(트랜잭션당 + 일일 한도)는 네이티브, EVM, SVM 레인 모두에서 강제되며, 키 관리 메시지는 결코 위임할 수 없습니다. 개별 오류 코드를 통해 지갑이 올바른 메시지를 표시할 수 있습니다: `5` 지출 한도 초과, `6` 인증자 만료, `10` 권한 거부, `11` 재전송 거부.
* **권한 스키마 조회** — `GET /qorechain/abstractaccount/v1/permission_schema`(gRPC/CLI에서도 가능)는 정규 권한 분류 체계(11개 권한), 메시지→권한 매핑, 위임 불가 메시지 목록을 반환하므로 지갑이 범위를 하드코딩하지 않고 검증할 수 있습니다.
* **동일 알고리즘 PQC 키 회전** — 새로운 **`MsgRotatePQCKey`**는 계정의 ML-DSA-87 키를 동일 알고리즘 내에서 회전시켜(기존 키와 새 키 모두로 이중 서명) 레거시 방식으로 파생된 키를 정규 주소 기반 파생 방식으로 마이그레이션하고 손상된 키를 폐기할 수 있게 합니다. 새 CLI: `tx pqc rotate-key`, `tx pqc recover-key`(니모닉으로부터의 결정론적 키 복구).
* **루트 키 트랜잭션에는 영향 없음** — 이번 변경은 추가적인 성격이며, 일반 지갑 및 거래소 흐름은 변경되지 않습니다. 노드 운영자는 네트워크 업그레이드 높이(height)까지 **v3.1.85**로 갱신해야 합니다.
* **현재 상태** — 스마트 계정 및 연결 지갑 기능은 구현되어 있으나 현재 두 네트워크 모두에서 **꺼져 있습니다**(`abstractaccount.enabled = false`). v3.2.0부터는 이 플래그가 꺼져 있는 동안 모든 인증자 경로가 거부됩니다. 연결 흐름을 제공하기 전에 `GET /qorechain/abstractaccount/v1/config`를 확인하세요.

## v3.1.84 — 인증자 권한 및 지출 한도

**릴리스 초점:** 위임 지출의 기반이 되는 권한 모델.

* **정규 권한 분류 체계** — 11개 권한(`all`, `send`, `delegate`, `withdraw`, `vote`, `evm`, `wasm`, `svm`, `amm`, `ibc`, `deploy`)과 기본 거부(fail-closed) 방식의 메시지→권한 매핑: 매핑되지 않은 메시지 유형은 거부되며, 키 관리 메시지는 결코 위임될 수 없습니다.
* **SpendingRule 강제 적용** — 허용 디놈(denom) 목록을 포함한 트랜잭션당 및 일일(UTC 기준) 지출 한도가 (계정, 인증자) 쌍 단위로 강제되고 기록됩니다.
* **SVM 레인 인가** — 외부 스킴 키(예: Phantom ed25519)에 의해 SVM 레인에서 인가된 작업은 동일한 중앙 인가 게이트를 거칩니다.

## v3.1.83 — 세 인터페이스 전체에 걸친 통합 계정 서명

**릴리스 초점:** 하나의 키, 하나의 계정 — 이제 Cosmos, EVM, SVM 인터페이스에서 잔액을 보유할 뿐 아니라 **서명**도 할 수 있는 단일 통합 신원.

* **모든 레인에서 서명하는 하나의 키** — 이더리움 네이티브 방식으로 생성된 계정(주소 = secp256k1 공개 키의 keccak)이 이제 EVM 트랜잭션에 더해 `eth_secp256k1` 스킴으로 Cosmos 레인 트랜잭션에도 서명합니다. 계정의 `qor1…`(Cosmos), `0x…`(EVM), Solana-VM(base58) 형식은 하나의 20바이트 신원이며, 이는 **하나의 잔액을 보유**하는 동시에 사후양자 하이브리드(ML-DSA-87) Cosmos 트랜잭션을 포함하여 **세 레인 모두에서 지출**합니다.
* **사후양자 서명은 변경 없음** — 통합 계정은 여전히 ML-DSA-87 키를 등록하고 체인이 요구하는 FIPS-204 하이브리드 서명을 사용하며, 고전 서명 부분은 coinType-118 스킴 대신 `eth_secp256k1`(keccak)입니다. 기존 coinType-118 계정은 영향을 받지 않습니다.
* **합의 계층에 중립적인 롤링 업그레이드** — **재제네시스 및 체인 정지 없이** 두 네트워크 모두에서 롤링 바이너리 업그레이드로 배포되었습니다. 계정 잔액, 이력, 제네시스는 변경되지 않습니다.
* **클라이언트 도구** — `@qorechain/wallet-adapter` 0.1.5는 이더리움 네이티브 Cosmos 서명(`signClassicalEth` / `signHybridEth`), 통합 3주소 생성, `walletFromSeed`(임의의 32바이트 시드 — 예: Phantom 서명 — 로부터 정규 계정을 파생)를 추가합니다. `@qorechain/chain-bridge`는 `eth_secp256k1` 서명 경로를 갖추게 되었습니다.

:::caution 노드 운영자 — 업그레이드 필요
풀 노드는 **v3.1.83 이상**을 실행해야 합니다. v3.1.83 이전 노드는 이더리움 네이티브(`eth_secp256k1`) 트랜잭션을 디코딩할 수 없으며, 블록에 해당 트랜잭션이 나타나는 즉시 동기화가 중단됩니다. [download.qore.host](https://download.qore.host)에서 현재 번들을 다운로드하세요.
:::

## v3.1.82 — SVM에서의 네이티브 QOR 가동 + 통합업체 지원 강화

**릴리스 초점:** 두 네트워크 모두에서 가동 중인 SVM 네이티브 QOR 통합, 그리고 거래소나 통합업체가 연동에 필요로 하는 모든 것.

* **세 인터페이스 전체에서 가동 중인 통합 네이티브 QOR 잔액** — SVM 통합(v3.1.81)이 메인넷과 테스트넷 모두에서 가동 중임이 확인되었습니다: 동일한 계정이 Cosmos에서는 `uqor`(소수점 6자리), EVM에서는 wei 방식 소수점 18자리, Solana 호환 인터페이스에서는 lamport(소수점 9자리; 1 uqor = 1,000 lamport)로 표시되는 하나의 잔액을 보유합니다.
* **검증된 공개 엔드포인트** — 합의 RPC, REST, EVM JSON-RPC, SVM JSON-RPC용 공개 HTTPS 엔드포인트가 두 네트워크 모두에 제공되며, 공개 [블록 익스플로러](https://explore.qore.network)도 포함됩니다. [네트워크](/appendix/networks)를 참고하세요.
* **다운로드** — 버전이 지정된 노드 바이너리 번들, 메인넷 제네시스, 최신 체인 데이터 스냅샷(SHA-256 체크섬 포함)이 [download.qore.host](https://download.qore.host)에 게시됩니다.
* **클라이언트 스택 전반의 결정론적 사후양자 서명** — `@qorechain/pqc` 0.1.1은 여섯 개 언어 바인딩 모두에서 ML-DSA-87을 결정론적으로(FIPS-204 §3.4) 서명하며, 체인이 수용하는 방식과 일치합니다. `@qorechain/wallet-adapter` 0.1.2는 이를 기반으로 하이브리드 트랜잭션 서명을 구현합니다.
* **통합업체 가이드** — 세 인터페이스 전반의 입금, 출금, 노드 운영을 다루는 새로운 [거래소 및 통합업체 가이드](/developer-guide/exchange-integration)가 추가되었습니다.

## v3.1.81 — SVM 네이티브 QOR 통합

**릴리스 초점:** Solana 호환 인터페이스에서 1급 자산으로서의 네이티브 QOR.

* **SVM에서의 네이티브 QOR** — SVM 런타임은 이제 별도의 SVM 전용 잔액을 추적하는 대신 계정의 네이티브 QOR 잔액을 직접(lamport 단위로) 노출합니다. `getBalance`와 `getSignaturesForAddress`는 네이티브 자금에 대해 작동하며, System Program 이체는 네이티브 QOR을 이동시킵니다.
* **SVM 주소 매핑** — 계정의 SVM 주소는 20바이트 계정 바이트(32바이트로 오른쪽 패딩, base58 인코딩)로부터 파생되므로, 하나의 키에 대한 Cosmos, EVM, SVM 주소는 모두 동일한 자금을 가리킵니다.

## v3.1.80 — 다층 상태 앵커 조회

**릴리스 초점:** 롤업을 위한 읽기 가능하고 오프라인에서 검증 가능한 정산 앵커.

* **앵커 읽기 조회** — `x/multilayer` 조회 서비스는 이제 `Anchor`(레이어의 최신 상태 앵커)와 `Anchors`(레이어의 앵커 이력)를 노출하므로, 클라이언트가 레이어의 정산 앵커를 가져와 독립적으로 검증할 수 있습니다.
* **다층 구조를 위한 REST 게이트웨이** — 모든 다층 구조 조회(`params`, `layers`, `layers/{layer_id}`, `anchor/{layer_id}`, `anchors/{layer_id}`, `routing-stats`)가 이제 gRPC뿐 아니라 REST로도 제공됩니다.
* **양자 안전 정산 영수증의 기반 마련** — 각 앵커는 정규화된 필드에 대한 **ML-DSA-87(Dilithium-5)** 서명을 포함하여, 롤업 개발 키트의 오프라인 정산 영수증 검증을 위한 온체인 근거를 제공합니다.

## v3.1.79 — 브리지 네트워크를 위한 검증인 자동 프로비저닝

**릴리스 초점:** 라이선스를 보유한 검증인을 위한 연결 네트워크 참여의 즉시 사용 가능화.

* **네트워크 드라이버 프레임워크** — 선언적 드라이버 프레임워크를 통해 관련 `validator_<chain>`(또는 `qcb_bridge`) 라이선스를 보유한 QoreChain 검증인이 동일 노드에서 QoreChain 오케스트레이션 하에 해당 외부 네트워크 클라이언트를 프로비저닝, 구성, 실행할 수 있으며 — 이는 라이선스가 활성화된 이후에만 가능합니다.
* **37개 브리지 네트워크 전체에 대한 드라이버** — 연결된 모든 네트워크를 아우르며, 참여 모델(권한 없는 검증인, 상한/선출/승인제, L2 풀 노드, 비스테이킹/신뢰 목록 역할)별로 분류됩니다. 외부 네트워크 스테이크와 서명 키는 네트워크마다 운영자가 별도로 공급하며, QoreChain은 프레임워크와 강제되는 라이선스 게이트를 제공합니다.

## v3.1.78 — 배포 사전 준비 완료

**릴리스 초점:** 지갑, 브리지, IBC, 라이선스 모두가 배포 이후 거버넌스 없이 출시 시점부터 작동합니다.

* **신뢰 없는 배포 후 브리지 활성화** — `bridge_admin` 키(또는 `qcb_bridge` 라이선스 보유자)는 단일 서명 트랜잭션(`tx bridge update-chain-config` / `set-verifier-bootstrap`)으로 연결된 어떤 체인의 브리지든 활성화할 수 있습니다 — 컨트랙트 주소, 확인 수, 아키텍처, 상태, 활성 검증자, 검증자 신뢰 루트를 설정하며, 거버넌스 제안이나 체인 업그레이드가 필요하지 않습니다.
* **검증인 네트워크 라이선스 게이트** — 오케스트레이터는 이제 외부 네트워크 클라이언트를 시작하기 전에 `validator_<chain>` / `qcb_bridge` 라이선스를 (기본 거부 방식으로) 강제합니다.
* **지갑 통합 패키지** — `@qorechain/wallet-adapter`와 `@qorechain/connect`가 npm에 게시되었습니다(v0.1.0). 원클릭 MetaMask 네트워크 등록(EIP-3085, EVM 레일에서 **소수점 18자리** 네이티브 QOR)과 Keplr 가스 가격 설정이 추가되었습니다.
* **IBC 즉시 사용 가능 릴레이어** — 8개 IBC 상대 네트워크를 위한 실행 준비 완료 릴레이어 구성과 채널 부트스트랩 도구가 제공되어, 별도 설정 없이도 배포 이후 채널이 열립니다.

## v1.1.0 — PQC 하이브리드 서명

**릴리스 초점:** 사후양자 암호화 보안과 알고리즘 애자일리티.

* **secp256k1(ECDSA) + ML-DSA-87 이중 서명** — 모든 트랜잭션이 고전 서명과 사후양자 서명을 모두 포함하며, AnteHandler 체인에서 검증됩니다
* **3가지 강제 적용 모드** — 구성 가능한 하이브리드 서명 강제 적용: 끔(모드 0), 허용(모드 1, PQC 선택 사항), 필수(모드 2, PQC 필수)
* **키 등록** — 초기 빌드는 첫 하이브리드 트랜잭션에서 PQC 공개 키를 자동으로 등록했으나 이 동작은 제거되었으며, 이제 키는 `MsgRegisterPQCKey`로 명시적으로 등록합니다([첫 트랜잭션](/getting-started/first-transaction#register-pqc-key) 참고)
* **SHAKE-256 해시 기반** — 모든 PQC 관련 해싱 연산은 양자 저항성 주소 파생을 위해 SHAKE-256(SHA-3 계열)을 사용합니다
* **TEE 증명 인터페이스** — PQC 키 생성 무결성을 증명하기 위한 신뢰 실행 환경(Trusted Execution Environment) 증명 지원
* **알고리즘 애자일리티 프레임워크** — 체인 업그레이드 없이 거버넌스를 통해 향후 PQC 알고리즘을 추가할 수 있는 플러그형 알고리즘 레지스트리

## v1.0.0 — 제네시스(토크노믹스 엔진)

**릴리스 초점:** 완전한 토크노믹스, 다중 VM 실행, AI 지원 운영을 갖춘 초기 프로토콜 출시.

* **x/burn 모듈** — 검증인, 소각, 트레저리, 스테이커에 걸친 4분할 배분을 갖춘 다채널 수수료 소각 메커니즘
* **x/xqore 모듈** — 단계적 조기 잠금 해제 페널티와 PvP 리베이스 재분배를 갖춘 거버넌스 스테이킹 파생상품
* **x/inflation 모듈** — 연간 감쇠를 적용한 에포크 기반 발행(v3.1.94에서 엄격한 누적 상한 하의 에포크당 고정 금액으로 대체됨)
* **PRISM 합의 계층** — 동적 체인 파라미터 조정을 위한 강화학습 최적화(PPO), 회로 차단기(circuit-breaker) 안전 제어 포함
* **트리플 풀 CPoS** — 평판 점수로 가중된 RPoS, DPoS, PoS 검증인 풀을 갖춘 복합 지분 증명(Composite Proof-of-Stake) (`x/qca`에 구현되어 있으나 아직 블록 생성에 연결되지 않음)
* **QDRW 거버넌스** — 평판 가중치를 적용한 2차 위임(Quadratic Delegation with Reputation Weighting) 투표권 산식(구현되어 있으나 가동 중인 네트워크에서는 비활성화)
* **EVM + QoreChain Native + SVM 런타임** — QoreChain EVM 엔진, QoreChain Native 스마트 컨트랙트, Solana Virtual Machine이라는 세 가지 동시 실행 환경
* **크로스 VM 브리지** — 단일 블록 내에서 EVM, QoreChain Native, SVM 런타임 간의 메시지 전달과 자산 이체
* **사후양자 암호화** — 고성능 PQC 라이브러리 기반의 양자 저항형 서명
* **QCAI** — 사기 탐지, 수수료 추정, 네트워크 최적화를 위한 온체인 휴리스틱 분석과 선택적 오프체인 사이드카
* **컨테이너화된 배포** — 사이드카 서비스와 블록 인덱서를 갖춘 완전한 다중 검증인 테스트넷 배포
* **블록 인덱서** — 과거 이력 조회와 분석을 위한 영구 저장소를 갖춘 블록 리스너
