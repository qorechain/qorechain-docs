# 버전 히스토리

QoreChain의 공개 버전 히스토리입니다. 최신 릴리스는 **v3.1.85**이며, 메인넷 **`qorechain-vladi`**(EVM 체인 ID **9801**, 2026년 6월 7일부터 가동 중)에서 실행되고 있습니다. 테스트넷 **`qorechain-diana`**(EVM 체인 ID **9800**)는 프리릴리스 빌드를 추적합니다.

:::note
아래 항목은 상위 수준의 기능 요약입니다. 이전 `v1.x` 항목은 메인넷 이전의 테스트넷 릴리스 라인에 대한 역사적 기록으로 보존되어 있습니다.
:::

---

## v3.1.85 — 연결된 지갑을 통한 위임 지출 (현재 릴리스)

**릴리스 초점:** 연결된 외부 지갑 키(Phantom, MetaMask)가 이제 하나의 정식 포스트 양자 계정에서 **지출**할 수 있습니다 — 최소 권한 원칙의 권한 설정, 지출 한도, 즉시 철회가 적용됩니다.

* **인증자 실행 레인** — 두 가지 새 메시지를 통해 등록된 인증자가 계정 소유자의 참여 없이 정식 계정에서의 이체를 승인할 수 있습니다: **`MsgExecuteEVM`**(계정의 `0x…` 주소에서 발생하는 EVM 호출/이체)과 **`MsgExecuteCosmos`**(Native 레인 뱅크 전송). **릴레이어**가 봉투(envelope)를 제출하고 수수료를 지불하며 — 릴레이어 자신의 하이브리드 PQC 서명이 트랜잭션 요건을 충족합니다 — 도메인 분리와 재사용 방지가 적용된 서명 바이트에 대한 인증자의 서명이 승인 역할을 합니다. 외부 키에는 ML-DSA 공동 서명이 전혀 필요하지 않습니다.
* **인증자로서의 MetaMask** — secp256k1 인증자를 이제 (기존의 33바이트 압축 키 형식에 더해) **20바이트 Ethereum 주소**로 등록하고 **EIP-191 `personal_sign`**으로 검증할 수 있으므로, 표준 MetaMask 계정을 연결하여 한도 내에서 지출할 수 있습니다.
* **세 레인 모두에서의 시행** — 권한 범위와 **SpendingRule** 금액 한도(트랜잭션당 + 일일 상한)가 Native, EVM, SVM 레인에서 시행되며, 키 관리 메시지는 절대 위임할 수 없습니다. 구분된 오류 코드를 통해 지갑이 올바른 메시지를 표시할 수 있습니다: `5` 지출 한도 초과, `6` 인증자 만료, `10` 권한 거부, `11` 재사용(replay) 거부.
* **권한 스키마 쿼리** — `GET /qorechain/abstractaccount/v1/permission_schema`(gRPC/CLI로도 제공)는 정식 권한 분류 체계(11개 권한), 메시지→권한 매핑, 위임 불가 메시지 목록을 반환하므로, 지갑이 하드코딩 없이 범위를 검증할 수 있습니다.
* **동일 알고리즘 PQC 키 로테이션** — 새로운 **`MsgRotatePQCKey`**는 계정의 ML-DSA-87 키를 동일 알고리즘 내에서 교체하며(기존 키와 새 키의 이중 서명), 레거시 방식으로 파생된 키를 정식 주소 결합 파생 방식으로 이전하고 손상된 키를 폐기할 수 있게 합니다. 새 CLI: `tx pqc rotate-key` 및 `tx pqc recover-key`(니모닉으로부터의 결정적 키 복구).
* **루트 키 트랜잭션은 영향 없음** — 이번 변경은 추가적(additive)이며, 일반 지갑, 거래소, Keplr 플로우는 변경되지 않습니다. 노드 운영자는 네트워크 업그레이드 높이까지 **v3.1.85**를 실행해야 합니다.

## v3.1.84 — 인증자 권한 및 지출 한도

**릴리스 초점:** 위임 지출을 뒷받침하는 권한 모델.

* **정식 권한 분류 체계** — 11개 권한(`all`, `send`, `delegate`, `withdraw`, `vote`, `evm`, `wasm`, `svm`, `amm`, `ibc`, `deploy`)과 실패 시 차단(fail-closed) 방식의 메시지→권한 매핑: 매핑되지 않은 메시지 타입은 거부되며, 키 관리 메시지는 절대 위임될 수 없습니다.
* **SpendingRule 시행** — 트랜잭션당 및 일일(UTC) 지출 상한과 허용 디놈(denom) 목록이 (계정, 인증자) 쌍별로 시행되고 기록됩니다.
* **SVM 레인 승인** — 외부 스킴 키(예: Phantom ed25519)가 SVM 레인에서 승인하는 작업도 동일한 중앙 승인 게이트를 거칩니다.

## v3.1.83 — 세 인터페이스 전체에 걸친 통합 계정 서명

**릴리스 초점:** 하나의 키, 하나의 계정 — 단일 통합 아이덴티티가 이제 Cosmos, EVM, SVM 인터페이스에서 잔액 보유뿐 아니라 **서명**까지 할 수 있습니다.

* **하나의 키가 모든 레인에서 서명** — eth 네이티브로 생성된 계정(주소 = secp256k1 공개 키의 keccak)이 이제 EVM 트랜잭션에 더해 `eth_secp256k1` 스킴으로 Cosmos 레인 트랜잭션에도 서명합니다. 해당 계정의 `qor1…`(Cosmos), `0x…`(EVM), Solana-VM(base58) 형태는 하나의 20바이트 아이덴티티로서, **하나의 잔액을 보유**하고 — 포스트 양자 하이브리드(ML-DSA-87) Cosmos 트랜잭션을 포함하여 — **세 레인 모두에서 지출**합니다.
* **포스트 양자 서명은 변경 없음** — 통합 계정도 여전히 ML-DSA-87 키를 등록하고 체인이 요구하는 FIPS-204 하이브리드 서명을 포함합니다. 클래식 부분이 coinType-118 스킴 대신 `eth_secp256k1`(keccak)일 뿐입니다. 기존 coinType-118 계정은 영향을 받지 않습니다.
* **합의 중립적 롤링 업그레이드** — 두 네트워크 모두에서 **재제네시스(re-genesis) 없이, 체인 중단 없이** 롤링 바이너리 업그레이드로 배포되었습니다. 계정 잔액, 이력, 제네시스는 변경되지 않습니다.
* **클라이언트 툴링** — `@qorechain/wallet-adapter` 0.1.5는 eth 네이티브 Cosmos 서명(`signClassicalEth` / `signHybridEth`), 통합 3주소 생성, `walletFromSeed`(임의의 32바이트 시드 — 예: Phantom 서명 — 로부터 정식 계정 파생)를 추가하며, `@qorechain/chain-bridge`에는 `eth_secp256k1` 서명 경로가 추가되었습니다.

:::caution 노드 운영자 — 업그레이드 필수
풀 노드는 **v3.1.83+**를 실행해야 합니다. 3.1.83 이전 노드는 eth 네이티브(`eth_secp256k1`) 트랜잭션을 디코딩할 수 없어, 해당 트랜잭션이 블록에 나타나는 순간 동기화가 중단됩니다. 최신 번들은 [download.qore.host](https://download.qore.host)에서 다운로드하세요.
:::

## v3.1.82 — SVM 네이티브 QOR 가동 + 통합사 지원

**릴리스 초점:** 두 네트워크 모두에서 가동 중인 SVM 네이티브 QOR 통합과 거래소 또는 통합사가 연동에 필요한 모든 것.

* **세 인터페이스 모두에서 통합 네이티브 QOR 잔액 가동** — SVM 통합(v3.1.81)이 메인넷과 테스트넷에서 정상 가동 중임이 확인되었습니다. 동일한 계정이 하나의 잔액을 보유하며, Cosmos에서는 `uqor`(6자리 소수점), EVM에서는 wei 방식의 18자리 소수점, Solana 호환 인터페이스에서는 lamports(9자리 소수점, 1 uqor = 1,000 lamports)로 표시됩니다.
* **검증된 공개 엔드포인트** — 두 네트워크 모두에서 합의 RPC, REST, EVM JSON-RPC, SVM JSON-RPC용 공개 HTTPS 엔드포인트와 공개 [블록 탐색기](https://explore.qore.network)를 제공합니다. [네트워크](/appendix/networks)를 참조하세요.
* **다운로드** — 버전별 노드 바이너리 번들, 메인넷 제네시스, 최신 체인 데이터 스냅샷(SHA-256 체크섬 포함)이 [download.qore.host](https://download.qore.host)에 게시되어 있습니다.
* **클라이언트 스택 전반의 결정적 포스트 양자 서명** — `@qorechain/pqc` 0.1.1은 6개 언어 바인딩 모두에서 ML-DSA-87을 결정적으로(FIPS-204 §3.4) 서명하며, 이는 체인이 수용하는 방식과 일치합니다. `@qorechain/wallet-adapter` 0.1.2는 이를 기반으로 하이브리드 트랜잭션 서명을 지원합니다.
* **통합사 가이드** — 세 인터페이스 전반의 입금, 출금, 노드 운영을 다루는 새로운 [거래소 및 통합사 가이드](/developer-guide/exchange-integration)가 추가되었습니다.

## v3.1.81 — SVM 네이티브 QOR 통합

**릴리스 초점:** Solana 호환 인터페이스에서 네이티브 QOR을 일급 자산으로 지원.

* **SVM에서의 네이티브 QOR** — SVM 런타임이 이제 별도의 SVM 전용 잔액을 추적하는 대신 계정의 네이티브 QOR 잔액을 직접(lamports 단위로) 노출합니다. `getBalance`와 `getSignaturesForAddress`가 네이티브 자금에 대해 작동하며, System Program 이체가 네이티브 QOR을 이동시킵니다.
* **SVM 주소 매핑** — 계정의 SVM 주소는 20바이트 계정 바이트로부터 파생되므로(32바이트로 오른쪽 패딩 후 base58 인코딩), 하나의 키에 대한 Cosmos, EVM, SVM 주소가 모두 동일한 자금을 가리킵니다.

## v3.1.80 — Multilayer 상태 앵커 쿼리

**릴리스 초점:** 롤업을 위한 읽기 가능하고 오프라인 검증 가능한 정산 앵커.

* **앵커 조회 쿼리** — `x/multilayer` 쿼리 서비스가 이제 `Anchor`(레이어의 최신 상태 앵커)와 `Anchors`(레이어의 앵커 이력)를 노출하므로, 클라이언트가 레이어의 정산 앵커를 가져와 독립적으로 검증할 수 있습니다.
* **multilayer용 REST 게이트웨이** — 모든 multilayer 쿼리(`params`, `layers`, `layers/{layer_id}`, `anchor/{layer_id}`, `anchors/{layer_id}`, `routing-stats`)를 이제 gRPC에 더해 REST로도 사용할 수 있습니다.
* **양자 안전 정산 영수증 지원 개시** — 각 앵커는 정식 필드에 대한 **ML-DSA-87 (Dilithium-5)** 서명을 포함하여, Rollup Development Kit의 오프라인 정산 영수증 검증을 위한 온체인 기반을 제공합니다.

## v3.1.79 — 브리지 네트워크용 밸리데이터 자동 프로비저닝

**릴리스 초점:** 라이선스를 보유한 밸리데이터를 위한 연결 네트워크 턴키 참여.

* **네트워크 드라이버 프레임워크** — 선언적 드라이버 프레임워크를 통해, 해당 `validator_<chain>`(또는 `qcb_bridge`) 라이선스를 보유한 QoreChain 밸리데이터는 — 라이선스가 활성화된 경우에 한해 — QoreChain 오케스트레이션 하에서 동일 노드에 해당 외부 네트워크 클라이언트를 프로비저닝, 구성, 실행할 수 있습니다.
* **37개 브리지 네트워크 전체를 위한 드라이버** — 참여 모델(퍼미션리스 밸리데이터, 상한/선출/승인제, L2 풀 노드, 논스테이킹/트러스트 리스트 역할)로 분류된 모든 연결 네트워크를 포괄합니다. 외부 네트워크의 스테이크와 서명 키는 네트워크별로 운영자가 계속 제공하며, QoreChain은 프레임워크와 강제되는 라이선스 게이트를 제공합니다.

## v3.1.78 — 배포 전 준비 완료

**릴리스 초점:** 지갑, 브리지, IBC, 라이선싱이 런칭 시점부터 모두 작동 — 배포 후 거버넌스 절차 불필요.

* **무신뢰 배포 후 브리지 활성화** — `bridge_admin` 키(또는 `qcb_bridge` 라이선스 보유자)는 단일 서명 트랜잭션(`tx bridge update-chain-config` / `set-verifier-bootstrap`)으로 — 컨트랙트 주소, 확인 수, 아키텍처, 상태, 활성 검증자(verifier), 검증자 트러스트 루트를 설정하며 — 거버넌스 제안이나 체인 업그레이드 없이 임의의 연결 체인의 브리지를 활성화할 수 있습니다.
* **밸리데이터 네트워크 라이선스 게이트** — 오케스트레이터가 이제 외부 네트워크 클라이언트를 시작하기 전에 `validator_<chain>` / `qcb_bridge` 라이선스를 (실패 시 차단 방식으로) 강제합니다.
* **지갑 통합 패키지** — `@qorechain/wallet-adapter`와 `@qorechain/connect`가 npm에 게시되었으며(v0.1.0), 원콜 MetaMask 네트워크 등록(EIP-3085, EVM 레일에서 **18자리 소수점** 네이티브 QOR)과 Keplr 가스 가격 구성이 추가되었습니다.
* **IBC 턴키 릴레이어** — 8개 IBC 상대 체인을 위한 즉시 실행 가능한 릴레이어 구성과 채널 부트스트랩 툴링을 제공하여, 별도의 맞춤 설정 없이 배포 후 채널이 개설됩니다.

## v3.1.77 — 브리지 및 소각 REST 엔드포인트

**릴리스 초점:** 크로스체인 및 공급 모듈을 위한 읽기 전용 REST 액세스.

* **브리지 REST 엔드포인트** — 브리지 모듈용 읽기 전용 HTTP 쿼리 엔드포인트로, gRPC에 더해 표준 REST로 브리지 상태를 노출합니다.
* **소각 REST 엔드포인트** — 소각(burn) 모듈용 읽기 전용 HTTP 쿼리 엔드포인트로, 수수료 분배 및 공급 데이터를 표준 REST로 조회할 수 있습니다.

## v3.1.76 — SVM 툴체인 현대화

**릴리스 초점:** Solana Virtual Machine 호환성 갱신.

* **최신 툴체인 프로그램 지원** — SVM 실행이 현대화되어 최신 Solana 툴체인으로 빌드된 프로그램이 QoreChain SVM 런타임에서 실행됩니다.

## v3.1.75 — SVM JSON-RPC 기본 활성화

**릴리스 초점:** 즉시 사용 가능한 Solana 호환 RPC.

* **Solana 호환 JSON-RPC** — SVM JSON-RPC 서버가 이제 기본으로 활성화되어(포트 **8899**) 노드와 함께 자동으로 시작되며, SVM 툴링을 위한 Solana 호환 RPC 인터페이스를 제공합니다.

## v1.1.0 — PQC 하이브리드 서명

**릴리스 초점:** 포스트 양자 암호화 보안과 알고리즘 민첩성.

* **이중 secp256k1 (ECDSA) + ML-DSA-87 서명** — 모든 트랜잭션이 클래식 서명과 포스트 양자 서명을 모두 포함하며, AnteHandler 체인에서 검증됩니다
* **3가지 강제화 모드** — 구성 가능한 하이브리드 서명 강제화: off(모드 0), permissive(모드 1, PQC 선택), mandatory(모드 2, PQC 필수)
* **자동 등록** — PQC 공개 키가 첫 하이브리드 트랜잭션에서 자동으로 등록되어 별도의 등록 단계가 필요 없습니다
* **SHAKE-256 해시 기반** — 모든 PQC 관련 해싱 작업이 양자 내성 주소 파생을 위해 SHAKE-256(SHA-3 계열)을 사용합니다
* **TEE 증명 인터페이스** — PQC 키 생성 무결성을 증명하기 위한 신뢰 실행 환경(TEE) 증명 지원
* **알고리즘 민첩성 프레임워크** — 체인 업그레이드 없이 거버넌스를 통해 향후 PQC 알고리즘을 추가할 수 있는 플러그형 알고리즘 레지스트리

## v1.0.0 — 제네시스 (토크노믹스 엔진)

**릴리스 초점:** 완전한 토크노믹스, 멀티 VM 실행, AI 지원 운영을 갖춘 최초 프로토콜 런칭.

* **x/burn 모듈** — 밸리데이터, 소각, 트레저리, 스테이커에 걸친 4방향 분배를 갖춘 멀티 채널 수수료 소각 메커니즘
* **x/xqore 모듈** — 단계별 조기 해제 페널티와 PvP 리베이스 재분배를 갖춘 거버넌스 스테이킹 파생 상품
* **x/inflation 모듈** — 유한 발행 경제 모델이 관리하는 연간 감쇠 방식의 에포크 기반 발행
* **PRISM 합의 레이어** — 서킷 브레이커 안전 장치를 갖춘 동적 체인 파라미터 튜닝을 위한 강화학습 최적화(PPO)
* **트리플 풀 CPoS** — 평판 점수로 가중치가 부여되는 Emerald, Sapphire, Ruby 밸리데이터 풀을 갖춘 분류형 지분 증명(Classified Proof-of-Stake)
* **QDRW 거버넌스** — 풀 간 보상 분배를 거버넌스 승인으로 조정할 수 있는 동적 보상 가중치(Dynamic Reward Weighting) 시스템
* **EVM + CosmWasm + SVM 런타임** — 세 개의 동시 실행 환경: QoreChain EVM Engine, CosmWasm 스마트 컨트랙트, Solana Virtual Machine
* **크로스 VM 브리지** — 단일 블록 내에서 EVM, CosmWasm, SVM 런타임 간 메시지 전달 및 자산 이전
* **포스트 양자 암호화** — 고성능 PQC 라이브러리로 뒷받침되는 양자 내성 서명
* **QCAI** — 사기 탐지, 수수료 추정, 네트워크 최적화를 위한 선택적 오프체인 사이드카를 갖춘 온체인 휴리스틱 분석
* **컨테이너화 배포** — 사이드카 서비스와 블록 인덱서를 포함한 완전한 멀티 밸리데이터 테스트넷 배포
* **블록 인덱서** — 과거 조회 및 분석을 위한 영구 스토리지를 갖춘 블록 리스너
