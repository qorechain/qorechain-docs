# 주요 기능

다음 표는 QoreChain의 모든 주요 기능을 도입된 릴리스 단계별로 정리한 것입니다. 현재 메인넷 릴리스는 **v3.2.3**이며, 2026년 6월 7일부터 가동 중입니다(`qorechain-vladi`, EVM 체인 ID 9801). 병행 운영 중인 테스트넷(`qorechain-diana`, EVM 체인 ID 9800)은 테스트넷 전용 릴리스인 v3.2.4를 실행합니다. 기능 목록 끝의 [기능 상태](#feature-status) 표는 현재 라이브 네트워크에서 무엇이 활성화되어 있는지 보여줍니다.

| 기능                    | 도입된 버전       | 설명                                                                                                                                                                                                                                                                                                                                                                                     |
| -------------------------- | ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| PQC 하이브리드 서명 (기본값으로 필수) | v1.1.0 (Security)   | 모든 코스모스 경로 트랜잭션에 적용되는 이중 서명입니다: 고전 방식의 secp256k1(ECDSA) 서명과 ML-DSA-87(Dilithium-5) 서명이 함께 사용됩니다. v3.1.71부터 네트워크 기본값은 **필수(required)**로 설정되어(`hybrid_signature_mode = required`, `allow_classical_fallback = false`) 고전 방식 서명만 사용한 코스모스 트랜잭션은 거부됩니다. 예외는 제네시스 gentx와 PQC 키 등록/마이그레이션 트랜잭션뿐입니다. EVM 트랜잭션은 `eth_secp256k1` 서명을 유지하지만, v3.2.0부터는 등록된 ML-DSA-87 키를 가진 계정에서 오고 열려 있는 [EVM 승인 창](/getting-started/first-transaction#evm-window)이 있을 때만 허용됩니다. 거버넌스로 제어되는 세 가지 시행 모드(disabled / optional / required)가 계속 제공됩니다.                                                                              |
| SHAKE-256 기본 해시     | v1.1.0 (Security)   | SHA-3 계열의 확장 출력 함수(XOF)입니다. v3.1.73부터 SHAKE-256(`qorehash` 패키지를 통해 제공)이 **기본 애플리케이션 해시**가 되어 PQC 기준선(Dilithium-5 + ML-KEM-1024 + SHAKE-256)이 완성되었습니다. 가변 길이 해싱, 고정 32바이트 출력, 머클 내부 노드 연결, 도메인 분리 해싱을 모두 순수 Go로 제공하며 FFI 의존성이 없습니다.                                                                                                                 |
| TEE 및 FL 인터페이스      | v1.1.0 (Security)   | 신뢰 실행 환경(TEE) 증명(SGX, TDX, SEV-SNP, ARM CCA)과 연합 학습(Federated Learning) 조정(FedAvg, FedProx, SCAFFOLD 집계 방식)을 위한 인터페이스 사양(아직 구현 없음)이며, 둘 다 향후 릴리스에서 계획되어 있습니다.                                                                |
| 온체인 RL 합의 (PRISM) | v1.0.0 (Genesis) | Go 네이티브 고정소수점 MLP(파라미터 73,733개)가 블록 라이프사이클 내에서 PPO 추론을 수행하도록 내장되어 있습니다. PRISM은 블록 시간, 가스 가격, 풀 가중치를 조정하도록 설계되었으며, 라이브 네트워크에서는 현재 관찰만 합니다(학습된 정책이 로드되어 있지 않고 제어 메시지는 비활성화되어 있습니다). 결정론적 테일러 급수 연산은 모든 검증인 간에 동일한 결과를 내도록 설계되었습니다. shadow, conservative, autonomous, paused의 네 가지 운영 모드가 있으며, 두 네트워크 모두 conservative로 설정되어 있습니다. 안전을 위한 서킷 브레이커 보호 기능도 포함됩니다. |
| 트리플 풀 복합 PoS  | v1.0.0 (Genesis)    | 설계 사항: 검증인은 1,000블록마다 RPoS(평판 가중), DPoS(위임 가중), PoS(표준) 풀로 분류됩니다. 풀 가중 소티션은 순수 지분 우위를 넘어 블록 생성을 다변화하고, 커스텀 본딩 커브는 자가 본딩된 지분, 충성 기간, 평판 품질, 프로토콜 단계를 반영합니다. `x/qca`에 구현되어 있지만 **아직 블록 생성, 보상, 슬래싱에서는 활성화되지 않았으며**, 블록 제안과 슬래싱은 현재 표준 지분 가중 규칙을 따릅니다.                            |
| QDRW 거버넌스            | v1.0.0 (Genesis)    | 평판 가중 이차 위임(Quadratic Delegation with Reputation Weighting) 방식입니다. 투표력은 시그모이드 평판 승수로 감쇠된 제곱근 함수를 사용하도록 설계되어, 고래(대규모 보유자)의 지배를 방지하는 동시에 장기적이고 정직한 참여에 보상을 제공합니다(지분이 100배 많아도 투표력은 약 10배에 그치며, xQORE 보유분은 투표 가중치를 두 배로 만듭니다). 구현되어 있지만 **라이브 네트워크에서는 비활성화되어 있으며**(`qdrw`가 꺼져 있음), 제안은 현재 본딩된 지분 기준으로 집계됩니다.                                                                               |
| 소각 엔진                | v1.0.0 (Genesis)    | 열두 가지 소각 원천이 있습니다: 가스 수수료, 컨트랙트 생성, AI 서비스 수수료, 브리지 수수료, 트레저리 바이백, 실패한 트랜잭션, xQORE 페널티, 자동 바이백, TGE 소각, 롤업 생성, 트랜잭션 수 마일스톤, AMM입니다. 메인넷에서는 지금까지 가스 수수료 채널과 실패한 트랜잭션 채널에서만 소각이 기록되었습니다. 에포크 발행분을 포함해 수수료 징수기에 있는 모든 금액은 **검증인에 37%, 영구 소각 30%, 트레저리에 20%, 스테이커에 10%, 라이트 노드에 3%**로 분배됩니다.                                                            |
| xQORE 스테이킹              | v1.0.0 (Genesis)    | 아직 라이브가 아닙니다: 모듈의 잠금 및 해제 트랜잭션이 라이브 네트워크에 연결되어 있지 않습니다([xQORE 스테이킹](/user-guide/xqore-staking) 참조). 설계된 동작: QOR을 잠그면 1:1 비율로 xQORE가 발행되어 QDRW 투표에서 거버넌스 가중치가 두 배가 됩니다. 단계적 탈퇴 페널티(30일 미만 50%, 30~90일 35%, 90~180일 15%, 180일 이후 0%)는 PvP 리베이스를 통해 남아 있는 보유자에게 재분배되며, 이는 장기 보유를 보상하고 단기 자본을 억제합니다.                                                                                      |
| 상한이 있는 발행량     | v1.0.0 (Genesis)    | 유한한 공급 경로입니다: 제네시스 시점 4,420,000,000 QOR(계획된 4,500,000,000 QOR 중 80,000,000 QOR가 TGE에서 소각됨)에, `x/inflation`이 발행하는 스테이킹 발행분이 누적 상한 590,000,000 QOR 아래에서 더해집니다(`fixed` 모드에서 43,200블록 에포크당 86,000 QOR, 2026년 10월 거버넌스 제안 10 이후). 소각은 토큰을 영구적으로 제거합니다. [토크노믹스](/architecture/tokenomics#supply-and-emission)를 참조하세요. |
| EVM 런타임                | v1.0.0 (Genesis)    | EIP-1559 가스 가격 책정, 포트 8545의 JSON-RPC(`eth_`, `web3_`, `net_`, `txpool_` 네임스페이스. `qor_` 네임스페이스는 아직 제공되지 않음), Hardhat·Foundry·Remix 등 표준 툴링 지원을 포함한 완전한 이더리움 호환성을 제공합니다. 기존 이더리움 워크플로를 사용하여 Solidity 컨트랙트를 배포하고 상호작용할 수 있으며, v3.2.0부터 발신자에게는 등록된 포스트 양자 키와 열려 있는 [EVM 승인 창](/getting-started/first-transaction#evm-window)이 필요합니다.                                                                                                                    |
| CosmWasm 런타임           | v1.0.0 (Genesis)    | Rust 기반 컨트랙트를 위한 WebAssembly 스마트 컨트랙트 엔진입니다. 인스턴스화, 실행, 조회, 마이그레이션 등 전체 라이프사이클을 지원합니다. 컨트랙트는 결정론적 실행이 보장되는 샌드박스 Wasm 환경에서 실행됩니다. 코드 업로드와 인스턴스화는 현재 두 네트워크 모두에서 **비활성화**되어 있습니다(거버넌스 설정 및 서킷 브레이커).                                                                                                                                                                                       |
| SVM 런타임                | v1.0.0 (Genesis)    | Rust 기반 실행기를 통한 BPF 프로그램 배포 및 실행입니다. 포트 8899의 솔라나 호환 JSON-RPC 서버가 `getAccountInfo`, `getBalance`, `getSlot` 등을 지원합니다. 읽기 메서드는 퍼블릭 엔드포인트에서 동작하며, SVM 트랜잭션 레인은 현재 네트워크 전체에서 **비활성화**되어 있습니다.                                                                                                                                    |
| 크로스 VM 브리지            | v1.0.0 (Genesis)    | 세 가지 VM 전반에 걸친 매끄러운 상호운용성을 제공합니다. EVM 컨트랙트는 프리컴파일을 통해 CosmWasm을 호출하고(아직 활성화되지 않음, [네트워크 상태](/developer-guide/evm-precompiles#network-status) 참조), CosmWasm 컨트랙트는 커스텀 메시지를 통해 EVM을 호출하며, SVM 프로그램은 비동기 이벤트 기반 브리징을 통해 참여합니다. 단일 체인 내에서 동기식 EVM-CosmWasm 호출과 비동기식 SVM 메시징이 모두 가능합니다. 크로스 VM 호출 메시지는 현재 메인넷에서 꺼져 있습니다.                                                                                                  |
| 크로스체인 연결성   | v1.2.0 (Interop)    | 최대 8개의 IBC 상대방(Cosmos Hub, Osmosis, Noble, Celestia, Stride, Akash, Babylon, Injective)과 **37개의 QCB 체인 설정(외부 체인 36개와 IBC를 통한 Injective)**을 위해 설계되었습니다. PQC로 서명된 검증인 증명, 체인별 확인 깊이, 서킷 브레이커 거래량 한도가 적용됩니다. 2026년 10월 기준 37개 체인 설정은 모두 `pending` 상태이며 어느 네트워크에서도 IBC 채널이 열려 있지 않습니다 — **라이브 아님**.                               |
| BTC 리스테이킹              | v1.2.0 (Interop)    | 설계 단계 — 이 모듈의 트랜잭션은 라이브 네트워크에서 활성화되어 있지 않습니다. 비트코인 파이널리티 보증을 위한 Babylon Protocol 통합입니다. 검증인은 BTC 스테이킹 포지션을 등록하게 됩니다(최소 100,000사토시). QoreChain 에포크 상태 루트는 IBC로 중계되는 Babylon 에포크를 통해 주기적으로 비트코인에 체크포인팅되어, BTC 해시레이트가 뒷받침하는 보조 파이널리티 레이어를 제공합니다.                                                                                           |
| 계정 추상화        | v1.2.0 (Interop)    | 프로토콜 계층에서 제공되는 프로그래머블 스마트 계정입니다(ERC-4337과 유사). 멀티시그, 소셜 리커버리, 세션 기반의 세 가지 계정 유형이 있습니다. 세분화된 권한과 만료 시점을 가진 세션 키, 계정별 일일 및 트랜잭션별 지출 규칙, 범위가 지정된 디놈(denom) 허용 목록을 포함합니다. 구현되어 있지만 현재 두 네트워크 모두에서 **꺼져 있습니다**(`abstractaccount.enabled = false`, `GET /qorechain/abstractaccount/v1/config`로 확인).                                                                      |

FairBlockDecorator 안테 핸들러는 배선이 완료되어 있으며, 키 세리머니 배포 이후 tIBE 임계값 복호화가 활성화됩니다. 현재 두 네트워크 모두에서 **비활성화**되어 있습니다(`enabled = false`).                                           |

| 온체인 유동성 (AMM)   | v1.2.0 (Interop)    | 네이티브 자동화된 마켓 메이커(`x/amm`)가 프로토콜 계층에서 온체인 유동성 풀과 스왑을 제공합니다. 모듈은 라이브이며, 아직 생성된 풀은 없습니다.                                                                                                                                                                                                                                                                                     |

## 기능 상태 (2026년 10월) {#feature-status}

2026년 10월 20일에 라이브 네트워크를 기준으로 확인했습니다. "라이브"는 해당 기능이 메인넷에서 활성화되어 있다는 뜻이며(행에 별도 표기가 없는 한 테스트넷에서도 마찬가지입니다), 위의 설명은 각 기능이 무엇을 하도록 설계되었는지를 나타냅니다.

| 기능 | 라이브 네트워크에서의 상태 |
| --- | --- |
| 하이브리드 ML-DSA-87 + secp256k1 서명 (Cosmos 레인) | **라이브**, 필수 (`hybrid_signature_mode = required`) |
| EVM 승인 창 | v3.2.0부터 **라이브** (선택적 범위 지정은 v3.2.3부터) |
| 시간 잠금 스테이킹 (`x/stakingtier`) | **테스트넷 전용** (v3.2.4). 메인넷에는 없음 |
| EVM, CosmWasm, SVM 런타임 | EVM **라이브**. CosmWasm 코드 업로드와 인스턴스화는 **비활성화**(거버넌스 설정 및 서킷 브레이커). SVM 트랜잭션 레인은 **비활성화**(읽기는 동작) |
| 소각 엔진 및 수수료 분배 (37/30/20/10/3) | **라이브**. 메인넷에서는 가스 수수료와 실패한 트랜잭션 소각 채널에서만 소각이 기록됨 |
| 상한이 있는 발행량 (`x/inflation`) | **라이브**, 에포크당 고정 86,000 QOR, 상한 590,000,000 QOR (메인넷) |
| 스테이킹, 슬래싱, 거버넌스 | **라이브** (표준 모듈. [체인 파라미터](/appendix/chain-parameters) 참조) |
| 라이트 노드 보상 | 보상 정산 **라이브**. 등록은 **열려 있으며** 라이선스로 제한됨, 등록된 라이트 노드는 아직 없음([현황](/light-node/overview#reward-program-status) 참조) |
| AMM (`x/amm`) | 모듈 **라이브**, 아직 생성된 풀 없음 |
| PRISM (`x/rlconsensus`) | **관찰 전용** — 로드된 정책 없음 |
| 트리플 풀 CPoS / QDRW (`x/qca`) | 구현됨, 블록 생성, 보상, 집계에 **연결되지 않음** |
| xQORE (`x/xqore`) | 회계만 존재 — 아직 **잠금/해제 트랜잭션 없음** |
| 스마트 계정 / 연결된 지갑 (`x/abstractaccount`) | 구현됨, **꺼져 있음** (`enabled = false`) |
| 롤업 개발 키트 (`x/rdk`), 멀티레이어 | 모듈 **라이브**, 아직 생성된 롤업이나 레이어 없음 |
| 크로스체인 브리지, IBC, Babylon 리스테이킹 | **보류 중** — 37개 체인 설정 모두 `pending`, 열려 있는 IBC 채널 없음, 리스테이킹 트랜잭션 없음 |
| FairBlock MEV 방지 | **비활성화** (`enabled = false`) |
| EVM 프리컴파일, `qor_` JSON-RPC 네임스페이스 | **활성화되지 않음 / 제공되지 않음** (활성 프리컴파일 목록이 비어 있음) |

## 버전 기록

<details>

<summary>v1.0.0 — 제네시스 릴리스</summary>

포스트 퀀텀 암호화(Dilithium-5, ML-KEM-1024), 온체인 강화학습 합의 레이어인 PRISM, 크로스 VM 메시징을 갖춘 트리플 VM 런타임(EVM, CosmWasm, SVM), 토크노믹스 엔진(소각, xQORE, 발행 모듈), 트리플 풀 복합 PoS 검증인 선정, QDRW 이차 거버넌스, AI 트랜잭션 처리 파이프라인 등 핵심 프로토콜을 확립했습니다.

</details>

<details>

<summary>v1.1.0 — 보안 강화 릴리스</summary>

고전 방식 secp256k1(ECDSA) 서명과 ML-DSA-87을 결합한 하이브리드 서명 아키텍처(거버넌스로 제어되는 세 가지 시행 모드 포함), 향후 머클 트리 교체를 위한 SHAKE-256 포스트 퀀텀 해시 기반, TEE 증명(SGX, TDX, SEV-SNP, ARM CCA) 및 연합 학습 조정(FedAvg, FedProx, SCAFFOLD)을 위한 프로덕션급 인터페이스 사양을 도입했습니다.

</details>

<details>

<summary>v1.2.0 — 상호운용성 및 UX 릴리스</summary>

크로스체인 연결성(8개 IBC 채널 + 36개 외부 체인을 다루는 37개 QCB 설정, 현재 테스트넷/보류 상태), Babylon Protocol을 통한 BTC 리스테이킹, 세션 키와 소셜 리커버리를 갖춘 스마트 계정 추상화, FairBlock MEV 방지 프레임워크, 다중 토큰 가스 추상화, 온체인 유동성(`x/amm`), 5레인 블록 공간 우선순위 지정을 추가했습니다.

</details>

<details>

<summary>v1.3.0 — 롤업 생태계 릴리스</summary>

네 가지 정산 패러다임(optimistic, zk, based, sovereign), 다섯 가지 프리셋 배포 프로필(defi, gaming, nft, enterprise, custom), 네이티브 DA 라우터, 뱅크 에스크로 라이프사이클 관리, EndBlocker 기반 자동 파이널라이제이션, PRISM 지원 롤업 구성, 체인 라이선싱(`x/license`)을 갖춘 롤업 개발 키트를 출시했습니다. 자동 사이드체인 등록 및 상태 앵커링을 위해 멀티레이어 아키텍처 모듈과 긴밀하게 통합됩니다.

</details>
