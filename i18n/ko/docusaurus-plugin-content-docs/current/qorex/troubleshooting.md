# 문제 해결

QoreX 앱과 확장 프로그램에 대한 일반적인 질문과 빠른 해결 방법입니다.

| 증상 | 원인 / 해결 방법 |
|---|---|
| 온보딩 중 **"먼저 기기를 보호하세요"** | 시스템 설정에서 Face ID / 지문 **또는 화면 잠금(PIN / 패턴)** 을 설정한 다음 돌아오세요. 지갑은 강력한 잠금 해제 요소가 있는 기기에서만 생성할 수 있습니다. Android에서 2D 얼굴 잠금 해제만으로는 *약한* 생체 인증입니다. 그 뒤에 있는 PIN이 자격을 충족하는 요소입니다. |
| **로그인 시트가 닫힘** / "해당 로그인 시도가 만료되었습니다" | 이전 시도가 중단되었습니다. 로그인을 다시 탭하기만 하면 됩니다. |
| Google / Dashboard 로그인 후 **"패스키 추가"가 없음** | 정상입니다. 패스키는 이메일 코드 계정에만 연결됩니다([계정 및 Dashboard](/qorex/account-and-dashboard#sign-in)의 참고 사항 참조). |
| **"핸들 곧 제공 예정"** | @handle 레지스트리에 일시적으로 연결할 수 없습니다. 지갑에는 영향이 없으며, 레지스트리가 복구되면 핸들이 자동으로 활성화됩니다. |
| **확장 프로그램: @handle로 결제할 때 조회 관련 오류와 함께 실패함** | 확장 프로그램 **0.3.7** 이상에서 수정되었습니다(이제 모든 스토어가 0.4.5를 제공합니다). 확장 프로그램이 더 오래된 버전이라면 브라우저의 확장 프로그램 페이지에서 업데이트하세요. 그때까지는 `qor1…` 주소를 대신 붙여넣거나 모바일 앱을 사용하세요. |
| **확장 프로그램에서 @handle을 청구할 방법이 없음** | 정상입니다. 청구에는 로그인된 계정이 필요하며 모바일 앱에서 이루어집니다. 청구한 뒤에는 확장 프로그램에서 해당 핸들로 결제하고 확인할 수 있습니다. |
| **청구하려던 핸들이 예약됨으로 거부됨** | QoreChain을 모방하는 이름(브랜드 이름, 또는 *official*, *support*, *airdrop*, *treasury* 같은 신뢰 단어. 비슷하게 보이는 철자 포함)은 예약되어 있습니다. 다른 핸들을 선택하세요. |
| **승인 화면에서 QoreX가 요청을 표시할 수 없다고 하거나 모호하다며 거부함** | QoreX는 해독할 수 없는 요청이나, 바이트가 두 가지로 읽힐 수 있는 요청(예: 수수료나 금액이 화면에서 읽히는 것과 체인에서 읽히는 것이 달라지도록 필드가 반복된 경우)을 표시하지 않습니다. 우회 방법을 찾지 마세요 - 해당 사이트가 안전하지 않거나 지원되지 않는 것을 보내고 있습니다. |
| **QoreX가 핸들의 주소가 변경되었다고 경고함** | 버그가 아니라 정상적인 보안 동작입니다. QoreX는 처음 해당 핸들로 결제했을 때 확인된 주소를 기억해 두고, 이후 주소가 바뀌면 아무 말 없이 신뢰하는 대신 경고를 표시합니다. 계속 진행하기 전에 별도의 경로로 수신자에게 새 주소를 직접 확인하세요. |
| 베스팅 계정에서 **"사용 가능한 잔액을 초과함"** 으로 보내기가 거부됨 | 잔액의 일부가 아직 베스팅 일정에 따라 잠겨 있습니다. **사용 가능한** 부분(Home, Send, 자산 상세 화면에 표시됨)만 보낼 수 있으며, 나머지는 점차 잠금 해제됩니다. |
| **지갑 요청에 "테스트넷/메인넷용이지만 현재 지갑은…"** 이라고 표시됨 | 해당 요청(예: Dashboard에서 온 요청)이 현재 연결된 네트워크와 다른 네트워크를 대상으로 하고 있습니다. 의도한 것이 맞다면 먼저 직접 네트워크를 전환하세요. QoreX가 대신 전환해 주지 않습니다. |
| 기기 연결 중 **"코드가 잘못되었거나 QR이 손상됨"** | 10자 코드를 다시 확인하고(알파벳에서 혼동되는 문자는 제외됩니다: 0/O/1/I/L 없음) 다시 스캔하세요. 두 항목 모두 일회용입니다. |
| **카메라 화면에 권한이 필요하다고 표시됨** | iOS: 설정 → QoreX → 카메라. Android: 앱 정보 → 권한 → 카메라. |
| **확장 프로그램: 처음 열었을 때 지갑이 없음** | 확장 프로그램은 **독립형** 지갑입니다. 팝업을 열고 **새 지갑 만들기** 또는 **복구 문구 가져오기** 를 선택하세요. 모바일 앱이 필요하지 않습니다. |
| **읽기 전용 주소에서 보내기가 거부됨** | 해당 주소는 다른 지갑에 속합니다(레이블에 어느 지갑인지 표시됩니다). QoreX는 자체적으로 파생된 계정에 대해서만 서명할 수 있습니다. 해당 주소를 소유한 지갑에서 보내세요. |
| **테스트넷 배지가 표시됨** | 테스트넷을 사용 중입니다. 앱에서는 설정 → <strong>"테스트넷 사용(개발자)"</strong>을 끄세요. 확장 프로그램에서는 팝업 홈 하단의 개발자 섹션에서 **메인넷으로 돌아가기**를 선택하세요. |
| **스왑 버튼이 비활성화됨** | 현재는 정상입니다(Android). 풀 유동성이 확보되면 스왑이 자동으로 켜지며, 앱 업데이트가 필요하지 않습니다. iOS에서는 Swap 탭이 표시되지 않으며, 확장 프로그램에는 Swap 화면이 없습니다. |
| **앱을 삭제했거나 확장 프로그램을 제거했더니 지갑이 보이지 않음** | 볼트는 해당 기기 또는 해당 브라우저에만 존재했습니다. 24단어 복구 구문을 백업해 두었다면 그것으로 복원하세요. [소셜 복구](/qorex/security-and-recovery#social-recovery)를 설정해 두었다면 가디언과 함께 복구를 시작하세요. 둘 다 없다면 해당 지갑은 복구할 수 없습니다 - 새 지갑을 만들면 즉시 보호할 수 있도록 [지금 백업하기](/qorex/security-and-recovery#back-up-now)를 참조하세요. |
| **24단어를 찾을 수 없음 / 앱이 한 번도 보여 주지 않았음** | 모바일 앱은 지갑을 만드는 동안 복구 문구를 보여 주지 않습니다. **Settings → Security → Reveal recovery phrase** 를 열고 생체 인증 또는 기기 PIN으로 확인한 다음 단어들을 적어 두세요. 확장 프로그램에서는 팝업의 **Reveal recovery phrase** 를 사용하세요(비밀번호가 필요합니다). 지갑이 이미 분실한 휴대폰에만 있다면 QoreChain은 이를 복구할 수 없습니다 - [지금 백업하기](/qorex/security-and-recovery#back-up-now)를 참조하세요. |
| **자금이 있는 계정이 "내 계정"에서 사라짐** | 유실된 것은 없습니다. 모든 계정은 복구 구문에서 다시 파생되므로, 이는 데이터 손실이 아니라 표시 문제입니다. **1.0.9** 이전 모바일 빌드에서 실제로 발생했던, 지금은 수정된 버그였습니다. 기기의 보안 저장소에서 순간적으로 읽기가 실패하면(잠금 해제 직후 발생할 가능성이 가장 큼) 계정 목록이 축약되어 표시될 수 있었습니다. QoreX를 업데이트하세요(수정 사항은 1.0.9와 이후 모든 버전에 포함되어 있습니다). 이미 최신 버전인데도 이런 현상이 발생한다면 앱을 껐다가 다시 열면 복구되어야 합니다 - "계정 추가"를 탭하면 사라진 계정이 복원되는 것이 아니라 **새** 계정이 생성되므로, 기존 계정이 다시 나타날 때까지는 이를 피하세요. |
| **"이 계정의 EVM 레인에는 열려 있는 승인 창이 필요합니다. 먼저 여기에서 하나를 여세요 - MetaMask로는 열 수 없습니다."**(또는 "EVM 승인 창이 만료되었습니다", 또는 "해당 승인 창이 거부되었습니다") | 계정에 열려 있는 창이 없거나(또는 블록, 트랜잭션, 금액 한도를 모두 소진하여) MetaMask / EVM 레인 트랜잭션이 거부되었습니다. [EVM 접근 창](/qorex/security-and-recovery#evm-window)(Ethereum 방식 coin-60 계정용)에서 창을 연 다음 다시 시도하세요. 전송하기 *전에* 여세요 - 창을 열면 계정 논스가 증가하므로, 그 이전에 준비한 트랜잭션은 "nonce too low"로 실패합니다. 계정에 아직 ML-DSA-87 키가 없다면, QoreX가 먼저 키를 등록하라고 안내합니다. |
| **"이 네트워크에는 업데이트된 QoreX가 필요합니다. 앱을 업데이트한 뒤 다시 시도하세요 - 아무것도 전송되지 않았습니다."** | 네트워크가 현재 빌드에서 만들어지는 것보다 더 새로운 서명 형식을 검증합니다. 스토어에서 QoreX를 업데이트한 뒤 다시 시도하세요. 아무것도 전송되지 않았으며 수수료도 차감되지 않았습니다. |
| **"이 계정에서 짧은 시간 안에 너무 많은 트랜잭션이 발생했습니다. 1분 기다린 후 다시 시도하세요."** | 네트워크는 하나의 계정이 짧은 기간에 보낼 수 있는 트랜잭션 수를 제한합니다. 1분 기다리세요. |
| **"해당 주소는 일반 전송을 받을 수 없습니다."** | 네트워크가 해당 주소(일부 시스템 또는 모듈 주소)로의 일반 전송을 거부합니다. 수신자를 확인하세요. |
| **"네트워크 수수료를 지불할 잠금 해제된 QOR이 부족합니다. 베스팅 중인 QOR로는 수수료를 지불할 수 없습니다…"** 또는 **"청구하려면 약 … QOR이 잠금 해제되어 있어야 합니다"** | 청구와 언스테이킹은 (보상이 도착하기 전에) *잠금 해제된* 잔액에서 수수료를 지불합니다. 해당 주소로 소량의 QOR을 보낸 다음 다시 시도하세요. |
| **"네트워크가 완료하기 전에 가스가 소진되었습니다. 수수료는 차감되었고 아무것도 이동하지 않았습니다 - 보상은 그대로 있습니다."** | 트랜잭션이 블록에 도달했지만 그곳에서 실패했습니다. 다시 시도하세요. 실패한 시도의 수수료는 소모됩니다. |
| **"이만큼 언스테이킹하면 검증자의 자기 본딩이 필요한 100,000 QOR 아래로 떨어집니다."** | 검증자 운영자에게만 해당합니다. 자기 본딩 하한은 검증자가 운영되는 동안 계속 적용됩니다. 더 적게 언스테이킹하세요. |
| Dashboard 또는 MetaMask에서 복원한 계정에서 보낼 때 **"Account 'qor1…' does not exist on chain"** | QoreX를 최신 버전으로 업데이트하세요. 해당 계정은 이더리움 방식(coin 60) 계정입니다 - [MetaMask 또는 Dashboard의 복구 문구 복원](/qorex/getting-started#restore-dashboard)을 참조하세요. 첫 전송 시 해당 계정의 ML-DSA-87 키도 함께 등록됩니다(소액의 수수료가 한 번 더 발생). |
| **복구 문구를 복원했는데 두 번째 계정 / 자금이 보이지 않음** | 복원하면 **Account 1**만 돌아옵니다. Settings → Your accounts에서 **Add an account**(그리고 MetaMask나 Dashboard에서 사용한 문구라면 **Add an Ethereum account (coin 60)**)를 탭하세요 - 계정은 동일한 주소로 다시 파생됩니다. |
| **확장 프로그램: "Wallets"에 패스키가 꺼졌다고 표시됨** | 지갑을 추가하거나 제거하면 볼트가 다시 봉인되고 패스키 잠금 해제가 해제됩니다(새 지갑을 포함할 수 없기 때문입니다). 팝업 홈 화면에서 다시 켜세요. Firefox는 패스키 잠금 해제를 제공하지 않습니다. |
| **푸시 알림이 도착하지 않음** | 푸시는 메인넷 전용이며, 휴대폰 설정에서 QoreX의 알림이 허용되어 있고 **Push notifications** 스위치가 켜져 있어야 합니다(Home → 종 아이콘). 푸시는 QOR이 도착했다는 사실만 알려 주며 금액은 알려 주지 않습니다. 세부 정보는 앱의 **Notifications** 목록에서 확인하세요. |
| **Android: 뒤로 가기 버튼** | 뒤로 가기는 이전 화면으로 이동하며, Home에서는 앱을 종료합니다. |
| **확장 프로그램이 잠긴 상태에서 사이트가 서명을 요청함** | 0.4.5부터 확장 프로그램은 비밀번호 화면으로 열리고 사이트 이름을 표시합니다. 비밀번호를 입력하면 그 창이 닫히고 요청의 승인 화면이 나타납니다. 대신 창을 닫으면 요청이 거부되며 아무것도 서명되지 않습니다. 사이트가 여전히 "wallet is locked"라고 응답하면 확장 프로그램을 업데이트하세요. |
| **확장 프로그램: 잠금 해제 버튼이 작동하지 않거나 오류가 표시됨** | Enter 또는 **잠금 해제**로 잠금 해제가 시작되며 버튼은 처리 중임을 보여 줍니다. 의도적으로 잠시 시간이 걸립니다. <strong>비밀번호가 올바르지 않습니다.</strong>는 비밀번호가 틀린 경우에만 나타납니다. 그 밖의 메시지는 다른 실패를 알려 주므로 읽어 보세요. [잠금 해제와 자동 잠금](/qorex/browser-extension#unlock)을 참고하세요. |
| **QoreX가 계속 스스로 잠김** | 자동 잠금입니다(기본 15분). 확장 프로그램의 팝업 홈이나 앱의 설정 → 보안에서 **자동 잠금 시간**을 변경하세요(1, 5, 15, 30, 60 또는 240분). |
| **"This account's post-quantum key on the network can no longer sign"**(또는 등록된 키가 더 이상 서명할 수 없다는 메시지) | 네트워크의 키 기록이 비어 있거나, 고전 키만 있거나, 그 밖의 이유로 사용할 수 없어 계정에서 보낼 수 없습니다. 아무것도 전송되지 않았고 수수료도 받지 않았습니다. 앱 1.2.5 / 확장 프로그램 0.4.5에서는 이전 메시지가 이후 업데이트를 언급하더라도 홈 화면에서 **키 다시 등록**을 제공합니다. 네트워크 수수료를 보여 주며 두 번째 탭이 필요합니다(앱에서는 생체 인증 추가). 자동으로 수행되는 일은 없습니다. 계정에 EVM 창이 있으면 네트워크가 닫으므로 이후 새 창을 여세요. [양자 내성 키 관리](/qorex/browser-extension#pqc-care)를 참고하세요. |
| **"네트워크에 있는 이 계정의 ML-DSA-87 키가 다른 지갑에 의해 등록되었다"는 메시지** | QoreX는 복구 문구에서 파생할 수 없는 키로 서명할 수 없습니다. 키를 등록한 지갑을 사용하세요. |
| **양자 내성 키를 교체한 후 같은 구문의 다른 지갑이 서명하지 못함** | 예상된 동작입니다. 같은 구문을 사용하는 다른 지갑은 교체된 키를 지원하기 전까지 이 계정에 서명할 수 없습니다. QoreX에서 구문을 복원하면 올바른 키를 찾습니다. 교체는 유출된 양자 내성 키는 보호하지만 유출된 복구 문구는 보호하지 못합니다. |
| **EVM 창이 열려 있는데도 사이트의 컨트랙트 호출이 거부됨** | 직접 여는 창은 기본적으로 **QOR 전송만**이며 컨트랙트 호출을 허용하지 않습니다. 열 때 **모든 컨트랙트**를 선택하거나(경고를 읽으세요. 컨트랙트가 옮기는 토큰은 상한의 제한을 받지 않습니다), 창을 닫고 사이트의 승인 화면이 해당 트랜잭션 한 건용 창을 열게 하세요. 열린 창의 문구가 무엇을 허용하는지 알려 줍니다. [EVM 접근 창](/qorex/security-and-recovery#evm-window)을 참고하세요. |
| **QoreX가 창을 열기 전에 한 번 더 묻는 경우**("The network did not accept a window limited to …" 또는 "This network cannot limit the window to QOR transfers yet") | 네트워크가 해당 제한을 적용할 수 없습니다. 승인하면 **모든 컨트랙트**를 허용하는 창이 열리고, 거부하면 아무것도 열리지 않고 아무것도 전송되지 않습니다. |
| **"What it does to your tokens was not checked"** | 노드는 호출이 실패하지 않는지만 확인할 수 있고, 무엇을 옮기는지는 확인할 수 없습니다. 사이트를 신뢰할 때만 승인하세요(두 번째 탭이 필요합니다). |
| **사이트의 트랜잭션이 승인 전에 거부됨** | QoreX는 컨트랙트 호출을 먼저 시뮬레이션합니다. 컨트랙트가 호출을 거부할 경우 승인 화면 대신 네트워크의 사유가 표시됩니다. 네트워크의 트랜잭션당 가스 한도를 넘는 트랜잭션도 아무것도 서명하기 전에 거부됩니다. |
| **사이트가 내 EVM 창을 닫거나 권한을 변경하지 못함** | 예상된 동작입니다. 이런 요청은 QoreX 자체 화면에서만 받습니다. **EVM 접근 창** 화면에서 창을 닫으세요. |
| **결제 링크가 거부됨** | QoreX가 이유를 알려 줍니다: 유효한 결제 링크가 아니거나, **서명된 뒤 변경**되었거나, **받는 주소의 소유자가 서명하지 않았거나**(이 두 경우는 결제하지 마세요), QoreX가 모르는 네트워크 또는 다른 네트워크용이거나(의도한 것이면 직접 전환), QOR이 아닌 코인을 요청합니다. 요청자에게 새 링크를 요청하세요. |
| **결제 요청이 계속 "아직 결제 안 됨"으로 표시됨** | 요청은 메모에 요청 태그가 있고 최소 해당 금액이 내 주소로 성공적으로 결제된 것이 체인에 나타날 때에만 결제 완료로 표시됩니다. 태그 없이 보낸 결제(예: 메모를 누락한 지갑에서 보낸 경우)는 일치하지 않습니다. 트랜잭션이 확인된 후 **상태 확인**을 다시 탭하세요. "상태를 알 수 없음"은 네트워크가 응답하지 않았다는 뜻입니다. |
| **앱에서 페이지를 열어야 하는 링크가 거부됨** | browse 링크는 도메인 이름의 `https://` 페이지만 열며, 포트, 사용자 이름이나 비밀번호, IP 주소, `localhost`가 없어야 하고 최대 2,048자입니다. 휴대폰에 지갑이 없으면 앱은 온보딩에 머뭅니다. |
| **네트워크가 느리거나 연결할 수 없다는 배너가 표시됨** | **느림**: 체인의 최신 블록이 1분 넘게 지나 트랜잭션이 더 오래 걸릴 수 있습니다. **네트워크에 연결할 수 없음**: 잔액이 최신이 아닐 수 있습니다. QoreX는 체인 자체에서 이를 읽습니다. 인터넷 연결을 확인하고 기다리세요. [내역](/qorex/browser-extension#history)(앱에서는 활동)을 확인하기 전에는 결제를 다시 보내지 마세요. |
| **잔액이 마지막으로 확인된 값으로 표시됨** | 네트워크가 응답하지 않아 QoreX가 마지막으로 읽은 값을 언제 기준인지와 함께 보여 줍니다. 네트워크가 응답하면 업데이트됩니다. |
| **트랜잭션이 "대기 중" 또는 "네트워크에서 찾을 수 없음"으로 표시됨** | 대기 중: 이 기기에서 보냈지만 체인 내역에 아직 나타나지 않습니다. 찾을 수 없음: 실패했을 수 있습니다. 다시 보내기 전에 트랜잭션을 확인하세요. |
| **주소가 아는 주소와 비슷해 보이기만 한다는 경고** | 사기범은 비슷한 주소를 심어 둡니다. 표시된 저장된 주소나 이전에 결제한 주소와 모든 문자를 비교하세요. 새 주소가 의도한 주소일 때만 계속하세요. |
| **개발자 도구를 찾을 수 없음** | 개발자 모드는 기본으로 꺼져 있습니다. 앱: 설정에서 **개발자 모드** 스위치를 켜면 하단 막대에 **개발자** 탭이 나타납니다. 확장 프로그램: 팝업 하단의 버전 번호를 일곱 번 탭한 다음 **개발자 도구**를 여세요. [개발자 모드](/qorex/developer-mode)를 참고하세요. |
| **AI 에이전트를 사용할 수 없거나 도우미 프로그램에 "연결할 수 없음"** | 확장 프로그램에서 에이전트는 아직 공개되지 않은 보조 프로그램을 통해 연결되며, 이 기능은 Safari에서 사용할 수 없습니다. 앱에서는 제안을 붙여넣거나 제안 링크를 여세요. |
| **"다른 체인으로 보내기", Bridge 화면, QoreChain의 Solana를 찾을 수 없음** | **테스트넷 전용**입니다(QoreChain의 Solana는 개발자 모드에도 있습니다). Bridge 화면은 각 경로의 실제 상태를 보여 줍니다. 현재 테스트넷의 모든 경로는 닫혀 있어 아무것도 제공되지 않습니다. [테스트넷 기능](/qorex/testnet-features)을 참고하세요. |

## 여전히 해결되지 않나요?

QoreX 안의 **지원**(앱의 설정 또는 확장 프로그램의 팝업 홈)을 여세요. 공식 채널만 나열됩니다.

- [Telegram 커뮤니티](https://t.me/QorechainCommunity)
- [Discord](https://discord.gg/qorechain)
- [도움말 페이지](https://qorechain.io/help/qorex)
- 이메일: team@qorechain.io
- 보안 문제: **취약점 신고**([qorechain.io/security](https://qorechain.io/security) 참고)

QoreX 직원은 복구 문구, 비밀번호 또는 키를 절대 요청하지 않습니다. 지원팀이 요청하면 해당 화면의 **요약 보기**가 구문, 키, 주소, 잔액이 없는 진단 요약을 제공합니다.

- 가디언 및 기기 연결에 대해서는 [보안 및 복구](/qorex/security-and-recovery) 페이지를 참조하세요.
- QoreChain 자체에 대한 질문은 [메인 문서](/introduction/what-is-qorechain) 또는 [qorechain.io](https://qorechain.io)에 링크된 커뮤니티 채널을 참조하세요.
