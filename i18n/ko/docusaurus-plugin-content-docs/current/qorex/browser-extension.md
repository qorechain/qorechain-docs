# 브라우저 확장 프로그램

QoreX **브라우저 확장 프로그램**(Chrome 및 Firefox, 동일한 기능을 갖춘 Safari 버전도 곧 출시 예정)은 데스크톱용 **dApp 커넥터**입니다. 웹사이트가 여러분의 지갑을 발견할 수 있게 하고, 모든 요청을 명시적인 승인으로 전환합니다. 개념적으로는 모바일 앱과 짝을 이루며, 스테이킹, 포트폴리오, 계정 기능은 **포함하지 않습니다** — 그러한 기능은 앱에 있습니다.

## 설정

이 확장 프로그램은 **QoreX 모바일 앱**에서 생성한 지갑과 짝을 이룹니다. 짝을 맺기 전에 팝업을 열면 **"No wallet yet — create one in the QoreX app."** 라고 표시됩니다.

## 잠금 해제

팝업은 여러분의 **볼트 비밀번호**(또는 브라우저가 패스키에서 파생된 키를 지원하는 경우 패스키)를 요청합니다. 볼트는 확장 프로그램 저장소에서 AES-256-GCM으로 암호화되며, 자동으로 잠기고, 모든 잠금 해제는 명시적입니다.

## dApp에 연결하기

웹사이트는 **EIP-6963**(다중 지갑 표준)과 QoreChain 연결 컨트랙트를 통해 QoreX를 발견합니다. QoreX는 `window.ethereum` 또는 `window.keplr`를 **절대 덮어쓰지 않습니다** — 다른 지갑과 **나란히** 나타나며, 사이트마다 어떤 지갑을 사용할지 여러분이 선택합니다.

1. 사이트가 연결을 요청하면, 승인 팝업이 **출처(origin)**를 표시합니다.
2. 승인하면 해당 출처에는 여러분의 **공개 주소**만 노출됩니다.
3. 승인은 **출처별**로 이루어지고, 브라우저를 재시작해도 유지되며, 한 사이트의 승인이 다른 사이트에는 어떤 권한도 부여하지 않습니다.

## 서명

모든 서명 요청은 **디코딩된 페이로드** — 수신자, 금액, 네트워크 — 를 보여주는 승인 창을 열며, 결코 벌거벗은 해시를 보여주지 않습니다.

- Native 레인 QoreChain 트랜잭션의 경우, 확장 프로그램은 **dApp이 포스트 양자 계층을 제공한다**는 점을 안내합니다(지갑은 고전적 절반을 서명합니다 — 기존 지갑들이 사용하는 동일한 패턴입니다).
- 요청이 **고전 전용**인 경우, 팝업은 명시적 경고를 표시합니다: **"⚠ This request is a classical signature — the app did not add a quantum-safe layer."**
- **거부(Reject)**는 항상 한 번의 클릭으로 가능하며, 요청은 스스로 만료됩니다.

## 외부 네트워크에서 전송

팝업에서 **ETH / BNB / POL / ARB / SOL** 및 **ERC-20 / SPL** 토큰을 전송할 수 있습니다(앱과 동일한 시드 파생을 사용). 전송하기 전에 고전 서명 안내를 확인해야 하며, 결과 링크가 블록 탐색기를 엽니다.

## 네트워크 및 보안 태세

- **활성 네트워크** — 기본값은 QoreChain **메인넷**(EVM 레인의 체인 `0x2649`)입니다. 테스트넷은 이를 요청하는 dApp을 위해 계속 지원되며, 교차 네트워크 서명 요청은 거부됩니다.
- **권한** — 확장 프로그램은 **`storage`만** 요청합니다. 콘텐츠 스크립트는 프로바이더 API만 주입하며, 지갑 요청 외에는 페이지 콘텐츠를 읽지 않고, 분석 도구도 원격 코드도 없습니다.
