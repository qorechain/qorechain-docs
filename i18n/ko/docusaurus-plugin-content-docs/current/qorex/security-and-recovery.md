# 보안 및 복구

지갑을 보호하고 복구하는 모든 기능은 **설정 → 보안 대시보드**에 있습니다. 홈 탭에는 소셜 복구가 설정될 때까지 계속 경고를 표시하는 **백업 상태(Backup health)** 카드도 있습니다.

## 지금 백업하세요 — 잃어버린 지갑은 누구도 대신 복구해 줄 수 없습니다 {#back-up-now}

:::danger 지갑에 자금을 입금하기 전에 반드시 읽어주세요
QoreX는 **비수탁형(non-custodial)** 지갑입니다. 사용자의 키는 오직 본인 기기에만 존재하며, QoreChain 협회는 이를 복사본으로도, 마스터 키로도 보유하지 않고 지갑을 재설정하거나 복원할 방법이 없습니다. **"비밀번호를 잊으셨나요" 절차도, 고객지원 티켓도, 고객서비스를 통한 예외 처리도 존재하지 않습니다** — 백업 없이 키에 대한 접근을 잃으면 자금은 영구적으로, 되돌릴 수 없이 사라집니다. 이는 QoreX만의 제약이 아니라 모든 비수탁형 지갑에 해당하는 사실이지만, 명확히 밝혀둘 가치가 있습니다.

**다음 중 최소 하나는 반드시 수행하세요 — 나중이 아니라 지갑을 만든 직후에:**

1. **24단어 복구 구문을 적어두고** 오프라인의 내구성 있는 곳에 보관하세요(스크린샷, 클라우드에 동기화되는 메모, 스스로에게 보내는 메시지는 안 됩니다). 이는 어떤 기기에서든 언제든 지갑을 복원할 수 있는 유일한 수단입니다.
2. 신뢰하는 보증인(guardian)과 함께 **[소셜 복구](#social-recovery)를 설정하세요**. 이를 통해 구문을 잃어버려도 지갑을 복구할 수 있으며, 어떤 단일 보증인도 혼자서는 자금에 접근할 수 없습니다.

두 가지를 모두 수행하는 것이 가장 안전합니다 — 구문은 기기를 바꾸거나 앱을 사용할 수 없는 상황에 대비하고, 보증인은 구문 자체를 잃어버린 상황에 대비합니다.

**앱을 삭제하면 해당 기기의 키도 함께 삭제됩니다.** 모바일 앱의 볼트와 브라우저 확장의 볼트는 각각 이를 생성한 기기에만 존재합니다. 앱을 삭제하거나, 휴대폰을 초기화하거나, 확장 프로그램을 제거/초기화하면 해당 사본이 삭제되며 — 백업도 연결된 기기도 없다면 QoreChain을 포함한 그 누구도 지갑을 복구할 수 없습니다.
:::

## 포스트 양자 키 {#pqc-key}

보안 대시보드는 포스트 양자 키의 실시간 온체인 상태를 **"첫 전송 시 등록됩니다"** → **"온체인 등록 완료 ✓"**로 표시합니다. 알고리즘은 **ML-DSA-87**(secp256k1과 결정론적으로 하이브리드)입니다.

**키 교체(Key rotation)** — 포스트 양자 키를 교체하는 것(온체인 `MsgRotatePQCKey` 작업)은 새로운 생체 인증 절차가 필요하며 **절대 자동화되지 않습니다**. 기본 메커니즘은 [키 교체](/developer-guide/post-quantum-signing#key-rotation)를 참고하세요.

## 소셜 복구 {#social-recovery}

소셜 복구를 이용하면 신뢰하는 **보증인(guardian)**이 사용자의 복구 구문을 전혀 보지 않고도 지갑 복원을 도와줄 수 있습니다.

- 사용자의 시드는 **ML-KEM으로 봉인된 조각**으로 분할되어 **임계값(threshold)** 방식(t-of-n)으로 보증인들에게 배분됩니다. *n*명의 보증인 중 *t*명이면 복구를 도울 수 있지만, 그보다 적으면 불가능합니다.
- 각 보증인은 자격 증명(credential)을 받습니다. 설정 과정에서 릴레이에는 읽을 수 있는 정보가 전혀 기록되지 않고 — 오직 불투명하게 봉인된 봉투만 남습니다.
- 복구를 진행하려면 임계값만큼의 보증인 승인이 필요하며, 이후 **48시간 타임락**이 진행되고 사용자에게 **취소 알림**이 전송되어, 악의적인 시도를 중단시킬 수 있습니다.

**설정 방법:** 보안 대시보드 → 소셜 복구 → 보증인과 임계값을 선택합니다. 이 설정이 완료되면 백업 상태 경고가 사라집니다.

**다른 사람의 복구 승인하기:** 다른 사람의 보증인으로 지정되어 있다면, 홈 탭의 **복구 도와주기(Help recover)**를 사용해 해당 요청을 승인할 수 있습니다.

## Legacy Protocol {#legacy}

**Legacy Protocol**은 양자 안전 상속 기능으로, 보증인 위에 데드맨 스위치를 얹은 구조입니다. 이를 통해 사용자와 연락이 닿지 않게 되었을 때 지정한 수혜자에게 자산이 전달될 수 있습니다. 선택 사항이며 보안 대시보드에서 설정합니다.

## 새 기기 연결 {#link-device}

**서버 없이, 24단어를 입력하지 않고도** 지갑을 두 번째 휴대폰이나 태블릿으로 옮길 수 있습니다.

1. **새 기기** → 온보딩 → **다른 기기에서 연결하기**. 일회성 **10자리 코드**가 표시되고 카메라가 열립니다.
2. **기존 기기** → 설정 → 보안 → **새 기기 연결하기** → 해당 코드를 입력 → 생체 인증으로 확인. **QR 코드**가 나타납니다(코드로부터 파생된 키로 시드를 봉인: scrypt N=2¹⁷ → AES-256-GCM).
3. **새 기기**가 QR을 스캔하면 → 로컬에서 복호화되어 → 동일한 지갑, 동일한 주소를 갖게 됩니다.

**안전한 이유:** 코드와 QR은 같은 화면에 동시에 나타나지 않습니다. QR만 촬영한 사진은 메모리 하드 키 유도 함수 뒤에 놓인 암호문일 뿐이며, 두 요소 모두 일회성이고 화면과 함께 사라집니다. 잘못된 코드를 입력하면 명확한 오류가 표시되므로 — 다시 시도하면 됩니다.

:::note
기기 연결은 **편의 기능**일 뿐 복구 수단이 아닙니다. 24단어 구문과 소셜 복구가 진짜 안전망입니다.
:::

## 연결된 dApp {#connected-dapps}

dApp 연결은 **출처(origin)별**로, **세션 범위**로 관리됩니다. 앱 내 dApp 브라우저를 닫으면 모든 연결이 해지됩니다. 보안 대시보드에서 활성 연결을 검토하고 연결을 끊을 수 있습니다.

## 연결된 서명자 및 지출 한도 {#linked-signers}

[대시보드](/qorex/account-and-dashboard#dashboard)를 통해 외부 키(Phantom / MetaMask)를 연결하면, 각 키는 **범위가 지정된 권한**과 인터페이스 수준이 아니라 **온체인에서 강제되는** **SpendingRule**을 갖게 됩니다. 키 관리 권한은 연결된 키에 절대 위임될 수 없습니다. 온체인 모델은 [연결된 지갑 인증자](/developer-guide/account-abstraction#authenticators)를 참고하세요. 대시보드는 항상 현재의 온체인 실제 상태를 보여줍니다.

## Q-Day 스캐너 {#q-day-scanner}

**Q-Day 스캐너**를 사용하면 어떤 주소든 — 본인 것이든 타인 것이든 — 입력하여 양자 노출 리포트를 확인할 수 있습니다. 어떤 자금이 고전 암호 전용 키에 있고 어떤 자금이 이미 포스트 양자로 보호되고 있는지 알려줍니다. 홈 탭의 빠른 버튼에서 접근할 수 있습니다.

## 보안 모델 요약

1. **비수탁형(Non-custodial)** — 키는 기기에서 생성되어 하드웨어 기반 볼트(모바일) 또는 암호화된 볼트(확장 프로그램)에 저장되며 절대 외부로 나가지 않습니다.
2. **동의 없이는 아무 일도 일어나지 않음** — 모든 연결은 출처별로 관리되고, 모든 서명은 개별적으로 승인되며(모바일에서는 생체 인증), 페이로드는 서명 전 항상 디코딩되어 표시됩니다.
3. **기본값으로 양자 안전** — 네이티브 레인 QOR 전송은 항상 ML-DSA-87 + secp256k1을 함께 사용하며, 고전 암호 방식인 경우 표시되며 절대 조용히 넘어가지 않습니다.
4. **데이터 수집 없음** — 분석, 트래킹, 광고가 전혀 없습니다. 선택 사항인 계정 로그인은 [QoreChain 개인정보 처리방침](https://qorechain.io/privacy)의 적용을 받습니다.
5. **복구 경로** — 24단어 구문(항상 가능), 보증인 + 48시간 타임락을 사용하는 소셜 복구(선택), Legacy 상속(선택), 기기 연결(편의 기능).
