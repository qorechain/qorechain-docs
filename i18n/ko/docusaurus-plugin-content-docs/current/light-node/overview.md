# 라이트 노드 개요

**QoreChain 라이트 노드**는 전체 검증자나 아카이브 노드를 실행하지 않고 QoreChain 네트워크를 따르는 경량 클라이언트입니다. 모든 트랜잭션을 다시 재생하는 대신, 여러 RPC 엔드포인트에 걸쳐 블록 헤더를 상호 검증하고, 운영자 계정의 위임과 보상을 체인에서 그대로 반영하며, 실시간 네트워크 텔레메트리를 스트리밍합니다 — 이 모든 것이 작고 독립적인 바이너리로 이루어집니다.

라이트 노드를 실행하면 전체 노드의 저장소, 대역폭, 운영 비용 없이 네트워크의 상태를 관찰할 수 있습니다. 라이트 노드 보상 분배에 참여하는 것은 라이선스로 제한되는 별도의 단계이며, 등록은 두 네트워크 모두에서 열려 있습니다 — [보상 프로그램 현황](#reward-program-status)을 참조하세요.

## 자체 버전 라인

라이트 노드는 **자체 버전 라인 — 현재 3.1.10**(3.1.9도 계속 허용됨)로 제공되며, 이는 **체인 릴리스 버전과는 별개입니다**(메인넷은 2026년 10월 23일부터 체인 `v3.2.4`를 실행하고, 테스트넷은 `v3.2.6`을 실행합니다). 각 네트워크용 바이너리는 `https://download.qore.host/<net>/lightnode/latest.json`에 **SHA-256 체크섬 매니페스트**와 함께 게시됩니다(`<net>`은 `mainnet` 또는 `testnet`). 두 채널 모두 동일한 3.1.10 빌드를 제공하며, 두 매니페스트 모두 `minCompatible`을 `3.1.9`로 설정하므로 이전 라이트 노드 빌드는 교체해야 합니다. 이 릴리스에는 12개의 바이너리 — Linux, macOS, Windows용 SX와 UX, 각각 amd64와 arm64 — 와 `SHA256SUMS` 파일이 포함됩니다. 다운로드 및 검증 단계는 [SX 에디션](/light-node/sx-edition#install)을, 소스 태그 `v3.1.10`에서 이미지를 빌드하는 방법은 [Docker](/light-node/sx-edition#docker)를 참조하세요.

Android 빌드는 GitHub 릴리스에 **프리뷰**로만 첨부되어 있습니다. 체인을 따르고 검증하지만, 등록하지 않으며 보상도 받지 않습니다.

문서나 릴리스 노트를 읽을 때, 라이트 노드의 버전(3.1.10)과 체인의 버전(메인넷 v3.2.4, 테스트넷 v3.2.6)을 우연히 동일한 메이저 시리즈를 공유하는 두 개의 별개 숫자로 취급하세요.

## 라이트 노드를 실행하는 이유 {#why-run-a-light-node}

- **라이트 노드 보상 분배에 참여하세요.** 스테이크 및 가동 시간 규칙을 충족하는 등록된 활성 라이트 노드는 아래에 설명된 **3% 라이트 노드 할당**의 대상이 됩니다. 등록에는 `lightnode_operator` 라이선스가 필요합니다 — [등록 및 라이선싱](/light-node/registration-and-licensing)을 참조하세요. 노드를 실행하고 동기화하는 데는 라이선스가 필요 없습니다.
- **표시되는 체인 상태를 교차 검증하세요.** 노드는 기본 RPC 엔드포인트와 구성된 모든 감시(witness) 엔드포인트에서 최신 높이를 병렬로 가져오며, 이들이 블록 해시에 대해 일치할 때만 헤더를 저장합니다 — 단일 엔드포인트를 신뢰하는 수준에서 구성된 모든 엔드포인트가 동시에 손상되어야 하는 수준으로 기준을 높입니다. 이는 독립적인 소스 간의 상호 검증이며, **완전한 암호학적 합의 검증은 아닙니다**(검증자 집합이나 커밋 서명 확인은 하지 않습니다). 사용자의 노드는 자신이 실행 중인 모드를 디버그 로그의 각 `synced header` 줄에 `assurance` 값으로 기록합니다(`log_level = "debug"`로 설정). 이 값은 노드의 대시보드나 `status`에는 표시되지 않으며, 사용자 노드의 RPC 선택이 사용자 환경에 국한되어 있기 때문에 QoreChain 중앙 서비스에서도 확인할 수 없습니다. **`trusted-single-source`** 모드는 감시 엔드포인트를 구성하지 않았을 때의 값이며, 정직하게 운영되는 단일 엔드포인트도 손상된 엔드포인트와 동일한 값을 보고하기 때문에 노드는 시작 시 이를 알리는 경고를 로그에 남깁니다. 독립적으로 운영되는 감시 엔드포인트를 추가하면 `corroborated-across-sources`로 전환됩니다.
- **스테이크를 지켜보세요.** 노드는 운영자 계정의 위임을 체인에서 그대로 반영하며, 위임한 검증자가 구성 가능한 평판 점수 아래로 떨어지면 경고합니다. 노드가 스테이크를 직접 이동하는 일은 없습니다 — 위임 변경은 사용자 본인의 지갑에서 이루어집니다.
- **네트워크를 실시간으로 관찰하세요.** 실시간 텔레메트리는 검증자, 합의, 브리지, 토크노믹스를 다룹니다.
- **첫날부터 포스트 양자.** 키와 서명은 Dilithium-5 (ML-DSA-87)을 사용합니다.

## 두 가지 에디션: SX와 UX

라이트 노드는 동일한 코드베이스에서 빌드된 두 가지 에디션으로 제공됩니다. 노드를 운영하려는 방식에 맞는 것을 선택하세요.

| 에디션 | 바이너리 | 대상 | 인터페이스 |
| --- | --- | --- | --- |
| **SX — Server eXperience** | `lightnode-sx` | 헤드리스 서버 배포 | 전체 CLI (데몬 + 관리 명령어) |
| **UX — User eXperience** | `lightnode-ux` | 데스크톱 및 운영자 사용 | 임베디드 웹 대시보드 |

- **SX 에디션**은 완전한 관리 CLI를 갖춘 헤드리스 데몬입니다. 서버, 자동화, 명령줄에서 활동하는 운영자에게 적합한 선택입니다. [SX 에디션](/light-node/sx-edition)을 참조하세요.
- **UX 에디션**은 동일한 데몬을 실행하지만, 브라우저에서 텔레메트리, 위임, 보상을 관찰할 수 있도록 임베디드 웹 대시보드를 추가합니다. [UX 에디션](/light-node/ux-edition)을 참조하세요.

두 에디션 모두 동일한 `config.toml`을 읽고, 동일한 홈 디렉터리(기본값 `~/.qorechain-lightnode`)에 데이터를 저장하며, 동일한 Dilithium-5 키링을 사용합니다.

## 3% 라이트 노드 보상 분배 {#the-3-light-node-reward-share}

QoreChain의 수수료 분배는 라이트 노드에 고정된 **3% 분배**(`reward_share` 파라미터, `0.03`)를 할당합니다. 전체 37% / 30% / 20% / 10% / 3% 분류(검증자, 소각, 트레저리, 스테이커, 라이트 노드)는 [토크노믹스](/architecture/tokenomics)를 참조하세요.

이 3%는 라이트 노드 모듈 계정에 입금되는 금액이며, 노드별 권리가 아닙니다. 100블록마다 체인은 이전 정산 이후 누적된 금액 중 각 적격 노드의 스테이크 가중 몫을 크레딧하며, 이는 **노드별로 제한됩니다**. 체인 v3.2.3부터 이 제한은 **노드당 30일에 2,000 QOR**(`max_reward_per_month_per_node`, `2000000000` uqor)이며, 이전 정산 이후 경과한 블록 시간에 비례하여 배분되고 노드의 가동 시간에 따라 조정됩니다. 이것이 `lightnode-monthly-cap` 규칙입니다. v3.2.3 이전에는 이 제한이 블록 단위(`max_reward_per_block_per_node`, `1713` uqor)로 정해졌으며, 보상 풀 쿼리는 여전히 이 값을 보고합니다. 이 제한은 상한일 뿐 약속된 금액이 아닙니다. 획득되지 않은 금액은 거버넌스 투표로만 해제할 수 있는 준비금으로 이동하므로, 가장 먼저 등록하는 사람을 위한 보상 풀이 쌓이지 않습니다. `GET /qorechain/lightnode/v1/reward_pool`로 실시간 분할을 확인할 수 있습니다.

보상을 받으려면 라이트 노드는 **온체인에 등록되고, 활성 상태**(하트비트로 활성 증명)여야 하며, 최소 본딩 스테이크 이상을 보유하고, 가동 시간을 최소 기준 이상으로 유지해야 합니다. 등록 및 라이선싱은 [등록 및 라이선싱](/light-node/registration-and-licensing)에서 다루며, 보상이 어떻게 크레딧되고, 청구되고, 모니터링되는지는 [보상 및 모니터링](/light-node/rewards-and-monitoring)에서 다룹니다.

## 보상 프로그램 현황 {#reward-program-status}

:::note 등록이 열려 있습니다
메인넷(`qorechain-vladi`, 체인 v3.2.4)과 테스트넷(`qorechain-diana`, 체인 v3.2.6)에서 등록이 열려 있습니다. 작성 시점(2026년 10월 23일)에 메인넷에서 7개의 `lightnode_operator` 라이선스가 부여되었으며 라이트 노드 1개가 등록되었습니다(블록 3,668,080). 보상 회계는 v3.2.0 업그레이드 이후 두 네트워크 모두에서 라이브입니다. 노드를 실행하고 동기화하는 데는 라이선스가 필요 없지만, 가동 시간은 **노드가 등록된 블록부터** 계산되므로 그 이전에 노드를 실행해도 크레딧은 적립되지 않습니다. 체인 릴리스 v3.2.4부터는 노드별 보상 한도도 노드 자신의 등록 시점부터 시작됩니다. 등록 후 첫 정산에서는 이전 정산 이후가 아니라 등록 이후에 누적된 금액만 크레딧될 수 있습니다. v3.2.4는 2026년 10월 19일부터 테스트넷에, 2026년 10월 23일부터 메인넷에 적용되어 있습니다(거버넌스 제안 13, 높이 3,742,566).

릴리스 매니페스트(`https://download.qore.host/<net>/lightnode/latest.json`)는 `registration.open` 필드에 공식 신호를 담고 있습니다. 실시간 상태는 `https://api.qore.host`(메인넷) 또는 `https://api-testnet.qore.host`(테스트넷)에서 `GET /qorechain/license/v1/holders/lightnode_operator`와 `GET /qorechain/lightnode/v1/stats`를 조회하세요.
:::

## 핵심 기능 한눈에 보기

- **다중 소스 헤더 상호 검증** — 전체 블록을 다운로드하지 않고 구성된 모든 감시 엔드포인트에 대해 최신 블록 해시를 신뢰하기 전에 교차 검증하여, 콜드 스타트에서도 빠르게 동기화합니다.
- **위임 추적** — 운영자 계정의 위임을 체인에서 그대로 반영합니다(읽기 전용).
- **옵트인 자동 청구** — 구성 가능한 간격으로 누적된 라이트 노드 보상을 운영자 계정으로 청구합니다. 기본적으로 꺼져 있으며, 재위임은 하지 않습니다.
- **평판 알림** — 위임한 검증자가 구성 가능한 평판 점수 아래로 떨어지면 경고하며, 스테이크를 이동하지는 않습니다.
- **실시간 텔레메트리** — 검증자, 합의, 브리지, 토크노믹스를 독립적인 간격으로 새로 고칩니다.
- **온체인 등록** — 노드를 보상 대상으로 유지하는 하트비트 활성 증명과 함께. 등록은 라이선스로 제한됩니다. 노드는 Linux, macOS, Windows에서 자체 트랜잭션에 직접 서명하며, 다른 소프트웨어는 필요하지 않습니다.
- **포스트 양자 암호화** — 전반에 걸친 Dilithium-5 (ML-DSA-87) 키와 서명.
- **로컬 전용 모드** — 가동 중인 체인을 가리키기 전에 전체 PQC 스택을 실행하고 노드를 독립 실행합니다.

라이트 노드는 **Apache 2.0** 라이선스로 배포됩니다.
