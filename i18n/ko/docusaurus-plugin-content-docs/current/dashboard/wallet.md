# 지갑

**지갑** 페이지에서는 잔액과 거래 내역을 확인하고, QOR을 받거나 보낼 수 있습니다. 페이지의 동작 방식은 네트워크에 따라 다릅니다.

- **메인넷 — 비수탁형(non-custodial).** 대시보드는 메인넷 키를 보관하지 않습니다. 사용자가 직접 자신의 지갑 — **QoreX**(공식 QoreChain 지갑, 확장 프로그램 또는 앱), **Keplr**, **MetaMask** 중 하나 — 를 연결하면, 실제 잔액과 내역이 체인에서 직접 읽혀지며, 어떤 레일에서든 자금을 받을 수 있습니다. **네이티브 레일**에서의 전송과 스테이킹에는 **QoreX가 반드시 필요**합니다. QoreChain 계정은 포스트 퀀텀 하이브리드 서명으로 서명하며, 이를 생성하는 지갑이 QoreX이기 때문에, 다른 지갑을 함께 연결해 두었더라도 대시보드의 보내기와 스테이크 탭은 QoreX를 통해 동작합니다. Keplr은 네이티브 레일(`qor1...`) 잔액을 조회하고 그 레일에서 자금을 받는 용도로는 계속 연결해 둘 수 있습니다. **MetaMask**는 **EVM 레일**(`0x...`)에 연결되어 EVM 트랜잭션에 직접 서명하지만, 체인 v3.2.0부터 EVM 레인은 등록된 포스트 퀀텀 키가 있고 **동시에** EVM 인가 윈도우가 열려 있는 계정의 트랜잭션만 허용합니다. MetaMask는 그 키를 등록하거나 윈도우를 열 수 없으며, QoreX는 할 수 있습니다. [MetaMask로 보내기](#send-metamask)를 참조하세요.
- **테스트넷 — 수탁형(custodial).** 대시보드가 사용자를 위해 테스트 지갑을 관리하므로, 별도 설정 없이 전송, 스왑, 스테이킹을 바로 시도해 볼 수 있습니다. [Faucet](/dashboard/faucet)에서 자금을 채우세요.

계정은 양자 내성 암호화로 보호되며, 모든 주소의 네이티브 인코딩은 `qor` bech32 접두사(`qor1...`)를 사용합니다.

## 하나의 계정, 세 가지 인코딩 {#one-account-three-encodings}

QoreChain 계정은 하나의 단일 아이덴티티이며, 실행 레일별로 세 가지 방식으로 표기될 수 있습니다.

| 레일 | 인코딩 | 형태 |
| --- | --- | --- |
| **네이티브 QOR** | bech32 | `qor1...` |
| **EVM** | hex | `0x...` |
| **SVM** | base58 | 예: `5Gv7...` |

세 인코딩 모두 **동일한 계정과 동일한 잔액**을 가리킵니다. 어느 레일에서 받든 자금은 하나의 잔액으로 모이며, 대시보드는 `qor1`(네이티브) 인코딩을 통해 잔액과 내역을 색인하므로 모든 레일의 활동이 함께 표시됩니다.

## 메인넷에서 지갑 사용하기 {#mainnet}

1. 대시보드 헤더를 **메인넷**으로 전환합니다.
2. 메시지가 표시되면 [1회성 위험 고지](/dashboard/overview#risk-acknowledgement)에 동의합니다 — 메인넷은 실제 자금을 이동시키고, 대시보드는 비수탁형이며, 거래는 되돌릴 수 없습니다.
3. 연결 화면에서 지갑을 고릅니다 — **QoreX로 연결**(권장, 공식 QoreChain 지갑 — 네이티브 레일에서 전송 및 스테이킹에 필수), **Keplr 연결**(네이티브 레일에서 조회/수신용), **MetaMask 연결**(EVM 레일에서 연결 및 수신용; 전송에는 열린 EVM 윈도우가 필요합니다. [MetaMask로 보내기](#send-metamask) 참조). 각각의 단계별 안내는 아래를 참고하세요. Phantom은 여기서 지갑으로 연결할 수 없습니다. [Keplr로 연결하기](#connect-keplr) 아래의 참고를 확인하세요.
4. 페이지가 체인으로부터 실제 잔액과 거래 내역을 불러옵니다.

연결이 완료되면 지갑 페이지는 모든 것을 여섯 개의 탭으로 정리합니다 — **지갑**(잔액 및 계정 요약), **QoreX에서 보내기**, **스테이크 / 위임**, **보상**, **세부 정보**(사용자의 `qor1...` / `0x...` / SVM 주소), **지갑 연결**(연결된 모든 지갑과 추가 연결 위치). 보내기, 스테이크, 보상 탭은 QoreX를 통해 동작합니다 — Keplr이나 MetaMask를 함께 연결해 두었더라도 마찬가지인데, 이는 네이티브 레일 거래에 QoreX가 생성하는 포스트 퀀텀 하이브리드 서명이 필요하기 때문입니다.

지갑에 아직 QoreChain이 설정되어 있지 않다면 먼저 추가하세요 — [지갑에 QoreChain 추가하기](#add-network)를 참고하세요.

### QoreX로 연결하기 — 브라우저 확장 프로그램 {#connect-qorex-extension}

1. 지갑 페이지에서 **QoreX 지갑** 카드를 찾아 **QoreX로 연결**을 선택합니다.
2. 이 브라우저에서 QoreX 확장 프로그램이 감지되었으므로, 대시보드가 연결 방식을 묻습니다. **브라우저 확장 프로그램**을 선택합니다.
3. QoreX 확장 프로그램이 자체 승인 팝업을 열고, 연결을 요청하는 사이트로 `dashboard.qorechain.io`를 표시합니다.
4. 팝업의 요청 내용을 검토하고 승인합니다 — 이는 사용자가 자신의 `qor1...` 주소를 소유하고 있음을 증명하는 1회성 서명이며, 자금이 이동하거나 다른 권한이 부여되지 않습니다.
5. 팝업이 닫히고 대시보드가 QoreX 카드에 **연결됨: qor1...**을 표시하며, 사용자의 주소로 지갑 페이지의 나머지 부분이 활성화됩니다. 확장 프로그램/앱 선택은 기억되므로, 다음에 이 브라우저에서 **QoreX로 연결**을 선택하면 묻지 않고 동일한 방식으로 재연결됩니다 — 방식을 바꾸고 싶다면 연결 카드의 **다른 방법 사용**을 선택하세요.

동일한 대시보드 계정에 QoreX 주소를 두 개 이상 연결할 수 있습니다 — 예를 들어 Firefox 확장 프로그램에서 하나, Chrome에서 하나, 또는 휴대폰과 노트북 각각 하나씩입니다. **다른 지갑 추가**를 선택하여 두 번째 주소로 흐름을 반복하세요. 연결된 각 주소에는 자체 라벨을 지정할 수 있으며 그중 하나가 전송용 기본값으로 지정되는데, 둘 다 **지갑 연결** 탭에서 할 수 있습니다.

**지갑 탭에서 지갑 전환하기.** 하나 이상의 지갑이 연결되면 — QoreX와 MetaMask, 또는 QoreX 주소 두 개 — **지갑** 탭 상단에 **보기**로 시작하는 지갑 칩(chip)들이 한 줄로 나타나며, 연결된 지갑마다 하나씩 있고 현재 활성화된 지갑이 표시됩니다. 칩을 클릭하면 탭을 벗어나거나 **지갑 연결**로 이동하지 않고도 어떤 지갑의 잔액과 내역을 볼지 전환할 수 있습니다. 연결된 지갑이 하나뿐일 때는 선택기가 할 일이 없으므로 이 줄이 표시되지 않습니다.

**QoreX 확장 프로그램에 있지만 아직 연결되지 않은 계정.** 하나의 복구 구문으로 여러 계정을 파생할 수 있으며, QoreX에서 계정을 만든다고 해서 대시보드가 그것을 알게 되는 것은 아닙니다 — 연결은 서명이 필요한 별도의 단계입니다. QoreX 확장 프로그램이 계정 목록을 제공할 수 있으면, **지갑**, **세부 정보**, **지갑 연결** 탭에 "QoreX 확장 프로그램의 계정 2개가 여기에 연결되어 있지 않습니다"와 같은 카드가 표시되며, 각 계정의 잔액(그리고 그중 스테이킹되어 보낼 수 없는 금액)도 함께 표시됩니다. **이 계정 연결**을 선택해 페어링하세요. 연결하면 대시보드가 해당 계정의 잔액과 내역을 표시할 수 있으며, 키에 대한 어떤 제어권도 부여되지 않습니다. 사용 중인 QoreX 빌드가 증명할 계정을 선택할 수 없는 경우 여기서는 활성 계정만 연결할 수 있으며, 카드가 먼저 QoreX에서 해당 계정으로 전환하라고 안내합니다.

**세부 정보** 탭의 **연결된 주소**에는 계정에 연결된 모든 주소가 출처 지갑과 함께 나열됩니다. 주소의 이름을 바꾸고, 하나를 전송용 기본값으로 지정하며, QoreX에서 제어할 수 있는지 조회 전용(자물쇠 아이콘)인지 확인할 수 있습니다.

### QoreX로 연결하기 — 모바일 앱 {#connect-qorex-app}

1. 지갑 페이지에서 **QoreX 지갑** 카드를 찾아 **QoreX로 연결**을 선택합니다.
2. 확장 프로그램 선택 창이 나타나면 **QoreX 앱**을 선택합니다(이 브라우저에서 확장 프로그램이 감지되지 않으면 대시보드가 바로 이 흐름으로 진행합니다).
3. 대시보드가 QR 코드와 **QoreX 열기** 링크를 표시합니다.
4. 휴대폰에서 QoreX 앱을 열고 QR 코드를 스캔하거나, 같은 휴대폰에서 브라우징 중이라면 **QoreX 열기**를 탭하여 `qorex://connect` 링크로 앱을 바로 실행합니다.
5. QoreX가 대시보드의 출처와 함께 페어링 요청을 표시합니다. 내용을 검토하고 생체 인증(Face ID / Touch ID / PIN)으로 승인합니다.
6. 대시보드는 백그라운드에서 승인 여부를 계속 확인하며, 몇 초 안에 QoreX 카드에 **연결됨: qor1...**을 표시하고, 사용자의 주소로 지갑 페이지의 나머지 부분이 활성화됩니다.

### Keplr로 연결하기 {#connect-keplr}

Keplr은 네이티브 레일 잔액, 내역, 수신 주소를 조회하기 위해 연결됩니다. 네이티브 레일에서의 전송과 스테이킹은 QoreX를 사용합니다(아래 참고) — QoreChain 계정은 포스트 퀀텀 하이브리드 서명으로 서명하기 때문에, 대시보드의 보내기와 스테이크 탭은 여기서 연결한 지갑이 아니라 QoreX를 통해 동작합니다.

1. 지갑 페이지에서 **Keplr 연결**을 선택합니다.
2. Keplr에 QoreChain이 아직 설정되어 있지 않다면, 대시보드가 Keplr의 `suggestChain` 프롬프트를 트리거합니다 — Keplr 팝업에서 네트워크 세부 정보(체인 ID, RPC/REST 엔드포인트)를 검토하고 **승인**을 선택해 추가합니다.
3. 이어서 Keplr이 연결할 계정을 선택하고 연결을 승인하도록 요청합니다 — **승인**을 선택합니다.
4. 대시보드가 사용자의 `qor1...` 주소를 읽고 잔액과 내역을 불러옵니다.

Phantom은 메인넷 지갑 페이지에서 지갑으로 연결할 수 없습니다. 이전에 연결된 Phantom 주소는 **연결된 지갑**에 계속 표시됩니다. Phantom 키를 서명자로 연결하는 방법은 [연결된 서명자 (Phantom)](#linked-signers)를 참조하세요.

### MetaMask로 연결하기 {#connect-metamask}

1. 지갑 페이지에서 **MetaMask 연결**을 선택합니다.
2. QoreChain EVM 네트워크가 아직 추가되어 있지 않다면, MetaMask가 체인 ID, RPC URL, 통화 기호가 미리 채워진 **네트워크 추가** 프롬프트(EIP-3085)를 표시합니다 — 내용을 검토하고 **승인**을 선택한 다음 **네트워크 전환**을 선택합니다.
3. MetaMask가 연결할 계정을 묻습니다 — 계정을 선택하고 **연결**을 확인합니다.
4. 대시보드가 사용자의 `0x...` 주소를 읽고 잔액과 내역을 불러옵니다.

### 메인넷에서 보내기 {#send-mainnet}

대시보드는 사용자의 메인넷 키를 보관하지 않으므로, 모든 전송은 대시보드에서 구성되지만 최종 서명은 사용자 자신의 지갑에서 이루어집니다. **네이티브 레일**에서는 그 지갑이 항상 **QoreX**입니다 — QoreChain 계정이 포스트 퀀텀 하이브리드 서명으로 서명하기 때문에, 다른 지갑을 함께 연결해 두었더라도 보내기와 스테이크 탭은 QoreX를 통해 동작합니다. **EVM 레일**에서는 계정에 이미 포스트 퀀텀 키와 열린 EVM 윈도우가 있다면 MetaMask가 트랜잭션에 서명합니다([MetaMask로 보내기](#send-metamask) 참조).

:::caution 실제 자금, 되돌릴 수 없는 전송
메인넷 거래는 되돌릴 수 없습니다. 승인 전에 항상 수신자 주소를 다시 한번 확인하세요.
:::

:::note 베스팅 잔액
잔액 일부가 아직 베스팅 중이라면, 스테이킹을 위해 위임할 수 있는 금액에는 포함되지만 거래 수수료를 지불할 수는 없습니다 — PQC 키 등록을 포함해 별도로 지출 가능한 QOR이 필요합니다. 베스팅 금액만 있는 지갑은 위임은 할 수 있지만 전송은 할 수 없습니다.
:::

#### QoreX로 보내기 — 브라우저 확장 프로그램

1. 지갑 페이지의 **QoreX에서 보내기** 카드에서 수신자(`qor1...` 주소 또는 `@handle`), QOR 단위 금액, 선택적으로 메모를 입력합니다. QoreX 지갑을 둘 이상 연결했다면 **보내는 지갑**에서 어느 지갑으로 결제할지 선택합니다.
2. **QoreX에서 계속하기**를 선택합니다.
3. 대시보드가 **브라우저 확장 프로그램에서 승인** 버튼을 표시합니다 — 선택하세요.
4. QoreX 확장 프로그램이 전송 내용(수신자와 금액)이 모두 해독되어 표시된 승인 팝업을 엽니다. 내용을 검토하고 확장 프로그램 자체의 보안 방식(생체 인증 또는 비밀번호 잠금 해제)으로 승인합니다.
5. 확장 프로그램이 하이브리드 PQC 서명으로 전송에 서명하고 체인으로 직접 브로드캐스트합니다 — 대시보드는 결과 거래 해시만 알게 됩니다.
6. 지갑 페이지에 거래 해시와 함께 **전송 확인됨**이 표시되며, [탐색기](/dashboard/explorer)에서 열어볼 수 있습니다.

#### QoreX로 보내기 — 모바일 앱

1. 지갑 페이지의 **QoreX에서 보내기** 카드에서 수신자(`qor1...` 주소 또는 `@handle`), QOR 단위 금액, 선택적으로 메모를 입력합니다. QoreX 지갑을 둘 이상 연결했다면 **보내는 지갑**에서 어느 지갑으로 결제할지 선택합니다.
2. **QoreX에서 계속하기**를 선택합니다.
3. 대시보드가 `qorex://tx` 요청을 담은 QR 코드와 **QoreX에서 열기** 링크를 표시합니다.
4. QoreX 앱으로 QR 코드를 스캔하거나, 같은 휴대폰에 있다면 **QoreX에서 열기**를 탭합니다.
5. QoreX가 요청을 해독하여 수신자와 금액을 모두 표시합니다. 내용을 검토하고 생체 인증으로 승인합니다.
6. QoreX가 하이브리드 PQC 서명으로 전송에 서명하고 브로드캐스트합니다.
7. 대시보드가 결과를 계속 확인하며, 온체인에 반영되면 거래 해시와 함께 **전송 확인됨**을 표시합니다. [탐색기](/dashboard/explorer)에서 열어볼 수 있습니다.

#### `@handle`로 보내기

**QoreX에서 보내기** 카드의 수신자 필드는 `qor1...` 주소 대신 `@handle`도 받을 수 있습니다. 이후 동작은 이 브라우저에서 해당 handle로 이전에 결제한 적이 있는지에 따라 달라집니다.

- **처음인 경우**: 해석된 주소가 "이 브라우저에서 @handle로 처음 보냅니다. 계속하기 전에 주소를 확인하세요:"라는 문구와 함께 전체가 표시되며, 사용할 수 있으려면 **이 주소가 맞습니다 — 계속**을 선택해야 합니다 — 주소가 해석되는 순간이 아니라 확인을 마친 후에야 기억(고정)됩니다.
- **이전과 같은 주소인 경우**: 가벼운 확인만으로 통과합니다 — 다시 입력할 필요가 없습니다.
- **이전과 다른 주소인 경우**: 흐름이 강제로 멈춥니다. 이전 주소와 새 주소가 모두 전체가 표시되며 — 잘림 처리는 절대 하지 않습니다. 중간 문자를 잘라내면 공격자가 비슷하게 보이도록 만들려는 바로 그 부분이 가려지기 때문입니다 — 주소가 변경되었다는 명시적 경고와 함께, 그래도 진행하려면 의도적으로 보조 스타일로 만든 **이 변경을 신뢰합니다 — 계속** 버튼이 제공됩니다.

이 고정 정보는 사용자 자신의 브라우저에만 저장되며 어떤 서버에도 저장되지 않으므로, 다른 컴퓨터를 사용하거나 브라우저 데이터를 지우면 다시 "처음"으로 표시됩니다 — 이는 의도된 동작입니다. Handle은 3~20자(`a-z`, `0-9`, `_`)이며 특정 주소에 속하므로, 여러 주소를 가진 사람은 각 주소마다 다른 handle을 사용할 수 있습니다. handle 조회를 일시적으로 사용할 수 없는 경우 필드에 그렇게 표시되며, 그래도 `qor1...` 주소로는 보낼 수 있습니다.

#### MetaMask로 보내기 {#send-metamask}

:::caution 체인 v3.2.0부터 MetaMask만으로는 메인넷에서 보낼 수 없습니다
EVM 레인은 등록된 포스트 퀀텀 키를 보유하고 **열려 있는 EVM 인가 윈도우**가 있는 계정의 트랜잭션만 허용합니다. 인가 윈도우는 계정이 포스트 퀀텀 서명 메시지로 여는, 시간·횟수·금액이 제한된 권한입니다. MetaMask는 그 메시지를 만들 수 없습니다. 윈도우 없이 보내면 체인이 트랜잭션을 거부합니다(전형적인 오류: 윈도우 없음, 윈도우 소진, 포스트 퀀텀 키 없음).
:::

1. **QoreX**(계정 자체의 지갑)에서 계정에 포스트 퀀텀 키가 없다면 등록한 다음(해당 계정에서의 첫 QoreX 전송이 이를 처리합니다) EVM 인가 윈도우를 엽니다 — [EVM 액세스 윈도우](/qorex/security-and-recovery#evm-window)를 참조하세요. 이는 MetaMask와 키를 공유하는 **이더리움 방식(코인 60) 계정**을 위한 것입니다. 동일한 복구 구문을 사용해 QoreX에서 **Add an Ethereum account (coin 60)**로 추가하세요([방법](/qorex/getting-started#restore-dashboard)). 어떤 MetaMask 키도 일반 코인 118 `qor1…` 계정에서는 보낼 수 없습니다. 윈도우는 블록 수(최대 17,280, 메인넷에서 약 15시간), 트랜잭션 수(최대 1,000), 그리고 각 금액에 최대 수수료를 **더해서** 계산하는 QOR 지출 한도로 제한됩니다. 편안하게 느끼는 한도를 선택하고 작게 유지하세요. 윈도우가 열려 있는 동안 MetaMask 트랜잭션은 포스트 퀀텀 서명 없이 QOR을 이동시킵니다. 새 윈도우를 열면 이전 윈도우가 대체되고 계정의 논스가 증가하므로, MetaMask에서 보내기 **전에** 윈도우를 여세요(미리 준비해 둔 트랜잭션은 "nonce too low"로 실패합니다). v3.2.3부터 체인은 더 좁은 범위로 지정한 윈도우도 지원하지만, QoreX에는 아직 이를 위한 화면이 없습니다.
2. MetaMask를 열고 QoreChain EVM 네트워크로 설정되어 있는지 확인합니다.
3. MetaMask 내에서 **Send**를 선택하고, 수신자의 `0x...` 주소와 금액을 입력한 다음, 가스 수수료를 검토하고 확인합니다.
4. 대시보드 지갑 페이지로 돌아오면, 거래가 온체인에 반영되는 즉시 내역에 표시됩니다(아직 표시되지 않았다면 새로고침하세요).

각 트랜잭션은 윈도우의 일부를 소모합니다. 시간, 트랜잭션 횟수 또는 금액 한도에 도달하면 QoreX에서 새 윈도우를 여세요. 작업을 마치면 QoreX에서 윈도우를 닫으세요.

### 특정 레일에서 받기 {#receive-mainnet}

1. **받기**를 선택합니다.
2. 받기 모달에서 선택기로 레일을 고릅니다 — **네이티브 QOR**, **EVM**, **SVM**.
3. 모달이 해당 레일의 인코딩(`qor1...`, `0x...`, 또는 base58)으로 사용자의 주소를 QR 코드 및 복사 버튼과 함께 표시합니다.
4. 주소를 복사하거나, 발신자가 QR 코드를 스캔하도록 합니다.

발신자가 어떤 레일을 사용하든, 자금은 동일한 계정으로 도착합니다 — 하나의 계정, 세 가지 인코딩, 하나의 잔액입니다.

### 거래 내역 확인하기 {#history}

메인넷에서 내역의 각 행은 다음을 표시합니다.

- **레일 배지** — Native, EVM, 또는 SVM — 거래에 사용된 레일을 알려줍니다.
- 일반 전송에는 **보냄** 또는 **받음**, 그 밖의 활동에는 설명적인 유형 라벨(예: *PQC 키 등록* 또는 컨트랙트 동작).
- 금액, 시간, **확인됨** / **실패** 상태와 함께, [탐색기](/dashboard/explorer)에서 열어볼 수 있는 거래 해시.

## 테스트넷에서 지갑 사용하기 {#testnet}

테스트넷(`qorechain-diana`)에서는 대시보드가 사용자를 위해 테스트 지갑을 관리하므로, 아무것도 연결하지 않고도 흐름 전체를 테스트해 볼 수 있습니다.

### 페이지에 표시되는 내용

- 지갑 라벨과 활성 주소(축약된 형태), 원클릭 복사 버튼.
- QOR 단위의 **총 잔액**.
- 양자 내성 암호화와 연결된 네트워크를 알려주는 보안 패널.
- 새로고침 컨트롤이 있는 최종 업데이트 표시기.
- **거래 내역** 탭과 **토큰** 탭이 있는 **자산 및 활동** 섹션.

언제든 새로고침 컨트롤을 사용해 체인에서 현재 잔액과 최신 활동을 가져올 수 있습니다.

:::caution 테스트넷 주소는 메인넷 주소와 똑같이 생겼습니다
테스트넷과 메인넷은 동일한 `qor1...` 형식을 사용하므로, 테스트넷 주소를 아무 경고 없이 거래소 출금이나 다른 지갑에 붙여넣을 수 있습니다 — 그리고 그 주소로 보낸 실제 QOR은 이 테스트넷 페이지에서 볼 수 없는 **메인넷**의 해당 주소에 도착합니다. 테스트넷 주소로 실제 QOR을 절대 보내지 마세요. 대시보드는 지갑 페이지의 주소 옆, **내 지갑** 목록, **받기** 화면에서 이 경고를 반복해서 표시합니다. 실제 QOR의 경우 메인넷으로 전환하고 거기에 표시된 주소를 사용하세요. 이미 테스트넷 주소로 실제 QOR을 보냈다면 지원팀에 문의하세요 — 직접 옮기려고 하지 마세요.
:::

### QOR 보내기 (테스트넷)

1. **보내기**를 선택합니다.
2. **수신자 주소**(`qor1...`)를 입력합니다.
3. **금액**(또는 **MAX**)과 선택적으로 **메모**를 입력합니다.
4. **거래 검토**를 선택하고 세부 정보와 예상 네트워크 수수료를 확인한 다음 **확인 및 전송**을 선택합니다.

수신자를 입력하는 동안 저장된 연락처와 최근 주소가 실수를 방지하도록 제안됩니다. 전송이 제출된 후, 거래 해시가 포함된 확인을 받게 되며, [탐색기](/dashboard/explorer)에서 열어볼 수 있습니다.

### QOR 받기 (테스트넷)

1. **받기**를 선택합니다.
2. 주소나 QR 코드를 발신자와 공유하거나, 원클릭으로 주소를 복사합니다.
3. 선택적으로 요청 금액과 메모를 입력해 결제 링크와 다운로드 가능한 QR 코드를 생성합니다.

### 테스트 지갑 관리하기

**내 지갑**을 선택해 주소 목록을 엽니다. 여기서 지갑 간 전환, 새 지갑 생성, 기존 지갑 가져오기, 더 이상 필요 없는 지갑 삭제를 할 수 있습니다. 활성 지갑은 테스트넷에서 대시보드 전반에 걸쳐 전송, 스왑, 스테이킹 및 기타 서명 작업에 사용되는 지갑입니다.

### 테스트 지갑의 복구 구문 백업 또는 내보내기 {#reveal-recovery-phrase}

테스트넷에서는 대시보드가 지갑을 대신 관리하지만, 지갑의 24단어 복구 구문을 내보내 QoreX와 같은 자기 수탁 지갑으로 가져올 수 있습니다.

1. 테스트넷 **지갑** 페이지에서 **복구 구문** 카드를 찾습니다. 이 카드는 대시보드가 관리하는 각 지갑을 **메인넷** 잔액과 함께(자금이 있는 지갑이 먼저) 나열하므로, 실제로 토큰을 보유한 지갑을 고를 수 있습니다.
2. 지갑 옆의 **공개**를 선택하고, 경고("…의 구문을 공개하시겠습니까?")를 읽은 다음 **계속**을 선택합니다.
3. 계정의 로그인 페이지에서 다시 로그인하도록 이동됩니다(새로운 비밀번호 확인이 필요하며, 대시보드는 비밀번호를 절대 보지 못합니다). 이후 자동으로 지갑으로 돌아옵니다.
4. 24개 단어가 60초 동안 표시됩니다. 적어서 오프라인으로 보관하세요. 확인 상자를 체크하거나 확인 입력란에 입력하는 동안에는 카운트다운이 일시 중지됩니다.
5. **복구 구문을 적어서 안전한 곳에 보관했습니다**를 체크하고, 적어 둔 사본에서 **3**, **5**, **9**번째 단어(*필수*로 표시됨)를 입력한 다음 **백업 확인**을 선택합니다. "복구 구문 저장됨"이 표시됩니다.
6. **확인 없이 숨기기**로 나가거나(또는 타이머가 만료되면) 카드에 "백업 미확인"이 표시되며 — 구문을 적었다는 사실은 어디에도 기록되지 않습니다 — **다시 공개하고 확인** 옵션이 제공됩니다.

이 24개 단어를 가진 사람은 누구나 지갑을 제어할 수 있습니다. QoreChain은 이를 복구하거나 재설정해 줄 수 없으며, 지원팀은 절대 이 단어를 요청하지 않습니다.

## 지갑에 QoreChain 추가하기 {#add-network}

지갑 페이지의 **지갑에 QoreChain 추가** 패널(메인넷에서는 **지갑 연결** 탭에 있으며 지갑이 연결되기 전까지는 연결 버튼 아래에 있습니다. 테스트넷에서는 페이지 하단에 있습니다)은 연결 방법별로 나란히 네 개의 카드를 보여주므로, 원클릭으로 자신의 지갑에 QoreChain을 추가할 수 있습니다.

| 카드 | 제공하는 것 |
| --- | --- |
| **네이티브(Cosmos) 지갑** | 복사 버튼이 딸린 RPC 및 REST 엔드포인트와 체인 ID — Keplr 및 기타 네이티브 레일 지갑용. |
| **EVM 지갑** | 바로 사용 가능한 EIP-3085 네트워크 파라미터 — 원클릭으로 MetaMask 및 다른 EVM 지갑에 QoreChain을 추가합니다. |
| **SVM 지갑** | SVM 호환 지갑 및 도구용 SVM RPC URL. |
| **모바일 지갑(WalletConnect)** | 호환되는 지갑의 모바일 버전용 WalletConnect v2 페어링 QR. |

QoreChain을 추가하려면:

1. **지갑** 페이지를 열고 **지갑에 QoreChain 추가**를 찾습니다.
2. 사용 중인 지갑의 레일에 맞는 카드를 고릅니다.
3. 추가 버튼(**Keplr에 추가** / **Cosmostation에 추가**, **MetaMask에 추가** 또는 다른 EVM 지갑, 또는 WalletConnect 페어링)을 선택하거나, 엔드포인트와 체인 ID를 지갑의 네트워크 추가 양식에 복사해 넣습니다(SVM 카드는 사용자 지정 RPC 설정에 붙여넣을 SVM RPC URL을 제공합니다).
4. 지갑에서 새 네트워크를 승인합니다.

공개 엔드포인트는 `rpc.qore.host`(Native RPC), `api.qore.host`(REST), `evm.qore.host`(EVM JSON-RPC), `svm.qore.host`(SVM RPC)이며, 테스트넷용으로는 `*-testnet` 변형(예: `rpc-testnet.qore.host`)이 있습니다. 체인 ID: 메인넷 `qorechain-vladi`(EVM 체인 ID `9801`), 테스트넷 `qorechain-diana`(EVM 체인 ID `9800`).

### 연결된 서명자 (Phantom) {#linked-signers}

**SVM 지갑** 카드에서는 Phantom 키를 계정에 **연결된 서명자(linked signer)**로 연결할 수도 있습니다 — 이는 기간이 제한(30일)되고 철회 가능한 인증자(authenticator)이며, QoreX, Keplr, MetaMask처럼 별도의 기본 지갑 연결이 아닙니다. **Phantom 연결**을 선택한 다음 **인증자 등록**을 선택하세요. 기존 지갑이 등록에 서명하며, Phantom이 자체적인 아이덴티티가 되는 것은 아닙니다.

:::caution 연결된 서명자 등록은 현재 체인에서 꺼져 있습니다
체인의 스마트 계정 및 연결된 지갑 기능은 구현되어 있지만 두 네트워크 모두에서 꺼져 있으며(`abstractaccount.enabled = false`; `GET /qorechain/abstractaccount/v1/config`로 확인), 그동안 체인은 새 연결된 서명자 등록을 거부합니다. 지금은 이 카드를 미리보기로 간주하고 등록이 성공하기를 기대하지 마세요.
:::

:::caution 연결된 서명자는 계정에 대한 실질적인 권한입니다
기능이 활성화되면, 부여한 권한은 키가 얼마를 이동할 수 있는지가 아니라 어떤 레인에서 동작할 수 있는지를 결정하며, 등록은 30일 동안 유효합니다. 계정 자체만큼 신뢰하는 Phantom 키만 연결하고, 더 이상 필요하지 않으면 철회하세요.
:::

온체인 권한 및 지출 한도 모델에 대해서는 QoreX 문서의 [연결된 서명자와 지출 한도](/qorex/security-and-recovery#linked-signers)를 참고하세요.
