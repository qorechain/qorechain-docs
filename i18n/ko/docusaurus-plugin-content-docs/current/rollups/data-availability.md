# 데이터 가용성

데이터 가용성(DA)은 롤업 상태의 배후에 있는 거래 데이터가 누구나 읽을 수 있는 어딘가에 게시된다는 보장입니다 — 그래야 누구나 독립적으로 롤업의 상태를 재구성하고 검증할 수 있습니다. RDK는 세 가지 DA 백엔드를 정의하며, 현재 구현된 것은 `native`뿐입니다.

| 백엔드 | 무엇인가 | 상태 |
| ------- | ---------- | ------ |
| **`native`** | QoreChain 자체 내의 온체인 블롭 저장소 | 모듈에 구현되어 있음. 아직 블롭을 게시할 공개 방법은 없음(아래 참조) |
| **`celestia`** | 전용 모듈식 DA 계층인 Celestia로 IBC를 통한 데이터 가용성 | 구현되지 않음 |
| **`both`** | 중복성을 위해 native와 Celestia를 함께 사용 | 현재는 `native`와 정확히 동일하게 동작 |

:::caution 초기 단계 기능
어느 네트워크에서도 아직 롤업이 생성되지 않았으며(2026년 10월 23일 확인), DA 백엔드는 부분적으로만 구현되어 있습니다. 각 백엔드의 상태는 아래에 명시되어 있습니다. 어느 것이든 의존하기 전에 **`qorechain-diana`** 테스트넷에서 검증하세요.
:::

---

## Native DA (온체인 블롭 저장소)

Native DA는 `x/rdk` 내부의 온체인 블롭 저장소입니다. 각 블롭은 롤업 ID와 블롭 인덱스로 키가 지정되고, 바이트의 **SHAKE-256 커밋먼트**를 지니며, 보존 기간이 지나면 가지치기되지만 커밋먼트는 유지됩니다.

:::caution 아직 블롭을 게시할 공개 방법이 없음
모듈은 블롭 저장, 보존, 가지치기를 정의하지만, 현재 릴리스에는 **블롭을 게시하기 위한 트랜잭션 메시지가 없습니다**. 제출 메시지가 출시되기 전까지 정산 배치는 `data_hash`를 비워 두어야 합니다 — `native` 또는 `both` 롤업에서 데이터 해시를 지정하는 배치는, 일치하는 블롭을 저장할 수 없으므로 거부됩니다.
:::

주요 개념:

* **블롭(Blobs).** 블롭은 롤업 ID와 블롭 인덱스에 연결됩니다.
* **커밋먼트(Commitments).** 각 블롭은 데이터의 32바이트 SHAKE-256 커밋먼트를 지니므로, 저장자를 신뢰하지 않고도 커밋된 내용과 블롭을 대조하여 검증할 수 있습니다. (TypeScript 헬퍼 `buildDaBlob()`는 현재 SHA-256으로 해시하므로, 그 `dataHash`는 체인의 커밋먼트와 일치하지 않습니다.)
* **네임스페이스(Namespaces).** 블롭은 롤업별 네임스페이스를 지닐 수 있어, 공유 저장소 내에서 각 롤업의 데이터가 논리적으로 분리되도록 유지합니다.
* **보존 및 가지치기(Retention and pruning).** Native 블롭은 `blob_retention_blocks`(432,000블록 — 메인넷의 현재 블록 시간 약 3.2초 기준 약 16일이며, 이 수치는 블록 시간에 따라 변합니다) 동안 보존된 후 온체인 저장소를 지속 가능하게 유지하기 위해 가지치기됩니다. 가지치기 후에는 원시 블롭 데이터는 제거되지만 커밋먼트 메타데이터는 보존되므로, 바이트가 더 이상 온체인에 저장되지 않더라도 과거 커밋먼트는 검증 가능한 상태로 남습니다.

최대 블롭 크기와 보존 기간은 실시간 모듈 파라미터에 의해 관리됩니다. 특정 한도를 기준으로 설계하기 전에 이를 조회하세요:

```bash
qorechaind query rdk config
```

블롭 메타데이터(바이트가 아님)는 REST의 `/qorechain/rdk/v1/blob/{rollup_id}/{blob_index}`에서 읽을 수 있으며, 두 네트워크 모두 이를 제공합니다. 여기에는 `expires_at_height`가 포함됩니다.

## Celestia DA (Celestia로의 IBC)

Celestia DA는 **구현되지 않았습니다**. DA 백엔드가 `celestia`인 롤업은 데이터를 게시할 수 없습니다(모듈이 오류를 반환합니다). 계획된 설계는 전용 모듈식 DA 네트워크인 **Celestia**로 IBC를 통해 데이터 가용성을 게시하면서, 정산은 여전히 QoreChain에 고정하는 것입니다. 현재 어느 네트워크에도 IBC 채널이 없습니다([브리지 아키텍처](/architecture/bridge-architecture) 참조). `native`를 사용하세요.

---

## Both (중복성)

`both` 백엔드는 **native와 Celestia에 함께** 기록하도록 의도되었습니다. 현재 `both`는 `native`와 정확히 동일하게 동작합니다: native 사본만 저장되고, Celestia 쪽은 경고 로그와 함께 건너뜁니다. 이를 두 개의 독립적인 사본으로 취급하지 마세요.

---

## 백엔드 선택하기

| 원하는 것이... | 선택 |
| -------------- | ------ |
| QoreChain 보안을 상속하는 가장 단순한 완전 온체인 옵션 | **`native`** |
| 전용 모듈식 계층으로 DA를 분리 | **`celestia`** — 구현되지 않음 |
| 두 저장소에 걸친 중복성 | **`both`** — 현재는 `native`와 동일 |

DA가 더 넓은 정산 구도에 어떻게 들어맞는지는 **[롤업 개요](/rollups/overview)**를 참조하세요. 더 낮은 수준의 모듈 레퍼런스는 **[Rollup Development Kit](/architecture/rollup-development-kit)** 페이지를 참조하세요.
