# xQORE 스테이킹

이 페이지는 **설계된** xQORE 거버넌스 스테이킹 메커니즘을 설명합니다. 이 설계에서 QOR 보유자는 토큰을 잠가 거버넌스 파워를 강화할 수 있으며, 장기 참여자에게 보상을 주는 PvP 리베이스 모델이 적용됩니다. **xQORE는 현재 어느 네트워크에서도 사용할 수 없으며**, 이 페이지의 어떤 내용도 아직 직접 해볼 수 있는 것이 아닙니다.

:::warning 아직 운영되지 않음
xQORE는 제네시스에서 활성화되어 있지만 메인넷(`qorechain-vladi`, 노드 릴리스 **v3.2.1**)과 테스트넷(`qorechain-diana`)에서 **아직 사용할 수 없습니다**. 노드에 이를 위한 트랜잭션, 쿼리, CLI, RPC 진입점이 없으므로 `tx xqore lock` / `unlock`도, `query xqore ...`도, xQORE REST 경로도, `qor_getXQOREPosition` 메서드도 없으며, 잠글 수 있는 QOR도 없고 xQORE를 보유한 사람도 없습니다. 향후 체인 릴리스에서 제공될 예정이며, 해당 릴리스에서는 출금 페널티의 재분배 방식도 변경되어 보유자 수가 얼마나 많아도 잠금 해제 비용이 낮게 유지됩니다. 릴리스되면 여기에서 해당 릴리스를 안내합니다.
:::

---

## 개요

설계상 QOR을 잠그면 **1:1 비율**로 xQORE가 발행되며, xQORE는 QDRW 투표력 공식에서 **두 배 가중치**로 계산됩니다:

```
VP = sqrt(staked + 2 * xQORE) * ReputationMultiplier(r)
```

QDRW 자체는 운영 중인 네트워크에서 꺼져 있고 거버넌스 투표는 본딩된 스테이크만으로 집계되므로([거버넌스](/user-guide/governance#voting-power) 참고), xQORE가 출시되더라도 향후 릴리스에서 QDRW가 활성화되기 전까지는 투표력이 바뀌지 않습니다.

---

## 설계된 출금 페널티 스케줄

제네시스 구성은 QOR을 잠근 기간이 길수록 낮아지는 출금 페널티를 정의합니다:

| 잠금 기간           | 출금 페널티 |
| ------------------ | ------------ |
| 30일 미만  | **50%**      |
| 30일 ~ 90일      | **35%**      |
| 90일 ~ 180일     | **15%**      |
| 180일 초과 | **0%**       |

설계상 페널티는 **소각되지 않으며**(`penalty_burn_rate`는 `0`), 페널티 전체가 남아있는 xQORE 보유자에게 비례적으로 재분배됩니다("PvP 리베이스"). 재분배 메커니즘은 xQORE를 연결하는 릴리스에서 바뀔 부분입니다.

---

## 사용할 수 없는 기능

* **잠금 및 잠금 해제.** QOR을 잠그거나 잠금 해제하는 `tx xqore` 명령어와 트랜잭션 유형이 없습니다.
* **포지션.** 어떤 인터페이스(CLI, REST, JSON-RPC)에도 xQORE 포지션을 조회하는 쿼리가 없으며, `total_locked`와 `total_xqore`는 모두 0입니다.
* **투표 보너스.** 현재 xQORE 투표 보너스는 없습니다.

지금 거버넌스에 참여하려면 QOR을 검증자에게 위임하고([스테이킹 및 위임](/user-guide/staking-and-delegation) 참고) 제안에 투표하세요([거버넌스](/user-guide/governance) 참고).
