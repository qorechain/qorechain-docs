# アセットのブリッジ

このガイドでは、QoreChainと他のブロックチェーンネットワーク間でのアセット移動が、どのように動作するよう設計されているかを説明します。QoreChainの相互運用レイヤーは、**37個のチェーン構成**(外部チェーン36個に加え、IBC経由で接続するInjective)と、Cosmosエコシステムのチェーン向けの最大**8つのIBCカウンターパーティ**を中心に構築されています。

:::caution どちらのネットワークでも稼働していません
ブリッジモジュールはメインネットとテストネットにデプロイされていますが、**有効なブリッジルートはありません**。37個すべてのチェーン構成は、ブリッジコントラクトが未設定の`pending`ステータスであり、ブリッジバリデータは登録されておらず、ブリッジ操作は一度も作成されたことがなく、メインネットにはIBCチャネルが存在せず(テストネットには、ID `provider` のチェーンへのICS-20テストチャネルが1つあるだけで、以下に挙げる相手先へのチャネルはありません)、以下の内容はすべて、想定されている設計の説明です。ブリッジされることを期待してアセットを送信しないでください。現在のステータス表については[ブリッジアーキテクチャ](/architecture/bridge-architecture)を参照してください。
:::

:::note
以下のコマンドは**`qorechain-diana`**テストネット(EVMチェーンID **9800**、チェーンバージョン**v3.2.6**)を使用しています。メインネット(**`qorechain-vladi`**、EVMチェーンID **9801**)は、チェーンバージョン**v3.2.4**(2026年10月23日から)で稼働しています。ルートが有効化された時点で、**メインネットへの接続**ページに記載のメインネットのチェーンIDとエンドポイントに置き換えてください。2026年10月27日に確認したステータス: 37個すべてのチェーン構成が、両ネットワークで`pending`です。
:::

---

## 接続の概要

QoreChainは2種類のブリッジプロトコルを提供するよう設計されています。

| プロトコル                                 | 接続数        | 用途                                                                 |
| ---------------------------------------- | ------------------ | ------------------------------------------------------------------------ |
| **IBC**(Inter-Blockchain Communication) | 最大8チャネル(開通しているものはなし)         | IBC対応チェーンとのネイティブな相互運用性                          |
| **QCB**(QoreChain Bridge)               | 37構成(すべて保留中)  | PQCで保護されたアテステーションによる非IBCネットワークとのクロスチェーン転送 |

すべてのチェーン構成の完全な一覧は、**ブリッジアーキテクチャ**ページに掲載されています。このガイドでは、ブリッジ転送がどのように動作するよう設計されているかに焦点を当てます。

---

## IBC

IBCは設計の一部です(Cosmos Hub、Osmosis、Noble、Celestia、Stride、Akash、Babylon、Injective)が、**これらの相手先はまだどれも接続されていません**。メインネットにはIBCチャネルもクライアントもなく、テストネットにはID `provider` のチェーンへのICS-20テストチャネルが1つあるだけです(2026年10月27日に確認)。そのため、これらのチェーンへ転送できるものはありません。チャネルが開通した時点で、このページに一覧を掲載します。

### テストネットでのIBCの追加機能(v3.2.6) {#ibc-testnet-v326}

3つのIBC機能はテストネットにのみ存在し、メインネットにはありません(メインネットの `/Stride-Labs/ibc-rate-limiting/ratelimit/ratelimits` ルートは 501 を返します):

* **IBCレート制限。** ガバナンスは、IBC転送のチャネルごとのクォータ(供給量の整数パーセントを、時間単位のウィンドウごとに設定)を設定できます。これは**自動ではありません**。現在、制限は設定されておらず、空の設定は無制限を意味します。転送されたパケットは両方のチャネルで課金され、返金ではクォータが戻ります。これは、[セキュリティモデル](#security-model)で説明するブリッジのサーキットブレーカーとは別のものです。
* **パケットフォワーディング。** IBC v1 で到着する転送は、`{"forward":{"receiver":"...","port":"transfer","channel":"channel-N"}}` の形式のメモを付けることで、別のチェーンへ転送できます。いずれかのホップが失敗した場合は、送信者に返金されます。再試行はなく、ホップは既定で 10 分後にタイムアウトします。到着時に ERC-20 に変換されるトークンは転送できません。
* **08-wasm ライトクライアント。** wasm ライトクライアントのバイナリの保存、移行、削除は権限者のみが実行でき、ガバナンスが `08-wasm` を追加するまで、許可されるクライアントタイプには標準クライアントのみが含まれます。

テストネットでは、`GET /Stride-Labs/ibc-rate-limiting/ratelimit/ratelimits` で制限を読み取れます(現在は `{"rate_limits":[]}` です)。

**どのネットワークに何があるか（2026年10月27日に確認）。**

| | メインネット `qorechain-vladi` (v3.2.4) | テストネット `qorechain-diana` (v3.2.6) |
|---|---|---|
| ICS-20 転送 (IBC v1) | 組み込み済みだが、開いているチャネルはない | 組み込み済み、チャネルが 1 つ開いている |
| IBC レート制限 | 利用不可 (501) | 利用可能、制限は未設定 |
| パケットフォワーディング | 利用不可 | 利用可能 (IBC v1 のみ) |
| 08-wasm ライトクライアント | 利用不可 | メッセージセットは存在するが、ガバナンスが `08-wasm` を許可するまで wasm クライアントは作成できない |

### テストネットのテストチャネル {#ibc-test-channel}

テストネットには、開いている転送チャネルが 1 つあります。`channel-0`（ポート `transfer`、`connection-0`、バージョン `ics20-1`、unordered）です。その相手側は Cosmos Hub のテストネット（チェーン ID `provider`、チャネル `channel-600`）です。テストネットでこれまでに確認された IBC denom は、`channel-0` で到着した `uatom` の 1 つだけです。QoreChain はそれ用の ERC-20 ペアも保持しており、モジュールが所有しています。状態は次のコマンドで読み取れます。

```bash
curl -s https://api-testnet.qore.host/ibc/core/channel/v1/channels
curl -s https://api-testnet.qore.host/ibc/apps/transfer/v1/denoms
```

テストチャネルで送信するには、転送を構築し、他のネイティブレーンのトランザクションと同様にハイブリッド署名を追加します。

```bash
qorechaind tx ibc-transfer transfer transfer channel-0 <receiver_on_the_hub_testnet> 1000uqor \
  --from mykey --chain-id qorechain-diana --gas 400000 --fees 40000uqor --generate-only > ibc.json
qorechaind tx pqc cosign ibc.json --from mykey --pqc-key mypqckey --chain-id qorechain-diana
```

これは 2 つのテストネットワーク間のテストチャネルであり、トークンに価値はありません。パケットの配信にはそのチャネル用のリレイヤーが稼働している必要がありますが、[QORel](/qorel/overview) を使えば自分で稼働させることもできます。このマニュアルは QoreChain が運営するリレイヤーサービスを約束しないため、転送が保留のままになることがあります。上記のコマンドをメインネットで使用しないでください。メインネットには開いているチャネルがなく、トランザクションは失敗します。

## 入金フロー(外部チェーンからQoreChainへ)

外部チェーンからQoreChainへの入金について、設計上の手順は次のとおりです。

1. **ロック** — 外部チェーン上でトークンをQCBブリッジのコントラクトまたはアドレスに送信してロックします。
2. **アテステーション** — ブリッジバリデータがロックトランザクションを検知し、PQC署名付きのアテステーションを生成します。
3. **しきい値** — バリデータのアテステーションが**10件中7件**集まると、ブリッジが入金を確定します。
4. **ミント** — 相当量のラップトークンがQoreChain上でミントされ、あなたの`qor1...`アドレスに入金されます。

ユーザーが実行する「入金を開始する」コマンドはありません。外部チェーン上でロックすると、ブリッジバリデータのアテステーションによってアカウントに入金されます。(チェーンの`qorechaind tx bridge deposit`コマンドは、すでにアテステーション済みの入金を反映するもので、ブリッジバリデータの署名が必要です。ユーザーが入金を開始する方法ではありません。)

---

## 出金フロー(QoreChainから外部チェーンへ)

QoreChainから外部チェーンへの出金について、設計上の手順は次のとおりです。

1. **バーン** — QoreChain上でラップトークンをバーン(焼却)します。
2. **アテステーション** — ブリッジバリデータがバーンを検知し、PQC署名付きのアテステーションを生成します。
3. **しきい値** — アテステーションが**10件中7件**集まると、出金が確定します。
4. **アンロック** — 元のトークンが外部チェーン上で指定した宛先アドレスに解放されます。

**CLIコマンド**(現時点ではブロックされています。有効なチェーンがないため、トランザクションは拒否されます):

```bash
# 1. Build the unsigned transaction
qorechaind tx bridge withdraw [destination-chain] [destination-address] [asset] [amount] \
  --from mykey \
  --chain-id qorechain-diana \
  --gas 300000 --fees 30000uqor \
  --generate-only > withdraw.json

# 2. Attach the post-quantum co-signature and broadcast
qorechaind tx pqc cosign withdraw.json --from mykey --pqc-key mypqckey --chain-id qorechain-diana
```

ネイティブレーンのすべてのトランザクションには、ハイブリッド耐量子共同署名と、ガス1単位あたり少なくとも0.1 uqorの手数料が必要です。[最初のトランザクション](/getting-started/first-transaction)を参照してください。

## セキュリティモデル {#security-model}

QoreChain Bridgeは、複数の防御レイヤーによって保護されるよう設計されています。

| メカニズム                    | 説明                                                                                                                                           |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| **7-of-10 PQCマルチシグ**     | すべてのブリッジ操作には、10のブリッジバリデータのうち少なくとも7つからのアテステーションが必要で、それぞれが耐量子暗号署名を使用します。               |
| **24時間チャレンジ期間**       | 大口転送のしきい値(100,000 QOR)を超える転送は、24時間のチャレンジウィンドウに入り、その間バリデータやウォッチャーが不正なトランザクションにフラグを立てることができます。 |
| **サーキットブレーカー**       | QCBブリッジ向けの設計です。異常な取引量や不審なパターンが検出されると、自動リミッターがブリッジ操作を停止し、手動レビュー後に操作が再開されます。これらはQCBブリッジに適用されるものでIBCには適用されません。IBCレート制限(テストネットのみ)はガバナンスが設定するもので、自動ではなく、現在制限は設定されていません。 |

## ブリッジステータスの照会

ブリッジの状態を読み取ります。

```bash
qorechaind query bridge config
qorechaind query bridge chains
qorechaind query bridge chain ethereum
qorechaind query bridge validators
qorechaind query bridge operations
qorechaind query bridge operation [id]
```

同じデータは、REST の `/qorechain/bridge/v1/` 配下でも取得できます([ブリッジアーキテクチャ](/architecture/bridge-architecture#rest-api-endpoints)を参照)。

---

## ヒント

* 宛先アドレスの形式が対象チェーンに一致していることを必ず確認してください(例: EVMチェーンでは`0x...`、Solanaではbase58)。
* 大口の転送(100,000 QOR超)は、24時間のチャレンジ期間が自動的に発動するよう設計されています。
* ブリッジ手数料は`bridge_fee`バーンチャネルを通じてバーンされます([トークン操作](/user-guide/token-operations)を参照)。
