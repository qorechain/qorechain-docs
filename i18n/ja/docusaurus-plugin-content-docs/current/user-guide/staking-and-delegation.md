# ステーキングとデリゲーション

このガイドでは、QORトークンをバリデーターにデリゲートする方法、バリデーター間で再デリゲートする方法、ステークをアンボンディングする方法、報酬を請求する方法、そしてQoreChainのステーキング設計のうち現時点で稼働している部分について説明します。

:::note
以下のコマンドは**`qorechain-diana`**テストネット(EVMチェーンID **9800**)を使用しています。メインネット(**`qorechain-vladi`**、EVMチェーンID **9801**)は2026年6月7日から稼働しており、リリース**v3.2.3**を実行しています。テストネットは**v3.2.4**を実行しています — メインネットでステーキングする際は、**Connecting to Mainnet**ページに記載のメインネットのチェーンIDとエンドポイントに置き換えてください。
:::

:::caution `tx pqc cosign` で署名する
メインネットとテストネットでは、Cosmosレーンのすべてのトランザクションにハイブリッドのポスト量子署名が必要なため、このページのコマンドはそのままではブロードキャストできません。コマンドに`--generate-only > tx.json`を追加し、続けて`qorechaind tx pqc cosign tx.json --from mykey --pqc-key mypqc --chain-id <chain-id>`を実行してください。[ハイブリッド署名](/cli-reference/transaction-commands#hybrid-signing)を参照してください。[QoreX](/qorex/portfolio-and-staking)と[ダッシュボード](/dashboard/staking-and-validators)は、この署名を自動で行います。
:::

## ロックイン期間はありますか? {#lock-in-period}

**現時点のメインネットでは**、ありません。取引所でよくあるように固定期間で販売されるステーキングではないため、選択すべき期間というもの自体が存在しません。デリゲーションは次のブロックから報酬を生みながらアクティブな状態を保ち続け、あなたが望む限り継続します。あなたがアンデリゲートを選択するまで、期限切れになるものも更新すべきものもありません。このガイド全体で言及されている**21日間のアンボンディング期間**は、事前に同意する類のロックインではありません — それはあなたが実際に*アンデリゲートを申請した*時点で初めて始まり、その時に引き出そうとしているQORにのみ適用されます。デリゲーションをあるバリデーターから別のバリデーターへ移す(再デリゲート)場合は、ステークがボンディングプールから離れることがないため、この待機を完全にスキップできます。この先の[ボンディングカーブ](#bonding-curve)にある「ロイヤルティ」の項はQoreChainの設計の一部ですが、**現在稼働中のチェーンでは適用されていません**。したがって、どれだけ長くデリゲートし続けても報酬率は変わりません。任意の、時間ロック型のステーキングは現在テストネットにあり、メインネットではブロック高3,742,566から利用できる予定です。[時間ロック型ステーキング(v3.2.4)](#time-locked-staking)を参照してください。

これは現在のメインネットの動作を説明したものであり、恒久的な保証ではありません — 最低ステーキング期間は、このページに記載されている他のあらゆるステーキングパラメーターと同様に、将来ガバナンスによって投票で導入され得るパラメーターです。もしそうなった場合、ウォレットはデリゲーションを確定する前に、その結果生じる待機時間(最低期間があればそれに21日間のアンボンディングを加えたもの)を表示するようになり、このページもそれに合わせて更新されます。

## トークンのデリゲート

QORをバリデーターにデリゲートして、ネットワークセキュリティに参加します。デリゲーターは、バリデーターが獲得した報酬から、バリデーターのコミッションを差し引いた分の取り分を受け取ります。

```bash
qorechaind tx staking delegate <validator_address> <amount>uqor \
  --from mykey \
  --chain-id qorechain-diana \
  --gas 400000 --fees 40000uqor
```

**例:** バリデーターに100 QORをデリゲートする場合:

```bash
qorechaind tx staking delegate qorvaloper1abc...xyz 100000000uqor \
  --from mykey \
  --chain-id qorechain-diana \
  --gas 400000 --fees 40000uqor
```

## 再デリゲート

アンボンディング期間を待たずに、あるバリデーターから別のバリデーターへデリゲーションを移動できます。

```bash
qorechaind tx staking redelegate <source_validator> <destination_validator> <amount>uqor \
  --from mykey \
  --chain-id qorechain-diana \
  --gas 400000 --fees 40000uqor
```

**例:**

```bash
qorechaind tx staking redelegate qorvaloper1src... qorvaloper1dst... 50000000uqor \
  --from mykey \
  --chain-id qorechain-diana \
  --gas 400000 --fees 40000uqor
```

再デリゲートには**ペナルティも、それ自体のロックもありません** — ステークがボンディングプールから離れることは一切なく、報酬が止まることもなく、即座に有効になります。21日間のアンボンディング期間の対象にも一切なりません。それは`unbond`にのみ適用されます。標準的なステーキングのルールが1つ適用されます。バリデーターに**移動した**ばかりのステークは、最初の移動が満期になる(21日間)まで、そのバリデーター**から**再度再デリゲートすることはできません。その間も、そのステークを`unbond`することや、他のステークを再デリゲートすることは可能です。

:::caution 本当の制限はクールダウンではなく件数です
デリゲーターが同一の(デリゲーター、移動元バリデーター、移動先バリデーター)の組み合わせに対して同時に保持できる進行中の再デリゲーションエントリは、最大**7件**までです — 各エントリは満了すると個別にクリアされ、枠が解放されます。これは通常の利用ではまず到達しない上限であり、一般的な「再デリゲートするには待つ必要がある」というルールではありません。
:::

## アンボンディング

バリデーターからデリゲートしたトークンを引き出します。アンボンディングの完了には**21日間**かかり、その間トークンは報酬を得ることも、送金することもできません。

```bash
qorechaind tx staking unbond <validator_address> <amount>uqor \
  --from mykey \
  --chain-id qorechain-diana \
  --gas 400000 --fees 40000uqor
```

**例:**

```bash
qorechaind tx staking unbond qorvaloper1abc...xyz 25000000uqor \
  --from mykey \
  --chain-id qorechain-diana \
  --gas 400000 --fees 40000uqor
```

21日間(1,814,400秒)のアンボンディング期間が終了すると、トークンは自動的にアカウントへ返還されます。デリゲーターが1つのバリデーターに対して同時に保持できるアンボンディングエントリは、最大7件です。

## 報酬の請求

デリゲートしたすべてのバリデーターから、蓄積されたステーキング報酬を引き出します。

```bash
qorechaind tx distribution withdraw-all-rewards \
  --from mykey \
  --chain-id qorechain-diana \
  --gas 400000 --fees 40000uqor
```

特定のバリデーターからのみ報酬を引き出す場合:

```bash
qorechaind tx distribution withdraw-rewards <validator_address> \
  --from mykey \
  --chain-id qorechain-diana \
  --gas 400000 --fees 40000uqor
```

ステーキング報酬は2つの財源から拠出されます。プロトコルの上限付き発行予算(エポックあたりの現在の額と上限については[Tokenomics](/architecture/tokenomics#staking-reward-schedule)を参照。どちらもガバナンスによって設定され、直近では2026年10月19日の提案10によるものです)と、すべての取引手数料に対するステーカー取り分です(v3.2.0アップグレード以降は通常のステーキング報酬として支払われます。[滞留していたステーカー取り分](/architecture/tokenomics#stranded-and-reserve)を参照)。報酬はバリデーターのコミッションとネットワークの稼働状況に左右され、保証されるものではありません。

## 時間ロック型ステーキング(v3.2.4) {#time-locked-staking}

:::note 適用される時期
リリースv3.2.4は、任意の時間ロック型ステーキングモジュール`x/stakingtier`を追加します。**`qorechain-diana`テストネット**では2026年10月19日から稼働しており、**メインネットではブロック高3,742,566から**の予定です(ガバナンス提案13。メインネットはそのブロックまでv3.2.3を実行します)。メインネットがアップグレードされるまで、メインネットのデリゲーションにロックインはありません([上記](#lock-in-period)を参照)。アップグレード後は、ロックはオプションとして利用可能になり、通常のデリゲーションはロックなしのままです。以下の仕組みは、稼働中のテストネットのパラメーターに照らして確認しています。
:::

デリゲーターは既存のデリゲーションの一部を、3、6、または12か月の固定期間でバリデーターにコミットできます。期間と金額はチェーンパラメーターです。現在の値は、このページではなく`GET /qorechain/stakingtier/v1/params`から読み取ってください。

* **ロックは任意です。** 通常のデリゲーション、再デリゲーション、アンボンディングは、このページで説明したとおりに動作します。制限されるのはロックした金額のみです。ロックが開いている間は、アンデリゲートも再デリゲートもできません。これはあらゆる経路(トランザクション、authz、グループ、コントラクト、ガバナンス)で成り立ちます。
* **最低ロック額**は10 QORで、デリゲーターあたり最大16件のロックを開けます。
* **早期解除**は可能です。ロックを終了し、未払いのロック報酬を失い、ロックした金額からペナルティをバーンします(テストネットのパラメーターでは5%で、`staking_tier_penalty`というバーンソースに記録されます)。残りはデリゲートされたまま、ロックが解除されます。
* **スラッシング**は、ロックされたデリゲーションにも他と同様に適用されます。ロックはデリゲーションとともに縮小します。
* **請求。** ロックは、モジュールパラメーターで定められたエポックごとの追加報酬分を獲得します。これは自動では支払われず、請求した時点で支払われます。このページでは料率を記載していません。現在の設定は`params`から読み取ってください。
* **満了時**にロックは解除され、デリゲーションは通常のものとして続きます。

コマンドは、コマンドラインと、REST ルート`GET /qorechain/stakingtier/v1/params`、`/locks/{holder}`、`/pool`から利用できます。金額は`uqor`の整数です(1 QOR = 1,000,000 uqor)。

```bash
qorechaind tx stakingtier lock <validator_address> <amount_in_uqor> <months> --from mykey \
  --chain-id qorechain-diana --gas 400000 --fees 40000uqor --generate-only > tx.json
qorechaind tx stakingtier unlock-early <lock_id> --from mykey --chain-id qorechain-diana \
  --gas 400000 --fees 40000uqor --generate-only > tx.json
qorechaind tx stakingtier claim --from mykey --chain-id qorechain-diana \
  --gas 400000 --fees 40000uqor --generate-only > tx.json
qorechaind query stakingtier locks <holder_address>
```

上記のチェーンIDはテストネットのものです。メインネットがv3.2.4アップグレードを適用した後は、メインネットでは`qorechain-vladi`を使用してください。このページの他の部分と同様に、生成された各トランザクションには`tx pqc cosign`で署名してください。

## Triple-Pool分類(設計上の状況)

QoreChainの設計には、バリデーターをその評判とデリゲーション量に基づいて3つのプールに分類し、プールごとにブロック報酬の加重配分を行う**Triple-Pool**モデルが含まれています。

| プール                                 | 参加条件                                              | 報酬ウェイト(設計上) |
| ------------------------------------ | ----------------------------------------------------------- | ------------- |
| **RPoS**(Reputation Proof of Stake) | 評判スコアが上位30%(70パーセンタイル以上)**かつ**ステーク量が中央値以上 | 40%           |
| **DPoS**(Delegated Proof of Stake)  | 総デリゲーション量が10,000 QOR以上                              | 35%           |
| **PoS**(Proof of Stake)             | それ以外のすべてのバリデーター                                    | 25%           |

:::note ライブネットワークでは無効です
プール分類、プール加重によるプロポーザー選出、プールごとの報酬ウェイトは`x/qca`モジュールに実装されており、そのパラメーターもオンチェーンにあります(`qorechaind query qca config`)が、**ブロック生成や報酬分配にはまだ組み込まれていません**。現在のブロック提案はステーク量に基づく標準的な方式でローテーションし、報酬はボンディングされたステーク量に比例して、各バリデーターのコミッションを差し引いた上で分配されます。バリデーターがどのプールに「所属」しているかは、受け取る報酬に影響しません。
:::

## ボンディングカーブ報酬 {#bonding-curve}

QoreChainの設計では、ボンディングカーブによる報酬の計算式も定義されています。

```
R = beta * S * (1 + alpha * log(1 + L)) * Q(r) * P(t)
```

| 変数 | 説明                                                          |
| -------- | -------------------------------------------------------------------- |
| `R`      | その期間の報酬額                                         |
| `beta`   | 基本報酬率(プロトコルパラメーター)                                |
| `S`      | ステーク量                                                        |
| `alpha`  | ロイヤルティ係数(プロトコルパラメーター)                             |
| `L`      | ステーキング期間(エポック数)                                              |
| `Q(r)`   | バリデーターの評判スコア`r`から導出される品質係数 |
| `P(t)`   | 時点`t`におけるプール係数(プールに応じて40%、35%、25%のいずれか)     |

:::note ライブネットワークでは無効です
上記のプール分類と同様に、ボンディングカーブの計算は**稼働中のチェーンから呼び出されていません**。報酬はこの計算式では計算されておらず、ステーキング期間もバリデーターの評判も、現時点では報酬に影響しません。パラメーター(`bonding_alpha`、`bonding_beta`)はオンチェーンに存在しますが、効果はありません。
:::

## スラッシングとジェイリング

QoreChainのスラッシングは、標準のCosmos SDKスラッシングモジュールに従い、次の稼働中のパラメーターが使われます(`qorechaind query slashing params`)。

| イベント                | ルール                                                                 | 結果                                  |
| -------------------- | -------------------------------------------------------------------- | -------------------------------------------- |
| ダウンタイム             | 直近10,000ブロックのうち署名したのが5%未満(メインネットの約3.2秒のブロックで約8.9時間) | 600秒間ジェイル。ステークの1%がスラッシュ |
| 二重署名       | 同じ高さで2つの異なるブロックに署名                      | ステークの5%がスラッシュ                          |

スラッシングはバリデーターのボンディング済みステーク総額に適用されるため、デリゲーターはその比例分を負担します。スラッシュされたバリデーターからすでにアンボンディング中のステークにも及ぶことがあり、そのためアンボンディング期間は単なる待機時間ではなくセキュリティ対策となっています。

## バリデーター情報の照会

任意のバリデーターの詳細を調べます。

```bash
qorechaind query staking validator <validator_operator_address>
```

**例:**

```bash
qorechaind query staking validator qorvaloper1abc...xyz
```

アクティブなバリデーターを一覧表示します。

```bash
qorechaind query staking validators --status BOND_STATUS_BONDED
```

現在のデリゲーション状況を照会します。

```bash
qorechaind query staking delegations <delegator_address>
```

---

:::tip

* デリゲートする前に、バリデーターのコミッション、稼働率、実績を確認してください。バリデーターのプールや評判は、現時点では受け取る報酬に影響しません。
* 再デリゲートは、ペナルティもロックもなく即座に有効になります。制限は、まったく同じ経路での同時再デリゲーション件数を7件までとする上限と、再デリゲートしたばかりのステークは満期になるまで移動先のバリデーターからさらに移動できないというルールです。
* 21日間のアンボンディング期間はセキュリティ対策です。この間もスラッシング事象がトークンに影響を及ぼす可能性があります。

:::
