# ロールアップのデプロイ

このガイドは、Rollup Development Kit（RDK）を使って、QoreChain 上で決済されるアプリケーション特化型ロールアップを立ち上げるための簡単な概要です。ステップごとのコマンドは **[ロールアップのデプロイ](/rollups/deploying-a-rollup)** にあります。このページでは、開始前に必要なものを説明します。

:::caution 初期段階の機能
どちらのネットワークでも、まだロールアップは作成されていません（2026 年 10 月 27 日に確認）。メインネット（**`qorechain-vladi`**、EVM チェーン ID **9801**）は、2026 年 10 月 23 日からチェーンバージョン **v3.2.4** で稼働しています。テストネット（**`qorechain-diana`**、EVM チェーン ID **9800**）は v3.2.6 で稼働しており（2026 年 10 月 27 日から）、そのデフォルトのチャレンジウィンドウは 7 日ではなく 1 時間です。まずテストネットで検証してください。チャレンジウィンドウの挙動については [Rollup Development Kit](/architecture/rollup-development-kit#optimistic-settlement) で説明しています。
:::

---

## ここでのロールアップとは {#what-a-rollup-is-here}

QoreChain のロールアップは、**オフチェーンで実行**し、**決済**に QoreChain を使うアプリケーション特化型チェーンです。ロールアップをオンチェーンに登録し、ステートルートのバッチを投稿し、（任意で）データ blob と出金コミットメントを投稿します。オンチェーンの記録には、プロファイル、決済モード、シーケンサーモード、データ可用性バックエンド、ガスモデル、VM ラベルが含まれます。ホストチェーンがロールアップのトランザクションを実行することはありません。

---

## プリセットプロファイル {#preset-profiles}

RDKには、一般的なアプリケーションカテゴリごとに調整された5種類のプリセットプロファイルが用意されています。

| プロファイル        | 決済(証明)  | シーケンサー | DA              | ガスモデル    | VM       | 想定ユースケース |
| -------------- | ------------------- | --------- | --------------- | ------------ | -------- | ----------------- |
| **defi**       | zk(SNARK)          | dedicated | native          | EIP-1559     | EVM      | DeFi/AMMアプリケーション(レンディング、DEX、デリバティブ) |
| **gaming**     | based               | based     | native          | flat         | custom   | 高スループットなゲーム状態管理とリアルタイム体験 |
| **nft**        | optimistic(fraud)  | dedicated | native(Celestia DA計画中) | standard | QoreChain Native | NFTミンティングおよびマーケットプレイス用途 |
| **enterprise** | based               | based     | native          | subsidized   | EVM      | 手数料をスポンサーする許可制・コンソーシアム型デプロイメント |
| **custom**     | デフォルト: optimistic(fraud) | dedicated | native | standard | EVM | 開始時のデフォルト。メッセージが許す範囲で調整してください |

詳細と成熟度に関する注記（例えば、ZK 決済、したがって `defi` プロファイルはどちらのネットワークでもまだ使用できないことや、`based` シーケンシングは現時点では作成者が提出することを意味することなど）については、[プリセットプロファイル](/rollups/preset-profiles)を参照してください。

## 要件 {#requirements}

| 要件 | 詳細 |
| ----------- | ------- |
| **ロールアップのステーク** | 最低 10,000 QOR（`min_stake_for_rollup`、10,000,000,000 uqor）。現在の値は `qorechaind query rdk config` で確認してください |
| **作成時のバーン** | 提供したステーク額の 1 % が作成時にバーンされます。残りはロールアップごとの台帳にエスクローされます。ロールアップを停止すると、その中に残っている分が返還されます（そこから支払われた出金や不正証明の報酬は返還額を減らします） |
| **ロールアップ ID** | 3〜64 文字：小文字の英字、数字、`.`、`_`、`-` で、英字または数字で始まります。これに違反する ID は、手数料を支払った後に拒否されるため、事前に確認してください（TypeScript の RDK 0.6.0 は、ブロードキャストの前にこれを確認します） |
| **レイヤー登録ステーク** | ロールアップを作成すると、multilayer モジュールにレイヤーも登録され、作成者からさらに 1,000 QOR がロックされます（ロールアップの停止時に返還されます）。その残高がないとレイヤーは作成されず、ロールアップをアンカーできません |
| **アカウント** | ポスト量子鍵が登録された、資金のあるアカウント（ネイティブレーンのすべてのトランザクションはハイブリッド署名されます） |

## ヒント {#tips}

* プリセットプロファイルから始めましょう。プリセットは決済モード、シーケンサー、データ可用性バックエンド、VM を設定します。`create-rollup` が受け取るのは、ID、プロファイル、ステーク、および任意の `--vm` だけです。
* 1 % の作成時バーンは、提供したステーク額に適用されます。
* 作成者のポスト量子署名を一緒に送らない限り、バッチはアンカーなしで決済されます（`tx rdk submit-batch` の `--anchor-signature`、v3.2.2 以降で利用可能）。[ステートアンカリング](/architecture/rollup-development-kit#state-anchoring)を参照してください。
* L1 への出金（`tx rdk execute-withdrawal`）はロールアップのエスクロー台帳から支払われ、v3.2.3 以降メインネットで動作します。出金ルートを持つファイナライズ済みバッチが必要で、`uqor` のみを使用します。
* 現時点では、ロールアップの作成者がバッチの提出者です（どのプリセットもシーケンサーアドレスを設定しません）。そのため作成者の鍵を安全に保管してください。ロールアップの一時停止、再開、停止ができるのは作成者だけです。
* RDK は 5 つの言語で公開されています（npm、PyPI、crates.io、Go モジュールプロキシでバージョン 0.6.2、Maven Central では 0.6.2 が公開されるまで 0.6.1、2026 年 10 月 27 日に確認）が、ハイブリッドトランザクションに署名するのは TypeScript クライアントだけで、しかもポスト量子キーペアを渡した場合に限られます。`qorollup` CLI と Python、Go、Rust、Java のクライアントはクラシカル署名のみで署名しますが、これは両ネットワークで拒否されます。[RDK の変更点と制限事項](/rollups/deploying-a-rollup#rdk-050-limits)を参照してください。
* `suggest-profile` ヘルパーは、現在、公開エンドポイントでは固定の `defi` フォールバックを返します。そのため、プロファイル表から選んでください。
