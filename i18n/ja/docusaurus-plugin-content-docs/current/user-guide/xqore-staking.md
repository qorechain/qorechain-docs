# xQORE ステーキング

このページでは、**設計上の** xQORE ガバナンスステーキングの仕組みを説明します。QOR 保有者がトークンをロックして強化されたガバナンス権限を得るもので、長期参加者に報いる PvP リベースモデルを採用しています。**xQORE は現在どちらのネットワークでも使用できません**。このページに書かれていることは、まだ実行できるものではありません。

:::warning まだ利用できません
xQORE はジェネシスで有効化されていますが、メインネット（`qorechain-vladi`、ノードリリース **v3.2.1**）およびテストネット（`qorechain-diana`）では**まだ使用できません**。ノードには、そのためのトランザクション、クエリ、CLI、RPC のエントリポイントがないため、`tx xqore lock` / `unlock` も、`query xqore ...` も、xQORE の REST ルートも、`qor_getXQOREPosition` メソッドもありません。QOR をロックすることはできず、xQORE を保有している人もいません。将来のチェーンリリースで提供される予定で、そのリリースでは、保有者の数にかかわらずアンロックのコストが低く保たれるよう、退出ペナルティの再分配方法も変更されます。リリースされた時点で、ここにそのリリースを記載します。
:::

---

## 概要

設計上、QOR をロックすると **1:1 の比率**で xQORE がミントされ、xQORE は QDRW の投票権計算式で**2 倍の重み**として数えられます。

```
VP = sqrt(staked + 2 * xQORE) * ReputationMultiplier(r)
```

QDRW 自体は稼働中のネットワークでは無効化されており、ガバナンス投票はボンドされたステークのみで集計されます（[ガバナンス](/user-guide/governance#voting-power)を参照）。そのため、xQORE が提供されたとしても、将来のリリースで QDRW が有効化されるまでは投票権は変わりません。

---

## 設計上の退出ペナルティスケジュール

ジェネシス設定では、QOR がロックされていた期間が長いほど低くなる退出ペナルティが定義されています。

| ロック期間      | 退出ペナルティ |
| ------------------ | ------------ |
| 30 日未満  | **50%**      |
| 30〜90 日      | **35%**      |
| 90〜180 日     | **15%**      |
| 180 日超 | **0%**       |

設計上、ペナルティは**バーンされません**（`penalty_burn_rate` は `0`）。ペナルティの全額が、残っている xQORE 保有者に比例配分されて再分配されます（「PvP リベース」）。再分配の仕組みは、xQORE を組み込むリリースで変更される部分です。

---

## 利用できないもの

* **ロックとアンロック。** QOR をロックまたはアンロックするための `tx xqore` コマンドもトランザクションタイプもありません。
* **ポジション。** どのインターフェース（CLI、REST、JSON-RPC）にも xQORE ポジションのクエリはなく、`total_locked` と `total_xqore` はどちらもゼロです。
* **投票ボーナス。** 現在、xQORE の投票ボーナスはありません。

今すぐガバナンスに参加したい場合は、バリデーターに QOR をデリゲートし（[ステーキングとデリゲーション](/user-guide/staking-and-delegation)を参照）、提案に投票してください（[ガバナンス](/user-guide/governance)を参照）。
