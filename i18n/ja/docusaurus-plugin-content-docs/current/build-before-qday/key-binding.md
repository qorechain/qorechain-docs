# 耐量子鍵がアカウントに結び付けられる仕組み

このセクションのどのチュートリアルでも、通常のアカウント鍵に加えて**耐量子鍵**を使います。このページでは、その鍵がどこから来るのか、チェーンがその鍵をあなたのアカウントのものだとどうやって知るのか、そしてそれを自分で確かめる方法を、やさしい言葉で説明します。読むだけなら、何も実行する必要はありません。[自分で確かめる](#check)の確認は、約5分で終わります。

## 1枚の図でわかる考え方 {#picture}

```text
リカバリーフレーズ（またはリカバリーコード）
        |
        v
2つの鍵を導出
  - 従来型の鍵 (secp256k1)
  - 耐量子の鍵 (ML-DSA-87)、アカウントアドレスに紐付く
        |
        v
所有証明を付けて、1回だけ登録
        |
        v
すべてのトランザクションをハイブリッド署名（両方の鍵）
        |
        v
バリデーターが両方の署名を検証
```

## このページで使う言葉 {#words}

| 言葉 | 意味 |
| --- | --- |
| 従来型の鍵 | 通常のアカウント鍵 (secp256k1)。この種類のどのブロックチェーンでも、すべてのトランザクションに署名します。 |
| ML-DSA-87 鍵 | 耐量子の署名鍵。将来の量子コンピューターでも破られないと見込まれています。 |
| リカバリーフレーズ（ニーモニック） | アカウントを復元する12語または24語。 |
| リカバリーコード | `QRC1` で始まる1行の文字列。アカウントが生の秘密鍵から作られている場合に、耐量子鍵のリカバリーフレーズの代わりになります。 |
| 登録 | どの ML-DSA-87 鍵があなたのアカウントのものかをチェーンに伝える、1回のトランザクション。 |
| 所有証明 | 登録する鍵の秘密の半分を本当に持っていることを示す署名。 |
| ハイブリッド署名 | 1つのトランザクションに付く2つの署名。 |

## 1. 生成ではなく導出する {#derive}

耐量子鍵はランダムに選ばれて、なくしかねないファイルに保存されるわけではありません。**導出**されます。同じ入力からは、いつも同じ鍵ができます。

- **リカバリーフレーズがある場合。** ML-DSA-87 鍵は、従来型の鍵と**同じリカバリーフレーズ**とアカウントアドレスから作られます。従来型の鍵も耐量子鍵も、フレーズから作り直せるので、**1つのバックアップで両方を復元できます**。QoreX と SDK の統合アカウントはこの方法です。
- **生の秘密鍵の場合。** 秘密鍵だけでは2つ目の鍵を作れません。そこで耐量子鍵は、`QRC1` で始まる別の**リカバリーコード**から作られます。Workshop 1 のプロジェクトでは `pnpm window recovery-code` で作成します。SDK では `generatePqcRecoveryCode()` です。

リカバリーコードの3つのルール:

1. 秘密鍵とは**別の場所**に保管します。同じ場所に置くと、1回盗まれただけで両方を失います。
2. 同じアカウントには、いつも**同じ**コードを使います。
3. **違うコードからは違う鍵**ができます。そうなると、チェーンは登録した鍵と一致しない鍵を見ることになります。

:::caution リカバリーコードは作り直せません
なくしたリカバリーコードを取り戻す方法はありません。作成したときに紙に書き留めてください。使い捨てのテストネットアカウントは例外です。新しいアカウントは1分で作れます。
:::

## 2. 所有証明を付けて1回だけバインドする {#bind}

バインドとは、アカウントごとに1回だけ送る、`MsgRegisterPQCKeyV2` という1つのトランザクションです。次の内容が含まれます。

- ML-DSA-87 の**公開鍵**（2,592 バイト）
- **所有証明**: 鍵が、チェーンとあなたのアカウントを名指しした短いテキストに署名します。持っていない鍵をバインドすることはできず、別のチェーンからバインドをコピーすることもできません。

これは、チェーンが**従来型の署名だけ**で受け付ける唯一のメッセージです。理由は単純で、この前の時点では、チェーンにはあなたのアカウントの耐量子鍵の記録がなく、2つ目の署名を照合する相手がないからです。

方法:

| 場所 | 方法 |
| --- | --- |
| QoreX | 最初の送金時に自動で行われます。1回限りの手数料は約 0.09 QOR です。 |
| Workshop 1 とサンプルアプリ | `pnpm window register`（[Workshop 1 ガイド](/build-before-qday/workshop-1#step-5)のステップ5）。 |
| 自分のコード | SDK の `ensurePqcRegistered`。 |

`ensurePqcRegistered` は、もう一度呼んでも安全です。まずアカウントを読み取り、あなたの鍵がすでにバインドされていれば、何も送りません。**別の**鍵がバインドされていれば、`PqcKeyMismatchError` で止まり、何も送りません。2回目の登録を手作業で送ると、チェーンは拒否し、**それでも手数料は取られます**。確認はヘルパーに任せてください。

:::note 現在のチェーンの要件
チェーンは所有証明が付いていれば必ず検証し、検証に通らなければ登録を拒否します。SDK と QoreX は自動で証明を付けます。メインネットでは、証明のない登録もまだ受け付けられます。テストネットでは、リリース v3.2.8 から、新しいアカウントの最初のトランザクションがこの登録でなければなりません。詳細: [耐量子署名](/developer-guide/post-quantum-signing#proof-of-possession)。
:::

## 3. バインドのあとは、すべてハイブリッド {#hybrid}

それ以降、ネイティブのトランザクションはすべて2つの署名を持ちます。

- 従来型の secp256k1 署名（64 バイト）
- `PQCHybridSignature` という拡張に入った ML-DSA-87 署名（4,627 バイト）

バリデーターは**両方**を検証します。検証が通ると、チェーンはステータス `verified` のイベント `pqc_hybrid_verify` を記録します。

登録された鍵がないと、トランザクションは `account has no PQC key and classical fallback is disabled` で拒否されます。

EVM レーンのトランザクション（たとえばコントラクトのデプロイ）には、もう1つ必要なものがあります。ハイブリッド署名されたメッセージで開く、EVM 認可ウィンドウです。[EVM ウィンドウリファレンス](/developer-guide/evm-window-reference)を参照してください。

## 自分で確かめる {#check}

`curl` が必要です。`jq` は任意です。どちらも[始める前に](/build-before-qday/prerequisites#curl-jq)で説明しています。

### 自分の鍵は登録されている？ {#check-account}

1. `qor1...` を自分のアドレスに置き換えて、実行します。

```bash
curl -s https://api-testnet.qore.host/qorechain/pqc/v1/account/qor1...
```

このコマンドの働き: 公開テストネットサーバーに、あなたのアカウントの鍵の記録を問い合わせます。

パラメーター:

- `curl`: Web アドレスの内容を取得するプログラム。
- `-s`: サイレントモード。進捗バーを隠し、返答だけを表示します。
- `https://api-testnet.qore.host/qorechain/pqc/v1/account/qor1...`: テストネットの REST アドレスに、あなたのアカウントを続けたもの。

**期待される結果:** 登録済みのアカウントでは、次のような返答になります（プレースホルダーで示しています。実際には本物の値が入ります）。

```json
{
  "found": true,
  "account": {
    "address": "qor1...",
    "public_key": "<base64 ML-DSA-87 public key>",
    "algorithm_id": 1,
    "algorithm_name": "dilithium5",
    "ecdsa_pubkey": "<your classical public key>",
    "key_type": "hybrid",
    "created_at_height": "<block height>",
    "migration_public_key": null,
    "migration_algorithm_id": 0,
    "classical_key_source": "auth_account",
    "possession_proven": true
  }
}
```

`found` は、鍵がバインドされていれば `true`、されていなければ `false` です。`possession_proven` は、鍵が検証済みの所有証明つきで登録されていれば `true` です。

### 自分のトランザクションはハイブリッド署名されている？ {#check-tx}

Workshop 1 のステップ6と同じ確認です。

1. `<HASH>` を自分のトランザクションのハッシュに置き換えて（`<` と `>` は付けません）、実行します。

```bash
curl -s https://api-testnet.qore.host/cosmos/tx/v1beta1/txs/<HASH>
```

このコマンドの働き: 公開テストネットサーバーに、あなたのトランザクションの完全な記録を問い合わせます。

**期待される結果:** 長いテキストのかたまりです。次の3つを探します。

1. `tx_response` の中の `"code": 0`。コード 0 は成功を意味します。
2. ML-DSA-87 署名を持つ `PQCHybridSignature` 拡張。64 バイトの secp256k1 署名の隣に、**4,627 バイト**あります。
3. `events` の中の、属性 `status` が `verified` になっている `pqc_hybrid_verify` タイプのイベント。

2. そのイベントだけを表示するには（`jq` が必要です）:

```bash
curl -s https://api-testnet.qore.host/cosmos/tx/v1beta1/txs/<HASH> | jq '.tx_response.events[] | select(.type=="pqc_hybrid_verify")'
```

このコマンドの働き: 同じ記録を取得して `jq` に渡し、検証イベントだけを残します。

**期待される結果:** `status` 属性が `verified` のイベントが1つ表示されます。

## 関連する鍵と変更 {#related}

- **暗号化鍵。** [QoreSeal](/developer-tools/qoreseal) がアカウント宛てにデータを暗号化するために使う ML-KEM-1024 鍵は、**別のレジストリ**にあります。`MsgRegisterKEMKey` で、ハイブリッド署名されたトランザクションの中で公開します。そのため、アカウントはすでに ML-DSA-87 鍵を持っている必要があります。
- **署名鍵の変更。** `MsgRotatePQCKey` は、たとえば漏えいした鍵を退役させるために、ML-DSA-87 鍵を同じ種類の新しい鍵に入れ替えます。`MsgMigratePQCKey` はアルゴリズム間の移行を行います。どちらも古い鍵と新しい鍵の両方の署名が必要で、アカウントが以前に使った鍵はチェーンに拒否されます。どちらもメインネットとテストネットで稼働中です。詳しい規則: [耐量子署名](/developer-guide/post-quantum-signing)。

## トラブルシューティング {#troubleshooting}

| 表示されるもの | 理由 | 対処 |
| --- | --- | --- |
| `account has no PQC key and classical fallback is disabled` | アカウントがまだ ML-DSA-87 鍵を登録していません。 | 先に登録し（`pnpm window register`、QoreX の最初の送金、または `ensurePqcRegistered`）、もう一度送信します。上のアカウント照会で確認できます。 |
| `PqcKeyMismatchError`、または `pnpm window status` の `registered, but NOT this key` | 別の鍵がすでにバインドされています。最初のときとは違うリカバリーコードまたはフレーズを使いました。 | 元のリカバリーコードまたはフレーズに戻します。使い捨てのアカウントなら、新しいアカウントでやり直します。 |
| すでに登録済みとして登録が拒否される | アカウントがすでに鍵を持っています。手作業の2回目の登録は、それでも手数料が取られます。 | 何もしません。上の照会でアカウントを読み取るか、先に確認してくれる `ensurePqcRegistered` を使います。 |
| リカバリーコードをなくした | 秘密鍵からは作り直せません。 | アカウントがリカバリーフレーズから作られているなら、同じフレーズを使います。同じ鍵ができます。そうでなければ新しいアカウントを使います。テストネットなら費用はかかりません。 |
| 手数料または残高のメッセージで登録に失敗する | アカウントの QOR が手数料（約 0.09 QOR）に足りないか、手数料がガス1単位あたり 0.1 uqor というネットワークの下限を下回っています。 | [フォーセット](https://dashboard.qorechain.io/faucet)から QOR を入手し、手作業の登録ではガスを約 600,000 に設定して、もう一度試します。 |
| 登録したのに `found` が `false` | 問い合わせ先のネットワークかアドレスが違います。 | テストネットには `api-testnet.qore.host`、アドレスには自分の `qor1...` を使っているか確認します。ウォレットが、プロジェクトとは別のネットワークを表示していることもあります。 |
| アカウントは `found: true` を返すが、トランザクションが失敗する | チェーン上の鍵が、プロジェクトが導出する鍵と違います。 | `pnpm window status` を実行し、`.env` のリカバリーコードと比べます。 |
