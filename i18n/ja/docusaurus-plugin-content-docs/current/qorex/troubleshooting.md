# トラブルシューティング

QoreX アプリと拡張機能に関するよくある質問と簡単な対処法です。

| 症状 | 原因 / 対処法 |
|---|---|
| オンボーディング時に **「まずデバイスを保護してください」** と表示される | システム設定で Face ID / 指紋認証 **または画面ロック（PIN / パターン）** を設定してから戻ってください。ウォレットは、強力なロック解除要素を備えたデバイスでのみ作成できます。Android では、2D の顔認証だけでは *弱い* 生体認証です。その背後にある PIN が条件を満たすものです。 |
| **サインインシートが閉じた** / 「そのサインイン試行は期限切れです」 | 前回の試行が中断されました。もう一度サインインをタップしてください。 |
| Google / ダッシュボードでのサインイン後に **「パスキーを追加」が表示されない** | 想定どおりです。パスキーはメールコードアカウントにのみ紐付きます（[アカウントとダッシュボード](/qorex/account-and-dashboard#sign-in) の注記を参照）。 |
| **「ハンドルは近日公開」** | @handle レジストリに一時的に接続できません。ウォレットには影響しません。復旧すると自動的にハンドルが有効になります。 |
| **拡張機能: @handle への支払いが、検索に関するエラーで失敗する** | 拡張機能 **0.3.7** 以降で修正されました（現在はすべてのストアが 0.4.5 を提供しています）。お使いの拡張機能が古い場合は、ブラウザの拡張機能ページから更新してください。更新するまでは、代わりに `qor1…` アドレスを貼り付けるか、モバイルアプリを使用してください。 |
| **拡張機能には @handle を取得する方法がない** | 想定どおりです。取得にはサインイン済みのアカウントが必要で、モバイルアプリ内で行います。取得後は、拡張機能から支払いと解決ができます。 |
| **取得しようとしたハンドルが予約済みとして拒否される** | QoreChain を模倣する名前（そのブランド名、または *official*、*support*、*airdrop*、*treasury* といった信頼を連想させる語。紛らわしい綴りを含む）は予約されています。別のハンドルを選んでください。 |
| **承認画面に、QoreX がリクエストを表示できない、または曖昧なものとして拒否すると表示される** | QoreX は、デコードできないリクエストや、バイト列が二通りに読めるリクエスト（たとえば、手数料や金額が画面上とチェーン上で異なって読めるようにフィールドが繰り返されているもの）は表示しません。回避策を探さないでください - そのサイトは安全でない、またはサポートされていないものを送信しています。 |
| **QoreX がハンドルのアドレスが変わったと警告する** | これはバグではなく想定どおりのセキュリティ動作です - QoreX は、あるハンドルに初めて送金した際に解決されたアドレスを記憶しており、後で変わった場合はそれを黙って信用せずに警告します。続行する前に、受取人と別の手段で新しいアドレスを確認してください。 |
| ベスティングアカウントで **「利用可能残高を超えています」として送金が拒否される** | 残高の一部がベスティングスケジュールによってまだロックされています。送金できるのは **利用可能** 部分（ホーム、送金、資産詳細に表示）のみで、残りは段階的にアンロックされます。 |
| **ウォレットリクエストに「テストネット/メインネット向けですが、あなたのウォレットは…」と表示される** | そのリクエスト（例：ダッシュボードからのもの）は、現在接続しているネットワークとは異なるネットワークを対象としています。意図したものであれば、まず自分でネットワークを切り替えてください - QoreX が自動で切り替えることはありません。 |
| デバイスのリンク中に **「コードが間違っているか QR が破損しています」** | 10 文字のコードを再確認し（アルファベットは紛らわしい文字を除いています。0/O/1/I/L はありません）、再スキャンしてください。どちらの成果物も 1 回限りです。 |
| **カメラ画面に権限が必要と表示される** | iOS: 設定 → QoreX → カメラ。Android: アプリ情報 → 権限 → カメラ。 |
| **拡張機能: 初回起動時にウォレットがない** | 拡張機能は **スタンドアロン** のウォレットです - ポップアップを開いて **ウォレットを作成** または **ウォレットをインポート** を選択してください。モバイルアプリは不要です。 |
| **読み取り専用アドレスからの送金が拒否される** | そのアドレスは別のウォレットに属しています（ラベルにどのウォレットかが表示されます）。QoreX は自身の派生アカウントについてのみ署名できます - それを所有するウォレットから送金してください。 |
| **テストネットバッジが表示される** | テストネットを使用しています。アプリでは設定 → **「テストネットを使う（開発者向け）」** をオフにします。拡張機能では、ポップアップのホーム下部の開発者セクションで **メインネットに戻る** を選びます。 |
| **スワップボタンが無効になっている** | 現時点では想定どおりです（Android） - プールの流動性が利用可能になると、スワップは自動的に有効になります。アプリの更新は不要です。iOS ではスワップタブは表示されず、拡張機能にはスワップ画面がありません。 |
| **アプリをアンインストールした / 拡張機能を削除したらウォレットが見当たらない** | ボールトはそのデバイスまたはそのブラウザにのみ存在していました。24 単語のフレーズをバックアップしていた場合は、それを使って復元してください。[ソーシャルリカバリー](/qorex/security-and-recovery#social-recovery) を設定していた場合は、ガーディアンとともに復旧を開始してください。どちらも行っていなかった場合、そのウォレットは復旧できません - 新しいウォレットを作成したらすぐに保護するために、[今すぐバックアップ](/qorex/security-and-recovery#back-up-now) を参照してください。 |
| **24 単語が見つからない / アプリが一度も表示しなかった** | モバイルアプリは、ウォレットの作成中にフレーズを表示しません。**設定 → セキュリティ → リカバリーフレーズを表示** を開き、生体認証またはデバイスの PIN で確認してから、単語を書き留めてください。拡張機能では、ポップアップの **リカバリーフレーズを表示** を使用します（パスワードが必要です）。ウォレットがすでに紛失した端末にしかない場合、QoreChain は復旧できません - [今すぐバックアップ](/qorex/security-and-recovery#back-up-now) を参照してください。 |
| **入金済みのアカウントが「あなたのアカウント」から消えた** | 何も失われていません - すべてのアカウントはリカバリーフレーズから再導出されるため、これはデータ損失ではなく表示上の問題です。これは **1.0.9** 以前のモバイルビルドに存在した実際の不具合で、現在は修正済みです。デバイスのセキュアストレージからの読み取りが（おそらくアンロック直後に）瞬間的に失敗し、アカウント一覧が短く表示されることがありました。QoreX を更新してください（修正は 1.0.9 以降のすべてのバージョンに含まれています）。すでに最新版でこの現象が発生した場合は、アプリを閉じて再度開くと表示が戻るはずです - 「アカウントを追加」をタップすると、欠けているアカウントが復元されるのではなく **新しい** アカウントが作成されるため、既存のアカウントが再び表示されるまではタップしないでください。 |
| **「The EVM lane needs an open authorisation window for this account. Open one here first - MetaMask cannot.」**（または「Your EVM authorisation window has run out」、あるいは「That authorisation window was refused」） | アカウントに開いているウィンドウがない（またはブロック数、トランザクション数、金額を使い切った）ため、MetaMask / EVM レーンのトランザクションが拒否されました。[EVM アクセスウィンドウ](/qorex/security-and-recovery#evm-window)（Ethereum 形式の coin-60 アカウント向けです）でウィンドウを開いてから、再試行してください。送信する *前* に開いてください - ウィンドウを開くとアカウントのナンスが進むため、それ以前に準備したトランザクションは「nonce too low」で失敗します。アカウントにまだ ML-DSA-87 鍵がない場合、QoreX は先に登録するよう案内します。 |
| **「This network needs an updated QoreX. Update the app and try again - nothing was sent.」** | ネットワークは、お使いのビルドが生成するものより新しい署名形式を検証します。ストアから QoreX を更新して再試行してください。何も送信されておらず、手数料も取られていません。 |
| **「Too many transactions from this account in a short time. Wait a minute and try again.」** | ネットワークは、1 つのアカウントが短時間に送信できるトランザクション数を制限しています。1 分待ってください。 |
| **「That address can't receive ordinary transfers.」** | ネットワークは、そのアドレス（一部のシステムまたはモジュールアドレス）への通常の送金を拒否します。受取人を確認してください。 |
| **「Not enough unlocked QOR to pay the network fee. Vesting QOR cannot pay fees…」** または **「Claiming needs about … QOR unlocked」** | 請求とアンステークの手数料は、（報酬が届く前の）*アンロック済み* 残高から支払われます。そのアドレスに少量の QOR を送ってから、再試行してください。 |
| **「The network ran out of gas before finishing. The fee was taken and nothing moved - your rewards are still there.」** | トランザクションはブロックに到達し、そこで失敗しました。再試行してください。失敗した試行の手数料は消費されています。 |
| **「Unstaking this much would drop your validator's self-bond below the required 100,000 QOR.」** | バリデーター運営者のみが該当します。セルフボンドの下限は、バリデーターが稼働している間は適用されます。アンステークする量を減らしてください。 |
| ダッシュボードまたは MetaMask から復元したアカウントから送金すると **「Account 'qor1…' does not exist on chain」** と表示される | QoreX を最新バージョンに更新してください。このアカウントは Ethereum 形式（coin 60）のアカウントです - [MetaMask またはダッシュボードからフレーズを復元する](/qorex/getting-started#restore-dashboard) を参照してください。最初の送金では、そのアカウントの ML-DSA-87 鍵も登録されます（少額の追加手数料がかかります）。 |
| **フレーズを復元したら 2 つ目のアカウント / 資金が見当たらない** | 復元で戻るのは **アカウント 1** のみです。設定 → あなたのアカウントで **アカウントを追加**（MetaMask やダッシュボードで使っていたフレーズの場合は **Ethereum アカウントを追加（coin 60）**）をタップしてください - アカウントは同じアドレスで再導出されます。 |
| **拡張機能: 「ウォレット」にパスキーがオフになったと表示される** | ウォレットを追加または削除すると、ボールトが再封印され、パスキーによるロック解除が解除されます（新しいウォレットをカバーできないためです）。ポップアップのホーム画面から再度オンにしてください。Firefox ではパスキーによるロック解除は提供されません。 |
| **プッシュ通知が届かなかった** | プッシュはメインネット専用で、端末の設定で QoreX の通知が許可されていることと、**プッシュ通知** のスイッチがオン（ホーム → ベルのアイコン）になっていることが必要です。通知は QOR が届いたことだけを知らせ、金額は表示しません。詳細はアプリの **通知** 一覧で確認できます。 |
| **Android: 戻るボタン** | 戻るボタンは前の画面に戻ります。ホームでは、アプリが終了します。 |
| **拡張機能がロックされている間に、サイトが署名を求めてきた** | 0.4.5 以降、拡張機能はパスワード画面を開き、サイト名を表示します。パスワードを入力すると、そのウィンドウは閉じ、リクエストの承認画面が表示されます。代わりにウィンドウを閉じるとリクエストは拒否され、何も署名されません。サイトがまだ「wallet is locked」と応答する場合は、拡張機能を更新してください。 |
| **拡張機能: ロック解除ボタンが反応しない、またはエラーが表示される** | Enter キーか **ロック解除** でロック解除が始まり、ボタンは処理中であることを示します。これは設計上少し時間がかかります。**パスワードが違います。** はパスワードが間違っている場合にのみ表示されます。それ以外のメッセージは別の失敗を示すので、内容を読んでください。[ロック解除と自動ロック](/qorex/browser-extension#unlock)を参照してください。 |
| **QoreX が何度もロックされる** | 自動ロックです（デフォルト 15 分）。拡張機能のポップアップのホーム、またはアプリの設定 → セキュリティで **自動ロックまでの時間** を変更してください（1、5、15、30、60、240 分）。 |
| **「This account's post-quantum key on the network can no longer sign」**（または、登録されている鍵ではもう署名できないというメッセージ） | ネットワーク上の鍵レコードが空、従来方式のみ、またはその他の理由で使用できないため、このアカウントは送金できません。何も送信されず、手数料も取られていません。アプリ 1.2.5 / 拡張機能 0.4.5 では、古いメッセージが今後のアップデートに言及していても、ホーム画面に **鍵を登録し直す** が表示されます。ネットワーク手数料が表示され、2 回目のタップが必要です（アプリでは生体認証も必要）。自動で行われることはありません。アカウントに EVM ウィンドウがある場合、ネットワークがそれを閉じるので、後で新しく開いてください。[ポスト量子鍵の管理](/qorex/browser-extension#pqc-care)を参照してください。 |
| **「This account's ML-DSA-87 key on the network was registered by another wallet」** | QoreX は、あなたのリカバリーフレーズから導出できない鍵では署名できません。その鍵を登録したウォレットを使用してください。 |
| **ポスト量子鍵をローテーションした後、同じフレーズを使う別のウォレットが署名できない** | 想定どおりです。同じフレーズを使う他のウォレットは、ローテーション後の鍵に対応するまで、このアカウントの署名ができません。QoreX でフレーズを復元すると正しい鍵が見つかります。ローテーションはポスト量子鍵の漏えいに対する保護であり、リカバリーフレーズの漏えいは防げません。 |
| **EVM ウィンドウが開いているのに、サイトのコントラクト呼び出しが拒否される** | 自分で開くウィンドウはデフォルトで **QOR の送金のみ** で、コントラクト呼び出しは許可されません。開くときに **任意のコントラクト** を選ぶ（警告を読んでください。コントラクトが動かすトークンは上限の対象外です）か、そのウィンドウを閉じて、サイトの承認でその 1 件の取引用のウィンドウを開かせてください。開いているウィンドウの説明文には、何が許可されるかが示されます。[EVM アクセスウィンドウ](/qorex/security-and-recovery#evm-window)を参照してください。 |
| **ウィンドウを開く前に QoreX が 2 回目の確認をする**（「The network did not accept a window limited to …」または「This network cannot limit the window to QOR transfers yet」） | ネットワークがその制限を適用できません。承認すると **任意のコントラクト** を許可するウィンドウが開きます。拒否すると何も開かず、何も送信されません。 |
| **「What it does to your tokens was not checked」** | ノードは呼び出しが失敗しないかを確認できるだけで、何を動かすかは確認できません。サイトを信頼できる場合にのみ承認してください（2 回目のタップが必要です）。 |
| **サイトのトランザクションが承認前に拒否される** | QoreX は先にコントラクト呼び出しをシミュレーションします。コントラクトが呼び出しを拒否する場合は、承認画面の代わりにネットワークが示す理由が表示されます。ネットワークの 1 トランザクションあたりのガス上限を超えるトランザクションも、何も署名される前に拒否されます。 |
| **サイトが EVM ウィンドウを閉じたり権限を変更したりできない** | 想定どおりです。これらのリクエストは QoreX 自体の画面からのみ受け付けます。**EVM アクセスウィンドウ** 画面でウィンドウを閉じてください。 |
| **支払いリンクが拒否される** | QoreX は理由を示します。有効な支払いリンクではない、**署名後に変更された**、**受取アドレスの所有者が署名したものではない**（この 2 つの場合は支払わないでください）、QoreX が知らないネットワーク向け、もう一方のネットワーク向け（それが意図どおりなら自分で切り替えてください）、または QOR 以外のコインを請求している、のいずれかです。請求者に新しいリンクを依頼してください。 |
| **支払いリクエストがまだ「未払い」と表示される** | リクエストが支払い済みになるのは、リクエストのタグをメモに含み、あなたのアドレス宛てに少なくともその金額の支払いが成功したことがチェーン上で確認された場合のみです。タグなしの支払い（メモを削除するウォレットからの送金など）は照合されません。取引が確定した後に **状態を確認** をもう一度タップしてください。「Status unknown」はネットワークが応答しなかったことを意味します。 |
| **アプリでページを開くはずのリンクが拒否される** | browse リンクが開けるのは、ドメイン名の `https://` ページで、ポート、ユーザー名やパスワード、IP アドレス、`localhost` を含まず、2,048 文字以内のものだけです。スマートフォンにウォレットがない場合、アプリはオンボーディングのままです。 |
| **ネットワークが遅い、または接続できないというバナーが表示される** | **遅い**: チェーンの最新ブロックが 1 分以上前のもので、取引に通常より時間がかかる可能性があります。**ネットワークに接続できない**: 残高が古い可能性があります。QoreX はこれをチェーン自体から読み取ります。インターネット接続を確認して待ってください。[履歴](/qorex/browser-extension#history)（アプリでは**履歴**）を確認するまで、支払いを再送しないでください。 |
| **残高に「最後に確認できた値」と表示される** | ネットワークが応答しなかったため、QoreX は最後に読み取った値と、その時刻を表示します。ネットワークが応答すると更新されます。 |
| **取引に「Pending」または「Not found on the network」と表示される** | Pending: この端末から送信され、チェーンの履歴にまだ表示されていません。Not found: 失敗した可能性があります。再送する前に取引を確認してください。 |
| **アドレスが知っているものに似ているだけだという警告** | 詐欺師はそっくりなアドレスを仕込みます。表示される保存済みや過去に支払ったアドレスと、1 文字ずつ比較してください。新しいアドレスが本当に意図したものである場合のみ続行してください。 |
| **開発者ツールが見つからない** | 開発者モードはデフォルトでオフです。アプリ: 設定の **開発者モード** スイッチをオンにすると、下部バーに **開発者** タブが表示されます。拡張機能: ポップアップ下部のバージョン番号を 7 回タップしてから **開発者ツール** を開きます。[開発者モード](/qorex/developer-mode)を参照してください。 |
| **AI エージェントが利用できない、または補助プログラムが「not reachable」になる** | 拡張機能では、エージェントはまだ公開されていないコンパニオンプログラム経由で接続します。この機能は Safari では利用できません。アプリでは、提案を貼り付けるか提案リンクを開いてください。 |
| **「別のチェーンへ送る」、Bridge 画面、QoreChain 上の Solana が見つからない** | これらは **テストネット専用** です（QoreChain 上の Solana は開発者モードにもあります）。Bridge 画面には各ルートの実際の状態が表示されます。現在テストネットではすべてのルートが閉じているため、何も提供されません。[テストネット機能](/qorex/testnet-features)を参照してください。 |

## それでも解決しない場合
