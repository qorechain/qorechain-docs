# セキュリティと復元

このページでは、QoreX がどのように鍵を保護し、どのようにウォレットを取り戻すのかを説明します。1 画面の保護チェック、ML-DSA-87 鍵とその管理、マルチシグアカウント、ソーシャルリカバリー、Legacy、デバイス連携、EVM アクセスウィンドウ、承認画面に表示される内容、自動ロック、Q-Day スキャナー、ヘルプの入手先を扱います。すべての QoreX ユーザー向けですが、復元ツールの多くはモバイルアプリにあります。ブラウザ拡張機能や Safari 拡張機能で違いがある場合は、本文に記載します。

## 革新点 {#innovations}

- **資産の保護状況。** バックアップ、接続済みサイト、チェーン上で付与した権限、トークンの承認をその場で確認し、取り消せる 1 画面です。[資産の保護状況](#protection)を参照してください。
- **ポスト量子鍵の管理。** リカバリーフレーズから ML-DSA-87 鍵をローテーションし、署名できなくなったレコードを修復し、ポスト量子マルチシグを運用できます。[鍵のローテーション](#pqc-rotation)、[修復](#pqc-repair)、[マルチシグアカウント](#multisig)を参照してください。
- **暗号化されたシェアとリカバリーキットによるソーシャルリカバリー。** ガーディアンは、ML-KEM で封印された、3 つのうち 2 つで復元できるシェアを保持し、ウォレットを復元するにはあなたのリカバリーキットも必要です。復元には 48 時間のタイムロックがあり、あなたに通知が届きます。キャンセルでき、キャンセルは遅らせることしかできず、資金を動かすことはありません。
- **Legacy。** ガーディアンの上に置かれるデッドマンスイッチで、あなたが選んだ受益者のためのものです。
- **デバイス連携。** ワンタイムコードと QR を、同じ画面に表示することは決してありません。QR 単体は、メモリハードな鍵導出の背後にある暗号文です。
- **決定論的な ML-DSA-87 鍵。** リカバリーフレーズから導出されるため（最初の鍵は `SHAKE256("qorechain:pqc:v1|" + address + "|" + mnemonic)` で、ローテーション後の鍵も同じフレーズから導出されます）、鍵に別途バックアップは不要です。[QoreSign](/qoresign/overview) を参照してください。
- **範囲を限定した EVM アクセス。** EVM トランザクションは、アクセスウィンドウが開いている間のみ受け付けられ、トランザクション数、金額、有効期限で制限されます。また、自分で開くウィンドウは、別の指定をしない限り QOR の送金のみを許可します。
- **読めないものは拒否する承認。** [承認ウィンドウに表示される内容](#approvals)を参照してください。
- **Q-Day スキャナー。** 任意の Bitcoin または Ethereum アドレスの露出レポート。

## 使い方と場所 {#how-to-use}

以下のほとんどは、モバイルアプリの **設定 → セキュリティ**にあります。**資産の保護状況**と**サポート**は**設定**にあります。ブラウザ拡張機能と Safari 拡張機能では、ポップアップのホーム画面に EVM アクセスウィンドウ、接続済みサイト、リカバリーフレーズを表示、ML-DSA-87鍵をローテーション、マルチシグアカウント、資産の保護状況、サポートのボタンと、自動ロックの設定があります。ソーシャルリカバリー、Legacy、デバイス連携、Q-Day スキャナーはモバイル専用です。QoreX は無料で、これらのいずれにもアカウントは不要です。ストアへのリンクは[概要](/qorex/overview#how-to-access)を参照してください。

ホームタブには**バックアップの健全性**カードも表示され、ソーシャルリカバリーを設定するまで警告が続きます。このカードが追跡するのはソーシャルリカバリーだけです。リカバリーフレーズを書き留めたかどうかは判断できないため、ご自身で行ってください (下記を参照)。

## 資産の保護状況 {#protection}

「自分の資産は安全か、誰が自分に代わって操作できるのか」に答える 1 画面です。アプリ: **設定 → 資産の保護状況**。拡張機能と Safari: ポップアップのホーム画面の**資産の保護状況**。各項目は開いたときに、この端末とネットワーク上で確認され、何も推測しません。読み取れない場合、QoreX は *「現在読み取れません。権限がないという意味ではありません。」* と表示します。

| 項目 | 確認する内容 | できること |
|---|---|---|
| **バックアップ確認済み**と**復元テスト済み** | リカバリーフレーズを保持していることを証明したかどうかと、その日時 | **復元フレーズをテストする**: フレーズの 3 つの単語を入力します。これは予行演習で、単語はこの端末上で照合され、入力内容は保存も送信もされず、何も復元・変更されません。単語が間違っていれば何も記録されません |
| **ガーディアン (ソーシャルリカバリー)** | ガーディアンが設定されているか、人数、必要な人数 | [ソーシャルリカバリー](#social-recovery)で設定します |
| **権限を持つアプリ** | あなたのアドレスを確認でき、署名を求められるサイト（アプリではアプリ内 dApp ブラウザのサイト、拡張機能では接続済みサイト） | どのサイトも**取り消す**ことができます |
| **ネットワーク上で付与した権限** | あなたのアカウントが他者に付与した継続中の **authz grant** と **fee grant** をチェーンから読み取り、無制限のものを先頭に、終了日とともに表示 | **取り消す**: QoreX はネットワーク手数料を含む確認画面を表示してから、ハイブリッド署名で取り消しに署名します |
| **ERC-20 トークンの承認** | **QoreChain の EVM** であなたのトークンを動かせる spender | **取り消す**: `approve(spender, 0)` を送信します |

**トークンの承認について。** アプリでは**トークンの承認を確認**をタップします。読み取りにはこのウォレットの Ethereum アドレスを使うため、一度だけフレーズが必要です。ノードが受け付ける範囲ごとに読み取るので、画面に *「トークンの承認はブロック \{from\} まで確認しました。それより古いものがある可能性があります。確認を続けるには、この画面をもう一度開いてください。」* と表示される場合があります。取り消しの際、QoreX はまず、ポスト量子鍵で署名され、そのトークンコントラクトに限定された**1 トランザクション分の EVM ウィンドウ**を開き、次に従来型の鍵で署名した EVM トランザクションを送信します。QoreChain の EVM で送信できるのは Ethereum 形式（coin 60）のアカウントのみのため、coin-118 アカウントはここで EVM の承認を取り消せず、QoreX はその旨を表示します。

**レーン別のポスト量子保護。** この画面は、どの署名が何を保護するかをわかりやすく説明します。

- **QoreChain (ネイティブ):** すべてのトランザクションにポスト量子（ML-DSA-87）と従来型の 2 つの署名があり、ネットワークは両方を検証します。
- **QoreChain EVM:** EVM トランザクションは、どの EVM ウォレットとも同じく従来型で署名されます。ネットワークは、ポスト量子署名で開いた[ウィンドウ](#evm-window)の中で、選んだ上限の範囲内でのみ受け付けます。
- **ほかのネットワーク (Ethereum、Solana、Cosmos):** 受け付けるのは従来型の署名のみです。そこでは QoreX はポスト量子保護を追加できません。

## 今すぐバックアップを取る - 失われたウォレットを代わりに復元できる人はいません {#back-up-now}

:::danger 資金を入れる前に必ずお読みください
QoreX は**ノンカストディアル**です。つまり、あなたの鍵はあなた自身のデバイス上にのみ存在し、QoreChain Association はそのコピーも、マスターキーも、ウォレットをリセットや復元する手段も一切持っていません。**「パスワードを忘れた」フローも、サポートチケットも、カスタマーサービスによる救済もありません** - バックアップなしで鍵へのアクセスを失った場合、資金は永久に、取り消し不能な形で失われます。これはあらゆるノンカストディアルウォレットに共通する事実であり、QoreX 特有の制約ではありませんが、はっきり述べておく価値があります。

**次のうち少なくとも 1 つを、ウォレット作成直後に - 後回しにせず - 行ってください。**

1. **24 語のリカバリーフレーズを書き留め**、オフラインで耐久性のある場所に保管してください (スクリーンショットや、クラウドに同期されるメモ、自分宛てのメッセージは不可)。これは、どのデバイスでも、いつでもウォレットを復元できる唯一の手段です - モバイルでは **設定 → セキュリティ → リカバリーフレーズを表示**から表示してください (ウォレットの作成中、アプリはフレーズを表示**しません**。そのためご自身で取りに行く必要があります - すぐに行ってください)。拡張機能では、ウォレット作成時に一度だけ表示され、その後はポップアップの**リカバリーフレーズを表示**からいつでも確認できます。[既存のウォレットを復元](/qorex/getting-started#2-restore-an-existing-wallet) を参照してください。
2. 信頼できるガーディアンと<strong>[ソーシャルリカバリー](#social-recovery)</strong>を設定してください。これにより、フレーズを失ってもウォレットを復元できるようになり、しかも単独のガーディアンがあなたの資金に一人でアクセスすることは決してできません。

両方を行うのが最も安全な選択です - フレーズはデバイスを乗り換えたときやアプリが利用できないときのために、ガーディアンはフレーズ自体を失ったときのために備えます。

**アプリをアンインストールすると、そのデバイスから鍵が削除されます。** モバイルアプリの保管領域とブラウザ拡張機能の保管領域は、それぞれそれを作成したデバイス上にのみ存在します。アプリのアンインストール、スマートフォンの初期化、または拡張機能の削除・クリアを行うと、そのコピーは削除されます - バックアップも連携済みデバイスもない場合、QoreChain を含め誰もあなたのウォレットを復元することはできません。**スマートフォンやブラウザからウォレットを削除する**場合 (設定 → ウォレット → *このスマートフォンから削除*、または拡張機能の *このブラウザから削除*) も、同様にそのウォレットの鍵がデバイスから削除されます - 資金はチェーン上に残りますが、元に戻せるのはそのリカバリーフレーズだけです。
:::

## ML-DSA-87 鍵 {#pqc-key}

**セキュリティ**画面には、ML-DSA-87 鍵のオンチェーン上の現在の状態がリアルタイムで表示されます:**「初回送金時に登録」** → **「オンチェーンに登録済み ✓」**。アルゴリズムは **ML-DSA-87** (secp256k1 とのハイブリッド、決定論的) です。

ウェブサイトから QoreX に対して、ML-DSA-87 鍵の登録・移行・ローテーションを要求することはできません。登録は最初の送金時に自動的に行われ、あなたが何かをする必要はありません - v3.2.3 以降、チェーンは登録時にオプションの*所有証明*も受け付けますが、現在のストアビルドでは QoreX が目に見えない形で処理します。自分で[鍵をローテーション](#pqc-rotation)したり、署名できなくなったレコードを[修復](#pqc-repair)したりすることもできます。基盤となる仕組みについては [鍵のローテーション](/developer-guide/post-quantum-signing#key-rotation) を参照してください。

### 署名できなくなった鍵を修復する {#pqc-repair}

まれに、ネットワークが保持しているあなたのアカウントの鍵レコードが**空、従来方式のみ、または退化した状態**で、そのアカウントから何も送信できないことがあります。QoreX は 2 つのケースを区別します。**別のウォレット**が登録した鍵はそのように報告し、**署名できなくなった**レコードの場合は、**ホーム**画面（アプリ）またはポップアップのホーム画面（拡張機能と Safari）に修復カードを表示します。

1. カードを読みます: *「このアカウントのネットワーク上のML-DSA-87鍵は署名できなくなっているため、このアカウントからは何も送信できません。鍵を登録し直すと解決します。」* ネットワーク手数料 **0.09 QOR** が表示され、アカウントに EVM ウィンドウがある場合はネットワークがそれを閉じること（後で新しく開いてください）も示されます。
2. **鍵を登録し直す**をタップします。
3. もう一度タップします（*もう一度タップして登録 (手数料 0.09 QOR)*）。アプリでは生体認証で確認します。

修復が**自動で行われることはありません**。常に 2 回のタップが必要です。送信するのは鍵の登録のみで、従来型の鍵で署名します。完了後、QoreX は *「鍵を登録し直しました。このアカウントから再び送信できます。」* と表示します。

### ポスト量子鍵のローテーション {#pqc-rotation}

**ML-DSA-87鍵をローテーション**は、ネットワーク上のアカウントの ML-DSA-87 鍵を、**リカバリーフレーズから導出される次の鍵**に置き換えます。アプリ: **設定 → セキュリティ → ML-DSA-87鍵をローテーション**。拡張機能と Safari: ポップアップのホーム画面の **ML-DSA-87鍵をローテーション**ボタン。タップしてから、もう一度タップして確定します（*もう一度タップして鍵をローテーション*）。アプリでは生体認証も求められます。トランザクションは現在の鍵と新しい鍵の両方で署名され、シミュレーションから算出したネットワーク手数料が結果に表示されます。

- **防げるもの:** ポスト量子鍵の漏えい。
- **防げないもの:** リカバリーフレーズの漏えい。フレーズを持つ人は、これらの鍵をすべて導出できます。その場合は、新しいフレーズの新しいウォレットに資金を移してください。
- **同じフレーズを使う他のウォレット**は、ローテーション後の鍵に対応するまで、このアカウントの署名ができません。
- **ネットワークはアカウントの EVM ウィンドウを閉じます。** 必要なら新しく開いてください。
- **復元は引き続き可能です。** QoreX は、フレーズから導出できる鍵の中からネットワークが保持するものを探すため、復元したウォレットはローテーション後の鍵で署名します。

ローテーションが自動で行われることはなく、Web サイトがそれを要求することもできません。

## マルチシグアカウント {#multisig}

**マルチシグアカウント**は、署名に複数のメンバーが必要です。QoreX は、メインネットとテストネットでポスト量子マルチシグに対応し、**QoreChain のコマンドラインと同じファイル**を使うため、各メンバーは QoreX でもコマンドラインツールでも署名できます。アプリ: **設定 → セキュリティ → マルチシグアカウント**。拡張機能と Safari: ポップアップのホーム画面の**マルチシグアカウント**。

**作成または追加**

1. **マルチシグを作成:** メンバーのアドレス（`qor1...`）を 1 行に 1 つずつ、必要な署名数（しきい値）、任意の名前を入力し、**保存**します。各メンバーは少なくとも 1 回のトランザクションを送信している必要があります。
2. または**既存のマルチシグを追加:** マルチシグ鍵（コマンドラインの `keys show <name> -p` の出力、または QoreX から共有された鍵）を貼り付けます。**マルチシグ鍵を共有**で他のメンバーに送れます。

**状態を確認する。** アカウント画面には、残高、**ポスト量子メンバーセット**が登録されているか（とそのバージョン）、使用中のアカウントがメンバーかどうか、そして各メンバーの鍵が準備完了、未登録、署名不能、証明なしで登録、確認不能のいずれかが表示されます。メンバーセットが登録されるまで、アカウントは送金できません。

**2 ラウンドで署名する**

1. **登録を準備**（最初に 1 回）または**送金を準備**。QoreX はシミュレーションからガスを算出し、ファイルを作成します。拡張機能と Safari ではファイルが**ダウンロード**され、アプリでは**テキストとして共有**されます。それを他のメンバーに送ります。
2. **ラウンド 1。** 各ポスト量子メンバーはファイルを開き（**メンバーからのファイルを開く**）、内容を確認して **ML-DSA-87メンバーとして署名**を選びます。アプリでは受け取ったテキストを**貼り付け**、拡張機能ではファイルを開きます。
3. メンバーの署名を**結合**します。
4. **ラウンド 2。** 従来型で署名するメンバーを選び（ちょうどしきい値の人数で、全員が同じ選択をします）、各自が内容を確認して**従来方式で署名**を選びます。もう一度結合します。
5. **ネットワークに送信。**

各署名の手順では、まず署名する内容が表示され、**2 回のタップ**が必要です。アプリでは生体認証も求められます。トランザクションが<strong>認証子（authenticator）</strong>を登録する場合、QoreX は警告します。認証子は、他のメンバーの署名なしにマルチシグの資金を動かせます。その他の種類のトランザクションをファイルからオフラインで署名するには、[開発者モード](/qorex/developer-mode)のオフラインおよびマルチシグ作業スペースを参照してください。

## ソーシャルリカバリー {#social-recovery}

ソーシャルリカバリーでは、信頼できる**ガーディアン**があなたのリカバリーフレーズを一切見ることなく、ウォレットの復元を手伝うことができます。

- あなたのシードは**暗号化されたシェア** (ML-KEM で封印) に分割されます。デフォルトでは 3 つに分割され、そのうち任意の **2 つ**が揃えば復元を手伝えます (2-of-3 のしきい値方式)。1 つだけでは復元できません。
- 各ガーディアンは資格情報を受け取ります。
- **リカバリーキット。** シードの暗号化コピーが**リカバリーキット**（`qorexkit1:` で始まります）で、あなた自身が保管します。ガーディアンだけではウォレットを復元できず、このキットも必要です。キットだけでもガーディアンなしでは役に立ちません。新しいセットアップでは、リカバリーサービスに送るのはガーディアンの数としきい値だけです。[リカバリーキット](#recovery-kit)を参照してください。
- 復元にはガーディアンのしきい値人数による承認が必要で、その後 **48 時間のタイムロック**が実行され、あなた宛てに**キャンセル通知**が送られます。これにより、悪意ある試みを止めることができます。

**設定方法:** ホーム → **リカバリーを設定** (または 設定 → セキュリティ → ソーシャルリカバリー) → **ガーディアン資格情報を作成**。QoreX は 3 つの資格情報 - *ガーディアン 1*、*ガーディアン 2*、*印刷用バックアップ* - を作成し、**3 つのうち任意の 2 つ**で復元を手伝えます。信頼できる人またはデバイスにそれぞれ 1 つずつ渡し、印刷用バックアップは安全な場所に保管してください。その後、次の説明に従ってリカバリーキットを保存します。セットアップが完了すると、バックアップの健全性の警告は消えます。

### リカバリーキット {#recovery-kit}

セットアップの最後に、QoreX は**リカバリーキット**を表示します。**リカバリーキットをコピー**または**共有または保存**を使い、自分が管理できて、**このスマートフォン以外にもある**場所（パスワードマネージャー、メモ、印刷物）にコピーを保管してください。**完了**を使うには、*リカバリーキットをこの電話以外の場所に保存しました* にチェックを入れる必要があります。復元するときは、**リカバリー ID またはリカバリーキット**を貼り付けます。

以前のバージョンでソーシャルリカバリーを設定した場合、キットの暗号化コピーがまだリカバリーサービスに残っていると QoreX が知らせることがあります。キットを保存してから、**リレーからコピーを削除**を選んでください。ガーディアンの資格情報は引き続き機能します。削除後、キットを持つのはあなただけです。

**他人の復元を承認する:** 誰かのガーディアンになっている場合、ホームタブの**復元を手伝う**からその人の復元リクエストを承認できます。

## Legacy Protocol {#legacy}

**Legacy Protocol** は、ガーディアンの上に置かれるデッドマンスイッチです。あなたが連絡不能になった場合に、資産を選んだ受益者へ引き継ぐことができます。任意機能であり、設定 → セキュリティから設定します。

## 新しいデバイスを連携する {#link-device}

**サーバーも 24 語の入力も不要**で、ウォレットを 2 台目のスマートフォンやタブレットへ移行できます。

1. **新しいデバイス** → オンボーディング → **別のデバイスから連携**。ワンタイムの**10 文字コード**が表示され、カメラが起動します。
2. **旧デバイス** → 設定 → セキュリティ → **新しいデバイスを連携** → そのコードを入力 → 生体認証で確認します。**QR コード**が表示されます (コードから導出された鍵でシードを封印したもの: scrypt N=2¹⁷ → AES-256-GCM)。
3. **新しいデバイス**がその QR をスキャンすると、ローカルで復号され、同じウォレット・同じアドレスになります。

**QR の写真だけでは足りない理由:** コードと QR コードが同じ画面に同時に表示されることはありません。QR コードだけを撮影しても、その中身はメモリハードな鍵導出関数の背後にある暗号文にすぎず、両方の要素はワンタイムで、画面とともに消えます。コードを間違えた場合は明確なエラーが表示されるだけなので、再試行してください。

:::note
デバイス連携は**利便性のための機能**であり、復元手段ではありません。24 語のフレーズとソーシャルリカバリーこそが、あなたの本当の安全網です。
:::

## EVM アクセスウィンドウ {#evm-window}

チェーン **v3.2.0** 以降、**EVM レーン**上のトランザクション - たとえば QoreChain の EVM ネットワークに対して MetaMask で署名するもの - は、**登録済みの ML-DSA-87 鍵**を持ち、*かつ* **認可ウィンドウが開いている** (ハイブリッド署名された `MsgOpenEVMWindow`) アカウントからのみ受け付けられます。EVM トランザクション自体が持つ署名は secp256k1 のみです。エクスプローラーは、このようなトランザクションに「Authorised by a PQC window」というラベルを付けます。ウィンドウを開くのは QoreChain Native レーンのメッセージであり、MetaMask では作成できないため、QoreX で開きます。QoreX 自身の送金は Native レーンを使うため、ウィンドウは不要です。

**誰に必要か。** ウィンドウが必要なのは **Ethereum 形式 (coin 60) のアカウント**です - 最初に MetaMask で使われたフレーズに対して *Add an Ethereum account (coin 60)* で追加するアカウントです ([MetaMask または Dashboard からフレーズを復元する](/qorex/getting-started#restore-dashboard) を参照)。MetaMask は Ethereum の鍵で署名しますが、それは coin-60 アカウントの鍵です。MetaMask のどの鍵も通常の coin-118 の `qor1…` アカウントから送金することはできないため、そのようなアカウントで開いたウィンドウは何も達成せず、手数料がかかるだけです。

ウィンドウを使えないアカウントを選んでいる場合、画面には取るべき手順と、**アカウント**へのボタンが表示されます。

ウィンドウを開く方法は 2 つあります。**自分で開く**（以下）か、サイトが承認を求めたときに [QoreX が 1 件のトランザクション用に開く](#per-transaction-windows)かです。

アプリでは **設定 → セキュリティ → EVM アクセスウィンドウ**から、拡張機能ではポップアップの **EVM アクセスウィンドウ**ボタンから開きます。まず**ウィンドウが許可するもの**を選びます。

- **QOR の送金のみ**（デフォルト、推奨）: コントラクト呼び出し、新しいコントラクト、受取人がコントラクトの送金はできません。
- **任意のコントラクト:** 別の選択肢で、次の警告があります: *「任意のコントラクトを呼び出せます。上限は QOR のみを数えます。コントラクトが動かすトークン、NFT、承認はウィンドウで制限されません。」*

ネットワークがウィンドウを QOR の送金のみに制限できない場合、QoreX はその旨を伝え、代わりに任意のコントラクト向けに開くかを尋ねます。まさにその内容に同意するまで、何も開かれません。

次に、次の項目を選択します。

| 項目 | 意味 | 上限 |
|---|---|---|
| **期間 (ブロック数、最大 17280)** | ウィンドウが開いている期間 | 最大 17,280 ブロック (メインネットで約 15 時間) |
| **トランザクション数 (最大 1000)** | 受け付ける EVM トランザクションの数 | 最大 1,000 |
| **支出上限、QOR** | 流出を許可する QOR の最大額 | **このアカウントから出ていくすべての QOR と各最大手数料**を計上します。トークンは数えません |

この画面では特定のコントラクトを指定できません。特定のコントラクトに限定したウィンドウは、QoreX が 1 件のトランザクション用に開きます（以下）。デフォルトは 300 ブロック (メインネットで約 16 分)、5 トランザクション、1 QOR です。ウィンドウを開くには通常のネットワーク手数料がかかり、通常のハイブリッド署名 (secp256k1 と ML-DSA-87) で署名されます。新しいウィンドウは、すでに開いているウィンドウを**置き換えます**。また、ウィンドウを開くとアカウントのノンスも進むため、**先に**ウィンドウを開いてから MetaMask で送信してください - 事前に準備していたトランザクションは「nonce too low」で拒否されます。**ウィンドウを閉じる**は、ウィンドウが有効な間のみ表示されます。

**開いているウィンドウには、何が許可されるかが正確に表示されます:** *許可: QOR の送金のみ*、*許可: 任意のコントラクト（トークンは上限に数えられません）*、または *許可: \{targets\} のみ*。最後の場合、QoreX は、**一覧のコントラクトは引き続きアカウントの代わりに動くことができ**、保有するトークンや承認したトークンも動かせ、QOR の上限はそれを対象にしないことも表示します。

画面には次の 4 つの状態のいずれかが表示されます。*あと \{blocks\} ブロック · \{txs\} トランザクション · \{value\} QOR 残り で開いています*、*開いているウィンドウはありません。このアカウントからの MetaMask トランザクションは拒否されます。*、*そのウィンドウは期限切れか使い切られています*、または *QoreX はネットワークからウィンドウを読み取れませんでした* - これは QoreX が把握できていないという意味であり、ウィンドウがないという意味では**ありません**。アカウントにまだ ML-DSA-87 鍵がない場合は、先に登録してください (最初の QoreX 送金で登録されます)。それ以前にウィンドウを開いても役に立ちません。

:::caution 小さく、短くしてください
ウィンドウがあると、通常の MetaMask トランザクションが **secp256k1 署名のみで**あなたの QOR を動かせます。上限は低く保ち - 小さな支出上限、少ないトランザクション数、短い期間 - コントラクトが必要でなければ **QOR の送金のみ**を選び、終わったらウィンドウを閉じてください。上限は最大手数料を含め、アカウントから出ていくすべての QOR を対象とするため、上限を超えることになるトランザクションは拒否されます。トークンは対象外です。
:::

### 1 件のトランザクション用のウィンドウ {#per-transaction-windows}

サイトが QoreX に QoreChain 上の EVM トランザクションの送信を求め、それを許可する開いたウィンドウがない場合、承認によって**まさにそのトランザクション用の**ウィンドウが、あなたのハイブリッド ML-DSA-87 鍵で署名されて開かれます。

- トランザクション 1 件、金額**に最大手数料を加えた**額まで、約 10 分間。
- ネットワークが対応していれば、呼び出すコントラクトに限定されます。
- 承認画面は、ウィンドウが許可する**すべてのコントラクトを名前で示し**（最近 permit への署名を求めたコントラクトを含む）、**開いているウィンドウは置き換えられる**ことを示します。
- QOR の上限は、最大手数料を含め、アカウントから出ていくすべての QOR を対象とします。一覧のコントラクトは引き続きアカウントの代わりに動くことができます（保有または承認したトークンや、他のコントラクトが保持する QOR を動かせます）。
- ネットワークがコントラクトに限定したウィンドウを受け付けない場合、QoreX は、その制限なしで開く前に **2 回目の確認をします**。いいえと答えると、何も開かず、何も送信されません。

QoreChain 上のコントラクトが検証する型付きデータの署名（permit）でも、同様にそのコントラクトを列挙した短いウィンドウが開きます。取引履歴では、EVM トランザクションがウィンドウからどれだけ使ったかが表示されます。開発者向けの説明は [dApp 連携](/qorex/dapp-integration)を参照してください。コントラクトを呼び出すアプリで MetaMask などの EVM ウォレットを使う場合は、自分でウィンドウを開くときに**任意のコントラクト**を選んでください。QoreX 経由でトランザクションを送るアプリなら、事前にウィンドウを開く必要はありません。手動のウィンドウと同じく、これは Ethereum 形式（coin 60）のアカウントに適用されます。

(QoreX から*他の*ネットワーク上で ETH、BNB などの資産を送ることは別の話です - [外部ネットワークとトークン](/qorex/send-and-receive#external-networks-tokens) を参照してください。)

## 承認ウィンドウに表示される内容 {#approvals}

QoreX が生成するすべての署名は、あなた自身が承認するものであり、承認画面には署名しようとしている内容が正確に一覧表示されます。QoreX は次の内容を表示します。

- リクエスト内の**すべてのメッセージ**のタイトルとラベル付きフィールド (authz の **MsgExec** にネストされたメッセージや、権限付与の条件を含みます)。表示できないものは**拒否**されます (「QoreX はこのメッセージを読み取れません … このサイトを完全に信頼する場合のみ承認してください」)。
- **手数料** (*手数料: \{amount\} · ガス \{gas\}*)、その支払者、およびフィー付与。手数料が読み取れない場合、QoreX はその旨を表示し、承認しないよう伝えます。
- 支出許可と authz 付与の**上限、許可されたアクション、有効期限**。*無制限*と*無期限*は明示的に表記されます。有効期限は秒単位で表示され (`YYYY-MM-DD HH:MM:SS UTC`)。許可されたアクションをよく確認してください。許可メッセージに `MsgExec` を含む手数料許可（`AllowedMsgAllowance`）は、被付与者がそれを通じて実行できるあらゆるメッセージを対象とし、汎用の authz 付与は、指定されたメッセージタイプのすべてを対象とします。ガバナンスの投票はデコードされるため、何に投票しているのかが分かります。読み取れないもの、無制限のもの、終わりのないものは、承認ボタンを**もう一度タップ**する必要があります (*もう一度タップして承認*)。
- 複数のアカウントがある場合は、署名アカウント (*署名者: …*)。
- 非常に多数のメッセージを含むリクエストの場合は、最初の 50 件と残りの件数。

**EVM** のリクエストでは、QoreX はトランザクションや型付きデータ（送金、*UNLIMITED* と明記される承認、permit など）をデコードし、未知の呼び出しや型は高リスクとして 2 回目のタップを求めます。ネットワークが許す場合はシミュレーションします。QoreChain の EVM ノードは、データを伴う呼び出しが失敗しないことを確認できるだけなので、承認画面には *「What it does to your tokens was not checked. Approve only if you trust this site.」*（トークンへの影響は確認されていない）と表示され、2 回目のタップが必要です。失敗するトランザクションや、シミュレーションできないトランザクションも 2 回目のタップが必要です。コントラクトを呼び出すネイティブのリクエストは承認前にシミュレーションされ、コントラクトが拒否する呼び出しはチェーンが示す理由とともに拒否されます。承認画面にはメモが表示され、メッセージ全体を開くこともできます。

QoreX は、**2 通りに読めるバイト列を持つリクエストも拒否します** (1.1.7 / 0.3.7 以降)。1 回だけ現れるはずのフィールドを繰り返すリクエスト - たとえば手数料や金額が二重になっているもの - は、ある見え方で表示されながら別の内容で実行される可能性があるため、QoreX は承認のために表示すること自体を行いません。ウェブサイトについては、QoreX はリクエストが自己申告する内容ではなく、ブラウザ自身が証明するオリジンによってリクエスト元のサイトを識別します。

ウォレットやアカウントの切り替え、またはウォレットのロックは、待機中のリクエストに「拒否」を返します。1 つのサイトが待機させられるリクエストは 1 件で、全体では 3 件まで待機できます。ビルドによっては、承認ウィンドウ内のフィールド名が英語で表示されます。

### サイトが決して要求できないもの {#never-requested}

次の操作は **QoreX 自体の画面からのみ**利用できます。サイトが何と言おうと、QoreX はどの Web サイトからの要求も拒否します。

- ポスト量子鍵の管理（登録、移行、ローテーション）
- 認証子（リンクされた署名者）と支出ルール
- EVM アクセスウィンドウの開閉とクリア
- QoreChain 上の Solana のウィンドウおよびリレーのメッセージ
- 他者がさらに権限を**付与**したり、あなたのアカウントとしてメッセージを**実行**したりできる権限（authz）。そのような付与があると、受け手はあなたとして行動できます。QoreX は、直接の場合も、どの深さの `MsgExec` に包まれていても、汎用の grant としても拒否します。

## そっくりなアドレス {#look-alike}

詐欺師は、あなたが使うアドレスと先頭と末尾が同じアドレスから少額を送り、間違ったアドレスをコピーさせようとします。QoreX は、QoreChain と外部ネットワークで、受取人を知っているアドレス（保存した連絡先、自分のアカウント、過去に支払ったアドレス）と比較し、どれかに**似ているだけ**のアドレスを送金前に警告します。メモにリンクがあるスパムの可能性が高いものは、履歴でも非表示になります。[連絡先とお気に入り](/qorex/send-and-receive#contacts)と[履歴](/qorex/send-and-receive#history)を参照してください。

## 自動ロック {#auto-lock}

QoreX はしばらく使わないと自動的にロックします。**自動ロックまでの時間**で **1、5、15、30、60 分、または 4 時間**を選びます。デフォルトは **15 分**です。アプリ: 設定 → セキュリティ。この時間が経過すると、QoreX は何かを表示する前に再び生体認証を求めます。拡張機能と Safari: 設定はポップアップのホーム画面の**ロック**ボタンの隣にあります。この時間が経過すると、パスワードの再入力が必要です。

## リカバリーフレーズとアクセシビリティツール {#phrase-privacy}

リカバリーフレーズの画面は、表示のたびに新たな生体認証またはデバイスの PIN を求め、単語を番号付きの読み取り専用グリッドとして表示し、**コピーボタンはなく**、Android ではスクリーンショットがブロックされ、アプリスイッチャーからも隠されます。**Android 14 以降**では、本物のアクセシビリティツールではないアクセシビリティサービスに対しても、単語が提供されません (TalkBack などの本物のスクリーンリーダーは引き続き読み取れます)。それより古い Android と iOS では、デフォルトでスクリーンリーダーに対して単語が隠されます。スクリーンリーダーを利用している場合は、その画面の通知をタップして読み上げを許可してください。フレーズは、誰にも画面を見られない状況でのみ表示してください。

## 接続中の dApp {#connected-dapps}

dApp との接続は**オリジンごと**で、削除するまで維持されます。アプリでは**この端末にウォレットごとに**保存されます（サイトのアドレスのみ）。確認と取り消しは[資産の保護状況](#protection)で行います。ブラウザ拡張機能と Safari では、ポップアップの**接続済みサイト**を開くと、このウォレットが承認したすべてのサイトが表示され、そのいずれも**取り消す**ことができます。

## 連携済みサイナーと利用限度額 {#linked-signers}

外部の鍵 (Phantom または MetaMask) を、独自の利用限度額を持つ**連携済みサイナー**として連携する機能は、**QoreX 内ではまだ利用できません** - 設定 → セキュリティにカードは表示されますが、操作には *近日公開* と表示されています。ご自身で QoreX の外部で行わない限り、ウォレットには何も連携されていません。鍵管理そのものを連携済みの鍵に委任することは決してできません。オンチェーンのモデルについては [連携ウォレットオーセンティケーター](/developer-guide/account-abstraction#authenticators) を参照してください。

## Q-Day スキャナー {#q-day-scanner}

**Q-Day スキャナー**では、任意のアドレス - 自分のものでも他人のものでも - を入力して、任意の Bitcoin または Ethereum アドレスの露出レポートを取得できます。ホームタブのクイックボタンからアクセスできます。**Bitcoin** アドレスを調べるには、QoreX は第三者が運営するサービス blockstream.info に問い合わせる必要があり、そのサービスにはアドレスと IP アドレスが見えます。スキャナーはその名前を示し、あなたが同意した後にのみスキャンします。

同じ画面には、**サポートから依頼された場合にのみ**コピーする任意の**診断概要**があります。含まれるのはアプリのバージョン、ネットワーク、エラーコードで、フレーズ、鍵、アドレス、残高は含まれません。

## セキュリティモデルの概要

1. **ノンカストディアル** - 鍵はデバイス上で生成され、ハードウェアで保護された保管領域 (モバイル) または暗号化された保管領域 (拡張機能) 内にとどまり、外部に出ることはありません。
2. **同意なしには何も行われない** - すべての接続はオリジンごとに管理され、すべての署名は個別に承認され (モバイルでは生体認証)、ペイロードは署名前にデコードされます。QoreX が読み取れないものは拒否されるか、はっきりと表示されて 2 回目のタップの後ろに置かれます。
3. **ハイブリッド署名のネイティブレーン。** ネイティブレーンの QOR 送金はすべて、従来型の鍵と ML-DSA-87 (FIPS 204) の 2 つで署名されます。従来型のもの (外部ネットワーク、EVM) はラベル表示され、決して黙って行われることはありません。
4. **解析ツールも、クラッシュレポートも、トラッキング SDK もありません。** 鍵、リカバリーフレーズ、保管領域、承認がデバイスの外に出ることはありません。任意のサインイン、プッシュ通知、ソーシャルリカバリーは、オンにしたときにのみサーバーを使用します。QoreX が送信するものの完全な一覧は [QoreX がネットワーク経由で送信するもの](/qorex/overview#data-and-privacy) にあり、[QoreChain プライバシーポリシー](https://qorechain.io/privacy) の対象です。
5. **復元手段** - 24 語のフレーズ (常時)、ガーディアンによるソーシャルリカバリー + 48 時間のタイムロック (任意)、Legacy による相続 (任意)、デバイス連携 (利便性のため)。

## 制限と既知の問題 {#limits}

- ソーシャルリカバリー、Legacy、デバイス連携、Q-Day スキャナーはモバイル専用です。
- ポスト量子鍵のローテーションは、ポスト量子鍵の漏えいは防ぎますが、リカバリーフレーズの漏えいは防げません。同じフレーズの他のウォレットは、ローテーション後の鍵に対応するまで、そのアカウントの署名ができません。
- 利用限度額付きの連携済みサイナーは、QoreX 内ではまだ利用できません。
- 手動の EVM ウィンドウ画面で選べるのは「QOR の送金のみ」か「任意のコントラクト」だけです。ウィンドウの QOR 上限はトークンを制限しません。
- トークンの承認の確認は QoreChain の EVM のみで、取り消すには coin-60 アカウントが必要です。
- デバイス連携は利便性のための機能であり、復元手段ではありません。フレーズを書き留めておらず、ソーシャルリカバリーも設定していない状態で失われたウォレットは、誰にも復元できません。
- ビルドによっては、承認ウィンドウに一部のフィールド名が英語で表示されます。
