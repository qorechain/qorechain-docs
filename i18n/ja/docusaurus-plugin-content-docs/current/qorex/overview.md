# QoreX ウォレット

**QoreX** は、**QoreChain**（メインネット `qorechain-vladi`）の公式 **非カストディアル** ウォレットです。QOR の保有、送金、ステーキング、受け取り、@handle による支払い、同じリカバリーフレーズで他のネットワークの資産を保有すること、そしてウェブサイトがウォレットに求める署名を承認することを望むすべての方のためのものです。秘密鍵は **お使いの端末上でのみ** 生成・保管されます。QoreChain Association があなたの資産にアクセスすることは一切なく、各アプリには **解析ツールも、クラッシュレポートも、トラッキング SDK もありません**。鍵、リカバリーフレーズ、保管領域、承認が端末の外に出ることはありません（[QoreX がネットワーク経由で送信するもの](#data-and-privacy)を参照）。Native レーンのすべての QOR 送金は、従来型の鍵と ML-DSA-87（FIPS 204）の2つで署名されます。

QoreX は、連携して動作する4つのビルドで構成されています。

- **モバイルアプリ**（Android・iOS）: フル機能のウォレットです。リカバリー、ステーキング、ポートフォリオ、アプリ内 dApp ブラウザ、Q-Day Scanner を備えています。[はじめに](/qorex/getting-started)と [dApp ブラウザ](/qorex/dapp-browser)をご覧ください。
- **ブラウザ拡張機能**（Chrome および Chromium 系ブラウザ、Firefox）: 単体で完結するデスクトップウォレットであると同時に、あらゆるウェブサイトが QoreX を検出し、すべてのリクエストを明示的な承認に変えるためのコネクタでもあります。[ブラウザ拡張機能](/qorex/browser-extension)をご覧ください。
- **Safari 拡張機能**: 同じ拡張機能を、Mac App Store の macOS アプリ **QoreX Wallet** に収めたものです。
- **開発者キット**: QoreX と連携するアプリ向けの、公開 npm パッケージ6つです。[開発者向け](#developers)をご覧ください。

:::caution ウォレットを作成したらすぐにリカバリーフレーズをバックアップしてください
QoreX は非カストディアルです。QoreChain Association が、紛失したウォレットを復旧したり、リセットしたり、代わりに復元したりすることはできません。**アプリをアンインストールする、スマートフォンをリセットする、または拡張機能を削除すると、その端末からあなたの鍵が削除されます。** 24語のリカバリーフレーズを書き留めてください（モバイルアプリはウォレットの作成中にはフレーズを表示しません。**設定 → セキュリティ → リカバリーフレーズを表示** から表示できます。拡張機能は作成時に一度だけ表示します）。可能であれば、[ソーシャルリカバリー](/qorex/security-and-recovery#social-recovery)も設定してください。[今すぐバックアップ](/qorex/security-and-recovery#back-up-now)をご覧ください。
:::

## 革新的な点 {#innovations}

- **ハイブリッド署名の Native レーン。** Native レーンのすべての QOR 送金は、従来型の secp256k1 鍵と ML-DSA-87（FIPS 204）の2つで署名されます。チェーンは両方を検証します。外部ネットワーク上のものは従来型の署名のみで、QoreX は確認の前にその旨を表示します。
- **1つのリカバリーフレーズ、1つの ML-DSA-87 鍵、2つ目のバックアップは不要。** ML-DSA-87 鍵は、同じ24語から決定論的に導出されます: `SHAKE256("qorechain:pqc:v1|" + address + "|" + mnemonic)`。この導出方法は [QoreSign](/qoresign/overview) で公開されているため、互換性のあるどのウォレットでも同じ鍵を導出できます。
- **自動で登録され、その後に確認されます。** ML-DSA-87 鍵は、最初のトランザクションとともにオンチェーンに登録されます（チェーン v3.2.3 以降では所有証明付き）。ブロードキャストのたびに、コミットされたトランザクションに ML-DSA-87 レイヤーが含まれているかをウォレットが確認し、含まれていなければ警告します。
- **読み取れないものは拒否する承認。** すべてのメッセージ、手数料、支出上限、有効期限が、署名の前にデコードされます。QoreX がデコードできないリクエストや、バイト列が2通りに読めるリクエストは拒否されます。
- **dApp 向けの `signAndBroadcast`。** ウェブサイトがメッセージを送ると、ウォレットがそれをデコードして表示し、ウォレットだけが作れる ML-DSA-87 レイヤーを加えてブロードキャストします。ページがそのレイヤーを作ることはできません。
- **EVM アクセスウィンドウ。** チェーン v3.2.0 より後では、EVM トランザクションは、アカウントにウィンドウが開いている間だけ受け付けられます。これは、ハイブリッド署名された `MsgOpenEVMWindow` で開かれ、トランザクション数、金額、有効期限で制限されます。QoreX はこれを開き、表示し、閉じます。
- **ピン留め付きの handle。** @handle は、レジストリの ed25519 アテステーションと所有者自身の secp256k1 署名によって `qor1…` アドレスに結び付けられます。QoreX は最初に解決したアドレスをピン留めし、黙って変更された場合は警告します。
- **会社を必要としないリカバリー。** ソーシャルリカバリーは、シードを ML-KEM で封印した暗号化シェアに分割し（ガーディアン3人中2人）、あなたに通知される48時間のタイムロックがあります。Legacy はガーディアンに対するデッドマンズスイッチです。端末リンクは、ワンタイムコードと、単独では役に立たない QR でウォレットを移します。[セキュリティとリカバリー](/qorex/security-and-recovery)をご覧ください。
- **小さな使用範囲。** 拡張機能がブラウザに求める API 権限は `storage` の1つだけで、解析やトラッキングのコードは含まれません。プッシュ通知でサーバーに伝わるのは公開アドレスだけで、通知の文面は「QOR received」だけです。

## 使い方 {#how-to-use}

1. 公式のストア掲載ページから QoreX をインストールします（[アクセス方法](#how-to-access)を参照）。
2. ウォレットを作成するか、復元します。モバイルアプリは[はじめに](/qorex/getting-started)、拡張機能は[ブラウザ拡張機能](/qorex/browser-extension#wallet)をご覧ください。
3. 24語を書き留めてから、QOR を送受信します: [送受信](/qorex/send-and-receive)。
4. ステーキング: [ポートフォリオとステーキング](/qorex/portfolio-and-staking)。万一に備えた保護策の設定: [セキュリティとリカバリー](/qorex/security-and-recovery)。
5. ウェブサイトを QoreX で使うには、拡張機能（デスクトップ）またはアプリの [dApp ブラウザ](/qorex/dapp-browser)で開きます。すべての接続とすべての署名は、あなたが与える承認です。

## アクセス方法 {#how-to-access}

- **ネットワーク:** メインネット `qorechain-vladi`（デフォルト）とテストネット `qorechain-diana`。モバイルでは、テストネットは **設定 → テストネットを使用（開発者向け）** です。
- **アカウント:** 不要です。サインイン（メール、Apple、Google）は任意で、@handle の取得、Dashboard へのリンク、支払いリクエストの利用にのみ必要です。
- **前提条件:** モバイルでは端末のロック解除（iOS は Face ID または Touch ID、Android はクラス3の生体認証または画面ロックの PIN）が必要で、ないと作成とインポートのボタンは無効のままです。拡張機能ではパスワードが必要です。
- **費用:** QoreX は無料です。送金、ステーキング、EVM ウィンドウの開設には、通常のネットワーク手数料がかかります（ネットワークの下限はガスあたり 0.1 uqor）。
- **必ず公式の掲載ページからインストールしてください:**

| Chrome, Brave, Edge, Arc, Opera | [Chrome Web Store](https://chromewebstore.google.com/detail/qorex/cflpnggbnnifibblifgbeobogdpfjpcg) | Chromium 系ブラウザ |

## 制限事項と既知の問題 {#limits}

- **署名されたもの以上の保証はありません。** ハイブリッド署名が対象とするのは Native レーンのトランザクションです。EVM トランザクションは secp256k1 署名のみで、EVM アクセスウィンドウが開いている間だけ受け付けられます。SVM および外部ネットワークへの送金は従来型の署名のみです。
- **拡張機能の EVM プロバイダーが応答するのは、アカウントとネットワークに関するクエリだけです。** 現時点では EVM トランザクションやメッセージに署名しません。メッセージ署名（`signArbitrary`）は提供されていません。
- **モバイルのみ:** ポートフォリオ、Q-Day Scanner、ソーシャルリカバリー、Legacy、支払いリクエスト、サインイン、端末リンク。
- **スワップは利用できません。** プールの流動性が揃うまでオフのままで、iOS では表示されません。
- **リンクされた署名者**（支出上限付きでリンクキーとして使う Phantom や MetaMask）は、QoreX 内ではまだ利用できません。
- ML-DSA-87 鍵の**鍵ローテーション**は、QoreX 内ではまだ利用できません。
- **handle サービスが停止している場合**、ウォレットは通常のアドレスにフォールバックし、それ以外はすべて動作し続けます。
- フレーズを書き留めておらず、ソーシャルリカバリーもないまま失われたウォレットは、誰にも復旧できません。

- 次に、ハイブリッド署名の Native レーンでの QOR の[送受信](/qorex/send-and-receive)の方法を学びましょう。

ストアの審査は各ストアごとのスケジュールで進むため、あるストアが別のストアより古いビルドをしばらく配信することがあります。**2026年10月27日**時点の**各ストアの**現在のバージョンは次のとおりです。

| ストア | 現在のバージョン | 備考 |
|---|---|---|
| Apple App Store（iOS） | 1.1.8 | 10月21日にリリース |
| Google Play（Android） | 1.1.9 | |
| Chrome Web Store | 0.3.8 | |
| Firefox Add-ons | 0.3.9 | |
| Safari（Mac App Store） | 1.7.8（拡張機能 0.3.8 を搭載） | Mac App Store は独自の `1.x` 番号体系を使用します |

ストアには常に現在のバージョンが表示され、まだ古いビルドを配信しているストアも自動的に追いつきます。ストアがまだリリースしていないビルドは、このマニュアルでは利用可能なものとして説明していません。

1.1.9 / 0.3.9 ビルドでの追加点（現時点では Android 1.1.9 と Firefox 拡張機能 0.3.9。iOS、Chrome、Safari は、各ストアがそのビルドを配信した時点で含まれます）:

- **ステーキングのロック。** ステークの一部を3、6、12か月ロックできます。表示されるボーナスは、ネットワークの上限の範囲内で、そのロックが現時点で得られるボーナスです。早期アンロックには、コストを明示する2回目の確認が必要で、**アンステーク**と**ステークの移動**はロックされていない部分に限られます。ティアのスケジュールには「最大」と表示し、その横に現時点の数値を示しています。[ポートフォリオとステーキング](/qorex/portfolio-and-staking#staking-locks)をご覧ください。
- 承認画面での **IBC 送金メモの分かりやすい表示**。
- 拡張機能での **MetaMask（coin 60）からインポートしたアカウントによるステーキング**。

1.1.8 / 0.3.8 ビルドでの変更点:

- **最初のページから使える MetaMask on QoreChain。** MetaMask が必要とする EVM アクセスウィンドウを開く、確認する、閉じることができ、残りの内容も確認できます。
- **より強力な署名チェック。** QoreX は、アプリの ML-DSA-87 署名をあなたのアカウントの登録済みの鍵に対して検証し、その鍵が別のウォレットによって登録されていた場合は明確に通知します。
- **報告されたセキュリティ問題の修正。**

1.1.7 / 0.3.7 ビルドでの変更点（1.1.8 / 0.3.8 に含まれます）:

- **2通りに読めるバイト列のリクエストを承認画面が拒否します。** 同じフィールドがリクエスト内に2回現れると、画面とチェーンとで署名される内容の解釈が食い違う可能性があります。たとえば、手数料や金額が実行されるものと異なって表示される場合です。QoreX は、そのようなリクエストについて一方の解釈だけを表示するのではなく、拒否するようになりました。[承認ウィンドウに表示されるもの](/qorex/security-and-recovery#approvals)をご覧ください。
- **許可の有効期限が秒単位で表示される**ようになり、ガバナンスの投票もデコードされて承認画面に表示されます。
- **サイトは、リクエストが自己申告する内容ではなく、ブラウザ自身が証明するオリジンで識別されます。**
- **拡張機能で @handle の検索が再び動作します。**
- **@handle の取得にはサインイン済みのアカウントが必要で、アプリ内で行います。** 拡張機能はそちらへ案内します。
- **QoreChain に紛らわしい名前は予約されている**ため、新しい handle がプロジェクトやそのスタッフになりすますことはできません。

1.0.9 / 0.2.6 以降の主な変更点:

- 1台のスマートフォンまたはブラウザで **複数のウォレット** を利用でき、それぞれが独自のリカバリーフレーズを持ち、ワンタップで切り替えられます - [複数のウォレット](/qorex/getting-started#several-wallets)をご覧ください。
- MetaMask や Dashboard で最初に使われたフレーズ向けに、手動で追加する **イーサリアム形式（coin 60）のアカウント** - [MetaMask または Dashboard からフレーズを復元する](/qorex/getting-started#restore-dashboard)をご覧ください。
- **コントラクトによるトークンの追加**、**任意のネットワークでの受け取り**、グローバル **検索**、初回 **ツアー**、**ホーム画面ウィジェット**、QOR の着金時の **プッシュ通知**（モバイル） - [送受信](/qorex/send-and-receive)をご覧ください。
- **受け取りと再ステーク**、受け取り前の手数料チェック、**アンステーク進行中** リスト、そしてアンステークできなくなるほどステークしてしまう前の警告 - [ポートフォリオとステーキング](/qorex/portfolio-and-staking)をご覧ください。
- すべてのメッセージ、手数料、支出上限、有効期限を表示し、QoreX が表示できないものは拒否する承認画面。dApp 向けの **`signAndBroadcast`**、**接続済みサイト** からの取り消し（拡張機能）、**EVM アクセスウィンドウ** - [セキュリティとリカバリー](/qorex/security-and-recovery)および[ブラウザ拡張機能](/qorex/browser-extension)をご覧ください。
- 修正: 残高のあるアカウントが一時的に「あなたのアカウント」から消えることがある問題（1.0.9）、Android のハードウェア戻るボタンが 1 画面だけ戻るようになりました（1.1.1）、Android 14 以降では、アクセシビリティ以外のサービスに対してリカバリーフレーズが隠されるようになりました（1.1.6）。

QoreX は、2026年10月23日からチェーン **v3.2.4** で動作しているメインネット `qorechain-vladi`（2026年6月7日から稼働）で動作します。これらのアップグレードで署名フォーマット、アドレス、小数桁数、メモ、手数料は変更されないため、QoreX のアップデートは必要ありません。

## 開発者向け {#developers}

自分のアプリから QoreX と連携するには、QoreX 開発者キットを使います。0.1.0 で公開された npm パッケージ6つです。インストールコマンド、例、制限事項は [QoreX integrations](/developer-tools/qorex-integrations) にあります。ウェブアプリでのウォレットの検出と署名については、[ウォレットアダプター](/developer-tools/wallet-adapter)も、QoreX が注入するブラウザプロバイダーについては[ブラウザ拡張機能](/qorex/browser-extension#standards)もご覧ください。

## QoreX がネットワーク経由で送信するもの {#data-and-privacy}

QoreX には **解析ツールも、クラッシュレポートも、トラッキング SDK もありません**。あなたの鍵、リカバリーフレーズ、保管領域、承認が **端末の外に出ることはありません**。どのウォレットでも必要なように、アプリはネットワークと通信します。以下が完全な一覧です。

**常時（残高の表示と送金に必要）:**

- **QoreChain の公開エンドポイント**（`qore.host` 上の `api`、`rpc`、`evm`、`svm`、および `-testnet` の対応するもの）- 残高、履歴、ブロードキャストのために使用します。これらのリクエストにはあなたの**公開** `qor1…` アドレスが含まれます。
- **価格の取得** - QOR の価格を取得するための1回のリクエストで、**アドレスは含まれません**。
- **保有または閲覧している外部ネットワーク** - そのネットワークの、第三者が提供する公開 RPC/REST サービス。そのネットワーク上のあなたの**公開**アドレスが含まれます。
- **@handle レジストリ** - 検索する handle、または公開アドレスが含まれます。

**有効にした場合のみ:**

- **プッシュ通知**（モバイル）- 有効にするまでオフです。有効にすると、サーバーは端末トークンと、使用中のウォレットの公開 `qor1…` アドレス（最大10個）を受け取ります。サーバーが90日間通信を受けていない端末は削除されます。
- **ソーシャルリカバリー** - リレーは**暗号文のみ**を保存します。
- **サインイン**（メール、または Apple や Google）- @handle の取得、Dashboard へのリンク、支払いリクエストの利用に必要です。
- **Dashboard の接続とリンク済みアドレス** - そのアドレスを所有していることの署名付き証明を送信します。
- **支払いリクエスト** - 送信元の handle、送信先の handle、金額、任意のメモを送信します。

**ホーム画面ウィジェット**は、QoreChain のサーバーに対して独自のリクエストを行いません。アプリがあなたのアドレス、残高、プライバシーフラグをローカルでウィジェットに渡し、ウィジェットは公開された QoreChain の REST エンドポイントから残高を更新します。

どちらのアプリにも **AI チャットも QCAI サービスもありません**。
