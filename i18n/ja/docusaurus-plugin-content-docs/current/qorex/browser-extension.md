# QoreX ブラウザ拡張機能

QoreX の **ブラウザ拡張機能** は、デスクトップ向けの QoreChain ウォレットです。**単体で完結するウォレット**であり(ウォレットの作成/インポート、QOR の保有・送金・ステーキング、dApp との接続ができます)、あらゆるウェブサイトが QoreX を検出し、すべてのリクエストを明示的にデコードされた承認へと変える役割も担っています。デスクトップブラウザから QoreChain を使うすべての人と、自分のウェブアプリを QoreChain ウォレットに対応させたい開発者を対象としています。

3つのストア(Chrome、Firefox、Safari)で **公開・提供中** で、いずれも拡張機能 0.4.5 を提供しています。[どのバージョンがどこで提供されているか](#versions)を参照してください。

## 革新的な点 {#innovations}

- **`signAndBroadcast`。** dApp はメッセージを送ります。ウォレットはデコードしたすべてのメッセージと手数料を表示したうえで、ウォレットだけが作成できる ML-DSA-87 レイヤーを追加し、ブロードキャストします。ページが ML-DSA-87 鍵を保持することはありません。
- **`signDirect` はレイヤーを登録済みの鍵に対して確認します。** dApp が自ら ML-DSA-87 レイヤーを付けた場合、QoreX は承認ウィンドウが開く前に、そのレイヤーをアカウントのオンチェーンに登録された鍵に対して確認します。トランザクションにレイヤーがない場合は、QoreX が追加します。最も簡単な経路は引き続き `signAndBroadcast` です([QoreChain トランザクションの送信](#sign-and-broadcast)を参照)。
- **権限は最小限。** 拡張機能が宣言するのは `storage` と、任意の開発者モードの AI エージェントツール用の `nativeMessaging`(Chrome と Firefox)だけです。ホスト権限はなく、解析、クラッシュレポート、トラッキングのコードもありません。[QoreX が要求する権限](#permissions)を参照してください。
- **封印されたボルト。** ボルトはパスワードから導出した鍵(Argon2id)のもとで AES-256-GCM により暗号化されます。ブラウザが WebAuthn PRF を公開している場合(Chrome と Edge)は、パスキーでアンロックすることもできます。パスワードは常にフォールバックとして残ります。
- **乗っ取らない検出。** QoreX は EIP-6963(`rdns` は `network.qore.qorex`)と Solana Wallet Standard で自身をアナウンスします。`window.ethereum` や `window.keplr` を上書きすることは決してありません。
- **ブラウザが識別する、オリジンごとの承認。** サイトとは、リクエストが主張する内容ではなく、ブラウザ自身が証明するオリジンのことです。同じフィールドを繰り返して2通りに読めるようにしたリクエストは拒否されます。
- **ロックされたウォレットは、再試行ではなくパスワードを求めます。** QoreX がロックされている間にサイトが署名を要求すると、パスワード画面が開いてサイト名が表示されます。ロックを解除すると、リクエストの承認画面が表示されます。パスワードなしには何も署名されません。
- **すべての送金の前に確認。** 送金フォームは、受取人の完全なアドレス、手数料、警告を示す確認画面に進み、その後で初めて署名します。
- **CSV 書き出し付きの履歴。** アカウントごとで、各取引はチェーンの報告どおりに保留中、確定、失敗と表示されます。
- ポップアップには**支払いリクエスト、連絡先、資産の保護状況、サポート**があります。[支払いリクエスト](#pay-requests)、[連絡先](#contacts)、[資産の保護状況](#protection)を参照してください。
- **17 個のツールを備えた開発者モード。** **開発者ツール** ボタン 1 つで、すべてが専用ページに開きます。[開発者モード](/qorex/developer-mode)を参照してください。

## 使い方 {#how-to-use}

1. 拡張機能をインストールし([アクセス方法](#how-to-access)を参照)、ポップアップを開きます。
2. **新しいウォレットを作成**(パスワードを設定すると、24語が一度だけ表示されます)または **リカバリーフレーズをインポート** を選びます。[ウォレットの作成または復元](#wallet)を参照してください。次に<strong>最初に何をしますか？</strong>で選ぶか、スキップします。
3. ポップアップの **送金**、**受け取る**、**QORをステーク**、**履歴**、**コインとトークン** を使います。[QOR を送る](#send)、[履歴](#history)、[拡張機能からステーキングする](#stake)、[外部ネットワークで送金する](#send-external)を参照してください。
4. dApp を開きます。最初の接続ではサイトのオリジンを示す承認が表示され、承認しても公開されるのはあなたの公開アドレスだけです。サイトは[接続済みサイト](#connected-sites)でいつでも取り消せます。
5. 開発者は、EIP-6963 で QoreX を検出し、`signAndBroadcast` でトランザクションを送ります。[dApp を QoreX に接続する](#connect)と [dApp から QoreChain トランザクションを送信する](#sign-and-broadcast)を参照してください。

## ウォレットの作成または復元 {#wallet}

ポップアップを開き、以下から選択してください。

- **新しいウォレットを作成** - パスワード(8文字以上)を設定すると、QoreX はお使いの端末上で新しい24語のリカバリーフレーズ(256ビットのエントロピー)を生成し、あなたの QoreChain アイデンティティを導出して、そのパスワード(および任意でパスキー - [セキュリティ](#security)を参照)でボルトに封印します。24語は**一度だけ**表示されます。書き留めて、*リカバリーフレーズを安全な場所に保管しました* にチェックを入れてから先へ進んでください。後からポップアップの **リカバリーフレーズを表示** で再表示できます(パスワードが必要です)。
- **バックアップを確認** - フレーズを保存したことを確認した直後に、QoreX はランダムな位置の 3 つの単語を、書き留めたとおりに入力するよう求めます。一致しない場合は紙を確認してもう一度試してください。**あとで確認**も選べます。後で**バックアップを確認**する場合はパスワードが求められ、フレーズは表示されません。目的は書き留めた控えを確認することだからです。
- **リカバリーフレーズをインポート** - 既存のフレーズから復元します。24語未満のフレーズでも資産は通常どおり復元されますが、その場合、あなたの ML-DSA-87 鍵の強度はフレーズ自体の強度にとどまることを QoreX が警告します。フル強度を得るには、新しい24語のウォレットを作成して資産を移してください。

:::danger 先へ進む前にフレーズを書き留めてください
拡張機能のボルトは、このブラウザ内にのみ存在します。**拡張機能を削除する、そのデータを消去する、またはブラウザをリセットすると、鍵は削除されます**。QoreChain Association を含め、誰もそれらを復元できません。書き留めた24語がなければ、資産は永久に失われます。[今すぐバックアップ](/qorex/security-and-recovery#back-up-now)を参照してください。
:::

作成またはインポートの後、QoreX は<strong>最初に何をしますか？</strong>と一度尋ねます。拡張機能では、**お金を受け取りたい**はコイン、そのアドレス、支払いリンクを順に案内し、**お金を送りたい**はウォレットへの資金追加、@handle の説明(ハンドルはアプリで取得します)、手数料の説明を含む最初の支払いを案内し、**暗号資産を安全に保ちたい**は入金アドレスとバックアップ確認を表示します。**今はスキップ**で飛ばせます。ポップアップのホームの<strong>何をしますか？</strong>で再び開けます。

拡張機能は独自の鍵を保持しており、モバイルアプリを必要としません。鍵が端末の外に出ることはありません。

## ロック解除と自動ロック {#unlock}

- **ロック解除** - パスワードを入力して **Enter** キーを押すか、**ロック解除**をタップします。ボタンは処理中であることを示します(ボルト鍵の導出は意図的に時間がかかります)。**パスワードが違います。** はパスワードが間違っている場合にのみ表示され、その他の失敗は内容が示されます。[パスキーでのロック解除](#security)がオンの場合は、**パスキーでロック解除**を使えます。
- **自動ロック** - ポップアップのホームの**自動ロックまでの時間**で、使わないまま QoreX が開いている時間を設定します: 1、5、15、30、60、240 分(分または時間で表示)。デフォルトは 15 分です。
- **ロック** - ポップアップのホームの**ロック**ボタンですぐにロックします。次の画面ではパスワードが求められます。
- **ロック中にサイトが要求した場合** - サイトからの署名リクエスト(ネイティブ、EVM、Solana)は、サイト名を表示したパスワード画面で QoreX を開きます。ロックを解除すると、そのウィンドウは閉じ、リクエストの承認画面が表示されます。代わりにウィンドウを閉じると、リクエストは拒否され、何も署名されません。

## 複数のウォレットとアカウント {#wallets}

- **ウォレット**(0.3.3 以降)- ポップアップの **ウォレット** 画面(「このブラウザ内のウォレット」)に、このブラウザ内のすべてのウォレットが一覧表示されます。それぞれが独自のリカバリーフレーズを持ち、**1つのパスワード**ですべてのロックが解除されます。切り替えると、QoreX が表示・署名に使用するウォレットが変わります(チェーン上では何も動きません)。ウォレットは、新規作成(フレーズは一度だけ表示)または復元によって**追加**できます。ボルトを再封印するため、パスワードは一度だけ求められます。ウォレットを追加または削除すると**パスキーによるアンロック**がオフになります。ホーム画面から再度オンにしてください。削除するには、*このブラウザから削除* をタップしてパスワードを入力します。最後の1つのウォレットは、この画面からは削除できません。削除するとその鍵はブラウザから消えます。元に戻せるのはそのリカバリーフレーズだけです。
- **アカウント**(0.2.2 以降)- **あなたのアカウント** では、同じフレーズから複数のアカウントを作成・切り替えできます(ウォレットごとに最大20個。番号が振られ、名前は変更できません)。書き留めたフレーズを復元すると **アカウント 1** が戻ります。他のアカウントは **アカウントを追加** で再度追加してください。切り替えを行うと、送金、ステーキング、受け取り、@handle が、アクティブなアカウントに連動して切り替わります。

### イーサリアム形式のアカウント {#coin60}

0.3.2 以降、(**アカウント** 画面にある)**Ethereum アカウントを追加（coin 60）** により、MetaMask または Dashboard で最初に使われたフレーズのアカウントを追加できます。[MetaMask または Dashboard のフレーズを復元する](/qorex/getting-started#restore-dashboard)を参照してください。その 0x アドレスは、同じ単語に対して MetaMask が表示するアドレスです。このアカウントではハンドルは提供されません。拡張機能 0.3.9 以降では、このアカウントから拡張機能内でステーキングできます。

ポートフォリオ、Q-Day Scanner、ソーシャルリカバリー、Legacy Protocol、アカウントのサインイン、端末リンクは引き続きモバイル専用です。[QoreX Wallet](/qorex/overview#platform-availability) を参照してください。

## アカウント、残高、@handle {#account}

ポップアップの待機画面には、あなたの `qor1…` アドレス(タップでコピー)とリアルタイムの QOR 残高が表示されるため、どちらを確認するにもブロックエクスプローラーを開く必要はありません。

### ベスティング(ロック中)残高 {#vesting}

アカウントにベスティング QOR(例えば未リリースの TGE 割り当てなど)がある場合、残高は **現在利用可能** と **まだロック中** に分かれ、利用可能額を超える送金はネットワークに到達する前に拒否されます(オンチェーンで失敗して手数料だけ取られることはありません)。QoreX はここに意図的に「次回ロック解除日」を表示**しません**。ベスティングスケジュールはガバナンスによって変更され得るため、残高カードに日付を表示すると、QoreX が保証できない約束のように読めてしまうからです。正確であり続けるのは、利用可能/ロック中の内訳です。

### @handle を取得する

一意の **@handle**(例: `@liviu`)の取得には**サインイン済みのアカウント**が必要で、**モバイルアプリ内**で行います。拡張機能はそちらへ案内するだけで、自身ではハンドルを取得しません。取得されたハンドルはそのアドレスに紐づけられるため、拡張機能はあなたがそれに支払う際にこれを解決し、他の人もあなたに名前で支払えるようになります。ハンドルが(ウォレット全体ではなく)アドレスにどのように紐づけられるかについては、[@handle](/qorex/account-and-dashboard#handle) を参照してください。

## QOR を送る {#send}

1. ポップアップを開き、**Send** をタップします。
2. 受取人(`qor1…` アドレスまたは @handle)、金額、任意のメモを入力します。[お気に入り](#contacts)はフォーム上にワンタップのチップとして表示されます。
3. **送金内容の確認。** 確認画面には、受取人の完全なアドレス(保存した連絡先の場合は連絡先名も)、金額、メモが表示されます。アカウントの最初のトランザクションの場合は、1 回限りの ML-DSA-87 鍵登録手数料と合計額も表示されます。
4. 警告を読んでください。QoreX は、このウォレットからそのアドレスへの最初の支払いである場合、アドレスが過去に支払ったアドレスや保存したアドレスに**似ているだけ**の場合(すべての文字を比較してください。**それでもこのアドレスに送るにはもう一度タップ**という 2 回目のタップが必要です)、ネットワーク手数料が送金額より大きい場合に知らせます。
5. **確認して送信**をタップします。QoreX はハイブリッド署名で署名して送信します。

メインネットとテストネットで利用できます。ネットワークの 1 トランザクションあたりのガス上限を超えるトランザクションは、何も署名される前に拒否されます。

## @handle 宛に送金する {#handle-send}

0.1.9 以降、アドレスを調べる代わりに、登録済みの @handle に直接支払うことができます(ハンドルの検索は、0.3.6 までのバージョンでは不具合により中断されていましたが、0.3.7 以降は再び動作します)。

1. ポップアップを開き、**Send** をタップします。
2. 受取人欄に、`qor1…` アドレスの代わりに `@` に続けてハンドル(例: `@liviu`)を入力します。
3. QoreX はハンドルを解決し、署名する前に **解決されたアドレス** を表示します。常に想定と一致しているか確認してください。
4. 金額を入力し、[確認画面](#send)を確認して確定します。

解決結果は、QoreX が利用する前に2つの方法で検証されます。拡張機能に組み込まれた信頼キーに対して照合されるレジストリの証明、そしてハンドル所有者自身による申請への署名です。いずれかの検証に失敗したレスポンスは無条件で拒否されます。QoreX は未検証のアドレスを表示するフォールバックを行いません。あるハンドルに初めて支払う際、QoreX はその解決先アドレスを記憶(ピン留め)します。そのハンドルが後で**異なる**アドレスに解決された場合、QoreX は処理を止め、続行するかどうかを判断できるように新旧両方のアドレスを全文表示します。この記憶は**ブラウザごと**に保持されるため、別のブラウザやコンピューターから同じハンドルに初めて支払う際は、そちらでも新規として表示されます。これは想定どおりの動作であり、エラーではありません。

## 受け取り {#receive}

ポップアップの**受け取る**をタップします。**最初にコインを選びます**。

1. **受け取るコインを選択** - 検索できる一覧(**コインまたはネットワークを検索**)で、QOR が先頭、続いて各ネットワーク固有のコインと同梱トークンが、それぞれの画像とネットワークの画像とともに表示されます。[コントラクトで追加した](#custom-tokens)トークンも一覧に表示されます。画像はウォレットに同梱されているため、表示のために第三者から何かを取得することはありません。
2. QoreX は、そのコインのネットワークのアドレスを QR コードとコピーボタンで表示し、コイン名を示した警告を出します: このアドレスには、そのコインだけを、そのネットワークで送ってください。1 つのアドレスが複数のネットワーク(EVM ネットワーク)で使える場合は、どのネットワークかを表示します。
3. **別のコインを選択**で一覧に戻ります。

対応ネットワークは QoreChain、Ethereum、BNB Chain、Polygon、Arbitrum、Base、OP Mainnet、Avalanche、Solana、Cosmos Hub、Osmosis、Celestia です。他のネットワークのアドレスはリカバリーフレーズから導出されるため、表示に 1 回の確認が必要な場合があります。Cosmos Hub、Osmosis、Celestia では、そのネットワークでの送金に署名するアドレスを表示します。

## 履歴 {#history}

ポップアップのホームの**履歴**をタップすると、アカウントで起きたことを確認できます。

- 送金だけでなく**すべての種類の QoreChain 取引**: 送金、受取、ステーク、アンステーク、ステークの移動、報酬の請求、ステークロック、EVM ウィンドウ、鍵の変更を、金額と手数料とともに表示します。EVM トランザクションには、[EVM アクセスウィンドウ](#evm-window)から使った量も表示されます。
- **状態はチェーンから読み取ります。** この端末から送った送金で、チェーンの履歴にまだ表示されていないものは、**保留中: ネットワークの確認待ち**と表示されます。ネットワークが見つけられない場合、QoreX は失敗した可能性があると表示するので、再送する前に確認してください(行は**閉じる**で消せます)。失敗した取引はその旨と、支払われた手数料が表示されます。
- **アカウントごと** - 複数のアカウントがある場合は、上部でアカウントを選びます。
- **同じ支払いを繰り返す** - 過去の支払いから送金フォームを再入力します。引き続き確認と確定が必要です。
- **CSV を書き出す** - ファイルは端末上で作成され、含まれるのは履歴のみ(フレーズも鍵もなし)で、表計算ソフトで安全に開けるようになっています。

ネットワークに接続できない場合、QoreX は履歴を読み込めなかったと表示し、「取引がない」と表示することはありません。現時点で履歴の対象は QoreChain のみです。メインネットとテストネットで利用できます。

## 支払いリクエスト {#pay-requests}

改変すれば分かるリンクで、相手に指定額の QOR を請求します。

**支払いを依頼する:**

1. ポップアップのホームの**支払いリクエスト**を開き、**新しいリクエスト**を作成します: QOR の金額、任意のメモ(最大 140 文字)、@handle がある場合はそれを表示するかどうか。
2. **リンクを作成**をタップします。QoreX はアカウント鍵でリクエストに署名します。**リンクをコピー**でコピーして、支払う人に送ります。
3. **自分のリクエスト**に一覧表示されます。**状態を確認**はチェーンを読み取り、**支払い済み**または**未払い**(あるいはネットワークが応答しなかったこと)を表示します。**来月も使う**は、以前のリクエストから新しいリクエストを作ります。

**リクエストを支払う:**

1. **リクエストを支払う**を開き、リンクを貼り付けて **Open** をタップします。
2. QoreX は署名、署名者が受取アドレスの所有者であること、正確なネットワーク、リクエストの @handle を確認します。改変されたリンク、誤った署名者、未知のネットワーク、QOR 以外のコインは拒否されます。リクエストがもう一方のネットワーク向けの場合は、自分で切り替えてください。QoreX は切り替えません。
3. **Pay** をタップします。何かが送信される前に、通常の[確認画面](#send)が表示されます。支払いにはメモにリクエストのタグが含まれ、請求者の QoreX はこれでチェーン上の支払いを見つけます。

署名付きリクエストにはアカウントもサインインも不要です。テストネットのリクエストにはその旨が表示されます: テストネットの QOR に価値はありません。開発者向けのリンク形式は [dApp 連携](/qorex/dapp-integration)にあります。

## 連絡先とお気に入り {#contacts}

ポップアップのホームの**連絡先**は、支払い先アドレスの名前を**この端末上にのみ**保存します。

- **連絡先を追加** - 名前と、少なくとも 1 つのアドレス: QoreChain(`qor1…`)、EVM(`0x…`)、Solana または Cosmos、および任意の @handle。**お気に入り**にすると、送金フォームにワンタップのチップとして表示されます。**&#123;name&#125; に支払う**は、入力済みのフォームを開きます。削除には 2 回のタップが必要です。一覧には最大 200 件まで保存できます。
- **@handle の連絡先**は、ハンドルが前回の支払い時と同じアドレスを指しているかを表示し、アドレスが**変わった**場合は警告します。
- **そっくりアドレス** - すでに知っているアドレスに似ているだけのアドレスは警告され、すべての文字を比較できるように両方が表示されます。

連絡先は安全性のチェックではありません。すべての支払いで、引き続き完全なアドレスが確認画面に表示されます。

## 資産の保護状況 {#protection}

ポップアップのホームの**資産の保護状況**は 1 つの画面で、開くたびに各項目を端末上とネットワーク上で確認します。読み取れない項目はそのように表示し、「問題なし」や「なし」とみなすことはありません。

- **バックアップ確認済み**と**復元テスト済み** - 日付、または**まだです**。**復元フレーズをテストする**は、フレーズの 3 つの単語を尋ねます。端末上で照合され、入力内容は保存も送信もされません。
- **権限を持つアプリ** - あなたのアドレスを確認でき、署名を求められるサイトです。**取り消す**ことができます。
- **ネットワーク上で付与した権限** - 別のアカウントがあなたの代わりに送信できる権限(authz)や、あなたの QOR をネットワーク手数料に使える権限(fee grant)を、無制限のものを先頭に表示し、**取り消す**ことができます。取り消しでは、署名する内容と手数料が表示され、その後確定します。
- **QoreChain の EVM 上のトークン承認** - **トークンの承認を確認**をタップします(読み取りには一度だけフレーズが必要です)。QoreX はどこまで確認したかを表示します。画面を再び開くと確認が続きます。**取り消す**は、トークンコントラクトに限定した 1 トランザクション分の EVM ウィンドウを開いてから、`approve(spender, 0)` を送信します。ここで取り消せるのは Ethereum 形式(coin 60)のアカウントのみです。
- **レーン別のポスト量子保護** - わかりやすく言うと、QoreChain のネイティブトランザクションは 2 つの署名(ML-DSA-87 と従来型)を持ちます。EVM トランザクションは従来型で署名され、ポスト量子署名で開いたウィンドウ内でのみ受け付けられます。他のネットワークは従来型の署名のみを受け付けます。

ガーディアンとソーシャルリカバリーはモバイルアプリにあります。[セキュリティとリカバリー](/qorex/security-and-recovery)を参照してください。

## サポートとネットワークの状態 {#help-and-status}

- ポップアップのホームの**サポート**には、公式の窓口のみが一覧表示されます: [Telegram コミュニティ](https://t.me/QorechainCommunity)、[Discord](https://discord.gg/qorechain)、[ヘルプページ](https://qorechain.io/help/qorex)、team@qorechain.io へのメール、**脆弱性を報告**。QoreChain のスタッフがリカバリーフレーズ、パスワード、鍵を求めることは決してありません。**概要を表示**は、サポートから依頼された場合にのみコピーする任意の診断概要(アプリのバージョン、ネットワーク、エラーコードで、フレーズ、鍵、アドレス、残高は含まれません)を表示します。
- **ネットワーク状態のバナー** - QoreX はチェーンの最新ブロックの時刻を読み取ります。1 分以上前の場合、ネットワークが遅いこととブロックがどれだけ古いかをバナーで表示します。ネットワークに接続できない場合は、残高が古い可能性があると表示します。ネットワークが正常な間は何も表示しません。
- **最後に確認できた値** - ネットワークが応答しない場合、ポップアップは最後に読み取った残高と委任を、その時刻とともに表示します。

## 拡張機能からステーキングする {#stake}

**0.2.2** 以降、ポップアップには専用のステーキング画面があります。拡張機能のみで作成されたウォレットでも、ステーキング報酬を得るためにモバイルアプリは必要ありません。ポップアップのホームの **QORをステーク** を開きます。操作ごとに 1 行の説明がある**メニュー**が開き、各操作は専用のエラー行を持つ個別の画面を開きます。**ステーキングに戻る**でメニューに戻ります。

| 画面 | 内容 |
|---|---|
| **QORをステーク** | バリデーターと金額を選びます。アクティブなバリデーターがコミッションとともに表示され、**jailed**(収監)されたバリデーターは除外されます。入力中、残高がトランザクション手数料を下回ることになる場合は QoreX が警告します(アカウントが再び QOR を保有するまで、デリゲート解除や報酬受け取りができなくなります)。 |
| **ステーキング解除** | アンボンディングを開始します。QOR を動かせるようになるまでの時間は**ネットワークから読み取られ**、金額は残り時間とともに**アンステーク処理中**に表示されます。 |
| **ステークを移動** | アンボンディングの待機なしのリデリゲートで、3 ステップです: (1) 移動**元**のバリデーター(まだ移し出せないものは日付付きでグレー表示)、(2) 移動**先**のバリデーター、(3) **金額**。**Max** があり、署名前にルートと分割内容が表示されます。ネットワークが拒否する移動は事前に検出されます。[バリデーター間でステークを移動する](/qorex/portfolio-and-staking#move-stake)を参照してください。 |
| **取得** | 報酬を回収します。手数料が報酬より大きい場合は、最初のタップで警告します。 |
| **受け取って再ステーク** | 報酬を、それを生んだバリデーターに 1 回のトランザクションで再ステークします(最大 127 バリデーター)。QoreX はまず、**ロック解除済み**の QOR で手数料を支払えるか確認します。手数料は報酬が届く前に支払われます。 |
| **ロックしてボーナスを得る** | ステークの一部を 3、6、または 12 か月間ロックします。[ステーキングロック](/qorex/portfolio-and-staking#staking-locks)を参照してください。 |
| **報酬の受け取り先** | 今後のステーキング報酬を**同じウォレットの別のアカウント**に送ります。それ以外のアドレスには送れません。現在の受け取り先を表示し、最初のタップで新しいアカウントの完全な名前を示し、2 回目で署名します。ステークは移動しません。 |

メニューの下の **ステーキングのしくみ** カードには、これまでに得た報酬、ステーキングの費用(バリデーターのコミッションとネットワーク手数料)、アンステークした QOR が戻る時期が示されます。複数のアカウントがある場合は、アカウントセレクターでステーキングに使うアカウントを選びます。すべての操作は Send と同様に必須のハイブリッド署名(secp256k1 と ML-DSA-87)で署名され、最初のトランザクションで鍵も登録される場合は画面にその旨が表示されます。年率はチェーン自体の数値から読み取ります。ステーキング、デリゲーション、報酬はすべて **Native** レーン上でのみ行われ、EVM プリコンパイルを経由することは決してありません - [ステーキングとデリゲーション](/user-guide/staking-and-delegation)を参照してください。

### Dashboard のステーキングリクエストを承認する {#stake-dashboard}

QoreChain [Dashboard](/dashboard/staking-and-validators) はステーキングリクエストを組み立てますが、署名はできません。あなたの鍵は拡張機能のボルトから外に出ることがないためです。Dashboard で **Continue in QoreX** をクリックすると、リクエストが拡張機能内で開き、Send と同様に、バリデーターと金額を確認して承認できます。

:::note トランザクションが「downgraded(降格)」と表示され、成功と表示されない場合
Dashboard は、まれにトランザクションを明確な成功ではなく **downgraded** と表示することがあります。これは資産の移動自体は行われたものの、そのトランザクションについてチェーン上で ML-DSA-87 署名レイヤーが見つからなかったことを意味します。これはあなたの操作ミスではなく、あなたの側で修正できるものでもありません。私たちの側の不具合ですので、調査できるようサポートまでご報告ください。このメッセージは、確認して報告する時間を確保できるよう、意図的に消えずに画面に表示され続けます。
:::

### 外部ネットワークで送金する {#send-external}

Native レーン上の QOR に加えて、ポップアップの**外部ネットワークで送金**画面は、他のネットワーク上の資産を送金します。すべて同じリカバリーフレーズから導出されます。以下のすべてのネットワークで送受信できます。

| 種類 | ネットワーク | 同梱されているトークン |
|---|---|---|
| EVM | Ethereum、BNB Chain、Polygon、Arbitrum、Base、OP Mainnet、Avalanche C-Chain | ERC-20 エントリ(各 EVM チェーンの USDC・USDT、Ethereum の DAI) |
| SVM | Solana | SPL エントリ(USDC、USDT) |
| Cosmos | Cosmos Hub、Osmosis、Celestia | IBC 経由の Noble USDC。任意のメモ欄あり |

1. コインまたはトークンを選び、受取人と金額(Cosmos ネットワークでは任意のメモも)を入力します。
2. 確認事項にチェックを入れます。英語では次の文言です: **"External networks accept only classical signatures. Unlike your QOR, this transfer has NO ML-DSA-87 signature. I understand."** (外部ネットワークは従来型の署名のみを受け付け、QOR と違ってこの送金には ML-DSA-87 署名がありません。)外部チェーンは ML-DSA-87 署名を扱えず、QoreX がそれを隠すことは決してありません。
3. EVM ネットワークでは、最初のタップで**最大ネットワーク手数料**(「Network fee: at most …」)を見積もり、2 回目でまさにその見積もりで送金します。何か編集すると見積もりは破棄されます。送るコインで支払う手数料が送金額より大きい場合は警告します。
4. そのネットワークで過去に支払ったアドレスに似ているだけの受取人は、完全な形で表示され、もう一度タップが必要です。

## 対応ウォレット標準 {#standards}

QoreX は3つのインターフェースを公開しており、いずれもページ上に `window.qorex`(`{ evm, native, svm }`)として注入され、EIP-6963 と Solana Wallet Standard を通じて検出されます。ウェブアプリでは、[ウォレットアダプター](/developer-tools/wallet-adapter)がこの検出をラップします。

| 標準 | 概要 | 開発者にとっての意味 |
|---|---|---|
| **EIP-1193** | Ethereum プロバイダーの JavaScript API(`request(...)`、イベント)。 | アカウントとネットワークの問い合わせ(`eth_requestAccounts`、`eth_accounts`、`eth_chainId`、`wallet_switchEthereumChain`)に加えて、QoreX は QoreChain の EVM レーン(チェーン ID 9801、テストネット 9800)と Ethereum で `personal_sign`、`eth_signTypedData_v4`、`eth_sendTransaction` に署名します。各承認画面は、何を許可するのかを端末上でデコードして表示し、可能な場合は先にトランザクションをシミュレーションします。QoreChain で送信できるのは Ethereum 形式(coin 60)のアカウントのみで、トランザクションには [EVM アクセスウィンドウ](#evm-window)が必要です。[dApp 連携](/qorex/dapp-integration)を参照してください。 |
| **EIP-6963** | 複数ウォレットのプロバイダー検出(announce/request イベント)。 | QoreX は他のあらゆるウォレットと並んで自身をアナウンスします。**`window.ethereum` を上書きすることは決してない**ため、ユーザーはサイトごとに競合なく QoreX を選択できます。 |
| **Native プロバイダー(Keplr 形式)** | `window.qorex.native`: `enable`、`getKey`、`signAndBroadcast`、`signDirect`、`getOfflineSigner`(cosmjs、cosmos-kit、Interchain Kit 向け)、`signArbitrary` / `verifyArbitrary`、および `capabilities` の一覧。Keplr の完全な代替では**ありません**。QoreX は `window.keplr` のエイリアスを作らず、amino 署名と `sendTx` は利用できません。 | QoreChain のトランザクションを送る最も簡単な方法は **`signAndBroadcast`** です([QoreChain トランザクションの送信](#sign-and-broadcast)を参照)。QoreX はデコードしたメッセージと手数料を表示し、ウォレットだけが作成できる ML-DSA-87 レイヤーを追加して、ブロードキャストします。`signDirect` や `getOfflineSigner` では、QoreX はページが付けたレイヤーをアカウントの登録済みの鍵に対して確認し、レイヤーがなければ自ら追加します。[dApp 連携](/qorex/dapp-integration)を参照してください。 |
| **Solana Wallet Standard**(0.1.5 以降) | Solana dApp 向けのネイティブなウォレット検出(`wallet-standard:register-wallet` / `app-ready`)。 | Solana dApp は **QoreX を自動検出**します - 独自の統合作業は不要です。対応機能: `standard:connect`、`standard:disconnect`、`standard:events`、`solana:signMessage`、`solana:signTransaction`、`solana:signAndSendTransaction`。チェーンは `solana:mainnet`。`legacy` と `v0` 両方のトランザクションに対応。 |

:::note SVM レーンに直接アクセスする
同じインターフェースは `window.qorex.svm`(`connect` / `signAndSendTransaction` / `signMessage`)でも利用できます。Wallet-Standard による自動検出と、完全実装された SVM レーンは **0.1.5** で提供され、Chrome と Firefox の両方で利用可能です([どのバージョンがどこで提供されているか](#versions)を参照)。

Solana の承認画面では**命令ごとに1行**が表示され、QoreX がデコードできるものはデコードされます。SOL 転送(受取人と lamports)、SPL トークン転送、**"ALLOW SPENDING of your tokens"**(approve)、**"HAND OVER control of the account"**(set authority)、トークンアカウントのクローズ。それ以外は、プログラムとともに「instruction QoreX cannot read」と表示されます。approve または set authority 命令を含むリクエストには、「wants authority over your Solana tokens - read every line below」という見出しが付きます。あなたのウォレットが署名者として含まれていないトランザクションは拒否され、`signMessage` は実際にはトランザクションであるバイト列には署名せず、署名は **classical(従来型)** として表示されます。[ハイブリッド署名](#pqc)を参照してください。
:::

## コインとトークン {#custom-tokens}

ポップアップの **コインとトークン** 画面では、**ERC-20 トークンをコントラクトで追加**できます。ネットワークを選び、コントラクトアドレスを貼り付けて、**コントラクトを確認** を押します。QoreX はトークンの名前と小数桁数をコントラクト自体から読み取り(ポップアップを信用せず、追加時にもバックグラウンドで再度読み取ります)、その後、誰でも任意の名前のトークンを作成できるというリマインダーとともに表示します。その後、トークンは **外部ネットワークで送金** と[受け取り](#receive)画面に表示されます。同梱済みのトークン、重複、EVM 以外のネットワーク、不正なアドレス、読み取れないコントラクト、そして同梱トークンの名前を借用しているコントラクトは拒否されます。

## 接続済みサイト {#connected-sites}

ポップアップの **接続済みサイト** には、このウォレットが承認したすべてのサイトが一覧表示されます。サイトはこのウォレットのアドレスを確認でき、署名を求めることができます。**Revoke** をタップすると削除できます。承認は**ウォレットごと**に保持されます。あるウォレットに対して承認されたサイトは、切り替え後に別のウォレットのアドレスを読み取ることはできません。

## EVM アクセスウィンドウ {#evm-window}

ポップアップの **EVM アクセスウィンドウ** 画面では、イーサリアム形式(coin 60)のアカウントが QoreChain の EVM レーン(v3.2.0 以降)で送金できるようにするウィンドウを開閉します。制限はアプリと同じです: 最大 17,280 ブロックと 1,000 トランザクション、およびアカウントから出ていくすべての QOR と各最大手数料を合算してカウントする QOR の支出上限。トークンは上限に数えられません。

1. 期間(ブロック)、トランザクション数、支出上限を選びます。
2. **ウィンドウが許可するもの**を選びます。
   - **QOR の送金のみ(推奨)**(デフォルト): コントラクト呼び出し、新しいコントラクト、受取人がコントラクトの送金はできません。
   - **任意のコントラクト**: どのコントラクトも呼び出せます。画面は、コントラクトが動かすトークン、NFT、承認はウィンドウで制限されないと警告します。ネットワークがウィンドウを QOR の送金のみに制限できない場合、QoreX は任意のコントラクト向けに開く前に確認します。いいえと答えると、何も開きません。
3. **ウィンドウを開く**をタップします。開いたウィンドウには、何が許可されるかが正確に表示されます。**ウィンドウを閉じる**で終了します。

**QOR の送金のみ**で開いたウィンドウでは、サイトはコントラクトを呼び出せません。サイト自身のトランザクションは、その承認画面から QoreX にまさにそのトランザクション用のウィンドウを開かせることができます。承認画面は、ウィンドウが許可するすべてのコントラクトを名前で示し、開いているウィンドウを置き換えることを表示します。

coin-118 アカウントは EVM レーンを使えません。画面には取るべき 3 つの手順と、**アカウント**へのボタンが表示されます。ウィンドウを開閉・クリアできるのはウォレット自体の画面だけで、サイトにはできません。[EVM アクセスウィンドウ](/qorex/security-and-recovery#evm-window)を参照してください。

## ポスト量子鍵の管理とマルチシグ {#pqc-care}

**鍵を登録し直す(修復)。** ネットワーク上のアカウントのポスト量子鍵レコードが署名できなくなった場合(空、従来方式のみ、その他の理由で使用不能)、ポップアップのホームにカードが表示されます。**鍵を登録し直す**をタップするとネットワーク手数料が表示され、もう一度タップすると登録します。QoreX が自動で行うことはありません。アカウントに EVM ウィンドウがある場合はネットワークが閉じるので、後で新しく開いてください。

**ポスト量子鍵のローテーション。** **ML-DSA-87鍵をローテーション**ボタンは、ネットワーク上のアカウントの ML-DSA-87 鍵を、リカバリーフレーズから導出される次の鍵に置き換えます。2 回タップします。手数料は結果に表示されます。ローテーションはポスト量子鍵だけが漏えいした場合の保護になりますが、リカバリーフレーズが漏えいした場合には**役立ちません**。その後、同じフレーズを使う他のウォレットは、ローテーション後の鍵に対応するまで、このアカウントの署名ができず、ネットワークはアカウントの EVM ウィンドウを閉じます。フレーズから復元すると、QoreX は正しい鍵を見つけます。

**マルチシグアカウント。** **マルチシグアカウント**は、複数のメンバーの署名が必要なアカウントを管理します。各メンバーの従来型署名に加え、ポスト量子署名も必要です。QoreX は QoreChain のコマンドラインと同じファイルを使うため、各メンバーは QoreX でもコマンドラインでも署名できます。

1. メンバーのアドレス(それぞれ少なくとも 1 回のトランザクションを送信済み)、必要な署名数、任意の名前から**マルチシグを作成**するか、鍵を貼り付けて**既存のマルチシグを追加**します。
2. 画面には残高と各メンバーの鍵の状態が表示されます。まずポスト量子メンバーセットの**登録を準備**します。登録されるまでアカウントは送金できません。次に**送金を準備**します。
3. 拡張機能ではファイルをダウンロードして開きます。**ラウンド 1:** メンバーがポスト量子署名を追加し、結合します。**ラウンド 2:** 合意したメンバーが従来型で署名します。次に**ネットワークに送信**します。
4. 署名には 2 回のタップが必要で、まず署名する内容を確認します。トランザクションが認証子(authenticator)を登録する場合、QoreX は警告します。認証子は他のメンバーの署名なしにマルチシグの資金を動かせるためです。

## 開発者ツール {#developer-tools}

開発者モードはデフォルトでオフです。拡張機能でオンにするには、ポップアップ下部の**バージョン番号**を 7 回タップします。ポップアップのホーム下部に開発者セクションが表示され、**開発者ツール**(`</>` ボタン)、**テストネット（diana）に切り替え**(または**メインネットに戻る**)、**開発者モードをオフにする**があります。

**開発者ツール**は、**確認**、**トランザクション**、**コントラクトとロールアップ**、**その他の仮想マシン**、**署名とエージェント**に分類されたツールを 1 ページに開きます。アプリと同じ 17 個のツールがあり、テストネットではその中に **QoreChain 上の Solana** も表示されます。開発者モードは署名のルールを一切変えません。署名するものは、引き続き署名内容を表示し、承認を待ちます。各ツールは[開発者モード](/qorex/developer-mode)で説明しています。

**AI エージェント**ツールは、コンピューター上の AI アシスタントが、許可した内容を読み取り、トランザクションを**提案**できるようにします。QoreX はすべての提案を確認してシミュレーションし、あなたは通常の承認ウィンドウで承認または拒否します。どのエージェントも署名できません。拡張機能ではコンピューター上のコンパニオンプログラムが必要ですが、**まだ公開されていません**。Safari では利用できません。

**テストネット**でのみ、ポップアップのホームに IBC による別のチェーンへの送金と QoreChain Bridge 画面も表示されます。どちらもメインネットでは提供されません。[テストネット機能](/qorex/testnet-features)を参照してください。

## 言語 {#language}

拡張機能は、モバイルアプリ・Dashboard・サイトと同じ10言語に対応しています: 英語、ルーマニア語、ドイツ語、スペイン語、フランス語、イタリア語、トルコ語、アラビア語、日本語、韓国語。デフォルトでは **ブラウザ** の言語に従います(それ以外の言語の場合は英語にフォールバック)。これはモバイルアプリが **スマートフォン** の言語に従うのとは異なる基準であるため、スマートフォンとブラウザの設定が異なると、両者で表示言語が異なる場合があります。ポップアップの待機画面にある言語選択から、検出された言語をいつでも上書きできます。アラビア語に切り替えると、テキストだけでなくポップアップ全体が即座に右から左のレイアウトに切り替わります。

## セキュリティと権限 {#security}

QoreX は、単に信頼されるだけでなく検証可能であるように作られています。

- **ボルト** - あなたの鍵は **AES-256-GCM** で封印されます。パスワード方式では、鍵の導出に **Argon2id**(RFC 9106、メモリハード: 64 MiB、t=3、p=1)を使用しているため、コピーされたボルトのデータは GPU や ASIC のハードウェアで総当たりしようとしても時間がかかります。(レガシーの PBKDF2 形式のデータも引き続き開くことができ、次回のアンロック時に Argon2id へ再封印されます。)
- **パスキーによるアンロック(任意、0.1.5 以降)** - お使いの認証器が **WebAuthn PRF** 拡張に対応している場合、QoreX は入力したパスワードの代わりに、パスキーの32バイトの PRF 出力からボルトをアンロックできます。パスワードは常にフォールバックとして残ります。

  :::note パスキーによるアンロックが表示される場所
  QoreX は WebAuthn を機能検出し、ブラウザが拡張機能ページに対してそれを公開している場合にのみ **パスキーによるアンロックを有効にする** を表示します。該当するのは **Chrome と Edge** です。**Firefox** ではこのオプションは表示されません。これは、Firefox が拡張機能ページに WebAuthn を公開していないためです。これは想定どおりの動作であり、不具合ではありません。
  :::
- **自動ロック** - QoreX はしばらく使わないと自動的にロックし(デフォルト 15 分)、**ロック**ボタンもあります。[ロック解除と自動ロック](#unlock)を参照してください。
- **Manifest V3 + 厳格な CSP** - `script-src 'self'; object-src 'self'; base-uri 'self'`。インストール後の**リモートコードの読み込みは一切なく**、`wasm-unsafe-eval` もありません。
- **解析なし、クラッシュレポートなし、トラッキング SDK なし、サインアップなし** - QOR の保有、送金、ステーキングにアカウントは不要です。あなたの鍵、リカバリーフレーズ、ボルト、承認情報がブラウザの外に出ることはありません。ただし、ネットワークリクエストは行います。残高、履歴、ブロードキャストのための QoreChain のパブリックエンドポイント(これらにはあなたの公開 `qor1…` アドレスが含まれます)、価格の取得(アドレスなし)、保有または閲覧している外部ネットワークのパブリックサービス(そのネットワーク上のあなたの公開アドレス)、そして @handle レジストリ(ハンドル、または公開アドレス)です。[Dashboard ペアリング](#dashboard-bridge)を使用する場合に限り、あなたがそのアドレスを所有していることの署名付き証明を送信します。[QoreX がネットワーク経由で送信する内容](/qorex/overview#data-and-privacy)を参照してください。

### QoreX が要求する権限とその理由 {#permissions}

このセクションが存在する理由は、Firefox の掲載ページに「すべてのウェブサイトのデータへのアクセス」という権限が表示され、これがホスト権限を宣言しないウォレットと矛盾しているように見え得るためです。以下は、マニフェストに記載された、編集を加えていないそのままの内容です。

拡張機能の `manifest.json` には次のように記載されています。

```json
"permissions": ["storage", "nativeMessaging"],
"host_permissions": [],
"content_scripts": [
  { "matches": ["<all_urls>"], "js": ["dist/content.js"], "run_at": "document_start" }
],
"web_accessible_resources": [
  { "resources": ["dist/inpage.js"], "matches": ["<all_urls>"], "use_dynamic_url": true }
]
```

- **`storage`** - 暗号化されたボルト、オリジンごとの接続承認、ウォレット自体の設定と一覧(連絡先など)を拡張機能のストレージに**ローカルに**保存します。
- **`nativeMessaging`** - 0.4.5 で追加され、開発者モードの [AI エージェント](#developer-tools)ツールだけが、自分のコンピューター上のコンパニオンプログラム(未公開)と通信するために使います。QoreX がその接続を開くのは、そのツールで**このコンピューターでAIエージェントの接続を許可する**をオンにした後だけです。**Safari** パッケージはこの権限を宣言していません。
- **`host_permissions: []`** - QoreX は**いかなる**ホスト権限も宣言していません。あなたに代わって任意のサイトへクロスオリジンのネットワークリクエストを行う能力は要求していません。
- **`web_accessible_resources`** - ページが QoreX 自身の `inpage.js`(プロバイダーを公開する小さなスクリプト)を読み込めるようにします。`use_dynamic_url` により、セッションごとのアドレスが割り当てられるため、サイトが存在を探ることで拡張機能をフィンガープリントすることはできません。
- **`content_scripts` の matches が `<all_urls>`** - これが、Firefox が「すべてのウェブサイトのデータへのアクセス」と表示する正直な理由です。QoreX は小さなプロバイダースクリプト(`content.js` → `inpage.js`)を**すべてのページ**に注入します。すべてのサイトで動作するコンテンツスクリプトは、技術的にはページを読み取ることが**可能**であり、ブラウザは、その能力の由来が `host_permissions` であってもコンテンツスクリプトのマッチであっても、まさにその文言で説明します。

**なぜコンテンツスクリプトがすべてのサイトで動作するのか。** それは、**あらゆる** dApp が、サイトごとに事前のアクセス許可を求められることなく EIP-6963 経由でウォレットを検出できるようにするためです。これは MetaMask、Keplr、Phantom をはじめとする、注入型ウォレットすべての動作方式と同じです。注入されたプロバイダーは、訪問先のサイトが何であれ、そのページのスクリプトが実行される前(`document_start`)に存在している必要があります。

**このスクリプトが行うこと、行わないこと。** このスクリプトは、ウォレットのメッセージを橋渡しするだけです(プロバイダーのアナウンス、接続/署名リクエストのサービスワーカーへの転送、結果の返送)。それらのウォレットリクエスト以外でページの内容を読み取ることは**なく**、何かをサーバーに送信することも、リモートコードを読み込むこともありません。また、ホスト権限がないため、任意のクロスオリジンのデータを取得することもできません。これらはすべて検証可能です。拡張機能は CSP によってロックされ、解析ツールは一切搭載されておらず、そのマニフェスト(上記)はインストールされたパッケージ内で読むことができます。

## dApp を QoreX に接続する {#connect}

dApp は **EIP-6963** を通じて QoreX を検出し(リクエストをアナウンスし、`rdns` が `network.qore.qorex` のウォレットを選びます)、返された EIP-1193 プロバイダーを使います。QoreChain の **Native** レーンには `window.qorex.native` を使い、このビルドの対応機能は `capabilities` を読んで確認します。QoreX が `window.ethereum` や `window.keplr` を設定することはありません。コード付きの完全な開発者ガイドは専用ページにあります: [dApp を QoreX と連携する](/qorex/dapp-integration)([QoreX を検出する](/qorex/dapp-integration#detection)と[接続](/qorex/dapp-integration#connect)を参照)。ウェブアプリでは、[ウォレットアダプター](/developer-tools/wallet-adapter)がこの検出をラップして提供し、[QoreX デベロッパーキット](/developer-tools/qorex-integrations)がアプリ側の統合を扱います。(`@qorechain/connect` は非推奨です。これを使った新しい作業は始めないでください。)

承認は**オリジンごと**に行われます。あるサイトへの最初の接続で、そのオリジンを示す承認ポップアップが開き、承認しても公開されるのはあなたの公開アドレスのみで、あるサイトへの承認が他のサイトに何かを許可することはありません。承認はウォレットごとに保持され、**接続済みサイト**で取り消すまで保持されます。1つのサイトが待機させられるリクエストは1件です(合計で3件まで)。ウォレットの切り替えやロックを行うと、待機中のリクエストには「拒否」が返されます。0.4.5 以降、QoreX がロックされている間のサイトの署名リクエストは、サイト名を表示したパスワード画面を開き、ロック解除後に承認画面を表示します。ウィンドウを閉じると拒否されます。[承認ウィンドウに表示される内容](/qorex/security-and-recovery#approvals)を参照してください。

### Dashboard ブリッジ(v0.1.5、v0.2.2 で拡張){#dashboard-bridge}

バージョン 0.1.5 では、**`dashboard.qorechain.io` のみ**を対象とするブリッジが追加されました。`window.qorex.native.connectProof(sessionId)` は *Connect with QoreX* のペアリング証明に署名し(バックエンドが署名を再検証します)、`executeTransfer({ to, amountUqor, memo })` は Dashboard が提案した QOR 送金を承認・ブロードキャストし、`txHash` を返します。これらのメソッドは、それ以外のオリジンからは拒否されます。

**0.2.2** では `native:executeRequest` が追加され、これは[ステーキング](#stake-dashboard)を含む Dashboard 提案リクエスト全体を受け付け、QoreX が他のあらゆる箇所で使用しているのと同じ共有パーサーで検証されます。ネットワークの不一致、見覚えのないオリジン、あなたのものではないアドレス、不明なリクエスト種別、または `toAddress` を含むステーキングリクエスト(ステーキングリクエストには本来 `toAddress` はありません)の場合は拒否されます。リクエスト種別は、send、delegate、undelegate、redelegate、claim です。Connect リクエストでは、リンクするアカウントを選択でき、`listAccounts()` はあなたのアカウントを返します(読み取り専用)。

`qor1…` アドレスはメインネットとテストネットの両方で同様に有効であるため、Dashboard が提案するリクエストには対象ネットワークが明記されており、それが拡張機能が現在接続しているネットワークと一致しない場合、QoreX はそのリクエストの実行を拒否します。リクエストに応じてネットワークを勝手に切り替えることは決してありません。

## dApp から QoreChain トランザクションを送信する: `signAndBroadcast` {#sign-and-broadcast}

ML-DSA-87 鍵が登録されたアカウントからの QoreChain のネイティブレーンのトランザクションはすべて、ハイブリッド署名(secp256k1 **と** ML-DSA-87)を必要とします。ML-DSA 鍵を保持しているのはウォレットだけなので、ページ側でそれを構築することはできません。dApp は `window.qorex.native.signAndBroadcast({ chainId, messages, memo?, gasLimit? })` でメッセージを送ります。QoreX はデコードしたメッセージと手数料を表示し、あなたが選択したアカウントのトランザクションを構築し、ハイブリッド署名を追加し(これがそのアカウントの最初のトランザクションであれば、先にアカウントの ML-DSA-87 鍵を登録します)、ブロードキャストして、`{ txHash, code, height?, shield }` で解決します。拡張機能 **0.3.5** 以降で利用できます。

- チェーンはウォレットのアクティブなネットワーク(メインネットでは `qorechain-vladi`)である必要があります。dApp がネットワークを切り替えることはできず、切り替えられるのはあなただけです。
- 1回の呼び出しにつき 1-32 件のメッセージ。手数料は承認前に表示されます。ML-DSA-87 鍵の管理などのウォレット専用メッセージは拒否されます。
- cosmjs、cosmos-kit、Interchain Kit は `getOfflineSigner`(0.4.0 以降)で動作し、QoreX が ML-DSA-87 レイヤーとそれに伴う手数料を追加します。
- `signArbitrary` は、アカウントの従来型鍵と ML-DSA-87 でメッセージに署名します(0.4.0 以降)。

ルール、ガス、エラー、完全なコードサンプルは [dApp を QoreX と連携する](/qorex/dapp-integration#sign-and-broadcast)にあります。

## ハイブリッド署名 {#pqc}

QoreX 自身が開始するすべてのネイティブ QOR 送金は、`@qorechain/sdk` のハイブリッドパイプラインを用いて、従来型の secp256k1 鍵と **ML-DSA-87**(FIPS 204)の2つで署名されます。**切り替えオプションはありません**。QoreChain がこれを必須としており、QoreX がこれなしで Native レーンの QOR 送金を送信することは決してありません。

- **dApp が開始する Native 署名** - [`signAndBroadcast`](#sign-and-broadcast) を使用してください。QoreX はすべてのメッセージをデコードし、手数料を表示し、ML-DSA-87 レイヤーを自ら追加します。`signDirect` と cosmjs の署名者(`getOfflineSigner`)はページが構築したトランザクションに署名します。ML-DSA-87 レイヤーがなければ QoreX が追加し、ページが付けたレイヤーは承認ウィンドウが開く前にアカウントの登録済みの鍵に対して確認されます(MetaMask からインポートしたアカウントは `signAndBroadcast` を使います)。QoreX はブラインド署名を一切行いません。デコードできないリクエストは拒否され、従来型署名のみの QoreChain トランザクションには決して署名しません。[dApp を QoreX と連携する](/qorex/dapp-integration#cosmjs)を参照してください。
- **従来型の署名には常にラベルが付きます** - 外部ネットワーク(ETH、BNB、Solana など)への送金は ML-DSA-87 署名を扱えません。QoreX は明示的な確認事項へのチェックを求め、黙って降格させるのではなく、従来型としてマークします。

**これがトランザクションサイズに与える影響。** ML-DSA-87 は大きな署名です。署名は **4,627 バイト**、公開鍵は **2,592 バイト**(FIPS-204 により固定)です。そのため、ハイブリッドの QoreChain トランザクションは、純粋な従来型トランザクションよりも数キロバイト大きくなります。自前でトランザクションを構築・ブロードキャストする場合は、この追加バイト分を見込んでバッファとガス見積もりのサイズを調整してください。QoreChain のガス計算はすでにこれを見込んでいます。プリミティブと決定論的署名の要件については、開発者ガイドの[ポスト量子署名](/developer-guide/post-quantum-signing)を参照してください。

## 制限事項と既知の問題 {#limits}

- **EVM の署名には制限があります。** プロバイダーは `personal_sign`、`eth_signTypedData_v4`、`eth_sendTransaction`(QoreChain、および Ethereum はサイトごと)に署名し、その他の署名メソッドは拒否します。QoreChain で送信できるのは MetaMask からインポートしたアカウントのみで、EVM トランザクションには認可ウィンドウが必要です(承認画面がそのトランザクション用に開きます)。持つのは secp256k1 署名のみです。[dApp を QoreX と連携する](/qorex/dapp-integration#evm)を参照してください。
- **`window.qorex.native` は Keplr 形式であり、Keplr の完全な代替ではありません。** `window.keplr` のエイリアスはありません。`signAmino` と `sendTx` はありません。Amino はコード `4200` で拒否されます。`getOfflineSigner` と `signDirect` は動作し、ページがレイヤーを付けない場合は QoreX が ML-DSA-87 レイヤーを追加します。`signArbitrary` と `verifyArbitrary`(メッセージ署名)は 0.4.0 以降で動作します。dApp はネットワークを切り替えられず、ウォレット専用のメッセージ(鍵の管理、支出ルール、EVM ウィンドウ、特定の grant)はどのサイトからも拒否されます。
- **モバイル専用:** ポートフォリオ、Q-Day Scanner、ソーシャルリカバリー、Legacy、サインイン、端末リンク、@handle の取得。
- 拡張機能には **Swap 画面がありません**。
- **パスキーによるアンロック**が提供されるのは、ブラウザが拡張機能ページに WebAuthn を公開している場合(Chrome と Edge)のみで、Firefox では表示されません。
- **Safari** では、承認はポップアップではなくブラウザタブで開きます。
- **外部ネットワーク**が受け付けるのは従来型署名のみです。QoreX は送金のたびにこれを確認するよう求めます。
- **テストネット専用:** IBC による別のチェーンへの送金、QoreChain Bridge 画面、QoreChain 上の Solana。[テストネット機能](/qorex/testnet-features)を参照してください。
- **AI エージェント**には、まだ公開されていないコンパニオンプログラムが必要で、Safari では利用できません。
- 現時点で**履歴**の対象は QoreChain のみです。
- 拡張機能のボルトは、このブラウザ内にのみ存在します。拡張機能を削除する、そのデータを消去する、またはブラウザをリセットすると鍵は削除されます。復元できるのは、書き留めた24語だけです。
