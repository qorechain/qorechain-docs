# 主な機能

次の表は、QoreChain のすべての主要機能を、それが導入されたリリースフェーズ別に整理して一覧化したものです。2026 年 6 月 7 日から稼働しているメインネット（`qorechain-vladi`、EVM チェーン ID 9801）は **v3.2.4** を実行しています（2026 年 10 月 23 日に高さ 3,742,566 で適用）。並行して稼働するテストネット（`qorechain-diana`、EVM チェーン ID 9800）は 2026 年 10 月 19 日から v3.2.4 を実行しています。機能一覧の末尾にある[機能ステータス](#feature-status)の表は、現在ライブネットワークで有効なものを示しています。

| 機能                       | 導入バージョン      | 説明                                                                                                                                                                                                                                                                                                                                                                                           |
| -------------------------- | ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| PQC ハイブリッド署名（デフォルトで必須） | v1.1.0 (Security)   | すべての cosmos パストランザクションでのデュアル署名: 従来の secp256k1（ECDSA）署名と ML-DSA-87（Dilithium-5）をペアにします。v3.1.71 以降、ネットワークのデフォルトは**必須**（`hybrid_signature_mode = required`、`allow_classical_fallback = false`）です。従来型のみの cosmos トランザクションは拒否されます。ジェネシス gentx と PQC 鍵の登録/移行トランザクションのみが免除されます。EVM トランザクションは `eth_secp256k1` 署名を維持しますが、v3.2.0 以降は、ML-DSA-87 鍵が登録済みで、かつ [EVM 認可ウィンドウ](/getting-started/first-transaction#evm-window)が開いているアカウントからのみ受け付けられます。3 つのガバナンス制御の強制モード（disabled / optional / required）が引き続き利用可能です。 |
| SHAKE-256 デフォルトハッシュ | v1.1.0 (Security)   | SHA-3 ファミリーの拡張可能出力関数（XOF）。v3.1.73 以降、SHAKE-256（`qorehash` パッケージ経由）は**デフォルトのアプリケーションハッシュ**であり、PQC ベースライン（Dilithium-5 + ML-KEM-1024 + SHAKE-256）を完成させます。可変長ハッシュ、固定 32 バイト出力、Merkle 内部ノード連結、ドメイン分離ハッシュを提供します。すべて FFI 依存なしの純粋な Go で実装されています。 |
| TEE および FL インターフェース | v1.1.0 (Security)   | Trusted Execution Environment アテステーション（SGX、TDX、SEV-SNP、ARM CCA）および連合学習（Federated Learning）協調（FedAvg、FedProx、SCAFFOLD 集約方式）のインターフェース仕様（実装はまだありません）。どちらも将来のリリースで予定されています。 |
| オンチェーン RL コンセンサス（PRISM） | v1.0.0 (Genesis) | Go ネイティブの固定小数点 MLP（73,733 パラメータ）が、PPO 推論のためにブロックライフサイクルに組み込まれています。PRISM は、ブロックタイム、ガス価格、プールの重みを調整するよう設計されています。ライブネットワークでは現在、観測のみを行っています（学習済みポリシーはロードされておらず、制御メッセージは無効です）。決定論的なテイラー級数数学により、すべてのバリデーターで同一の結果が得られるよう設計されています。4 つの動作モード（shadow、conservative、autonomous、paused）があり、両ネットワークとも conservative に設定されています。安全のためのサーキットブレーカー保護。 |
| トリプルプール複合 PoS     | v1.0.0 (Genesis)    | 設計上の仕様: バリデーターは 1,000 ブロックごとに RPoS（評判加重）、DPoS（委任加重）、PoS（標準）プールに分類されます。プール加重のソーティションにより、純粋なステーク優位を超えてブロック生成が多様化され、カスタムボンディングカーブは、自己ボンドステーク、ロイヤルティ期間、評判品質、プロトコルフェーズを考慮します。`x/qca` に実装されていますが、**ブロック生成、報酬、スラッシングではまだ有効ではありません**。ブロック提案とスラッシングは現在、標準のステーク加重ルールに従っています。 |
| QDRW ガバナンス            | v1.0.0 (Genesis)    | 評判加重を伴う二次委任（Quadratic Delegation with Reputation Weighting）。投票力は、シグモイド評判乗数によって減衰された平方根関数を使用し、クジラによる支配を防ぎつつ、長期的で誠実な参加に報いるよう設計されています（100 倍のステーク優位は約 10 倍の投票力をもたらし、xQORE 保有は投票の重みを 2 倍にします）。実装済みですが、**ライブネットワークでは無効**です（`qdrw` はオフ）。提案は現在、ボンドされたステークに基づいて集計されます。 |
| バーンエンジン             | v1.0.0 (Genesis)    | 12 のバーンソース（ガス手数料、コントラクト作成、AI サービス手数料、ブリッジ手数料、トレジャリーによる買い戻し、失敗したトランザクション、xQORE ペナルティ、自動買い戻し、TGE バーン、ロールアップ作成、トランザクション数マイルストーン、AMM）。メインネットでは、これまでにバーンが記録されたのはガス手数料チャネルと失敗トランザクションチャネルのみです。エポック発行を含め、手数料コレクターに入るすべては、**37% がバリデーターへ、30% が永久にバーン、20% がトレジャリーへ、10% がステーカーへ、3% がライトノードへ**分割されます。 |
| xQORE ステーキング         | v1.0.0 (Genesis)    | まだ稼働していません: このモジュールのロックおよびロック解除トランザクションはライブネットワークに接続されていません（[xQORE ステーキング](/user-guide/xqore-staking)を参照）。設計上の挙動: QOR をロックして 1:1 の比率で xQORE をミントし、QDRW 投票で 2 倍のガバナンス重みを得ます。段階的離脱ペナルティ（30 日未満で 50%、30〜90 日で 35%、90〜180 日で 15%、180 日後は 0%）は、PvP リベースを通じて残りの保有者に再分配され、確信に報い、短期資本にペナルティを課します。 |
| 上限付き発行               | v1.0.0 (Genesis)    | 有限の供給経路: ジェネシス時点で 4,420,000,000 QOR（計画された 4,500,000,000 QOR のうち 80,000,000 QOR は TGE でバーン）に加えて、`x/inflation` がミントするステーキング発行が、累計 590,000,000 QOR の厳格な上限のもとで行われます（`fixed` モードでは 43,200 ブロックのエポックあたり 86,000 QOR。2026 年 10 月のガバナンス提案 10 以降）。バーンはトークンを永久に取り除きます。[トークノミクス](/architecture/tokenomics#supply-and-emission)を参照してください。 |
| EVM ランタイム             | v1.0.0 (Genesis)    | EIP-1559 ガス価格設定、ポート 8545 での JSON-RPC（`eth_`、`web3_`、`net_`、`txpool_` 名前空間。`qor_` 名前空間はまだ提供されていません）、標準ツールサポート（Hardhat、Foundry、Remix）を備えた完全な Ethereum 互換性。既存の Ethereum ワークフローを使用して Solidity コントラクトをデプロイおよび操作できます。v3.2.0 以降、送信者にはポスト量子鍵の登録と、開いている [EVM 認可ウィンドウ](/getting-started/first-transaction#evm-window)が必要です。 |
| QoreChain Native ランタイム        | v1.0.0 (Genesis)    | QoreChain における CosmWasm ランタイムの呼称。Rust ベースのコントラクト向け WebAssembly スマートコントラクトエンジン。完全なライフサイクルサポート: instantiate、execute、query、migrate。コントラクトは決定論的実行を備えたサンドボックス化された Wasm 環境で実行されます。コードのアップロードとインスタンス化は、現在両ネットワークで**無効**です（ガバナンス設定とサーキットブレーカー）。 |
| SVM ランタイム             | v1.0.0 (Genesis)    | Rust ベースのエグゼキューターによる BPF プログラムのデプロイと実行。ポート 8899 での Solana 互換 JSON-RPC サーバーは `getAccountInfo`、`getBalance`、`getSlot` などをサポートします。読み取りメソッドはパブリックエンドポイントで動作します。SVM のトランザクションレーンは現在、ネットワーク全体で**無効**です。 |
| クロス VM ブリッジ         | v1.0.0 (Genesis)    | 3 つすべての VM 間でのシームレスな相互運用性。EVM コントラクトはプリコンパイル経由で QoreChain Native を呼び出し（まだ有効ではありません。[ネットワークステータス](/developer-guide/evm-precompiles#network-status)を参照）、QoreChain Native コントラクトはカスタムメッセージ経由で EVM を呼び出し、SVM プログラムは非同期イベントベースのブリッジングを通じて参加します。単一チェーン内での同期的な EVM-QoreChain Native 呼び出しと非同期の SVM メッセージング。クロス VM 呼び出しメッセージは現在、メインネットでオフになっています。 |
| クロスチェーン接続性       | v1.2.0 (Interop)    | 最大 8 つの IBC カウンターパーティ（Cosmos Hub、Osmosis、Noble、Celestia、Stride、Akash、Babylon、Injective）に加え、**37 の QCB チェーン設定（36 の外部チェーンと、IBC 経由の Injective）**を想定して設計されています。PQC 署名のバリデーターアテステーション、チェーンごとの確認深度、サーキットブレーカーのボリューム上限。2026 年 10 月時点で、37 すべてのチェーン設定が `pending` ステータスにあり、どちらのネットワークでも IBC チャネルは開かれていません — **ライブではありません**。 |
| BTC リステーキング         | v1.2.0 (Interop)    | 設計段階 — このモジュールのトランザクションはライブネットワークで有効化されていません。Bitcoin ファイナリティ保証のための Babylon Protocol 統合。バリデーターは BTC ステーキングポジション（最小 100,000 サトシ）を登録することになります。QoreChain のエポック状態ルートは、IBC リレーされた Babylon エポックを介して定期的に Bitcoin にチェックポイントされ、BTC ハッシュレートに支えられた二次的なファイナリティレイヤーを提供します。 |
| アカウント抽象化           | v1.2.0 (Interop)    | プロトコルレイヤーでのプログラマブルなスマートアカウント（ERC-4337 に類似）。3 つのアカウントタイプ: マルチシグ、ソーシャルリカバリー、セッションベース。きめ細かい権限と有効期限を持つセッションキー、アカウントごとの日次およびトランザクションごとの支出ルール、スコープ付き denom 許可リスト。実装済みですが、現在は両ネットワークで**オフ**になっています（`abstractaccount.enabled = false`。`GET /qorechain/abstractaccount/v1/config` で確認できます）。 |
| MEV 保護                   | v1.2.0 (Interop)    | 暗号化メンプール向けの FairBlock しきい値 ID ベース暗号化（tIBE）フレームワーク。トランザクションが含まれるまでブロックプロポーザーに対して不透明に保つよう設計されています。FairBlockDecorator ante ハンドラーは配線済みです。tIBE しきい値復号は鍵セレモニーのデプロイ後に有効化されます。現在、両ネットワークで**無効**です（`enabled = false`）。 |
| ガス抽象化                 | v1.2.0 (Interop)    | ユーザーが受け入れられたネイティブ以外のトークンで手数料を支払えるよう設計されています。設定には、レート 1:1 の `ibc/USDC` とレート 10:1 の `ibc/ATOM` が記載されています。IBC チャネルはまだ開かれていないため、そのようなトークンはネットワーク上に存在せず、手数料は現在 QOR で支払われます。 |
| 5 レーン優先順位付け       | v1.2.0 (Interop)    | レーン定義（PQC、MEV、AI、Default、Free）は設定として存在しますが、ブロックスペースのレーンは、ライブのメンプールやプロポーザルハンドラーによって強制されていません。 |
| オンチェーン流動性（AMM）  | v1.2.0 (Interop)    | ネイティブな自動マーケットメーカー（`x/amm`）が、プロトコルレイヤーでオンチェーンの流動性プールとスワップを提供します。このモジュールは稼働中ですが、プールはまだ作成されていません。 |
| RDK ロールアップ           | v1.3.0 (Rollups)    | 4 つの決済パラダイム（optimistic、zk、based、sovereign）、5 つのプリセットプロファイル（defi、gaming、nft、enterprise、custom）、SHAKE-256 ブロブストレージと自動プルーニングを備えたネイティブ DA ルーター、設定可能な作成バーン率を備えた bank エスクローライフサイクル、EndBlocker 自動ファイナライズ、コンセンサスモジュール経由の PRISM 支援設定を備えた Rollup Development Kit。ロールアップ機能はホストチェーンフレームワークとして提供されます。ライブネットワークでは、ロールアップはまだ作成されていません。 |
| チェーンライセンス         | v1.3.0 (Rollups)    | `x/license` モジュールは、プロトコルネイティブなチェーンライセンスを提供します。 |

## 機能ステータス（2026 年 10 月） {#feature-status}

2026 年 10 月 20 日にライブネットワークで検証しました。「ライブ」とは、その機能がメインネットで有効であること（行に別途記載がない限り、テストネットでも有効であること）を意味します。上記の説明は、各機能が何を行うよう設計されているかを示しています。

| 機能 | ライブネットワークでのステータス |
| --- | --- |
| ハイブリッド ML-DSA-87 + secp256k1 署名（Cosmos レーン） | **ライブ**、必須（`hybrid_signature_mode = required`） |
| EVM 認可ウィンドウ | v3.2.0 以降**ライブ**（v3.2.3 以降は任意のスコープ指定） |
| 時間ロック付きステーキング（`x/stakingtier`、任意） | v3.2.4 以降**ライブ**（テストネットでは 2026 年 10 月 19 日から、メインネットでは 2026 年 10 月 23 日から） |
| EVM、QoreChain Native、SVM ランタイム | EVM は**ライブ**。QoreChain Native のコードアップロードとインスタンス化は**無効**（ガバナンス設定とサーキットブレーカー）。SVM のトランザクションレーンは**無効**（読み取りは動作） |
| バーンエンジンと手数料分配（37/30/20/10/3） | **ライブ**。メインネットでバーンが記録されたのはガス手数料と失敗トランザクションのバーンチャネルのみ |
| 上限付き発行（`x/inflation`） | **ライブ**。エポックあたり 86,000 QOR の固定、上限は 590,000,000 QOR（メインネット） |
| ステーキング、スラッシング、ガバナンス | **ライブ**（標準モジュール。[チェーンパラメーター](/appendix/chain-parameters)を参照） |
| ライトノード報酬 | 報酬の集計は**ライブ**。登録は**受付中**でライセンスによる制限があり、登録済みのライトノードはまだありません（[ステータス](/light-node/overview#reward-program-status)を参照） |
| AMM（`x/amm`） | モジュールは**ライブ**、プールはまだ作成されていません |
| PRISM（`x/rlconsensus`） | **観測のみ** — ポリシーはロードされていません |
| トリプルプール CPoS / QDRW（`x/qca`） | 実装済み、ブロック生成、報酬、集計には**接続されていません** |
| xQORE（`x/xqore`） | 集計のみ — **ロック/ロック解除トランザクションはまだありません** |
| スマートアカウント / リンクされたウォレット（`x/abstractaccount`） | 実装済み、**オフ**（`enabled = false`） |
| Rollup Development Kit（`x/rdk`）、マルチレイヤー | モジュールは**ライブ**、ロールアップもレイヤーもまだ作成されていません |
| クロスチェーンブリッジ、IBC、Babylon リステーキング | **保留中** — 37 すべてのチェーン設定が `pending`、IBC チャネルは開かれておらず、リステーキングのトランザクションもありません |
| FairBlock MEV 保護 | **無効**（`enabled = false`） |
| EVM プリコンパイル、`qor_` JSON-RPC 名前空間 | **有効でない / 提供されていない**（有効なプリコンパイルの一覧は空です） |

## バージョン履歴

<details>

<summary>v1.0.0 — ジェネシスリリース</summary>

ポスト量子暗号（Dilithium-5、ML-KEM-1024）、PRISM オンチェーン強化学習コンセンサスレイヤー、クロス VM メッセージングを備えたトリプル VM ランタイム（EVM、QoreChain Native、SVM）、トークノミクスエンジン（burn、xQORE、発行モジュール）、トリプルプール複合 PoS バリデーター選択、QDRW 二次ガバナンス、AI トランザクション処理パイプラインを備えたコアプロトコルを確立しました。

</details>

<details>

<summary>v1.1.0 — セキュリティ強化リリース</summary>

従来の secp256k1（ECDSA）署名と ML-DSA-87 をペアにするハイブリッド署名アーキテクチャ、3 つのガバナンス制御の強制モード、将来の Merkle ツリー置き換えのための SHAKE-256 ポスト量子ハッシュ基盤、TEE アテステーション（SGX、TDX、SEV-SNP、ARM CCA）および連合学習協調（FedAvg、FedProx、SCAFFOLD）のための本番グレードのインターフェース仕様を導入しました。

</details>

<details>

<summary>v1.2.0 — 相互運用性と UX リリース</summary>

クロスチェーン接続性（8 つの IBC チャネル + 36 の外部チェーンをカバーする 37 の QCB 設定、現在テストネット/保留中）、Babylon Protocol を介した BTC リステーキング、セッションキーとソーシャルリカバリーを備えたスマートアカウント抽象化、FairBlock MEV 保護フレームワーク、マルチトークンガス抽象化、オンチェーン流動性（`x/amm`）、5 レーンブロックスペース優先順位付けを追加しました。

</details>

<details>

<summary>v1.3.0 — ロールアップエコシステムリリース</summary>

4 つの決済パラダイム（optimistic、zk、based、sovereign）、5 つのプリセットデプロイプロファイル（defi、gaming、nft、enterprise、custom）、ネイティブ DA ルーター、bank エスクローライフサイクル管理、EndBlocker 駆動の自動ファイナライズ、PRISM 支援ロールアップ設定、チェーンライセンス（`x/license`）を備えた Rollup Development Kit を出荷しました。自動サイドチェーン登録と状態アンカリングのためのマルチレイヤーアーキテクチャモジュールとの深い統合。

</details>
