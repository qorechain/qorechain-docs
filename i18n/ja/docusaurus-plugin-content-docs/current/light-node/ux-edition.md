# UX エディション — Web ダッシュボード

**UX(User eXperience)**エディションは SX エディションと同じライトノードデーモンを実行しますが、ブラウザでノードとネットワークを確認できる**組み込みの Web ダッシュボード**が追加されています。バイナリは `lightnode-ux` です。SX エディションと同様、これはライトノードの**v3.1.2**系列です(チェーンバージョンとは別の、独自のバージョン)。

UX エディションは、デスクトップでの利用や、コマンドラインよりビジュアルなインターフェースを好むオペレーターにとって最適な選択肢です。

## インストール

プリビルドされたバイナリは**ネイティブ依存関係ゼロの5つのプラットフォーム**でネイティブに動作します — Linux(amd64、arm64)、macOS(Intel、Apple Silicon)、Windows(amd64、arm64)。各バイナリはおよそ16 MBです。

### ソースからのビルド

UX エディションは**Go 1.26.1**を必要とします。そのポスト量子暗号は純粋な Go による実装です(CGO なし、ネイティブライブラリなし)。

```bash
go build -o build/lightnode-ux ./cmd/lightnode-ux/
```

これにより `build/lightnode-ux` が生成されます。

### Docker

UX サービスは `Dockerfile.ux` からビルドされます。

```bash
docker compose up lightnode-ux
```

UX コンテナは、`/root/.qorechain-lightnode` にある名前付きボリュームにデータを永続化し、チェーン RPC アドレスを `QORECHAIN_RPC_ADDR` 環境変数から読み取ります。

## 実行

UX ノードを起動します。

```bash
build/lightnode-ux start
```

これにより、デーモンと組み込みのダッシュボードサーバーが同時に起動します。UX エディションは常にダッシュボードを有効にします。起動時、バイナリはダッシュボードの URL を出力します。

UX エディションは SX エディションとセットアップを共有します。同じ `~/.qorechain-lightnode` の `config.toml` を読み取り、同じ Dilithium-5 キーリングを使用します。まだノードを設定していない場合は、先に SX ウィザード(`lightnode-sx onboard`)を実行して設定を書き込み、鍵をインポートまたは生成してください — 詳細は[SX エディション](/light-node/sx-edition)を参照してください。

## ポート8420 の Web ダッシュボード

ダッシュボードは**ポート8420**で公開されます。これは `lightnode-ux` の Docker イメージが宣言しているポート(`EXPOSE 8420`)であり、バイナリがデフォルトでバインドするポートでもあるため、Docker で実行する場合もダッシュボードは `8420` で公開されます。

```
http://localhost:8420
```

:::caution compose のポートマッピングを確認してください
他の文書ではダッシュボードのポートとして8080が記載されている箇所があります。正しい値は**8420**です — これがイメージが実際に公開し、デーモンがデフォルトでバインドするポートです。独自の `docker-compose.yml` やリバースプロキシを設定する場合は、8080ではなく**8420**にマッピングしてください。
:::

:::caution ダッシュボードのどのルートも認証を行いません
ポート8420の背後には、ログインやアクセス制御が一切ありません — 到達できる人は誰でも、あなたの設定、委任、報酬を読み取ることができます。秘密鍵が提供されることは決してありません。バイナリは現在、すべてのインターフェースではなく**デフォルトでループバックのみ**(`127.0.0.1:8420`)にバインドし、より広くリッスンするよう設定されている場合は起動時に警告を出力します — ただし、この警告は拒否ではなく、認証を追加するものでもありません。意図的にバインドを広げる場合(たとえば別のマシンから到達させるため、または Docker からポートを公開しているため)は、直接公開するのではなく、認証を要求するリバースプロキシの背後に置いてください。WebSocket テレメトリ接続もブラウザの `Origin` を確認します。広いネットワークバインドだけでは、同じブラウザで開いている別のページからの接続を防げないためです。
:::

## ダッシュボードに表示される内容

ダッシュボードは以下のビューで構成されています。

- **概要(Overview)** — ブロック高と一目でわかるノードステータス。
- **バリデーター(Validators)** — ボンドされたバリデーターセット。
- **委任(Delegation)** — 現在の委任とその分割。
- **ネットワーク(Network)** — ライブのネットワークテレメトリと最近同期されたヘッダー。
- **ブリッジ(Bridge)** — クロスチェーンブリッジのテレメトリ。
- **トークノミクス(Tokenomics)** — トークンエコノミクスのテレメトリ。
- **設定(Settings)** — ノードの有効な設定。

テレメトリはリアルタイムで更新され、デーモンはバリデーター、ネットワーク、ブリッジ、トークノミクスのデータをそれぞれ独立した間隔で更新します(`config.toml` の `[telemetry]` で設定可能)。

### ローカルのみバナー

ノードに**チェーン RPC エンドポイントが設定されていない**場合、ダッシュボードは**ローカルのみモード**で動作し、その状態を説明する目立つバナーを表示します。PQC スタックは検証済みですが、ノードはどのチェーンも同期していないため、ブロック高は `0` のままです。バナーは、ホスト上でオンボーディングウィザードを実行するよう促します。

```bash
lightnode-sx onboard
```

ウィザードは PQC セルフテストを実行し、チェーンエンドポイントを尋ね、バリデーター鍵をインポートまたは生成します。エンドポイントが設定されたら、ノードを再起動すると、ダッシュボードにライブのチェーンデータが表示され始めます。
