# 登録とライセンス

[ライトノード報酬シェア3%](/light-node/rewards-and-monitoring)を得るには、ライトノードが**オンチェーンで登録**されており、かつ稼働していることを証明し続けている必要があります。このページでは、登録の仕組み、ノードが稼働証明(liveness)を行う方法、そしてDashboardを通じてノードを登録・ライセンス化する方法について説明します。

## オンチェーン登録

登録は、あなたのライトノードをチェーン上に記録し、プロトコルがそのノードの存在、種別(`sx`または`ux`)、そしてどのオペレーターキーがそれを制御しているかを把握できるようにします。登録が完了し稼働状態になると、そのノードはライトノード報酬シェアの対象になります。

### 登録コマンドの生成

SXエディションは、このノードを登録するための正確なチェーンコマンドを出力できます。次を実行してください。

```bash
lightnode-sx register
```

このコマンドはキーリングからオペレーターキーを読み取り、あなたのオペレーターアドレス、ノード種別、バージョンとともに、すぐに実行できる`qorechaind`トランザクションを出力します。このコマンドは2つの任意フラグを取ります。

- `--type` — ノード種別。`sx`または`ux`(デフォルトは`sx`)。
- `--version` — 登録するノードバージョン(デフォルトはバイナリ自身のバージョン)。

出力されたコマンドは、オンチェーンの`x/lightnode`モジュール配下でノードを登録します。参加するネットワーク(テストネット`qorechain-diana`またはメインネット`qorechain-vladi`)上の、資金のあるオペレーターアカウントでこれを送信してください。

:::note
`lightnode-sx register`は登録トランザクションを**出力する**だけで、あなたがそれを確認・送信するためのものです — 自動的にブロードキャストされることはありません。これにより、ノードがいつ、どのように登録されるかをあなた自身がコントロールできます。
:::

## ハートビート稼働証明

登録だけでは対象資格を維持するには不十分です。登録済みのライトノードは、**ハートビート稼働証明(heartbeat liveness proofs)**を継続的に送信することで、自身がオンラインであることを証明し続けなければなりません。このハートビートによって、チェーンは稼働中のノード(報酬シェアの対象)と、登録はされているがオフラインのノードとを区別します。

実務上これが意味するのは、登録され、稼働し続けている(かつ同期している)ノードは対象資格を維持し続ける一方、オフラインになったノードは稼働証明の送信を停止し、復帰するまで対象資格を失うということです。したがって、デーモンを稼働・健全な状態に保つことは報酬を得るための一部です — ハートビートと同期の健全性を確認する方法については[Rewards and Monitoring](/light-node/rewards-and-monitoring)を参照してください。

### PQC共署名ハートビートパイプライン {#pqc-cosigned-heartbeat-pipeline}

QoreChainは**デフォルトでPQC必須**であるため、ハートビート稼働証明トランザクションは、従来型の署名のみではなく、耐量子(post-quantum)共署名パイプラインを通じて生成されます。デーモンは未署名のハートビートを組み立てた後、ブロードキャスト前に**ハイブリッドDilithium-5(ML-DSA-87)**署名でそれに共署名します — これはチェーンがすべてのトランザクションに対して強制している耐量子姿勢と同一のものです。ノードは`interval_blocks`ウィンドウ(チェーンの`heartbeat_interval`パラメータに対応)ごとに1回ハートビートを送信し、早期送信による拒否を避けるためブロック高に合わせてペースを調整します。

オンチェーンのハートビートはデーモン内で任意設定です。ノード設定の`[heartbeat]`セクションを有効化し(`enabled = true`)、`qorechaind_path`を`qorechaind`バイナリに向けてください。これにより生成後に共署名を行うフローが実行されます。これが設定されていない場合、ノードはオンチェーンハートビートを送信せずに稼働し、オペレーターは出力されたチェーンコマンドを使って手動で稼働証明を送信できます。

## Dashboardを通じた登録とライセンス化

QoreChain Dashboardの**Tools**ページから、ノードを起動し、そのライセンス状況を確認することもできます。ノードを稼働させることと、報酬プログラムに参加することは別のことであり、Dashboardは単一のガイド付きサインアップフローとして提示するのではなく、この2つを明確に分けています。

1. **ノードを起動する(Tools → Light Node、ステップ1)。** これにはライセンスも、いかなる種類のオンチェーンチェックも必要なく、他の何よりも先にすべての訪問者に表示されます。現在のネットワークマニフェストをライブで読み込み、バイナリのダウンロードと検証、ジェネシスによるノードの初期化、`config.toml`をネットワークのピアに向ける設定、そしてジェネシスからの同期の代わりにステートシンクを行う手順を案内します。
2. **報酬プログラムのステータスを確認する(Tools → Light Node)。** ライトノード報酬シェアへの参加は、別個の、オンチェーンでゲートされたステップです。これには、オンチェーンで付与された有効な`lightnode_operator`ライセンス、最低限のQORデリゲート量(バリデータごとではなく、あなたが委任しているすべてのバリデータの合計として数えられ、自己申告ではなくステーキングからライブで読み取られます)、そして少額のオンチェーン登録手数料が必要です。**登録受付はまだ開始されていません**。**Buy License**を通じてライセンスを購入しても、それによって早期に開始されることはありません — 現時点では申し込めるものは何もありません。開始されるまでは、このタブはフォームとしてではなく、確認すべきステータスとして要件を表示します。それまでの間、ノードを稼働させ同期させておいてください。登録受付開始前の稼働時間は、開始後にカウントされる見込みです。
3. **ライセンスがオンチェーンで付与されたら登録する(Tools → Light Node)。** **Buy License**を通じて購入したライセンスは、まず私たち側で記録されます。それをオンチェーンで認識させる付与処理は別のステップであり、その付与が反映されるまで登録は拒否されます。付与が反映されると、このタブはステータスパネルを登録フォームに置き換えます。あなたのオペレーターアドレス(`qor1…`)、モニカー、公開エンドポイントURL、そしてステークコミットメントへの同意です。
4. **確認してステークをボンドする。** 送信後、Dashboardは登録内容(モニカー、オペレーターアドレス、エンドポイント、ステーク意向、ステータス)の確認サマリーを表示します。対象資格が開始したら、オペレーターアドレスから同意済みのステークをボンドしてください。

CLIよりUIを好む場合、またはライセンス管理と登録を一箇所でまとめて行いたい場合はDashboardフローを利用してください。上記の`lightnode-sx register`コマンドは、自分でトランザクションを構築・確認したい人のために引き続き利用可能です — オンチェーン登録と報酬プログラムの対象資格は、どちらの方法を使っても同じようにチェーンによって管理されます。
