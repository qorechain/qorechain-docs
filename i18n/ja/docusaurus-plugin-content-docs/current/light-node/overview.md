# ライトノード概要

**QoreChain ライトノード**は、フルバリデーターやアーカイブノードを実行せずに QoreChain ネットワークを追跡する軽量なクライアントです。すべてのトランザクションを再生する代わりに、複数の RPC エンドポイントにまたがってブロックヘッダーを照合し、オペレーターアカウントの委任と報酬をチェーンから反映し、ライブのネットワークテレメトリをストリーミングします。これらすべてが、小さく自己完結したバイナリから行われます。

ライトノードを実行することで、フルノードのストレージ、帯域幅、運用コストをかけずに、ネットワークの状態を観察できます。ライトノード報酬分配への参加は、ライセンスが必要な別のステップであり、登録は両ネットワークで開放されています — [報酬プログラムのステータス](#reward-program-status)を参照してください。

## 独自のバージョンライン

ライトノードは**独自のバージョンライン — 現在 3.1.9** で出荷されており、これは**チェーンリリースバージョンとは別個のもの**です（メインネットはチェーン `v3.2.3` を実行しています）。各ネットワーク向けのバイナリは、`https://download.qore.host/<net>/lightnode/latest.json` に **SHA-256 チェックサムマニフェスト**とともに公開されています（`<net>` は `mainnet` または `testnet`）。どちらのチャネルも同じ 3.1.9 ビルドを配布しており、両方のマニフェストが `minCompatible` を `3.1.9` に設定しているため、古いライトノードビルドは置き換える必要があります。このリリースには 12 個のバイナリ — Linux、macOS、Windows 向けの SX と UX、それぞれ amd64 と arm64 — と `SHA256SUMS` ファイルが含まれます。ダウンロードと検証の手順については [SX Edition](/light-node/sx-edition#install) を、ソースタグ `v3.1.9` からイメージをビルドする方法については [Docker](/light-node/sx-edition#docker) を参照してください。

Android ビルドは GitHub リリースに**プレビュー**としてのみ添付されています。チェーンを追跡して検証しますが、登録は行わず、報酬も獲得しません。

ドキュメントやリリースノートを読む際は、ライトノードのバージョン（3.1.9）とチェーンのバージョン（v3.2.3）を、たまたま同じメジャーシリーズを共有する 2 つの別個の番号として扱ってください。

## ライトノードを実行する理由 {#why-run-a-light-node}

- **ライトノード報酬分配に参加する。** ステークとアップタイムのルールを満たす、登録済みでアクティブなライトノードは、以下で説明する **3% のライトノード割り当て**の対象となります。登録には `lightnode_operator` ライセンスが必要です — [Registration and Licensing](/light-node/registration-and-licensing) を参照してください。ノードの実行と同期にライセンスは不要です。
- **提示されたチェーン状態をクロスチェックする。** ノードは、プライマリの RPC エンドポイントと、設定されたすべての witness エンドポイントから並行して最新の高さを取得し、それらがブロックハッシュについて一致した場合にのみヘッダーを保存します — これにより、単一のエンドポイントを信頼するという水準から、設定されたすべてのエンドポイントが同時に侵害される必要があるという水準へと基準が引き上げられます。これは独立した複数のソースにまたがる照合であり、**完全な暗号学的コンセンサス検証ではありません**（バリデーターセットやコミット署名のチェックは行いません）。あなたのノードは、動作しているモードを、デバッグログ（`log_level = "debug"` を設定）の各 `synced header` 行にある `assurance` の値として記録します。これはノードのダッシュボードにも `status` にも表示されず、ノードの RPC 選択があなたの環境にローカルなものであるため、QoreChain の中央サービスから見ることもできません。**`trusted-single-source`** は、witness が設定されていない場合の状態です — 正直に運用されている単一のエンドポイントも、侵害されたエンドポイントと同じ値を報告するため、ノードは起動時にその旨の警告をログに記録します。独立して運用される witness を追加すると、`corroborated-across-sources` に移行します。
- **ステークを見守る。** ノードは、オペレーターアカウントの委任をチェーンから反映し、委任先のバリデーターが設定可能な評判スコアを下回ると警告します。ノード自身がステークを動かすことはありません — 委任の変更は、あなた自身のウォレットから行います。
- **ネットワークをライブで監視する。** リアルタイムのテレメトリは、バリデーター、コンセンサス、ブリッジ、トークノミクスをカバーします。
- **初日からポスト量子。** 鍵と署名は Dilithium-5（ML-DSA-87）を使用します。

## 2 つのエディション: SX と UX

ライトノードは、同じコードベースから構築された 2 つのエディションで提供されます。ノードをどのように運用したいかに合ったものを選択してください。

| エディション | バイナリ | 対象 | インターフェース |
| --- | --- | --- | --- |
| **SX — Server eXperience** | `lightnode-sx` | ヘッドレスサーバーデプロイ | 完全な CLI（デーモン + 管理コマンド） |
| **UX — User eXperience** | `lightnode-ux` | デスクトップおよびオペレーター利用 | 組み込み Web ダッシュボード |

- **SX エディション**は、完全な管理 CLI を備えたヘッドレスデーモンです。サーバー、自動化、コマンドラインで生活するオペレーターにとって正しい選択です。[SX Edition](/light-node/sx-edition) を参照してください。
- **UX エディション**は、同じデーモンを実行しますが、組み込み Web ダッシュボードを追加し、テレメトリ、委任、報酬をブラウザで監視できます。[UX Edition](/light-node/ux-edition) を参照してください。

両エディションは、同じ `config.toml` を読み込み、同じホームディレクトリ（デフォルトでは `~/.qorechain-lightnode`）にデータを保存し、同じ Dilithium-5 キーリングを使用します。

## 3% のライトノード報酬分配 {#the-3-light-node-reward-share}

QoreChain の手数料分配は、**固定の 3% 分配をライトノードに**割り当てます（`reward_share` パラメータ、`0.03`）。完全な 37% / 30% / 20% / 10% / 3% の内訳（バリデーター、バーン、トレジャリー、ステーカー、ライトノード）については [Tokenomics](/architecture/tokenomics) を参照してください。

この 3% はライトノードのモジュールアカウントに支払われる額であり、ノードごとの受給権ではありません。100 ブロックごとに、チェーンは各適格ノードに対し、前回の決済以降に蓄積された額のうちステーク加重の分配分をクレジットし、これには**ノードごとに上限**が設けられています。チェーン v3.2.3 以降、この上限は**ノードあたり 30 日ごとに 2,000 QOR**（`max_reward_per_month_per_node`、`2000000000` uqor）で、前回の決済以降に経過したブロック時間に応じて按分され、ノードのアップタイムに応じてスケールされます。これが `lightnode-monthly-cap` ルールです。v3.2.3 より前は、上限はブロック単位（`max_reward_per_block_per_node`、`1713` uqor）で定められており、報酬プールのクエリは現在もこの値を報告します。この上限はあくまで天井であり、約束された金額ではありません。獲得されなかった分は、ガバナンス投票でのみ解放できる準備金に移されるため、最初に登録した者のためにプールが積み上がることはありません。ライブの分配状況は `GET /qorechain/lightnode/v1/reward_pool` で確認できます。

報酬の対象となるには、ライトノードが**オンチェーンで登録され、アクティブ**（ハートビートでライブネスを証明）であり、最低限のボンドステークを保有し、アップタイムを最低値以上に維持している必要があります。登録とライセンスは [Registration and Licensing](/light-node/registration-and-licensing) で扱われ、報酬がどのようにクレジットされ、請求され、監視されるかは [Rewards and Monitoring](/light-node/rewards-and-monitoring) で扱われます。

## 報酬プログラムのステータス {#reward-program-status}

:::note 登録は開放されています
登録はメインネット（`qorechain-vladi`、チェーン v3.2.3）とテストネット（`qorechain-diana`）で開放されています。2026 年 10 月時点で、メインネットでは 6 件の `lightnode_operator` ライセンスが付与されており、登録されたライトノードはまだありません。報酬の会計処理は、v3.2.0 アップグレード以降、両ネットワークで稼働しています。ノードの実行と同期にライセンスは不要ですが、アップタイムは**ノードが登録されたブロックから**カウントされるため、事前にノードを動かしていてもクレジットは得られません。

リリースマニフェスト（`https://download.qore.host/<net>/lightnode/latest.json`）は、その `registration.open` フィールドで公式のシグナルを示します。ライブの状態については、`https://api.qore.host`（メインネット）または `https://api-testnet.qore.host`（テストネット）で `GET /qorechain/license/v1/holders/lightnode_operator` と `GET /qorechain/lightnode/v1/stats` をクエリしてください。
:::

## コア機能の概要

- **マルチソースヘッダー照合** — フルブロックをダウンロードすることなく、設定されたすべての witness エンドポイントに対して最新のブロックハッシュをクロスチェックしてから信頼し、コールドスタートからでも迅速に同期します。
- **委任のトラッキング** — オペレーターアカウントの委任をチェーンから反映します（読み取り専用）。
- **オプトインの自動請求** — 蓄積されたライトノード報酬を、設定可能な間隔でオペレーターアカウントへ請求します。デフォルトではオフで、再委任は行いません。
- **評判アラート** — 委任先のバリデーターが設定可能な評判スコアを下回ると警告します。ステークは動かしません。
- **リアルタイムテレメトリ** — バリデーター、コンセンサス、ブリッジ、トークノミクスを、独立した間隔で更新します。
- **オンチェーン登録** — ノードを報酬の対象として維持するハートビートライブネス証明を備えています。登録にはライセンスが必要です。ノードは Linux、macOS、Windows で自身のトランザクションに署名し、他のソフトウェアは必要ありません。
- **ポスト量子暗号** — 全体を通じて Dilithium-5（ML-DSA-87）の鍵と署名を使用します。
- **ローカル限定モード** — ライブチェーンに向ける前に、完全な PQC スタックを試し、ノードをスタンドアロンで実行します。

ライトノードは **Apache 2.0** ライセンスの下でリリースされています。
