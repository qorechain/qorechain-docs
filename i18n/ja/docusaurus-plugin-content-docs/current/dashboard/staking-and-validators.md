# ステーキングとバリデーター

**Validators** ページ(`/validators`)では、ネットワークのバリデーターを確認できます。これは読み取り専用のブラウザであり、ウォレット接続もデリゲートボタンもありません。実際のステーキング操作(delegate、undelegate、claim)は代わりに **Wallet** ページの **Stake / Delegate** タブと **Rewards** タブにあり、そこで QoreX ウォレットを接続してから行います。デリゲートを行うとネットワークのセキュリティ確保に貢献し、ステーキング報酬を得られます。デリゲートと報酬の背景にある概念については、[Staking & Delegation](/user-guide/staking-and-delegation) を参照してください。

QoreChain のステーキングは耐量子署名で行われるため、ダッシュボードがデリゲーションに署名できる鍵を保持することは一切ありません。以下のステーキング操作はすべて同じ流れで動作します。ダッシュボード上でリクエスト(どのバリデーターに、どれだけ)を作成し、[Send フロー](/dashboard/wallet#mainnet)とまったく同様に、接続済みの **QoreX ウォレット** — アプリ、または**バージョン 0.2.2 以降**のブラウザ拡張機能([どのバージョンがどこで提供されているか](/qorex/overview#platform-availability)を参照。古い拡張機能ビルドの場合、Dashboard は黙って失敗するのではなく更新を求めます) — 内で承認・署名します。ダッシュボードは `qorex://tx?...` リンクを通じてパラメーターのみを送信し、QoreX が実際のトランザクションを再構築し、署名し、ブロードキャストします。先にウォレットを接続してください。詳細は [メインネットでウォレットを使う](/dashboard/wallet#mainnet) を参照してください。

ステーキング、デリゲーション、バリデーションはすべてネイティブ(Cosmos)レーンでハイブリッド耐量子署名を用いて行われ、EVM プリコンパイル経由で行われることは決してありません。これは一時的な制約ではなく、恒久的なセキュリティ特性です。EVM レーンは単一の ante デコレーターしか実行しないため、もしステーキングをそこで公開すれば、ネイティブレーンの ante に存在するバリデーターライセンス、最低自己ボンド、PQC のチェックがすべて回避されてしまいます。MetaMask に紐づいたアドレスは QOR の送受信はできますが([メインネットでウォレットを使う](/dashboard/wallet#mainnet)を参照)、ステーキングはできません。ステーキングできるのは QoreX に接続されたアドレスのみです。

## バリデーターを確認する

:::caution メインネットで、このページは現在テストネットのバリデーターを表示しています
メインネット上の **Validators** ページは、実際のメインネットのバリデーターセット(8ノード)ではなく、テストネットのバリデーターセット(4ノード)を表示しています。これはバックエンドのデータの問題であり、あなたの接続やアカウントに問題があるわけではありません。このページをメインネットのバリデーターを判断する材料に使わないでください。代わりに [ブロックエクスプローラー](https://explore.qore.network) か直接のチェーンクエリ(`qorechaind query staking validators`)を使用してください。とはいえ、これは純粋に表示上の不一致にすぎません。[Wallet ページの Stake タブ](/dashboard/wallet#mainnet)にある **Delegate** のバリデーター選択欄は、チェーンから直接、別の正しいルートを読み取っているため、実際にはメインネットに存在しないバリデーターを選んだりデリゲートしたりすることはできません。そちらに進めば、単に別の(そして正しい)一覧が表示されるだけです。
:::

このページは、アクティブなバリデーター数、ボンド済み QOR の合計、平均コミッション、平均稼働率のサマリーカードから始まります。その下にバリデーターの一覧があります。各バリデーターの行には次の項目が表示されます。

- **順位**とバリデーターの **モニカー**(名前)、アドレスとコピーボタン。
- **投票力(Voting power)** — バリデーターのボンド済みステークとその全体に占める割合。
- **コミッション** — バリデーターが報酬から受け取る割合。
- **APY** — 数値ではなくダッシュ(—)として表示されます。QoreChain のエミッションはカスタムモジュールから発生しており、標準の利回り推定エンドポイントではそれを把握できません。そのため、ここで計算された数値を表示すれば、データを装った推測にすぎなくなります。「利用不可」として表示するのは意図的な修正であり、バグではありません。ライブでチェーンに基づいたステーキング APY を計算するエンドポイントは現時点で存在しません。他所で特定のパーセンテージを見かけても、未検証のものとして扱ってください。
- **ステータス** — 例えば active または jailed。
- 運用情報: リージョン、稼働率、ブロック提案数、ソフトウェアバージョン、最終確認時刻。

検索ボックスでバリデーター名またはアドレスによる絞り込みができます。

このページはバリデーターを比較するためだけのものです。実際にデリゲートするには **Wallet** ページに移動してください(下記参照)。

## バリデーターを選ぶ

デリゲート先のバリデーターを選ぶ際は、次の点を考慮してください。

- **コミッション** — 料率が低いほど自分に残る報酬は多くなりますが、持続可能な運営のためには運営者側にも適切な取り分が必要です。
- **稼働率とステータス** — 稼働率の高いアクティブなバリデーターを優先してください。jailed 状態のバリデーターは報酬を生みません。バリデーターは、10,000 ブロックのウィンドウ(蓄積に要する時間はおおよそ6時間)内でブロック署名の失敗が 5% を超えると jail されます。jail 中は unjail するまで、自分自身にも委任者にも報酬は発生しません。ダウンタイムによる jail は固定で**600秒(10分)**続き、バリデーターは**ステークの1%**を失います。二重署名はこれとは別の、より重大な違反であり、**5%**がスラッシュされます。これらの数値は現行のチェーンパラメーターであり、他所で見かけたそれより古い数値は現在では上書きされたものとして扱ってください。
- **投票力** — 複数のバリデーターにステークを分散させることは分散化を支えます。Delegate パネルでは、まさにこの理由からバリデーターが投票力の小さい順に表示されます。

## デリゲート、リデリゲート、アンデリゲート、報酬の請求

これら4つの操作はすべて **Wallet** ページ(`/dashboard/wallet`)にあり、Validators ページにはありません。ウォレットを開き、まだ接続していなければ QoreX を接続し([メインネットでウォレットを使う](/dashboard/wallet#mainnet)を参照)、デリゲートとアンデリゲートには **Stake / Delegate** タブを、請求には **Rewards** タブを使用します。

### デリゲート {#delegate}

1. **Wallet** ページで **Stake / Delegate** タブを選択します。
2. **Delegate QOR** パネルで、上部の情報ボックスを確認します。ここには現在のボンド済み合計とライトノードのステーク閾値との比較、およびすでに閾値を満たしているかどうかが表示されます。この閾値は**すべてのバリデーターを合わせた委任ステーク合計**に対してチェックされ、バリデーターごとではありません。そのため不足分は複数のバリデーターに分けても構いません。デリゲーションは常に特定のバリデーターに対して行われるものであり、ライトノードの資格判定はそれとは別の、合計額に対するチェックであるため、「ライトノードに直接デリゲートする」という方法自体が存在しません。
3. **Validator** ドロップダウンを開き、1つ選びます。バリデーターはステークの小さい順に表示されます。
4. **Amount (QOR)** を入力します。
5. 金額欄の下にある注記を読んでください。アンボンディングには 21 日かかり、ボンドされた QOR はその期間が終わるまで移動も売却もできません。
6. パネルに、このアドレスには手数料をまかなうのに十分な spendable QOR がないという警告が表示された場合は、先にこのアドレスへ少額の spendable QOR を送ってください。ベスティング中またはボンド済みのコインでは手数料を支払えません。この問題が解消されるまで **Continue in QoreX** ボタンは無効のままです。
7. **Continue in QoreX** をクリックします(リクエスト作成中は **Preparing…** と表示されます)。
8. パネルには **Approve it in QoreX** と、**Open QoreX** リンクおよびリクエスト ID が表示されます。QoreX は署名前にバリデーターと金額を表示します。あなたが承認するまで何も送信されません。
9. QoreX を開き(リンク/ディープリンクで開けます)、デリゲーションを承認します。QoreX がトランザクションを構築、署名、ブロードキャストします。ダッシュボードがあなたの鍵を見ることは決してありません。

### リデリゲート {#redelegate}

ダッシュボード自体には専用の Redelegate パネルはありませんが、もはやそれは必要ありません。**QoreX 自体が、バリデーター間でステークを直接移動できるようになりました**(app 1.0.8 以降、拡張機能 0.2.6 以降)。21日間のアンボンディング待ちも報酬の損失もなく、さらに1回のトランザクションで移動先の複数のバリデーターに分割することもできます。QoreX で **Stake** を開き、離れたいバリデーターをタップして、移動先を選んでください。完全な手順は [バリデーター間でステークを移動する](/qorex/portfolio-and-staking#move-stake) を参照してください。これはダッシュボード自身のリクエスト用コントラクトが提供できるものより優れた解決策なので、以下の回避策ではなく、こちらを直接使ってください。

この機能をまだ持たない古い QoreX ビルドを使っている場合は、代わりにこのページ上のフローを使って2段階でバリデーターを乗り換えてください。

1. 離れたいバリデーターから**[アンデリゲート](#undelegate)**します。
2. そのフローに表示されるアンボンディング期間を待ちます。この間、QOR は移動も報酬の獲得もできません。
3. アンボンドされた QOR が使用可能になったら、新しいバリデーターに**[デリゲート](#delegate)**します。

この回避策は、直接の移動に比べて21日分の報酬損失と余分な手数料がかかるため、可能であれば頼らずに QoreX を更新してください。

### アンデリゲート {#undelegate}

デリゲーションを解除する機能は、現在ではダッシュボード上で利用できます。以前はデリゲートはできてもここからのアンボンドはまったくできない時期があったため、もし「なかったはず」と記憶している場合はそれが理由です。

:::caution 21日間のアンボンディング期間
アンデリゲートした QOR はすぐには届きません。まず**21日間のアンボンディング期間**を経る必要があり、その間は報酬が発生せず、移動も売却もできません。このパネルはこの注意をわざと二度表示します。一度はサブタイトルとして、もう一度は確認ボタンのすぐ上に。急いでこの画面にたどり着く人(市場の急落時、あるいはバリデーターが jail されたとき)こそ、署名前にこれを目にする必要があるからです。
:::

1. **Wallet** ページで **Stake / Delegate** タブを選択し、Delegate の下にある **Unbond QOR** パネルまでスクロールします。そのサブタイトルにはすでに21日間のアンボンディングに関する警告が繰り返されています。
2. このアドレスにアクティブなデリゲーションがない場合、パネルはその旨を表示してそこで終わります。
3. **Unbond from** ドロップダウンを開き、減らしたいデリゲーションを選びます。実際にデリゲートしているバリデーターのみが、ボンド済み金額とともに一覧表示されます。
4. アンボンドする **Amount (QOR)** を入力するか、**Unbond all `<amount>` QOR** をクリックしてそのバリデーターへのボンド済み金額全額を入力します。
5. そのバリデーターへのボンド額を超える金額を入力すると、パネルがその旨を伝え、送信をブロックします。
6. 確認ボタンのすぐ上に、警告が再度表示されます。QOR は今日ではなく21日後に届き、それまでは何も報酬を生みません。これは意図的な繰り返しであり、ドキュメントの誤記ではありません。続行する前にもう一度読んでください。
7. アドレスが手数料をまかなえない場合(ボンド済みのコインでは手数料を支払えないため、先に少額の spendable QOR がここに必要です)、パネルが警告を表示し、ボタンを無効化します。
8. **Continue in QoreX** をクリックします(リクエスト作成中は **Preparing…** と表示されます)。
9. パネルに **Approve it in QoreX** と、**Open QoreX** リンクおよびリクエスト ID が表示されます。QoreX は署名前にバリデーターと金額を表示します。
10. QoreX を開いて承認します。QoreX がアンデリゲーションに署名しブロードキャストします。QOR は21日間のアンボンディング期間が終了して初めて再び使用可能になります。

### 報酬を請求する {#claim}

1. **Wallet** ページで **Rewards** タブを選択します。
2. **Staking rewards** パネルには、デリゲートしているすべてのバリデーターにわたる未受領の報酬が表示されます。このアドレスから何もステークされていない場合は、その旨が表示され、請求できるものはありません。
3. そうでなければ、請求待ちの合計金額と、バリデーターごとに発生した金額の内訳が表示されます。報酬は継続的に発生し、待っても失われることはありません。期限はありません。
4. **Claim in QoreX** をクリックします。これは一括請求です。表示されているすべてのバリデーターから発生した報酬を1回のリクエストでまとめて請求します。バリデーターごとの個別請求ボタンはありません。
5. **Open QoreX** リンク経由で QoreX 上で請求を承認し、署名・ブロードキャストします。

:::note アンボンディング期間
アンデリゲートされた QOR は、再び使用可能になるまでに21日間のアンボンディング期間を経る必要があり、その間は報酬が発生しません。詳細は [Staking & Delegation](/user-guide/staking-and-delegation) を参照してください。
:::
