# ツールハブ

**ツール** ページには、QoreChainの運用者向け・ビルダー向けツールが、次の順序で7つのタブにまとめられています。**Information**、**Validator Application**、**Buy License**、**Light Node**、**Node Registration**、**Rollups**、**SDK** です。**Information** タブは、バリデーターおよびライトノードプログラムの読み取り専用の概要で、参加の3つの方法（ジェネシスバリデーター、ライトノード、デリゲーター）、ライセンスティア、ステーキングとスラッシングの基礎、ハードウェア要件、プログラムの運営者、そしてFAQを掲載しています。その他のタブについては以下で概要を説明し、詳細なドキュメントへのリンクも示します。公開されているビルドはネットワークごとに異なる場合があるため、ツールページはヘッダーのネットワーク切り替えに連動します。

登録を記録したり申請を送信したりするツールを使用するには、サインインしてください。[サインイン](/dashboard/overview#sign-in)をご覧ください。

## ライトノード

ライトノードを稼働させることと、その報酬プログラムに参加することは別の話です。ライトノードタブは、この2つを1つの申し込みフローとしてまとめず、明確に分けて扱います。

1. **ソフトウェアを入手する — 今すぐ利用可能。** ライセンスもオンチェーンでの確認も承認も不要で、ライセンスの状態に関わらず最初に表示されます。このタブはライブのネットワークマニフェストを読み込み、フルのQoreChainノード向けに、バイナリのダウンロードと検証、ジェネシスによるノードの初期化、ネットワークのピアへの接続、そしてジェネシスからの同期の代わりにステートシンクを行うための、そのままコピーして使えるコマンドを提示します。ライトノード自体に必要なのは `lightnode-sx` または `lightnode-ux` バイナリのみです。[ライトノード概要](/light-node/overview)をご覧ください。コマンドの下にある **Download the light node** には、公開されているビルドがsha256チェックサムとともに一覧表示されます。**Desktop edition**（Webダッシュボードを含む）と **Server edition**（ヘッドレス、コマンドライン）が6つのプラットフォームで提供されており、実行する前にファイルをチェックサムと照合してください。選択したネットワーク向けに公開されたビルドがない場合は、パネルにその旨が表示されます。
2. **チェーンの要件を確認する — Light node status。** このパネルはライブのチェーンパラメータを読み取ります（これらはガバナンスパラメータであり、このページを編集しなくても変更される可能性があります）。必要な委任ステーク（バリデーターごとではなく、委任先のすべてのバリデーターにわたる合計値で、現在1,000 QOR）、登録手数料（現在1 QOR）、報酬に必要なアップタイム、ハートビートが期待される頻度（および許容される猶予）、そしてライトノードの最大数です。任意で運用者アドレスを入力すると、そのアドレスにライトノードが登録されているか、期限内に報告しているか、そして蓄積された報酬を確認できます。
3. **報酬への登録はまだ開始されていません。** ライトノードの報酬シェアに参加するには、オンチェーンで付与されたアクティブな `lightnode_operator` ライセンス、委任ステークの最低額、そして登録手数料が必要です。登録自体がまだ開始されておらず（[報酬プログラムのステータス](/light-node/overview#reward-program-status)を参照）、ライセンスを購入しても早期に開始されることはないため、現時点では申し込めるものはありません。それまでの間は、ノードを稼働させて同期しておいてください。アップタイムは、ノードがオンチェーンで登録されたブロックからカウントされ、それ以前はカウントされません。
4. **登録記録。** アカウントがアクティブとして記録されたライセンスを保有している場合、このタブには、運用者アドレス（`qor1…`）、モニカー、パブリックエンドポイントURL、ステークのコミットメントの確認からなる短いフォームと、送信した内容のサマリーも表示されます。このフォームはダッシュボード上でThe Qore Trustへの登録リクエストを記録するもので、オンチェーンの登録トランザクションを送信**せず**、チェーンの確認も行いません。オンチェーン登録はノード自体から `lightnode-sx register` で行い（[登録とライセンス](/light-node/registration-and-licensing)を参照）、チェーン上でアクティブな付与が確認でき、運用者アドレスからステークがすでにボンドされており、登録が開始されている場合にのみ成功します。

全体像については、[ライトノード概要](/light-node/overview)および[登録とライセンス](/light-node/registration-and-licensing)をご覧ください。

## ノード登録

ノード登録タブは、ダッシュボード上でThe Qore Trustへのバリデーター登録を記録します。バリデーター自体をオンチェーンで作成するわけではありません。それは自分のノードから行います（下記の手順1および5）。前提条件と手順：

1. **まずPQC鍵を登録する — 自分のバリデーターノード上でCLIから実行します。** バリデーターは、ライセンスの申請・利用やバリデーターの作成に先立って、自らPQC鍵の登録を実行する必要があります。これは自動では行われません。CLIコマンドについては[バリデーターの運用](/developer-guide/running-a-validator#pqc-key-registration)をご覧ください。
2. **ライセンスを保有していることを確認する。** フォームには、アカウントでアクティブとして記録されたバリデーターライセンスが必要です。`create-validator` が受理されるかどうかを決めるのは**チェーン**であり、チェーンはオンチェーンの運用者への付与を要求します。**Buy License** を通じて購入したライセンスは当方側で記録されますが、オンチェーンでの付与は別の手動のステップで、その後に行われます。チェーンが現在何を認識しているかは、**Validator Readiness**（Validator Applicationタブ内）で確認してください。まだライセンスをお持ちでない場合、このタブから **Buy License** にリンクします。バリデーターライセンスの取得には、事前に承認済みの[バリデーター申請](#validator-application)が必要です。
3. **登録フォームに入力する。** バリデーターアドレスまたはコンセンサス公開鍵、モニカー、コミッション料率（ライセンスで許可された範囲内）、任意のパブリックエンドポイントを入力します。ライセンスにクロスネットワークチェーンが含まれている場合は、このバリデーターがサービスを提供するチェーンを選択します。
4. **セルフステーク要件を確認する。** バリデーターのセルフステークの下限は固定で100,000 QORです。これは調整可能な設定ではなく、プロトコルレベルの定数であり、アンボンディング期間の対象となり、ダウンタイムや二重署名はスラッシュの対象となります。これを確認したうえで、送信して登録します。
5. **同期してバリデーターを作成する。** ここで登録すると、バリデーターの情報が記録されます。ただし、ノードを現在のチェーンの最新状態まで同期させ、QoreChainのすべてのトランザクションと同様にハイブリッドPQC共同署名で `create-validator` を自分自身で送信する必要があります。手順1で登録した鍵が、その署名を有効にするものです。
6. **確認してステークをボンドする。** サマリーパネルに登録内容（モニカー、バリデーターアドレス、コミッション、セルフステークの意思表示、クロスネットワークチェーン、ステータス）が表示され、アクティブなバリデーターセットに加わるためにセルフステークをボンドするよう案内されます。ボンド自体は、ダッシュボードではなく、耐量子共同署名されたトランザクションによって自分のノード上で行われます。

ステーキングとバリデーターの作成は、QoreChainのネイティブトランザクションレーンでのみ行われます。MetaMaskのような連携済みのEVMウォレットを通じてバリデーターを登録・ボンドする方法はありません。

[バリデーターの運用](/developer-guide/running-a-validator)および[ステーキングとバリデーター](/dashboard/staking-and-validators)をご覧ください。

## ロールアップ

QoreChainを基盤としたロールアップをリクエストします。フォームでは、ロールアップに名前を付け、希望する仮想マシン（EVM、CosmWasm、SVM）、データ可用性レイヤー、ガストークン、シーケンサーモデル、決済先を指定できます。送信すると、The Qore Trustがレビューするプロビジョニングリクエストが記録されます。ロールアップがオンチェーンで作成されるわけではありません。選択肢は、オンチェーンのロールアップモジュールが現在サポートしている範囲よりも広くなっています。ロールアップを自分でオンチェーンに登録するには[ロールアップのデプロイ](/rollups/deploying-a-rollup)を、コンセプトについては[ロールアップ概要](/rollups/overview)をご覧ください。

## SDK

コードでQoreChain上に構築するためのクイックスタートとリファレンスのハブです。このセクションでは、インストール手順に加え、接続、3つのランタイムにわたるアカウントの導出、状態の読み取り、送金、量子耐性署名のための、そのままコピーして使えるスニペットを紹介し、さらに言語別パッケージの一覧表と、リポジトリ・サンプル・エクスプローラーへのリンクを掲載しています。[QoreChain SDK概要](/sdk/overview)および[インストール](/sdk/install)をご覧ください。

## バリデーター申請 {#validator-application}

ジェネシスバリデーターになるために申請します。

1. **組織情報を入力する。** 法人名、国・管轄区域、連絡先メールアドレスを入力します。
2. **希望するティアを選択する。** バリデーターティアのカタログから選択します（各ティアにはスロット数と機能セットが記載されています）。これは承認後にライセンスを取得する予定のティアであり、まだ購入ではありません。
3. **インフラについて記載する。** インフラのリージョンおよびハードウェア／データセンターの詳細を記入します。
4. **動機を説明する。** チームのバリデーター／インフラ運用経験と、QoreChainのジェネシスバリデーターを運用したい理由について、簡潔に記述します。
5. **コンプライアンスを確認して送信する。** ライセンスが付与される前に、申請者の組織およびその実質的所有者に対するKYC/AML確認が必要であることを確認したうえで、送信します。
6. **ステータスを追跡する。** このタブには、申請が審査中、承認済み、または理由付きで非承認（修正して再提出するオプション付き）のいずれであるかが表示されます。申請が保留中または承認済みになると、ライブの **Validator Readiness** パネルが、購入済みの内容ではなく、チェーンに対して直接3つの項目を確認します。すなわち、PQC鍵の登録、セルフボンド（固定で100,000 QOR — 使用可能な残高のみが対象で、ベスティング中の資金はカウントされません）、そして運用者ライセンスが実際にオンチェーンで付与されており、現在有効であるかどうか（停止されておらず、有効期限を過ぎていないこと — ライセンスはブロック高で期限切れとなり、チェーンの最新ブロックを読み取れない場合、期限が近いライセンスは有効としてではなく*確認できなかった*として報告されます）です。各チェックは、「満たしている」「まだ満たしていない」「チェーンに接続できず確認できなかった」の3つの状態のいずれかを報告します。確認に失敗した場合が「保有していない」として表示されることは決してありません。そう表示すると、すでに保有しているものをやり直すよう促してしまうためです。承認されると、**Buy License** に進んでバリデーターライセンスを取得できます。

[バリデーターの運用](/developer-guide/running-a-validator)をご覧ください。

## ライセンス購入

ネットワークインフラを運用するために必要なライセンスを取得します。

1. **ライセンスの付与先アドレスを入力する。** 上部の **QoreChain address** フィールドはすべての購入で必須です。ライセンスをオンチェーンで付与する `qor1…` アドレスを入力してください。ご自身が管理し、今後も保持するアドレスを使用してください。付与はそのアドレスに紐づけられ、後から変更するにはサポートへの依頼が必要です。アドレスがなければライセンスを注文できません。
2. **支払いネットワークを選択する。** **Pay with USDT on:** の下で、ERC-20、BEP-20、TRC-20のいずれかを選択します。
3. **購入するものを選ぶ。** ライトノードライセンスは誰でも購入できます。バリデーターライセンス（各ティア）は、[バリデーター申請](#validator-application)が承認された場合にのみ解放されます。クロスネットワークアドオンは、バリデーターライセンスを追加のチェーンに拡張するもので、チェーンごと・年ごとの料金です。希望するチェーンを選択してから購入してください。
4. **支払いを完了する。** 各購入は支払いステップに進み、金額とネットワークを確認したうえで、ライセンスが支払い済みとして記録される前に、オンチェーンで支払いを検証します。
5. **オンチェーンでの付与を待ってから登録する。** 支払い後、ライセンスには **Paid — awaiting on-chain grant** と表示されます。付与は手作業でバッチ単位に発行されるため、即時ではありません。ステータスが **Active** に変わるのは、チェーン自体が付与を確認した後のみです。チェーンへの登録は当方の記録ではなくチェーンを確認するため、付与が反映される前に登録しようとすると拒否されます。バッジが **Active** と表示されたら、**Light Node** または **Node Registration** に戻り、対応する登録を行ってください。

:::note アドレスが必須になる前に購入したライセンス
アドレスが収集される前にライセンスを購入した場合、Buy Licenseタブは **This licence needs a QoreChain address** と表示されて開きます。アドレスを入力し、**Save address** を選択してください。保存されるまで、ライセンスは付与できません。
:::

ネットワーク全体でのライセンスの仕組みについては、[チェーンライセンス](/architecture/chain-licensing)をご覧ください。
