# ツールハブ

**ツール** ページには、QoreChainの運用者向け・ビルダー向けツールがタブ形式で一箇所にまとめられています。ここからインフラの登録、ロールアップのデプロイ、SDKへのアクセス、バリデーターになるための申請、そしてこれらの役割に必要なライセンスの取得を行えます。各セクションについて以下で概要を説明し、詳細なドキュメントへのリンクも示します。

インフラを登録したり申請を送信したりするツールを使用するには、ウォレットを接続してください。[概要とはじめに](/dashboard/overview#connect-your-wallet)をご覧ください。

## ライトノード

ライトノードを稼働させることと、その報酬プログラムに参加することは別の話です。**ライトノード**タブは、この2つを1つの申し込みフローとしてまとめず、明確に分けて扱います。

1. **ノードを起動する — 今すぐ利用可能。** ライセンスもオンチェーンでの確認も承認も不要で、ライセンスの状態に関わらず最初に表示されます。ライブのネットワークマニフェストを読み込み、バイナリのダウンロードと検証、ジェネシスによるノードの初期化、ネットワークのピアへの接続、そしてジェネシスからの同期の代わりにステートシンクを行うための、そのままコピーして使えるコマンドを提示します。
2. **報酬プログラムのステータスを確認する。** ライトノードの報酬シェアへの参加は別のステップであり、オンチェーンでのゲートがかかっています。オンチェーンで付与されたアクティブな `lightnode_operator` ライセンス、委任されたQORの最低数量（バリデーターごとではなく、委任先のすべてのバリデーターにわたる合計値をステーキングからライブで読み取ります）、そして少額のオンチェーン登録手数料が必要です。**登録はまだ開始されていません**。ライセンスを購入しても早期に開始されることはないため、現時点では申し込めるものはありません。開始されるまで、このタブは要件を提出用フォームとしてではなく、確認用のステータスとして表示します。
3. **ライセンスがオンチェーンで付与されたら登録する。** **Buy License** を通じて購入したライセンスは、まず当方側の記録として保存されます。オンチェーンでの付与は別のステップであり、その付与が反映されるまで登録は拒否されます（詳細は後述のBuy Licenseに関する注記を参照）。付与が反映されると、このタブのステータスパネルは登録フォームに切り替わります。フォームでは、運用者アドレス（`qor1…`）、モニカー、パブリックエンドポイントURL、そしてステークのコミットメントに関する確認が求められます。
4. **確認してステークをボンドする。** 送信後、サマリーパネルに登録内容（モニカー、運用者アドレス、エンドポイント、ステークの意思表示、ステータス）が表示され、資格が開始されたら、運用者アドレスから確認済みのステークをボンドするよう案内されます。

全体像については、[ライトノード概要](/light-node/overview)および[登録とライセンス](/light-node/registration-and-licensing)をご覧ください。

## ノード登録

**ノード登録**タブでは、バリデーターノードをオンチェーンで登録します。

1. **まずPQC鍵を登録する — 自分のバリデーターノード上でCLIから実行します。** 通常のアカウントの最初のトランザクションのように自動では行われません。バリデーターは、ライセンスの申請・利用やバリデーターの作成に先立って、自らPQC鍵の登録を実行する必要があります。CLIコマンドについては[バリデーターの運用](/developer-guide/running-a-validator#pqc-key-registration)をご覧ください。
2. **ライセンスを保有していることを確認する。** ここで登録するには、アクティブなバリデーターライセンスが必要です。**Buy License** を通じて購入したライセンスは当方側で記録されますが、オンチェーンでの付与は別のステップであり、その付与が反映されるまで登録は拒否されます。まだライセンスをお持ちでない場合、このタブから **Buy License** にリンクします。バリデーターライセンスの取得には、事前に承認済みの[バリデーター申請](#validator-application)が必要です。
3. **登録フォームに入力する。** バリデーターアドレスまたはコンセンサス公開鍵、モニカー、コミッション料率（ライセンスで許可された範囲内）、任意のパブリックエンドポイントを入力します。ライセンスにクロスネットワークチェーンが含まれている場合は、このバリデーターがサービスを提供するチェーンを選択します。
4. **セルフステーク要件を確認する。** バリデーターのセルフステークの下限は固定で100,000 QORです。これは調整可能な設定ではなく、プロトコルレベルの定数であり、アンボンディング期間の対象となり、ダウンタイムや二重署名はスラッシュの対象となります。これを確認したうえで、送信して登録します。
5. **同期してバリデーターを作成する。** ここで登録すると、バリデーターの情報が記録されます。ただし、ノードを現在のチェーンの最新状態まで同期させ、QoreChainのすべてのトランザクションと同様にハイブリッドPQC共同署名で `create-validator` を自分自身で送信する必要があります。手順1で登録した鍵が、その署名を有効にするものです。
6. **確認してステークをボンドする。** サマリーパネルに登録内容（モニカー、バリデーターアドレス、コミッション、セルフステークの意思表示、クロスネットワークチェーン、ステータス）が表示され、アクティブなバリデーターセットに加わるためにセルフステークをボンドするよう案内されます。

ステーキングとバリデーターの作成は、QoreChainのネイティブトランザクションレーンでのみ行われます。MetaMaskのような連携済みのEVMウォレットを通じてバリデーターを登録・ボンドする方法はありません。

[バリデーターの運用](/developer-guide/running-a-validator)および[ステーキングとバリデーター](/dashboard/staking-and-validators)をご覧ください。

## ロールアップ

QoreChainを基盤とした独自のロールアップをデプロイします。設定フォームでは、ロールアップに名前を付け、仮想マシン（EVM、CosmWasm、SVM）、データ可用性レイヤー、ガストークン、シーケンサーモデル、決済先を選択できます。送信後、ロールアップは稼働開始前にレビューを経てプロビジョニングされます。[ロールアップ概要](/rollups/overview)および[ロールアップのデプロイ](/rollups/deploying-a-rollup)をご覧ください。

## SDK

コードでQoreChain上に構築するためのクイックスタートとリファレンスのハブです。このセクションでは、インストール手順に加え、接続、3つのランタイムにわたるアカウントの導出、状態の読み取り、送金、量子耐性署名のための、そのままコピーして使えるスニペットを紹介し、さらに言語別パッケージの一覧表と、リポジトリ・サンプル・エクスプローラーへのリンクを掲載しています。[QoreChain SDK概要](/sdk/overview)および[インストール](/sdk/install)をご覧ください。

## バリデーター申請 {#validator-application}

ジェネシスバリデーターになるために申請します。

1. **組織情報を入力する。** 法人名、国・管轄区域、連絡先メールアドレスを入力します。
2. **希望するティアを選択する。** バリデーターティアのカタログから選択します（各ティアにはスロット数と機能セットが記載されています）。これは承認後にライセンスを取得する予定のティアであり、まだ購入ではありません。
3. **インフラについて記載する。** インフラのリージョンおよびハードウェア／データセンターの詳細を記入します。
4. **動機を説明する。** チームのバリデーター／インフラ運用経験と、QoreChainのジェネシスバリデーターを運用したい理由について、簡潔に記述します。
5. **コンプライアンスを確認して送信する。** ライセンスが付与される前に、申請者の組織およびその実質的所有者に対するKYC/AML確認が必要であることを確認したうえで、送信します。
6. **ステータスを追跡する。** このタブには、申請が審査中、承認済み、または理由付きで非承認（修正して再提出するオプション付き）のいずれであるかが表示されます。申請が保留中または承認済みになると、ライブの **Validator Readiness** パネルが、購入済みの内容ではなく、チェーンに対して直接3つの項目を確認します。すなわち、PQC鍵の登録、セルフボンド（固定で100,000 QOR — 使用可能な残高のみが対象で、ベスティング中の資金はカウントされません）、そして運用者ライセンスが実際にオンチェーンで付与されているかどうかです。各チェックは、「満たしている」「まだ満たしていない」「チェーンに接続できず確認できなかった」の3つの状態のいずれかを報告します。確認に失敗した場合が「保有していない」として表示されることは決してありません。そう表示すると、すでに保有しているものをやり直すよう促してしまうためです。承認されると、**Buy License** に進んでバリデーターライセンスを取得できます。

[バリデーターの運用](/developer-guide/running-a-validator)をご覧ください。

## ライセンス購入

ネットワークインフラを運用するために必要なライセンスを取得します。

1. **ライセンスの付与先アドレスを入力する。** ライセンスをオンチェーンで付与する `qor1…` アドレスを入力します。ネットワークが確認するのはこのアドレスなので、実際にノードを運用するアドレスを使用してください。
2. **支払いネットワークを選択する。** ERC-20、BEP-20、TRC-20のいずれかのUSDTを選択します。
3. **購入するものを選ぶ。** ライトノードライセンスは誰でも購入できます。バリデーターライセンス（各ティア）は、[バリデーター申請](#validator-application)が承認された場合にのみ解放されます。クロスネットワークアドオンは、バリデーターライセンスを追加のチェーンに拡張するもので、チェーンごと・年ごとの料金です。希望するチェーンを選択してから購入してください。
4. **支払いを完了する。** 各購入は支払いステップに進み、金額とネットワークを確認したうえで、当方の記録上ライセンスがアクティブとしてマークされる前に、オンチェーンで支払いを検証します。
5. **オンチェーンでの付与を待ってから登録する。** ここでアクティブと表示されているライセンスは、当方側の記録として保存された状態です。オンチェーンで認識されるようにする付与は別のステップです。登録は当方の記録ではなくチェーンを確認するため、付与が反映される前に登録しようとすると拒否されます。付与が確認されたら、**Light Node**または**Node Registration**に戻り、対応するオンチェーン登録を完了してください。

ネットワーク全体でのライセンスの仕組みについては、[チェーンライセンス](/architecture/chain-licensing)をご覧ください。
