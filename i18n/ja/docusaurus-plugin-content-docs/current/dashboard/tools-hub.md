# ノードとバリデーター（ツールハブ）

**Nodes & Validators** ページには、QoreChainの運用者向け・ビルダー向けツールが、次の順序で6つのタブにまとめられています。**Validator Program**、**Validator Application**、**Light Node**、**Node Registration**、**Rollups**、**SDK** です。このページはヘッダーのネットワーク切り替えに連動し、チェーンの確認、ダウンロード、ノードのステータスは選択中のネットワークから読み取られます。ライセンスの販売は**メインネットのみ**です。テストネットでは無料のライセンスをリクエストします（[ライトノード](#light-node)を参照）。

Dashboardのサイドバーでは、この項目は **Nodes & Validators** と表示されます（以前は Tools と呼ばれていました。アドレスは引き続き `/tools` です）。PQC鍵のステータス、トランザクションシミュレーター、署名プレイグラウンドなどのビルダー向けツールは、別の公開ページである[Developers](/dashboard/developers)にあります。

このページ全体にはサインイン済みのアカウントが必要で、これは両方のネットワークで同じです。サインインしていない場合は「Authentication Required」画面が表示されます。[サインイン](/dashboard/overview#sign-in)をご覧ください。

## バリデータープログラム

バリデーターがネットワークに参加するための仕組みである **QoreChain Validator Program** の読み取り専用の概要です。プログラムが提供するもの（オンチェーンの運用者付与、Association管理下のステークからの委任、サービスレベルを満たす独立運用者へのQOR支給金）、プログラムの要件、選考プロセス、そしてFAQを掲載しています。このタブのプロトコルパラメータ（アンボンディング期間、スラッシング、最大バリデーター数）はチェーンからライブで読み取られます。一方、プログラムのルール（100,000 QORのセルフステーク、コミッションの範囲、支給金）はAssociationが定めるもので、その旨が表示されます。バリデーターはパッケージを購入するのではなく、申請を行い、選考を通過した場合にのみ **$1,000 のプログラム手数料** を支払います。

## バリデーター申請 {#validator-application}

Validator Programに申請します。

1. **申請書に入力する。** 法人名、管轄区域、連絡先メールアドレス、**運用者アドレス**（`qor1…`。`create-validator` を実行するアカウントで、オンチェーンの運用者付与はこのアドレスに対して発行されます）、ホスティングプロバイダー・リージョン・種別、現在運用しているネットワーク、任意でテストネットのバリデーターアドレスと提供している公開インフラ（パブリックRPC、スナップショット、アーカイブ）、トラック（標準、または予約枠向けのグローバル）、そしてプログラム規約への同意を入力します。申請は無料です。
2. **審査とテストネットでの試験運用。** 審査中の申請は **Submitted** と表示されます。次の段階に進んだ申請は、dianaテストネットで14日間の試験運用としてバリデーターを稼働させ、**Testnet trial** と表示されます。
3. **選考とプログラム手数料。** 選考を通過した申請には **Selected** と **Pay the $1,000 programme fee** ボタンが表示されます。支払いステップはライトノードライセンスと同じ仕組みです。ネットワークを選び（ERC-20、BEP-20、TRC-20のUSDT）、表示された正確な金額を支払い、トランザクションハッシュを貼り付けて **Verify payment** を選択すると、支払いがオンチェーンで検証されます。手数料は申請書の運用者アドレスに紐づけられ、別のアドレスに対して支払うことはできません。承認と支払いは常に別々に表示されます。申請が選考を通過していても、未払いのままである場合があります。
4. **オンチェーンの運用者付与。** 支払い後、Associationがオンチェーンで運用者アドレスに `validator_operator` 付与を発行します。メインネットの付与は手作業でバッチ単位に署名されるため、即時ではありません。チェーンに付与が反映され次第、タブに **Operator grant on chain** と表示され、バリデーターがボンドされると **In the active set** と表示されます。

送信済み、テストネット試験運用中、選考通過済み、付与済みの申請には、**Validator Readiness** パネル（アドレス入力欄があり、ヘッダーのネットワークに連動します）が運用者アドレスについてチェーンを直接確認します。登録済みのポスト量子鍵、セルフステークに十分な使用可能QOR、運用者付与、そしてバリデーターがボンドされているかどうかです。[PQC鍵の登録](/developer-guide/running-a-validator#pqc-key-registration)は自分のノードで早めに実行してください。この鍵を代わりに登録してくれるものはありません。

以前のバリデーター募集（2026年10月より前）で承認された申請は **Earlier application** と表示され、Associationが申請者に直接連絡します。

## ライトノード {#light-node}

ライセンスの取得からオンチェーンに登録されたノードまで、ライトノード運用者に必要なものがすべて揃っています。

1. **ライセンスを購入する（メインネット）。** ライトノードライセンスは **$50** で、ERC-20、BEP-20、TRC-20のUSDTで支払い、オンチェーンで検証されます。支払いの前に、ライセンスを付与する `qor1…` アドレスを入力してください。リカバリーワードを自分で保持しているアカウント（自分のワード、Keplr、または `qorechaind`）を使用し、できればノード専用のアカウントにしてください。ヘッダーが **testnet** に設定されている場合、販売されているものはありません。タブには「Nothing is sold on testnet」と表示され、代わりに無料のセルフサービスライセンスが提供されます（[無料のテストネットライセンス](#testnet-licence)を参照）。
2. **オンチェーンでの付与を待つ。** 支払い後、ライセンスには **Paid, awaiting on-chain grant** と表示され、チェーンが `lightnode_operator` 付与を確認した時点で初めて **Active on chain** に変わります。メインネットの付与は手作業でバッチ単位に署名されます。「支払い済み」と「オンチェーンで付与済み」は別の事実です。チェーンに付与が反映される前に、タブがライセンスを有効と表示することはありません。
3. **ノードをインストールして登録する。** タブには、ネットワーク向けに公開されたビルドとそのチェックサム（サーバー版 `lightnode-sx`、デスクトップ版 `lightnode-ux`、Linux・macOS・Windows向け）、そして現在のリリースの手順が一覧表示されます。キーリングのパスフレーズを設定し、`lightnode-sx onboard`、`lightnode-sx keys add-operator --recover`（ライセンス対象のアカウントを追加）、`lightnode-sx register`（ノードのポスト量子鍵を紐づけて登録。アドレスのステークが不足している場合は `--delegate-to <qorvaloper…>` を追加）、続いて `lightnode-sx start` と `lightnode-sx status` を実行します。これらの手順は、ネットワークのリリースマニフェストが対応するビルドを公開している場合にのみ現行の手順として表示され、タブにはそのネットワークで登録が開始されているかどうかも表示されます。
4. **アドレスに関する通知。** ライセンスのアドレスが自分のカストディアル型ダッシュボードウォレットのいずれかである場合、タブは警告を表示します（その鍵はダッシュボードが保持しているため、ノードはその鍵で署名できません）。また、アドレスにすでにオンチェーンのポスト量子鍵がある場合もその旨を通知します（リカバリーワードから導出された鍵であればノードはそれを再利用し、そうでなければ拒否して専用アカウントの使用を推奨します）。
5. **ステータス。** パネルがチェーンを読み取り、現在適用されている要件（登録手数料、委任ステーク、アップタイム、ハートビートの期間、ライトノードの最大数）と、指定したアドレスについてライトノードが登録されているか、期限内に報告しているかを表示します。表示されるステータスには、「Registered, waiting for its first heartbeat」、「Rewards accrued」、そしてノードが非アクティブとマークされたときの通知が含まれます。

### 無料のテストネットライセンス {#testnet-licence}

テストネット（`qorechain-diana`）では、ライトノードライセンスは無料でセルフサービスです。ヘッダーをテストネットに設定して **Light Node** タブを開き、**Free testnet licence** の下に `qor1…` アドレスを入力して **Request licence** を選択します。リクエストは「Requested for …」と表示され、続いて「Granted to … You can register your node now.」と表示されます。付与を署名できなかった場合はタブにその旨が表示され、再度リクエストできます。付与は自動的に署名され、通常は数分以内です。リクエストはアカウントごとに1回、アドレスごとに1回です。メインネットのライセンスは異なります。$50で購入し、その付与は手作業でバッチ単位に行われます。

[ライトノード概要](/light-node/overview)および[登録とライセンス](/light-node/registration-and-licensing)をご覧ください。

:::note アドレスが必須になる前に購入したライセンス
アドレスが収集される前にライセンスを購入した場合、タブは **This licence needs a QoreChain address** と表示されて開きます。アドレスを入力し、**Save address** を選択してください。保存されるまで、ライセンスは付与できません。
:::

## ノード登録

バリデーターの詳細をAssociationに記録します。バリデーターをオンチェーンで作成するものではなく、それは自分のノードから `create-validator` で行います。

フォームは、チェーン上で運用者アドレスに有効な `validator_operator` 付与が確認でき、かつ選考を通過したValidator Programの申請（またはプログラム開始前のバリデーターライセンス）を保有している場合に利用できます。バリデーター運用者アドレス、モニカー、5%から20%の間のコミッション料率、任意のパブリックエンドポイントを入力し、100,000 QORのセルフステーク、21日間のアンボンディング期間、スラッシングについて確認します。

オンチェーンの手順は[バリデーターの運用](/developer-guide/running-a-validator)にあります。PQC鍵を登録し、QoreChainのすべてのトランザクションと同様にPQC共同署名した `create-validator` を、100,000 QOR以上のセルフステークとともに送信します。ステーキングとバリデーターの作成は、QoreChainのネイティブトランザクションレーンでのみ行われます。MetaMaskのような連携済みのEVMウォレットを通じてバリデーターを登録・ボンドする方法はありません。フォームの下には、ネットワークのリリースマニフェストに基づき、フルノードに必要なもの（リリースバイナリ、ジェネシス、ピア）も一覧表示され、ネットワークが新しいバリデーターを受け付けていない場合は「Joining is temporarily suspended」のバナーが表示されることがあります。

[ステーキングとバリデーター](/dashboard/staking-and-validators)をご覧ください。

## ロールアップ

QoreChainを基盤としたロールアップをリクエストします（フォームのタイトルは **Deploy a Rollup** です）。ロールアップに名前を付け、希望する仮想マシン（EVM、QoreChain Native、SVM）、データ可用性レイヤー、ガストークン、シーケンサーモデル、決済先を指定できます。**Deploy rollup** を選択すると、プロビジョニングリクエストが記録されるだけで、フォームの下にそのステータスとともに一覧表示されます。ロールアップがオンチェーンで作成されるわけではありません。選択肢は、オンチェーンのロールアップモジュールが現在サポートしている範囲よりも広くなっています。ロールアップを自分でオンチェーンに登録するには[ロールアップのデプロイ](/rollups/deploying-a-rollup)を、コンセプトについては[ロールアップ概要](/rollups/overview)をご覧ください。

## SDK

コードでQoreChain上に構築するための、インストール手順、スニペット、リンクをまとめた静的なハブです（接続、アカウントの導出、状態の読み取り、送金、ハイブリッドML-DSA-87署名（FIPS 204）による署名）。その内容はSDKのリリースに合わせて更新されているわけではないため、バージョンとインストールコマンドは、代わりに[インストール](/sdk/install)および[QoreChain SDK概要](/sdk/overview)を参照してください。

ネットワーク全体でのライセンスの仕組みについては、[チェーンライセンス](/architecture/chain-licensing)をご覧ください。
