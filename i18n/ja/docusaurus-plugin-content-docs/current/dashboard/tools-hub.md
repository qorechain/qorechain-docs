# ノードとバリデーター

**Nodes & Validators** ページ（サイドバーの **Build** グループ、アドレスは `/tools`。2026年10月27日までは Tools および Tools Hub と呼ばれていました）は、Dashboardの運用者向けページです。次の順序で5つのタブがあります。**Validator Program**、**Validator Application**、**Light Node**、**Node Registration**、**Rollups** です。バリデーターやライトノードを運用したい方、またはアプリケーションロールアップを依頼したい方向けのページです。SDKタブは公開ページの[Developers](/dashboard/developers)に移動しました。Developersページには、ビルダー向けツール（PQC鍵のステータス、シミュレーター、署名プレイグラウンド、QoreXテストウォレット）もあります。

## イノベーション {#innovations}

- **チェーンの確認はチェーンから取得します。** **Validator Readiness** パネルは、選択中のネットワークで4つの項目を確認します。登録済みのML-DSA-87鍵、セルフステーク用の使用可能なQOR（ベスティング分は除く）、オンチェーンの運用者付与、そしてバリデーターがボンドされているかどうかです。**Light node status** パネルは、現在適用されている要件（登録手数料、委任ステーク、アップタイム、ハートビートの期間、ライトノードの最大数）と、そのアドレスの登録状態およびハートビートの状態を読み取ります。
- **「支払い済み」と「オンチェーンで付与済み」は別の事実です。** 支払い済みのライセンスは、チェーンが付与を確認するまで **Paid, awaiting on-chain grant** と表示され、確認後に **Active on chain** と表示されます。チェーンに付与が反映される前に、タブがライセンスを有効と表示することはありません。
- **プロトコルのルールとプログラムのルールは区別して表示されます。** 各パラメータの行には、それがプロトコル由来（チェーンから読み取り）か、プログラム由来（Associationが適用）かが示されます。
- **セルフサービスのテストネット用ライトノードライセンス。** **Free testnet licence** の下に `qor1...` アドレスを入力して **Request licence** を選択すると、付与は自動的に署名され、通常は数分以内に完了します。メインネットの付与は引き続き手作業です。
- **ノードの手順はネットワークのリリースマニフェストに従います。** ダウンロード（サーバー版 `lightnode-sx`、デスクトップ版 `lightnode-ux`、プラットフォームごと、SHA-256チェックサム付き）、登録が開始されているかどうか、手順が最新かどうかは、すべてマニフェストから取得されます。

## 使い方 {#how-to-use}

すべてのタブの前提条件はサインインです。タブはヘッダーのネットワーク切り替えに連動します（チェーンの確認、ダウンロード、ノードのステータスは選択中のネットワークから読み取られます）。サインインしていない場合、ページには「Authentication Required」と表示されます。[サインイン](/dashboard/overview#sign-in)をご覧ください。

### Validator Program {#validator-program}

バリデーターがネットワークに参加するための仕組みである **QoreChain Validator Program** の読み取り専用の概要です。プログラムが提供するもの（オンチェーンの運用者付与、Association管理下のステークからの委任、サービスレベルを満たす独立運用者へのQOR支給金）、プログラムの要件、選考プロセス、そしてFAQを掲載しています。**Apply** と **Ask a question** のボタンがあります。プロトコルパラメータ（アンボンディング期間、スラッシング、最大バリデーター数）はチェーンからライブで読み取られます。一方、プログラムのルール（100,000 QORのセルフステーク、コミッションの範囲、支給金）はAssociationが定めるもので、その旨が表示されます。バリデーターはパッケージを購入するのではなく、申請を行い、選考を通過した場合にのみ **$1,000 のプログラム手数料** を支払います。支給金の金額についてはタブ自体をご覧ください。

### Validator Application {#validator-application}

1. **申請書に入力する。** 法人名、管轄区域、連絡先メールアドレス、**運用者アドレス**（`qor1...`。`create-validator` を実行するアカウントで、オンチェーンの運用者付与はこのアドレスに対して発行されます）、ホスティングプロバイダー・リージョン・種別、現在運用しているネットワーク、任意でテストネットのバリデーターアドレス（`qorvaloper1...`）と提供している公開インフラ（パブリックRPC、スナップショット、アーカイブ）、トラック（Standard、または予約枠向けのGlobal）、そしてプログラム規約への同意を入力します。**Submit application** を選択します。申請は無料です。
2. **審査とテストネットでの試験運用。** 申請は **Application submitted** と表示され、次の段階に進んだ申請は **Testnet trial**（`qorechain-diana` でバリデーターを稼働させる14日間の試験運用）と表示されます。却下された申請は **Not selected** と表示され、**Apply again** が利用できます。
3. **選考とプログラム手数料。** 選考を通過した申請には **Selected** と **Pay the $1,000 programme fee** ボタンが表示されます。ネットワークを選び（ERC-20、BEP-20、TRC-20のUSDT）、表示された正確な金額を支払い、トランザクションハッシュを貼り付けて **Verify payment** を選択すると、支払いがオンチェーンで検証されます。手数料は申請書の運用者アドレスに紐づけられ、別のアドレスに対して支払うことはできません。承認と支払いは別々に表示されます。申請が選考を通過していても、未払いのままである場合があります。支払い後、カードには「Programme fee paid」と表示されます。
4. **オンチェーンの運用者付与。** 支払い後、Associationがオンチェーンで運用者アドレスに `validator_operator` 付与を発行します。メインネットの付与は手作業でバッチ単位に署名されるため、即時ではありません。チェーンに付与が反映され次第、タブに **Operator grant on chain** と表示され、バリデーターがボンドされると **In the active set** と表示されます。
5. **準備状況。** 送信済み、試験運用中、選考通過済み、付与済みの申請には、**Validator Readiness** パネル（アドレス入力欄あり）が運用者アドレスについてチェーンを確認します。[PQC鍵の登録](/developer-guide/running-a-validator#pqc-key-registration)は自分のノードで早めに実行してください。この鍵を代わりに登録してくれるものはありません。

以前のバリデーター募集（2026年10月より前）で承認された申請は **Earlier application** と表示され、Associationが申請者に直接連絡します。

### Light Node {#light-node}

ライセンスの取得から登録済みのノードまで、ライトノード運用者に必要なものがすべて揃っています。

1. **ライセンスを購入する（メインネット）。** ライトノードライセンスは **$50** で、ERC-20、BEP-20、TRC-20のUSDTで支払い、オンチェーンで検証されます。ライセンスを付与する `qor1...` アドレスを入力し、USDTのネットワークを選んで **Buy for $50** を選択します。リカバリーワードを自分で保持しているアカウント（自分のワード、Keplr、または `qorechaind`）を使用し、できればノード専用のアカウントにしてください。支払い後、カードには **Payment received** と表示され、続いてオンチェーンでの付与が行われます。下には **Your past orders** が一覧表示されます。
2. **オンチェーンでの付与を待つ。** ライセンスには **Paid, awaiting on-chain grant** と表示され、チェーンが `lightnode_operator` 付与を確認した時点で **Active on chain** に変わります。メインネットの付与は手作業でバッチ単位に署名されます。
3. **ノードをインストールして登録する。** タブには、ネットワーク向けに公開されたビルドとそのチェックサム、そして現在のリリースの手順が一覧表示されます。キーリングのパスフレーズを設定し、`lightnode-sx onboard`、`lightnode-sx keys add-operator --recover`（ライセンス対象のアカウントを追加）、`lightnode-sx register`（ノードのポスト量子鍵を紐づけて登録。アドレスのステークが不足している場合は `--delegate-to <qorvaloper...>` を追加）、続いて `lightnode-sx start` と `lightnode-sx status` を実行します。これらの手順は、ネットワークのリリースマニフェストが対応するビルドを公開している場合にのみ現行の手順として表示され、タブには登録が開始されているかどうかも表示されます。
4. **アドレスに関する通知。** ライセンスのアドレスが自分のカストディアル型ダッシュボードウォレットのいずれかである場合、タブは警告を表示します（「This address cannot run a node」。その鍵はダッシュボードが保持しています）。また、アドレスにすでにオンチェーンのポスト量子鍵がある場合もその旨を通知します（リカバリーワードから導出された鍵であればノードはそれを再利用し、そうでなければ拒否して専用アカウントの使用を推奨します）。
5. **ステータス。** パネルには、現在適用されている要件と、ライトノードが登録されているか、期限内に報告しているかが表示されます。表示されるステータスには、「Registered, waiting for its first heartbeat」、「Rewards accrued」、そしてノードが非アクティブとマークされたときの通知が含まれます。

#### Free testnet licence {#testnet-licence}

テストネット（`qorechain-diana`）では何も販売されておらず（「Nothing is sold on testnet」）、ライトノードライセンスは無料でセルフサービスです。

1. ヘッダーを **Testnet** に設定し、**Light Node** タブを開きます。
2. **Free testnet licence** の下に `qor1...` アドレスを入力し、**Request licence** を選択します。
3. リクエストは「Requested for ...」と表示され、続いて「Granted to ... You can register your node now.」と表示されます。付与を署名できなかった場合はタブにその旨が表示され、再度リクエストできます。

付与は自動的に署名され、通常は数分以内です。リクエストはアカウントごとに1回、アドレスごとに1回です。**最小限の例：** Testnet、**Light Node**、**Request licence**、「Granted to ...」と表示されるのを待ち、その後 `lightnode-sx onboard` から `register` までを実行します。

[ライトノード概要](/light-node/overview)および[登録とライセンス](/light-node/registration-and-licensing)をご覧ください。

:::note アドレスが必須になる前に購入したライセンス
アドレスが収集される前にライセンスを購入した場合、タブは **This licence needs a QoreChain address** と表示されて開きます。アドレスを入力し、**Save address** を選択してください。保存されるまで、ライセンスは付与できません。
:::

### Node Registration {#node-registration}

バリデーターの詳細をAssociationに記録します。バリデーターをオンチェーンで作成するものではなく、それは自分のノードから `create-validator` で行います。付与がオンチェーンに反映されるまで、このタブはロックされています。

フォームは、チェーン上で運用者アドレスに有効な `validator_operator` 付与が確認でき、かつ選考を通過したValidator Programの申請（またはプログラム開始前のバリデーターライセンス）を保有している場合に開きます。運用者アドレス、**Moniker**、5%から20%の間の **Commission**、任意のエンドポイントを入力し、確認事項（100,000 QORのセルフステーク、21日間のアンボンディング期間、スラッシング）にチェックを入れて、**Register validator** を選択します。

オンチェーンの手順は[バリデーターの運用](/developer-guide/running-a-validator)にあります。PQC鍵を登録し、QoreChainのすべてのトランザクションと同様にPQC共同署名した `create-validator` を、100,000 QOR以上のセルフステークとともに送信します。ステーキングとバリデーターの作成は、ネイティブトランザクションレーンでのみ行われます。MetaMaskのような連携済みのEVMウォレットを通じてバリデーターを登録・ボンドする方法はありません。フォームの下には、リリースマニフェストに基づき、フルノードに必要なもの（リリースバイナリ、ジェネシス、ピア）も一覧表示され、ネットワークが新しいバリデーターを受け付けていない場合は「Joining is temporarily suspended」のバナーが表示されることがあります。[ステーキングとバリデーター](/dashboard/staking-and-validators)をご覧ください。

### Rollups {#rollups}

このタブのタイトルは **Request a Rollup** です。フォームに、名前、仮想マシン（EVM、QoreChain Native、SVM）、データ可用性レイヤー（QoreChain DA、Celestia、EigenDA）、ガストークン、シーケンサー（Shared sequencer、Dedicated (single)、Decentralized）、決済先（QoreChain mainnet、Ethereum）を入力し、**Request deployment** を選択します。これはリクエストを記録するだけで、フォームの下にそのステータスとともに一覧表示されます。この段階でオンチェーンに何かが作成されるわけではありません。選択肢は、オンチェーンのロールアップモジュールが現在サポートしている範囲よりも広くなっています。ロールアップを自分でオンチェーンに登録するには[ロールアップのデプロイ](/rollups/deploying-a-rollup)を、コンセプトについては[ロールアップ概要](/rollups/overview)をご覧ください。

## アクセス方法 {#how-to-access}

- **URL：** [dashboard.qorechain.io/tools](https://dashboard.qorechain.io/tools)、またはサイドバーの **Build** グループにある **Nodes & Validators**。
- **サインイン：** ページ全体で必要です。両方のネットワークで同じです。
- **ネットワーク：** ヘッダーに従います。$50のライセンス購入はメインネットのみ、無料ライセンスはテストネットのみです。
- **費用：** 申請は無料です。バリデーターのプログラム手数料は$1,000で、選考通過後にのみ支払います。メインネットのライトノードライセンスは$50、テストネットのライセンスは無料です。
- **ウォレット：** ノード用に、リカバリーワードを自分で保持しているアカウント。タブを閲覧するだけならウォレットは不要です。

## 制限と既知の問題 {#limits}

- **メインネットの付与は手作業で、** バッチ単位に署名されるため、支払い済みのライセンスは「Paid, awaiting on-chain grant」の状態で待機します。テストネットの付与は自動です。
- **無料のテストネットリクエストは、** アカウントごと、アドレスごとに1回です。
- **Rollups は両方のネットワークでリクエストフォームであり、** オンチェーンには何も作成しません。
- **バリデーターとしての参加は一時停止されることがあります**（「Joining is temporarily suspended」のバナー）。
- **USDTの受取情報と支給金の金額は、** 支払いまたは申請の時点にタブの中でのみ表示されます。

ネットワーク全体でのライセンスの仕組みについては、[チェーンライセンス](/architecture/chain-licensing)をご覧ください。
