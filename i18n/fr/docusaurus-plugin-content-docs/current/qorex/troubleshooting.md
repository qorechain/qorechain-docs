# Dépannage

Questions courantes et solutions rapides pour l'application et l'extension QoreX.

| Symptôme | Cause / solution |
|---|---|
| **« Sécurisez d'abord votre appareil »** lors de l'intégration | Configurez Face ID / une empreinte digitale **ou un verrouillage d'écran (code PIN / schéma)** dans les paramètres de votre système, puis revenez. Un portefeuille ne peut être créé que sur un appareil doté d'un facteur de déverrouillage robuste. Sur Android, le déverrouillage facial 2D seul est une biométrie *faible* - c'est le code PIN qui le sous-tend qui est qualifiant. |
| **Feuille de connexion fermée** / « Cette tentative de connexion a expiré » | Une tentative précédente a été abandonnée - appuyez simplement de nouveau sur connexion. |
| **« Ajouter une clé d'accès » absent** après une connexion Google / Dashboard | Comportement attendu : les clés d'accès ne se rattachent qu'aux comptes par code e-mail (voir la note dans [Compte et Dashboard](/qorex/account-and-dashboard#sign-in)). |
| **« Les identifiants arrivent bientôt »** | Le registre des @handles est temporairement injoignable. Votre portefeuille n'est pas affecté ; les identifiants s'activent automatiquement à son retour. |
| **Extension : le paiement d'un @handle échoue avec une erreur sur la recherche** | Corrigé dans l'extension **0.3.7** et ultérieure (tous les stores servent désormais la 0.4.5). Si votre extension est plus ancienne, mettez-la à jour depuis la page des extensions de votre navigateur ; en attendant, collez plutôt l'adresse `qor1…`, ou utilisez l'application mobile. |
| **L'extension n'a aucun moyen de réclamer un @handle** | Comportement attendu : la réclamation nécessite un compte connecté et se fait dans l'application mobile. Une fois réclamé, vous pouvez le payer et le résoudre depuis l'extension. |
| **Un handle que j'ai essayé de réclamer est refusé comme réservé** | Les noms qui imitent QoreChain (ses noms de marque, ou des mots de confiance tels que *official*, *support*, *airdrop*, *treasury*, y compris les orthographes qui leur ressemblent) sont réservés. Choisissez un autre handle. |
| **Une approbation indique que QoreX ne peut pas afficher la requête, ou la refuse comme ambiguë** | QoreX n'affichera pas une requête qu'il ne peut pas décoder, ni une dont les octets pourraient se lire de deux façons (par exemple un champ répété de sorte que des frais ou un montant se lisent différemment à l'écran et sur la chaîne). Ne cherchez pas de contournement - le site envoie quelque chose de dangereux ou non pris en charge. |
| **QoreX vous avertit que l'adresse d'un identifiant a changé** | Comportement de sécurité attendu, pas un bug - QoreX mémorise l'adresse à laquelle un identifiant a résolu la première fois que vous l'avez payé, et signale tout changement ultérieur plutôt que de lui faire confiance silencieusement. Confirmez la nouvelle adresse hors bande avec le destinataire avant de continuer. |
| **Envoi refusé pour « plus que votre solde disponible »** sur un compte avec acquisition progressive (vesting) | Une partie de votre solde est encore verrouillée par un calendrier d'acquisition progressive (vesting). Seule la portion **disponible** (affichée sur Accueil, Envoyer et le détail de l'actif) peut être envoyée ; le reste se libère progressivement. |
| **Une demande de portefeuille indique qu'elle est « pour le testnet/mainnet, mais votre portefeuille est sur… »** | La demande (par exemple depuis le Dashboard) cible un réseau différent de celui auquel vous êtes actuellement connecté. Changez vous-même de réseau au préalable si c'est bien votre intention - QoreX ne changera pas de réseau à votre place. |
| **« Code erroné ou QR endommagé »** lors de l'association d'appareils | Revérifiez le code à 10 caractères (l'alphabet exclut les caractères ressemblants : pas de 0/O/1/I/L) et rescannez. Les deux éléments sont à usage unique. |
| **L'écran de la caméra indique qu'une autorisation est nécessaire** | iOS : Réglages → QoreX → Caméra. Android : Infos sur l'appli → Autorisations → Caméra. |
| **Extension : aucun portefeuille à la première ouverture** | L'extension est un portefeuille **autonome** - ouvrez la fenêtre contextuelle et choisissez **Créer un portefeuille** ou **Importer un portefeuille**. Elle ne nécessite pas l'application mobile. |
| **Envoi refusé depuis une adresse en lecture seule** | Cette adresse appartient à un autre portefeuille (l'étiquette indique lequel). QoreX ne peut signer que pour ses propres comptes dérivés - envoyez depuis le portefeuille qui la possède. |
| **Badge Testnet affiché** | Vous êtes sur le testnet. Dans l'application, désactivez Réglages → **« Utiliser le testnet (développeurs) »**. Dans l'extension, choisissez **Revenir au mainnet** dans la section développeur en bas de l'accueil de la fenêtre. |
| **Le bouton d'échange est désactivé** | Comportement attendu pour l'instant (Android) - l'échange s'active automatiquement dès que la liquidité du pool est disponible ; aucune mise à jour de l'application n'est nécessaire. L'onglet Échange n'est pas affiché sur iOS, et l'extension n'a pas d'écran d'échange. |
| **J'ai désinstallé l'application / retiré l'extension et je ne vois plus aucun portefeuille** | Le coffre ne vivait que sur cet appareil ou dans ce navigateur. Si vous aviez sauvegardé votre phrase de 24 mots, restaurez-la avec elle. Si vous aviez configuré la [récupération sociale](/qorex/security-and-recovery#social-recovery), lancez une récupération avec vos gardiens. Sans l'un ou l'autre, le portefeuille ne peut pas être récupéré - consultez [Sauvegardez maintenant](/qorex/security-and-recovery#back-up-now) pour protéger immédiatement tout nouveau portefeuille. |
| **Je ne retrouve pas mes 24 mots / l'application ne me les a jamais montrés** | L'application mobile n'affiche pas la phrase pendant qu'elle crée le portefeuille. Ouvrez **Réglages → Sécurité → Afficher la phrase de récupération** et confirmez avec la biométrie ou le code PIN de votre appareil, puis notez les mots. Dans l'extension, utilisez **Afficher la phrase de récupération** dans la fenêtre contextuelle (votre mot de passe est requis). Si le portefeuille n'existe que sur un téléphone que vous avez déjà perdu, QoreChain ne peut pas le récupérer - consultez [Sauvegardez maintenant](/qorex/security-and-recovery#back-up-now). |
| **Un compte financé a disparu de « Vos comptes »** | Rien n'est perdu - chaque compte se redérive de votre phrase de récupération, il s'agit donc d'un problème d'affichage, pas d'une perte de données. C'était un vrai bug, désormais corrigé, sur les versions mobiles antérieures à **1.0.9** : un échec momentané de lecture depuis le stockage sécurisé de l'appareil (le plus probable juste au déverrouillage) pouvait afficher une liste de comptes raccourcie. Mettez à jour QoreX (le correctif est livré dans la 1.0.9 et toutes les versions ultérieures) ; si vous êtes déjà à jour et que cela se produit, fermer puis rouvrir l'application devrait le faire réapparaître - appuyer sur « ajouter un compte » créerait un **nouveau** compte au lieu de restaurer celui qui manque, donc évitez cela tant que le compte existant n'est pas réapparu. |
| **« The EVM lane needs an open authorisation window for this account. Open one here first - MetaMask cannot. »** (ou « Your EVM authorisation window has run out », ou « That authorisation window was refused ») | Une transaction MetaMask / lane EVM a été refusée parce que le compte n'a pas de fenêtre ouverte (ou qu'elle a épuisé ses blocs, ses transactions ou sa valeur). Ouvrez-en une sous [Fenêtre d'accès EVM](/qorex/security-and-recovery#evm-window) (elle concerne les comptes de type Ethereum, coin 60), puis réessayez. Ouvrez-la *avant* d'envoyer - l'ouverture d'une fenêtre fait avancer le nonce du compte, donc une transaction préparée plus tôt échoue avec « nonce too low ». Si votre compte n'a pas encore de clé ML-DSA-87, QoreX vous demande d'en enregistrer une d'abord. |
| **« This network needs an updated QoreX. Update the app and try again - nothing was sent. »** | Le réseau vérifie une forme de signature plus récente que celle que produit votre version. Mettez à jour QoreX depuis votre store et réessayez ; rien n'a été envoyé et aucun frais n'a été prélevé. |
| **« Too many transactions from this account in a short time. Wait a minute and try again. »** | Le réseau limite le nombre de transactions qu'un compte peut envoyer sur une courte période. Attendez une minute. |
| **« That address can't receive ordinary transfers. »** | Le réseau refuse les transferts simples vers cette adresse (certaines adresses système ou de module). Vérifiez le destinataire. |
| **« Not enough unlocked QOR to pay the network fee. Vesting QOR cannot pay fees… »** ou **« Claiming needs about … QOR unlocked »** | Les réclamations et le unstaking paient leurs frais depuis votre solde *déverrouillé* (avant l'arrivée des récompenses). Envoyez un petit montant de QOR à cette adresse, puis réessayez. |
| **« The network ran out of gas before finishing. The fee was taken and nothing moved - your rewards are still there. »** | La transaction a atteint un bloc et y a échoué. Réessayez ; les frais de la tentative échouée sont dépensés. |
| **« Unstaking this much would drop your validator's self-bond below the required 100,000 QOR. »** | Ne concerne que les opérateurs de validateurs : le plancher d'auto-délégation s'applique aussi longtemps que le validateur fonctionne. Retirez moins. |
| **« Account 'qor1…' does not exist on chain »** lors d'un envoi depuis un compte restauré à partir du Dashboard ou de MetaMask | Mettez QoreX à jour vers la version actuelle ; le compte est un compte de type Ethereum (coin 60) - voir [Restaurer une phrase depuis MetaMask ou le Dashboard](/qorex/getting-started#restore-dashboard). Le premier envoi enregistre aussi la clé ML-DSA-87 de ce compte (un petit frais supplémentaire). |
| **J'ai restauré ma phrase et mon deuxième compte / mes fonds sont manquants** | La restauration ne ramène que le **Compte 1**. Appuyez sur **Ajouter un compte** (et, pour une phrase utilisée dans MetaMask ou sur le Dashboard, **Ajouter un compte Ethereum (coin 60)**) dans Réglages → Tes comptes - les comptes se redérivent aux mêmes adresses. |
| **Extension : « Portefeuilles » indique que la clé d'accès a été désactivée** | Ajouter ou retirer un portefeuille re-scelle le coffre et supprime le déverrouillage par clé d'accès (il ne pouvait pas couvrir le nouveau portefeuille). Réactivez-le depuis l'écran d'accueil de la fenêtre contextuelle ; Firefox ne propose jamais le déverrouillage par clé d'accès. |
| **Aucune notification push n'est arrivée** | Le push n'existe que sur le mainnet et exige que les notifications soient autorisées pour QoreX dans les réglages de votre téléphone, ainsi que l'interrupteur **Notifications push** activé (Accueil → cloche). Il vous indique seulement que du QOR est arrivé, pas le montant ; la liste **Notifications** de l'application en donne le détail. |
| **Android : le bouton Retour** | Retour ramène à l'écran précédent ; sur Accueil, il quitte l'application. |
| **Un site m'a demandé de signer alors que l'extension était verrouillée** | À partir de la 0.4.5, l'extension s'ouvre sur l'écran du mot de passe et nomme le site. Saisissez votre mot de passe ; cette fenêtre se ferme et la demande affiche sa propre approbation. Fermer la fenêtre à la place refuse la demande, et rien n'est signé. Si un site répond encore « wallet is locked » (portefeuille verrouillé), mettez l'extension à jour. |
| **Extension : le bouton de déverrouillage ne fait rien ou affiche une erreur** | La touche Entrée ou **Déverrouiller** lance le déverrouillage et le bouton montre qu'il travaille, ce qui prend volontairement un moment. **Mot de passe incorrect.** n'apparaît que pour un mauvais mot de passe ; tout autre message désigne un autre échec, lisez-le donc. Voir [Déverrouillage et verrouillage automatique](/qorex/browser-extension#unlock). |
| **QoreX se verrouille sans cesse** | C'est le verrouillage automatique (15 minutes par défaut). Modifiez **Verrouiller automatiquement après** sur l'accueil de la fenêtre de l'extension, ou dans l'application sous Réglages → Sécurité (1, 5, 15, 30, 60 ou 240 minutes). |
| **« This account's post-quantum key on the network can no longer sign »** (la clé post-quantique du compte ne permet plus de signer, ou un message indiquant que la clé enregistrée ne peut plus signer) | L'enregistrement de clé sur le réseau est vide, uniquement classique ou autrement inutilisable ; le compte ne peut donc pas envoyer ; rien n'a été envoyé et aucuns frais n'ont été prélevés. Dans l'application 1.2.5 / l'extension 0.4.5, même si un ancien message mentionne une mise à jour ultérieure, l'écran d'accueil propose **Enregistrer la clé à nouveau** : il affiche les frais de réseau et demande un second toucher (plus la biométrie dans l'application). Ce n'est jamais fait à votre place. Si le compte a une fenêtre EVM, le réseau la ferme ; ouvrez-en une nouvelle ensuite. Voir [Entretien de la clé post-quantique](/qorex/browser-extension#pqc-care). |
| **« This account's ML-DSA-87 key on the network was registered by another wallet »** (la clé ML-DSA-87 du compte a été enregistrée par un autre portefeuille) | QoreX ne peut pas signer avec une clé qu'il ne peut pas dériver de votre phrase de récupération. Utilisez le portefeuille qui a enregistré la clé. |
| **Après le changement de la clé post-quantique, un autre portefeuille avec la même phrase ne peut pas signer** | C'est attendu : les autres portefeuilles utilisant la même phrase ne peuvent pas signer pour ce compte tant qu'ils ne prennent pas en charge les clés changées. Restaurer la phrase dans QoreX retrouve la bonne clé. Le changement protège contre la fuite d'une clé post-quantique, pas contre la fuite d'une phrase de récupération. |
| **L'appel de contrat d'un site est refusé alors qu'une fenêtre EVM est ouverte** | Une fenêtre que vous ouvrez vous-même est par défaut en **Transferts de QOR uniquement**, ce qui n'admet aucun appel de contrat. Choisissez **N'importe quel contrat** à l'ouverture (lisez l'avertissement : les jetons déplacés par un contrat ne sont pas limités par le plafond), ou fermez-la et laissez l'approbation du site ouvrir une fenêtre pour cette seule transaction. Le texte de la fenêtre ouverte indique ce qu'elle admet. Voir [Fenêtre d'accès EVM](/qorex/security-and-recovery#evm-window). |
| **QoreX demande une seconde fois avant d'ouvrir une fenêtre** (« The network did not accept a window limited to … » ou « This network cannot limit the window to QOR transfers yet ») | Le réseau ne peut pas appliquer cette limite. Approuver ouvre une fenêtre qui admet **n'importe quel contrat** ; rejeter n'ouvre rien et n'envoie rien. |
| **« What it does to your tokens was not checked »** (l'effet sur vos jetons n'a pas été vérifié) | Le nœud peut seulement vérifier que l'appel n'échouerait pas, pas ce qu'il déplace. N'approuvez (il faut un second toucher) que si vous faites confiance au site. |
| **La transaction d'un site est refusée avant l'approbation** | QoreX simule d'abord les appels de contrat ; si le contrat devait refuser l'appel, vous voyez le motif du réseau au lieu d'une approbation. Une transaction dépassant la limite de gaz par transaction du réseau est aussi refusée avant toute signature. |
| **Un site ne peut pas fermer ma fenêtre EVM ni modifier mes autorisations** | C'est attendu : ces demandes ne sont acceptées que depuis les écrans de QoreX. Fermez la fenêtre sur l'écran **Fenêtre d’accès EVM**. |
| **Un lien de paiement est refusé** | QoreX dit pourquoi : le lien n'est pas un lien de paiement valide, a été **modifié après sa signature**, ou n'a **pas été signé par le propriétaire de l'adresse de réception** (ne payez dans aucun de ces deux derniers cas) ; il vise un réseau que QoreX ne connaît pas, ou l'autre réseau (changez-en vous-même si c'est bien ce que vous voulez) ; ou il demande une cryptomonnaie autre que QOR. Demandez un nouveau lien au demandeur. |
| **Une demande de paiement indique toujours « Pas encore payée »** | Une demande n'est marquée comme payée que lorsque la chaîne montre un paiement réussi d'au moins ce montant vers votre adresse avec l'étiquette de la demande dans son mémo. Un paiement envoyé sans l'étiquette (par exemple depuis un portefeuille qui a perdu le mémo) n'est pas rapproché. Touchez à nouveau **Vérifier le statut** après la confirmation de la transaction ; « Status unknown » (statut inconnu) signifie que le réseau n'a pas répondu. |
| **Un lien censé ouvrir une page dans l'application est refusé** | Un lien browse n'ouvre qu'une page `https://` sur un nom de domaine, sans port, nom d'utilisateur ni mot de passe, adresse IP ou `localhost`, et d'au plus 2,048 caractères. Sans portefeuille sur le téléphone, l'application reste sur l'écran de bienvenue. |
| **Une bannière indique que le réseau est lent ou injoignable** | **Lent** : le dernier bloc de la chaîne date de plus d'une minute ; les transactions peuvent donc prendre plus de temps. **Réseau injoignable** : les soldes ne sont peut-être pas à jour. QoreX lit cela sur la chaîne elle-même. Vérifiez votre connexion Internet et patientez ; ne renvoyez pas un paiement avant d'avoir consulté l'[Historique](/qorex/browser-extension#history) (ou Activité dans l'application). |
| **Les soldes sont désignés comme dernières valeurs connues** | Le réseau n'a pas répondu ; QoreX affiche donc ce qu'il a lu en dernier et indique de quand cela date. La mise à jour a lieu quand le réseau répond. |
| **Une transaction affiche « En attente » ou « Introuvable sur le réseau »** | En attente : elle a été envoyée depuis cet appareil et l'historique de la chaîne ne la montre pas encore. Introuvable : elle a peut-être échoué. Vérifiez la transaction avant de renvoyer. |
| **Un avertissement indique qu'une adresse ne fait que ressembler à une adresse que je connais** | Les escrocs glissent des adresses ressemblantes. Comparez chaque caractère avec l'adresse enregistrée ou déjà payée qui est affichée. Ne continuez que si la nouvelle adresse est bien celle que vous voulez. |
| **Je ne trouve pas les outils développeur** | Le Mode développeur est désactivé par défaut. Application : activez l'interrupteur **Mode développeur** dans les Réglages ; un onglet **Développeur** apparaît dans la barre du bas. Extension : touchez sept fois le numéro de version en bas de la fenêtre, puis ouvrez **Outils développeur**. Voir [Mode développeur](/qorex/developer-mode). |
| **Les agents IA sont indisponibles, ou le programme auxiliaire est « injoignable »** | Dans l'extension, les agents se connectent via un programme compagnon qui n'est pas encore publié, et la fonctionnalité n'est pas disponible dans Safari. Dans l'application, collez une proposition ou ouvrez un lien de proposition. |
| **Je ne trouve pas « envoyer vers une autre chaîne », l'écran Bridge ou Solana sur QoreChain** | Ils sont **réservés au testnet** (Solana sur QoreChain se trouve aussi sous le Mode développeur). L'écran Bridge montre l'état réel de chaque route ; toutes les routes sont fermées sur le testnet aujourd'hui, donc rien n'est proposé. Voir [Fonctionnalités du testnet](/qorex/testnet-features). |

## Toujours bloqué ?

Ouvrez **Assistance** dans QoreX (les Réglages de l'application, ou l'accueil de la fenêtre de l'extension). L'écran liste uniquement les canaux officiels :

- [Communauté Telegram](https://t.me/QorechainCommunity)
- [Discord](https://discord.gg/qorechain)
- [Page d'aide](https://qorechain.io/help/qorex)
- E-mail : team@qorechain.io
- Problèmes de sécurité : **Signaler une vulnérabilité** (voir [qorechain.io/security](https://qorechain.io/security))

L'équipe QoreX ne demande jamais votre phrase de récupération, votre mot de passe ni vos clés. Si l'assistance le demande, **Afficher le résumé** sur cet écran donne un résumé de diagnostic sans phrase, clés, adresses ni soldes.

- Consultez la page [Sécurité et récupération](/qorex/security-and-recovery) pour les gardiens et l'association d'appareils.
- Pour des questions sur QoreChain lui-même, voir la [documentation principale](/introduction/what-is-qorechain) ou les canaux communautaires liés sur [qorechain.io](https://qorechain.io).
