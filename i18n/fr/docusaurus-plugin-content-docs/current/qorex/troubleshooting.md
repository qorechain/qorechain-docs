# Dépannage

Questions courantes et solutions rapides pour l'application et l'extension QoreX.

| Symptôme | Cause / solution |
|---|---|
| **« Sécurisez d'abord votre appareil »** lors de l'intégration | Configurez Face ID / une empreinte digitale **ou un verrouillage d'écran (code PIN / schéma)** dans les paramètres de votre système, puis revenez. Un portefeuille ne peut être créé que sur un appareil doté d'un facteur de déverrouillage robuste. Sur Android, le déverrouillage facial 2D seul est une biométrie *faible* — c'est le code PIN qui le sous-tend qui est qualifiant. |
| **Feuille de connexion fermée** / « Cette tentative de connexion a expiré » | Une tentative précédente a été abandonnée — appuyez simplement de nouveau sur connexion. |
| **« Ajouter une clé d'accès » absent** après une connexion Google / Dashboard | Comportement attendu : les clés d'accès ne se rattachent qu'aux comptes par code e-mail (voir la note dans [Compte et Dashboard](/qorex/account-and-dashboard#sign-in)). |
| **« Les identifiants arrivent bientôt »** | Le registre des @handles est temporairement injoignable. Votre portefeuille n'est pas affecté ; les identifiants s'activent automatiquement à son retour. |
| **QoreX vous avertit que l'adresse d'un identifiant a changé** | Comportement de sécurité attendu, pas un bug — QoreX mémorise l'adresse à laquelle un identifiant a résolu la première fois que vous l'avez payé, et signale tout changement ultérieur plutôt que de lui faire confiance silencieusement. Confirmez la nouvelle adresse hors bande avec le destinataire avant de continuer. |
| **Envoi refusé pour « plus que votre solde disponible »** sur un compte avec acquisition progressive (vesting) | Une partie de votre solde est encore verrouillée par un calendrier d'acquisition progressive (vesting). Seule la portion **disponible** (affichée sur Accueil, Envoyer et le détail de l'actif) peut être envoyée ; le reste se libère progressivement. |
| **Une demande de portefeuille indique qu'elle est « pour le testnet/mainnet, mais votre portefeuille est sur… »** | La demande (par exemple depuis le Dashboard) cible un réseau différent de celui auquel vous êtes actuellement connecté. Changez vous-même de réseau au préalable si c'est bien votre intention — QoreX ne changera pas de réseau à votre place. |
| **« Code erroné ou QR endommagé »** lors de l'association d'appareils | Revérifiez le code à 10 caractères (l'alphabet exclut les caractères ressemblants : pas de 0/O/1/I/L) et rescannez. Les deux éléments sont à usage unique. |
| **L'écran de la caméra indique qu'une autorisation est nécessaire** | iOS : Réglages → QoreX → Caméra. Android : Infos sur l'appli → Autorisations → Caméra. |
| **Extension : aucun portefeuille à la première ouverture** | L'extension est un portefeuille **autonome** — ouvrez la fenêtre contextuelle et choisissez **Créer un portefeuille** ou **Importer un portefeuille**. Elle ne nécessite pas l'application mobile. |
| **Envoi refusé depuis une adresse en lecture seule** | Cette adresse appartient à un autre portefeuille (l'étiquette indique lequel). QoreX ne peut signer que pour ses propres comptes dérivés — envoyez depuis le portefeuille qui la possède. |
| **Badge testnet affiché** | Paramètres → **« Utiliser le testnet (développeurs) »** est activé. Désactivez-le pour revenir au mainnet. |
| **Le bouton d'échange est désactivé** | Comportement attendu pour l'instant (Android) — l'échange s'active automatiquement dès que la liquidité du pool est disponible ; aucune mise à jour de l'application n'est nécessaire. L'onglet Échange n'est pas affiché sur iOS, et l'extension n'a pas d'écran d'échange. |
| **J'ai désinstallé l'application / retiré l'extension et je ne vois plus aucun portefeuille** | Le coffre ne vivait que sur cet appareil ou dans ce navigateur. Si vous aviez sauvegardé votre phrase de 24 mots, restaurez-la avec elle. Si vous aviez configuré la [récupération sociale](/qorex/security-and-recovery#social-recovery), lancez une récupération avec vos gardiens. Sans l'un ou l'autre, le portefeuille ne peut pas être récupéré — consultez [Sauvegardez maintenant](/qorex/security-and-recovery#back-up-now) pour protéger immédiatement tout nouveau portefeuille. |
| **Je ne retrouve pas mes 24 mots / l'application ne me les a jamais montrés** | L'application mobile n'affiche pas la phrase pendant qu'elle crée le portefeuille. Ouvrez **Paramètres → Sécurité → Afficher la phrase de récupération** et confirmez avec la biométrie ou le code PIN de votre appareil, puis notez les mots. Dans l'extension, utilisez **Afficher la phrase de récupération** dans la fenêtre contextuelle (votre mot de passe est requis). Si le portefeuille n'existe que sur un téléphone que vous avez déjà perdu, QoreChain ne peut pas le récupérer — consultez [Sauvegardez maintenant](/qorex/security-and-recovery#back-up-now). |
| **Un compte financé a disparu de « Vos comptes »** | Rien n'est perdu — chaque compte se redérive de votre phrase de récupération, il s'agit donc d'un problème d'affichage, pas d'une perte de données. C'était un vrai bug, désormais corrigé, sur les versions mobiles antérieures à **1.0.9** : un échec momentané de lecture depuis le stockage sécurisé de l'appareil (le plus probable juste au déverrouillage) pouvait afficher une liste de comptes raccourcie. Mettez à jour QoreX (le correctif est livré dans la 1.0.9 et toutes les versions ultérieures) ; si vous êtes déjà à jour et que cela se produit, fermer puis rouvrir l'application devrait le faire réapparaître — appuyer sur « ajouter un compte » créerait un **nouveau** compte au lieu de restaurer celui qui manque, donc évitez cela tant que le compte existant n'est pas réapparu. |
| **« The EVM lane needs an open authorisation window for this account. Open one here first — MetaMask cannot. »** (ou « Your EVM authorisation window has run out », ou « That authorisation window was refused ») | Une transaction MetaMask / lane EVM a été refusée parce que le compte n'a pas de fenêtre ouverte (ou qu'elle a épuisé ses blocs, ses transactions ou sa valeur). Ouvrez-en une sous [Fenêtre d'accès EVM](/qorex/security-and-recovery#evm-window), puis réessayez. Ouvrez-la *avant* d'envoyer — l'ouverture d'une fenêtre fait avancer le nonce du compte, donc une transaction préparée plus tôt échoue avec « nonce too low ». Si votre compte n'a pas encore de clé post-quantique, QoreX vous demande d'en enregistrer une d'abord. |
| **« This network needs an updated QoreX. Update the app and try again — nothing was sent. »** | Le réseau vérifie une forme de signature plus récente que celle que produit votre version. Mettez à jour QoreX depuis votre store et réessayez ; rien n'a été envoyé et aucun frais n'a été prélevé. |
| **« Too many transactions from this account in a short time. Wait a minute and try again. »** | Le réseau limite le nombre de transactions qu'un compte peut envoyer sur une courte période. Attendez une minute. |
| **« That address can't receive ordinary transfers. »** | Le réseau refuse les transferts simples vers cette adresse (certaines adresses système ou de module). Vérifiez le destinataire. |
| **« Not enough unlocked QOR to pay the network fee. Vesting QOR cannot pay fees… »** ou **« Claiming needs about … QOR unlocked »** | Les réclamations et le unstaking paient leurs frais depuis votre solde *déverrouillé* (avant l'arrivée des récompenses). Envoyez un petit montant de QOR à cette adresse, puis réessayez. |
| **« The network ran out of gas before finishing. The fee was taken and nothing moved — your rewards are still there. »** | La transaction a atteint un bloc et y a échoué. Réessayez ; les frais de la tentative échouée sont dépensés. |
| **« Unstaking this much would drop your validator's self-bond below the required 100,000 QOR. »** | Ne concerne que les opérateurs de validateurs : le plancher d'auto-délégation s'applique aussi longtemps que le validateur fonctionne. Retirez moins. |
| **« Account 'qor1…' does not exist on chain »** lors d'un envoi depuis un compte restauré à partir du Dashboard ou de MetaMask | Mettez QoreX à jour vers la version actuelle ; le compte est un compte de type Ethereum (coin 60) — voir [Restaurer une phrase depuis MetaMask ou le Dashboard](/qorex/getting-started#restore-dashboard). Le premier envoi enregistre aussi la clé post-quantique de ce compte (un petit frais supplémentaire). |
| **J'ai restauré ma phrase et mon deuxième compte / mes fonds sont manquants** | La restauration ne ramène que le **Compte 1**. Appuyez sur **Ajouter un compte** (et, pour une phrase utilisée dans MetaMask ou sur le Dashboard, **Ajouter un compte Ethereum (coin 60)**) dans Paramètres → Vos comptes — les comptes se redérivent aux mêmes adresses. |
| **Extension : « Portefeuilles » indique que la clé d'accès a été désactivée** | Ajouter ou retirer un portefeuille re-scelle le coffre et supprime le déverrouillage par clé d'accès (il ne pouvait pas couvrir le nouveau portefeuille). Réactivez-le depuis l'écran d'accueil de la fenêtre contextuelle ; Firefox ne propose jamais le déverrouillage par clé d'accès. |
| **Aucune notification push n'est arrivée** | Le push n'existe que sur le mainnet et exige que les notifications soient autorisées pour QoreX dans les réglages de votre téléphone, ainsi que l'interrupteur **Notifications push** activé (Accueil → cloche). Il vous indique seulement que du QOR est arrivé, pas le montant ; la liste **Notifications** de l'application en donne le détail. |
| **Android : le bouton Retour** | Retour ramène à l'écran précédent ; sur Accueil, il quitte l'application. |
